دیباگرها چه می‌کنند؟

یک دیباگر مثل gdb به شما اجازه می‌دهد اجرای برنامه را ببرید، در نقطه‌های شکست (breakpoint) متوقف کنید، و وضعیت حافظه و پشته را بررسی کنید. برای نوشتن دیباگر لینوکس، مفاهیم اصلی سه‌گانه‌اند: ptrace (API هسته برای کنترل فرآیندها)، ELF (فرمت باینری) و DWARF (متادیتای دیباگِ ترسیمی).

این آموزش در چند «قسمت»، از صفر همین سه لایه را پیاده می‌کند و در پایان به یک tui دیباگر قابل استفاده می‌رسد.

ptrace: بنیان همه‌چیز

مهم‌ترین فراخوانی، `ptrace` است که با `PTRACE_ATTACH` به فرآیند می‌چسبد، با `PTRACE_CONT` آن را ادامه می‌دهد و با `PTRACE_PEEKDATA` حافظه را می‌خواند. برای خواندن وضعیت رجیسترها از `PTRACE_GETREGS` استفاده می‌شود:

C++// شروع: پیوستن به یک فرآیند و خواندن رجیسترها
#include <sys/ptrace.h>
#include <sys/user.h>
#include <sys/wait.h>

void continue_execution(pid_t pid) {
    if (ptrace(PTRACE_CONT, pid, nullptr, nullptr) == -1) {
        perror("ptrace CONT");
        return;
    }
    waitpid(pid, nullptr, 0);
}

void get_registers(pid_t pid, user_regs_struct& regs) {
    if (ptrace(PTRACE_GETREGS, pid, nullptr, &regs) == -1) {
        perror("ptrace GETREGS");
    }
}

در این مرحله، وقتی فرآیند متوقف شد، `PTRACE_GETREGS` محتوای رجیسترها (مثل rip) را برمی‌گرداند و شما می‌توانید پشته را دنبال کنید.

نقطه‌های شکست

ساده‌ترین روش برای breakpoint، جایگزینی بایت اول دستور در آدرس موردنظر با `0xcc` (دستور INT3) است و پس از وقفه، مقدار اصلی را دوباره برمی‌گردانید. به یاد داشته باشید پس از برخورد، يكبایت must به قبل برگردد (rip--).

C++// تنظیم breakpoint: ذخیره بایت اصلی و جایگزینی با 0xcc
uint64_t set_breakpoint(pid_t pid, uint64_t addr) {
    uint64_t data = ptrace(PTRACE_PEEKDATA, pid, addr, nullptr);
    uint64_t intr = (data & 0xFFFFFFFFFFFFFF00) | 0xCC;
    ptrace(PTRACE_POKEDATA, pid, addr, intr);
    return data;   // برای بازیابی بعدی
}

void unset_breakpoint(pid_t pid, uint64_t addr, uint64_t orig) {
    ptrace(PTRACE_POKEDATA, pid, addr, orig);
}

این دو تابع، هستهٔ هر سیستم دیباگینگ هستند — همان چیزی که در gdb رخ می‌دهد.

مفاهیم DWARF و متادیتا

برای نمایش نام متغیرها و خطوط کد، باید بخش `.debug_info` فایل ELF را بخوانیم (استاندارد DWARF). دیباگر شما باید درتمامآدرس‌ها jumptable داشته باشد: آدرس ← نام فایل/خط، stdin تا بتوانید «مکان فعلی اجرا» را نشان دهید.

پیاده‌سازی کامل، در سری آموزش گام‌به‌گام تاjابادبلیو بخش‌های خط (line table) و expression‌های DWARF پیش می‌رود.

جمع‌بندی

ساختن دیباگر، عمیق‌ترین درک را از «اجرای برنامه» به شما می‌دهد: رجیسترها، پشته، breakpoint و فرآیندهای یونیکس. اگر می‌خواهید پشت صحنهٔ gdb/LLDB را بفهمید یا ابزار دیباگ خودتان را بسازید، این سری کامل‌ترین مرجع است.
