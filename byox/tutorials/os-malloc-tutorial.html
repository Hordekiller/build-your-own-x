Malloc Tutorial — ساخت malloc به زبان ساده (danluu)

⚙ زبان: C 🧠 مدیریت حافظه ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور مقالهٔ «Malloc Tutorial» از دن لو (Dan Luu) است — ساخت یک تخصیص‌دهندهٔ حافظهٔ ساده با C، بدون وابستگی، که می‌تواند جایگزین malloc استاندارد شود. این آموزش بر پایهٔ راهنمای «Build your own malloc» ماروان بورل (Marwan Burelle) نوشته شده.
↗ مشاهده منبع اصلی

۱. چرا malloc بسازیم؟

malloc از دید برنامه‌نویس یک «جعبهٔ جادویی» است. این آموزش جعبه را باز می‌کند: یک تخصیص‌دهندهٔ حافظه می‌سازیم که از سیستم‌عامل (با فراخوان sbrk) حافظهٔ خام می‌گیرد و آن را به برنامهٔ کاربر با ساختار بلوک‌ها تحویل می‌دهد. این پروژه پلی است بین برنامه‌نویسی معمولی و دنیای سیستم‌عامل — همان حافظه‌ای که kernelها مدیریت می‌کنند.

۲. ساختار داده: بلوک‌های لینک‌شده

قلب پیاده‌سازی، یک لینک‌لیست بلوک‌ها است. هر بلوک یک هدر دارد که چهار فیلد را نگه می‌دارد: اندازهٔ داده، اشاره‌گر به بلوک بعدی، پرچم آزاد بودن و یک «عدد جادویی» برای تشخیص خرابی حافظه:

ctypedef struct block_meta {
    size_t size;          // اندازه‌ی داده‌ی این بلوک
    struct block_meta *next;  // بلوک بعدی در لیست
    int free;             // 1 = آزاد، 0 = در حال استفاده
    int magic;            // عدد جادویی (برای پیدا کردن خرابی)
} block_meta_t;

#define META_SIZE sizeof(block_meta_t)
#define MAGIC 0x77777777
#define ALIGN 8            // هم‌ترازی: بلوک‌ها روی مرز ۸ بایت

void *global_base = NULL;  // ابتدای لیست بلوک‌ها

۳. تخصیص: پیدا کردن بلوک و شکستن آن

الگوریتم malloc: در لیست به دنبال یک بلوک آزاد و به‌اندازه‌ی کافی می‌گردیم. اگر پیدا شد، آن را آزاد بودن برمی‌داریم؛ اگر نه، با sbrk یک بلوک جدید از سیستم می‌گیریم. اگر بلوک آزاد خیلی بزرگ‌تر از نیاز بود، می‌توانیم آن را شکافت (split) کنیم و باقی‌مانده را به‌عنوان بلوک آزاد نگه داریم:

cvoid *malloc(size_t size) {
    block_meta_t *block;

    // هم‌ترازی ۸ بایتی اندازه
    size = (size + ALIGN - 1) & ~(ALIGN - 1);

    if (!global_base) {
        // اولین بار: یک بلوک اولیه از سیستم می‌گیریم
        block = request_space(NULL, size);
        if (!block) return NULL;
        global_base = block;
    } else {
        // جست‌وجوی یک بلوک آزادِ به‌اندازه
        block = find_free_block(global_base, &size);
        if (!block) {
            block = request_space(global_base, size);
            if (!block) return NULL;
        } else {
            block->free = 0;    // اشغال می‌شود
            block->magic = MAGIC;
        }
    }
    return block + 1;   // داده بعد از هدر شروع می‌شود
}

۴. آزادسازی و ادغام

برای free فقط کافی است پرچم بلوک را به «آزاد» تغییر دهیم (و با فراخوان munmap بلوک‌های آخر را به سیستم پس بدهیم). اما برای جلوگیری از پراکندگی حافظه (fragmentation)، بلوک‌های آزادِ کنار هم را با ادغام (coalescing) یکی می‌کنیم — اگر بلوک بعدی هم آزاد بود، بلوک فعلی را بزرگ‌تر اعلام می‌کنیم:

cvoid free(void *ptr) {
    if (!ptr) return;
    block_meta_t *block = (block_meta_t *) ptr - 1;
    block->free = 1;
    block->magic = 0;

    // ادغام با بلوک آزادِ بعدی
    if (block->next && block->next->free) {
        block->size += META_SIZE + block->next->size;
        block->next = block->next->next;
    }
}

جالب است که free خیلی ساده‌تر از malloc است — چون واقعاً «حذف» نمی‌کنیم، فقط به سیستم می‌گوییم این ناحیه قابل استفادهٔ مجدد است.

۵. نتیجه و آزمایش

آموزش با یک برنامهٔ تست تمام می‌شود که تخصیص و آزادسازی را با الگوهای مختلف بررسی می‌کند. تست کامل، این موارد را چک می‌کند: کارکرد ساده، تخصیص مکرر، آزادسازی، تخصیص مجدد همان آدرس، و نشت حافظهٔ احتمالی:

bashgcc -o test malloc.c test.c
valgrind --leak-check=full ./test
# خروجی: هیچ نشت حافظه‌ای وجود ندارد
نکتهٔ تکمیلی: این پروژه کوچک اما کامل، مفاهیمی را که در «مدیریت حافظهٔ هیپ» کرنل‌ها (مثل بخش ۷ آموزش جیمز مولی) می‌بینید، پیش از ورود به دنیای kernel به زبان ساده آموزش می‌دهد.
