مقدمه — داستان آجرها

یک روز، زنی هنگام قدم‌زدن به یک کارگاه ساختمانی رسید و سه مرد را دید که کار می‌کنند. از نفر اول پرسید: «چه می‌کنی؟» مرد اول که از سوال اذیت شده بود گفت: «نمی‌بینی آجر می‌چینم؟» زن که از جوابش راضی نشده بود از مرد دوم پرسید چه می‌کند. مرد دوم جواب داد: «دارم دیوار آجری می‌سازم.» باز راضی نشد و از مرد سوم پرسید. مرد سوم در حالی که به آسمان نگاه می‌کرد گفت: «من دارم بزرگ‌ترین کلیسای جامعی را می‌سازم که این دنیا به خودش دیده.»

مفهوم داستان این است که وقتی کل سیستم را می‌شناسید و می‌فهمید اجزای مختلف (آجرها، دیوارها، کلیسای جامع) چطور کنار هم می‌نشینند، می‌توانید مشکلات را سریع‌تر شناسایی و رفع کنید.

این چه ربطی به ساختن وب سرور از صفر دارد؟

نویسنده معتقد است برای بهتر شدن باید درک بهتری از سیستم‌های نرم‌افزاری زیربنایی که روزانه استفاده می‌کنید به دست آورید — زبان‌های برنامه‌نویسی، کامپایلرها و مفسرها، پایگاه‌های داده و سیستم‌عامل‌ها، وب سرورها و فریم‌ورک‌های وب. و برای درک عمیق‌تر این سیستم‌ها باید آن‌ها را از صفر بازسازی کنید: آجر به آجر، دیوار به دیوار.

کنفوسیوس این‌طور گفته: «می‌شنوم و فراموش می‌کنم. می‌بینم و به یاد می‌آورم. انجام می‌دهم و می‌فهمم.»

در این مجموعهٔ سه‌قسمتی نشان می‌دهم چگونه وب سرور پایهٔ خودتان را بسازید. بگذارید شروع کنیم.

وب سرور چیست؟

در یک کلام، یک سرور شبکه است که روی یک سرور فیزیکی نشسته و منتظر می‌ماند کلاینتی درخواستی بفرستد. وقتی درخواست را دریافت می‌کند، یک پاسخ تولید می‌کند و برای کلاینت برمی‌فرستد. ارتباط بین کلاینت و سرور با پروتکل HTTP انجام می‌شود. کلاینت می‌تواند مرورگر شما یا هر نرم‌افزار دیگری باشد که HTTP صحبت می‌کند.

پیاده‌سازی خیلی سادهٔ یک وب سرور چه شکلی است؟ این برداشت نویسنده است. مثال به زبان پایتون (تست‌شده روی Python 3.7+) — حتی اگر پایتون نمی‌دانید، باید بتوانید مفاهیم را از کد و توضیحات پایین بفهمید:

python# Python3.7+
import socket

HOST, PORT = '', 8888

listen_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
listen_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
listen_socket.bind((HOST, PORT))
listen_socket.listen(1)
print(f'Serving HTTP on port {PORT} ...')
while True:
    client_connection, client_address = listen_socket.accept()
    request_data = client_connection.recv(1024)
    print(request_data.decode('utf-8'))

    http_response = b"""\
HTTP/1.1 200 OK

Hello, World!
"""
    client_connection.sendall(http_response)
    client_connection.close()

کد بالا را به‌عنوان webserver1.py ذخیره کنید (یا مستقیم از GitHub دانلودش کنید) و در خط فرمان اجرا کنید:

Bash$ python webserver1.py
Serving HTTP on port 8888 ...

حالا در نوار آدرس مرورگر http://localhost:8888/hello را تایپ کنید و Enter بزنید؛ «Hello, World!» را در مرورگر می‌بینید. واقعاً امتحانش کنید — نویسنده صبر می‌کند تا تست کنید!

تمام شد؟ عالی. حالا بگذارید دربارهٔ نحوهٔ کار این‌ها صحبت کنیم.

چطور کار می‌کند

اول با آدرس وب‌ای که وارد کردید شروع کنیم. به آن URL می‌گویند و ساختار پایه‌اش این است:

این‌طور به مرورگر می‌گویید آدرس وب سروری که باید پیدا کند و وصل شود چیست و صفحهٔ (مسیر) مورد نظر روی سرور کدام است. اما قبل از اینکه مرورگر بتواند درخواست HTTP بفرستد، اول باید یک اتصال TCP با وب سرور برقرار کند. بعد یک درخواست HTTP روی اتصال TCP به سرور می‌فرستد و منتظر می‌ماند سرور یک پاسخ HTTP برگرداند. وقتی مرورگر پاسخ را می‌گیرد نمایشش می‌دهد — در این مورد «Hello, World!».

بگذارید دقیق‌تر بررسی کنیم کلاینت و سرور چگونه قبل از فرستادن درخواست‌ها و پاسخ‌های HTTP اتصال TCP برقرار می‌کنند. برای این کار هر دو از «سوکت‌ها» استفاده می‌کنند. به‌جای استفاده مستقیم از مرورگر، با telnet در خط فرمان مرورگرتان را شبیه‌سازی می‌کنید.

روی همان کامپیوتری که وب سرور را اجرا می‌کنید، یک نشست telnet از خط فرمان باز کنید، میزبان localhost و پورت 8888 را مشخص کنید و Enter بزنید:

Bash$ telnet localhost 8888
Trying 127.0.0.1 ...
Connected to localhost.

در این نقطه با سروری که روی میزبان محلی اجرا می‌شود اتصال TCP برقرار کرده‌اید و آمادهٔ فرستادن و دریافت پیام‌های HTTP هستید. در تصویر زیر رویهٔ استانداردی را می‌بینید که یک سرور برای پذیرش اتصالات TCP جدید باید انجام دهد.

در همان نشست telnet، GET /hello HTTP/1.1 را تایپ کنید و Enter بزنید:

Bash$ telnet localhost 8888
Trying 127.0.0.1 ...
Connected to localhost.
GET /hello HTTP/1.1

HTTP/1.1 200 OK
Hello, World!

تازه مرورگرتان را دستی شبیه‌سازی کردید! یک درخواست HTTP فرستادید و یک پاسخ HTTP گرفتید. این ساختار پایهٔ یک درخواست HTTP است:

درخواست HTTP از خطی تشکیل شده که متد HTTP (GET — چون از سرور می‌خواهیم چیزی برگرداند)، مسیر /hello که «صفحهٔ» مورد نظرمان روی سرور است و نسخهٔ پروتکل را نشان می‌دهد.

برای سادگی، وب سرورمان در این نقطه کاملاً خط درخواست بالا را نادیده می‌گیرد. به‌جای «GET /hello HTTP/1.1» هر زباله‌ای هم تایپ کنید، باز «Hello, World!» می‌گیرید.

این پاسخ HTTP است که سرور به کلاینت می‌فرستد:

بگذارید تجزیه‌اش کنیم. پاسخ شامل یک خط وضعیت HTTP/1.1 200 OK، سپس یک خط خالیِ الزامی و بعد بدنهٔ پاسخ HTTP است. خط وضعیت HTTP/1.1 200 OK از نسخهٔ HTTP، کد وضعیت HTTP و عبارت دلیل OK تشکیل شده. وقتی مرورگر پاسخ را می‌گیرد، بدنهٔ پاسخ را نمایش می‌دهد و به همین دلیل «Hello, World!» را در مرورگر می‌بینید.

خلاصه

و این مدل پایهٔ کار یک وب سرور است. خلاصه: وب سرور یک سوکت شنونده می‌سازد و در یک حلقه شروع به پذیرش اتصالات جدید می‌کند. کلاینت یک اتصال TCP آغاز می‌کند و بعد از برقراری موفق، کلاینت یک درخواست HTTP به سرور می‌فرستد و سرور با یک پاسخ HTTP پاسخ می‌دهد که به کاربر نمایش داده می‌شود. برای برقراری اتصال TCP، کلاینت‌ها و سرورها هر دو از سوکت‌ها استفاده می‌کنند.

حالا یک وب سرور پایهٔ کارا دارید که می‌توانید با مرورگر یا هر کلاینت HTTP دیگری تستش کنید. همان‌طور که دیدید و امیدوارم امتحان کرده باشید، می‌توانید با telnet و تایپ دستی درخواست‌های HTTP، خودتان هم یک کلاینت HTTPِ انسانی باشید.

سوالی برای شما: «چطور می‌توانید یک برنامهٔ Django، برنامهٔ Flask و برنامهٔ Pyramid را زیر وب سرور تازه‌ساخته‌تان اجرا کنید بدون اینکه یک تغییر در سرور برای سازگاری با این فریم‌ورک‌های مختلف بدهید؟»
