ترمینال داخلش چه کار می‌کند؟

شبیه‌ساز ترمینال (مانند xterm یا st) در ظاهر فقط یک پنجرهٔ متنی است، اما پشت آن یک مکانیزم مهم وجود دارد: یک اندازهٔ grid از سلول‌های کاراکتری، یک buffer برای حفظ محتوا، و مدیریت escape sequences — یعنی همان کدهای کنترلی که رنگ، حرکت مکان‌نما و وضعیت صفحه را تغییر می‌دهند.

وقتی برنامهای مثل vim یا ls را اجرا می‌کنید، این برنامه توالی‌هایی از بایت‌ها (مثل `\x1b[31m` برای قرمز) می‌فرستد؛ ترمینال باید آن‌ها را تفسیر کند و بکگراند و متن را مطابق آن رندر کند.

مدل داده: سلول و بافر

قلب ترمینال، یک آرایهٔ دوبعدی از «سلول» است. هر سلول شامل کاراکتر، رنگ جلو و رنگ پس‌زمینه و چند ویژگی (پررنگ، زیرخط) است:

Ctypedef struct {
    char c;          // کاراکتر سلول
    int fg, bg;      // رنگ جلو و پس‌زمینه
    int bold, underline;
} Cell;

// بافر: آرایه‌ای از خطوط، هر خط آرایه‌ای از سلول‌ها
typedef struct {
    int rows, cols;
    Cell** cells;
} Buffer;

// پاک‌کردن صفحه و تنظیم مکان‌نما
void term_clear(Buffer* buf) {
    for (int y = 0; y < buf->rows; y++)
        for (int x = 0; x < buf->cols; x++) {
            buf->cells[y][x].c = ' ';
            buf->cells[y][x].fg = DEFAULT;
        }
}

این ساختار ساده، پایهٔ همهٔ عملیات رندر است: هر عملیات فقط مقادیر این آرایه را تغییر می‌دهد و بعد یک «پاس رندر» آن را روی صفحه می‌کشد.

تفسیر escape sequences

بخش اصلی کد، یک ماشین حالت است که بایت‌های ورودی را می‌خواند. وقتی بایت `0x1b` دیده شد، ترمینال وارد حالت «escape» می‌شود و دنبالهٔ بعدی (مثل `[2J` برای پاک‌کردن صفحه) را تفسیر می‌کند:

C// پردازش دنباله‌های CSI (Control Sequence Introducer)
void handle_csi(char* params, int plen) {
    // "J" یعنی پاک‌کردن: 2J کل صفحه
    if (params[plen-1] == 'J') {
        term_clear(&buf);
        return;
    }
    // "H" یعنی حرکت مکان‌نما به (row, col)
    if (params[plen-1] == 'H') {
        int row = 0, col = 0;
        if (plen > 1)
            sscanf(params, "%d;%d", &row, &col);
        cursor.row = row - 1;
        cursor.col = col - 1;
    }
}

برای یک ترمینال کامل، باید صدها دنبالهٔ مختلف را پشتیبانی کنید، اما با همین چند تابع، رفتار پایهٔ xterm شبیه‌سازی می‌شود.

جمع‌بندی

ساخت یک ترمینال، مفاهیم سیستم‌عامل (pty، control signals)، گرافیک متنی و ماشین‌های حالت را با هم ترکیب می‌کند. بعد از این مقدمه، می‌توانید سراغ پروژه‌های کامل مثل «st» یا «alacritty» بروید و معماری آن‌ها را واقعاً بفهمید.

کپیرایت: نویسندهٔ پست «Basics of writing a terminal emulator». این صفحه فقط ترجمهٔ فارسی و مرور آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. برای مشاهدهٔ اصل مطلب به سایت اصلی مراجعه کنید.
