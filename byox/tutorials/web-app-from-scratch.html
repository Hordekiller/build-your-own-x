مقدمه

این اولین پست از مجموعه‌ای است که در آن فرایند ساخت یک برنامهٔ وب (و وب سرورش) را از صفر در پایتون مرور می‌کنیم. برای این مجموعه، فقط به کتابخانهٔ استاندارد پایتون تکیه می‌کنیم و استاندارد WSGI را نادیده می‌گیریم.

بدون مقدمه‌چینی، بگذارید شروع کنیم!

وب سرور

برای شروع، قرار است سرور HTTP را بنویسیم که وب‌اپ ما را تغذیه می‌کند. اما اول باید کمی وقت بگذاریم و ببینیم پروتکل HTTP چگونه کار می‌کند.

HTTP چگونه کار می‌کند

به زبان ساده، کلاینت‌های HTTP روی شبکه به سرورهای HTTP متصل می‌شوند و رشته‌ای از داده را که نشان‌دهندهٔ درخواست است می‌فرستند. سرور آن درخواست را تفسیر می‌کند و یک پاسخ برای کلاینت برمی‌فرستد. کل پروتکل و قالب‌های درخواست‌ها و پاسخ‌ها در RFC2616 توصیف شده.

قالب درخواست

درخواست‌ها با مجموعه‌ای از خطوط جدا شده با \r\n نمایش داده می‌شوند که اولین‌شان «خط درخواست» نام دارد. خط درخواست از یک متد HTTP، سپس فاصله، سپس مسیر فایلِ درخواستی، سپس فاصلهٔ دیگر، سپس نسخهٔ پروتکل HTTP که کلاینت حرف می‌زند و در نهایت کاراکتر بازگشت (\r) و خط‌تغذیه (\n) تشکیل شده:

HTTPGET /some-path HTTP/1.1\r\n

بعد از خط درخواست، صفر یا چند خط هدر می‌آید. هر خط هدر از نام هدر، سپس دونقطه، سپس یک مقدار اختیاری و بعد \r\n تشکیل شده:

HTTPHost: example.com\r\n
Accept: text/html\r\n

پایان بخش هدرها با یک خط خالی اعلام می‌شود: \r\n. در نهایت، ممکن است درخواست «بدنه» داشته باشد — یک بار اضافه که همراه درخواست به سرور فرستاده می‌شود.

همهٔ این‌ها را کنار هم بگذاریم، یک درخواست سادهٔ GET:

HTTPGET / HTTP/1.1\r\n
Host: example.com\r\n
Accept: text/html\r\n
\r\n

و یک درخواست سادهٔ POST با بدنه:

HTTPPOST / HTTP/1.1\r\n
Host: example.com\r\n
Accept: application/json\r\n
Content-type: application/json\r\n
Content-length: 2\r\n
\r\n
{}

قالب پاسخ

پاسخ‌ها هم مثل درخواست‌ها از مجموعه‌ای خطوط جدا شده با \r\n تشکیل شده‌اند. اولین خط در پاسخ «خط وضعیت» نام دارد و از نسخهٔ پروتکل HTTP، فاصله، کد وضعیت پاسخ، فاصلهٔ دیگر، دلیل کد وضعیت و سپس \r\n تشکیل شده:

HTTPHTTP/1.1 200 OK\r\n

بعد از خط وضعیت، هدرهای پاسخ، سپس یک خط خالی و سپس بدنهٔ پاسخ اختیاری می‌آید:

HTTPHTTP/1.1 200 OK\r\n
Content-type: text/html\r\n
Content-length: 15\r\n
\r\n
<h1>Hello!</h1>

یک سرور ساده

بر اساس آنچه دربارهٔ پروتکل می‌دانیم، سروری می‌نویسیم که بدون توجه به درخواست ورودی، همان پاسخ را می‌فرستد.

برای شروع باید یک سوکت بسازیم، به یک آدرس bind کنیم و بعد شروع به گوش‌دادن برای اتصالات کنیم:

pythonimport socket

HOST = "127.0.0.1"
PORT = 9000

# به‌طور پیش‌فرض، socket.socket سوکت TCP می‌سازد.
with socket.socket() as server_sock:
    # این به هسته می‌گوید سوکت‌هایی را که در حالت TIME_WAIT هستند دوباره استفاده کند.
    server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)

    # این به سوکت می‌گوید به چه آدرسی bind شود.
    server_sock.bind((HOST, PORT))

    # 0 تعداد اتصالات در انتظاری است که سوکت قبل از ردکردن
    # اتصالات جدید ممکن است داشته باشد. چون این سرور قرار است هر بار
    # یک اتصال را پردازش کند، می‌خواهیم اتصالات اضافه رد شوند.
    server_sock.listen(0)
    print(f"Listening on {HOST}:{PORT}...")

اگر این کد را الان اجرا کنید، روی 127.0.0.1:9000 گوش‌دادن را چاپ می‌کند و بعد خارج می‌شود. برای پردازش واقعی اتصالات ورودی باید متد accept را روی سوکت‌مان صدا بزنیم. این کار فرایند را مسدود می‌کند تا وقتی کلاینتی به سرور متصل شود:

pythonwith socket.socket() as server_sock:
    server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_sock.bind((HOST, PORT))
    server_sock.listen(0)
    print(f"Listening on {HOST}:{PORT}...")

    client_sock, client_addr = server_sock.accept()
    print(f"New connection from {client_addr}.")

وقتی اتصال سوکت به کلاینت را داریم، می‌توانیم با آن ارتباط برقرار کنیم. با متد sendall یک مثال پاسخ به کلاینتی که متصل شده می‌فرستیم:

pythonRESPONSE = b"""\
HTTP/1.1 200 OK
Content-type: text/html
Content-length: 15

<h1>Hello!</h1>""".replace(b"\n", b"\r\n")

with socket.socket() as server_sock:
    server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_sock.bind((HOST, PORT))
    server_sock.listen(0)
    print(f"Listening on {HOST}:{PORT}...")

    client_sock, client_addr = server_sock.accept()
    print(f"New connection from {client_addr}.")
    with client_sock:
        client_sock.sendall(RESPONSE)

اگر کد را الان اجرا کنید و به http://127.0.0.1:9000 در مرورگر موردعلاقه‌تان بروید، باید رشتهٔ «Hello!» را رندر کند. متأسفانه، سرور بعد از فرستادن پاسخ خارج می‌شود، پس رفرش صفحه شکست می‌خورد. بگذارید این را درست کنیم:

pythonRESPONSE = b"""\

در این نقطه یک وب سرور داریم که می‌تواند در هر درخواست یک صفحهٔ وب سادهٔ HTML را سرو کند — همه در حدود ۲۵ خط کد. بد نیست!

یک فایل سرور

بگذارید سرور HTTP را گسترش دهیم تا بتواند فایل‌ها را از دیسک سرو کند.

انتزاع درخواست

قبل از هر چیز باید دادهٔ درخواست ورودی را از کلاینت بخوانیم و پارس کنیم. چون می‌دانیم دادهٔ درخواست با خطوطی نمایش داده می‌شود که هر کدام با \r\n جدا شده‌اند، یک تابع مولد می‌نویسیم که داده را از سوکت می‌خواند و هر خط را yield می‌کند:

pythonimport typing


def iter_lines(sock: socket.socket, bufsize: int = 16_384) -> typing.Generator[bytes, None, bytes]:
    """با گرفتن یک سوکت، همهٔ خطوط جدا شده با CRLF را می‌خواند
    و هر کدام را yield می‌کند تا وقتی به یک خط خالی برسد. باقی‌مانده
    بعد از خط خالی را برمی‌گرداند.
    """
    buff = b""
    while True:
        data = sock.recv(bufsize)
        if not data:
            return b""

        buff += data
        while True:
            try:
                i = buff.index(b"\r\n")
                line, buff = buff[:i], buff[i + 2:]
                if not line:
                    return buff

                yield line
            except IndexError:
                break

ممکن است ترسناک به نظر برسد، اما کاری که می‌کند این است: هر مقدار داده‌ای که بتواند از سوکت بخواند (در قطعات bufsize) می‌خواند، آن را در یک بافر (buff) کنار هم می‌گذارد و مدام بافر را به خطوط جدا تقسیم می‌کند و هر بار یکی را yield می‌کند. وقتی به یک خط خالی برسد، دادهٔ اضافه‌ای که خوانده را برمی‌گرداند.

با iter_lines می‌توانیم درخواست‌هایی که از کلاینت‌ها می‌گیریم را چاپ کنیم:

یک کلاس Request تعریف می‌کنیم که فعلاً فقط روش، مسیرها و هدرهای درخواست را می‌داند:

pythonimport typing


class Request(typing.NamedTuple):
    method: str
    path: str
    headers: typing.Mapping[str, str]

برای در بر گرفتن منطق ساخت درخواست، یک متد کلاس به نام from_socket به Request اضافه می‌کنیم:

pythonclass Request(typing.NamedTuple):
    method: str
    path: str
    headers: typing.Mapping[str, str]

    @classmethod
    def from_socket(cls, sock: socket.socket) -> "Request":
        """خواندن و پارس‌کردن درخواست از یک شیء سوکت.

        استثناها:
          ValueError: وقتی درخواست قابل پارس نیست.
        """
        lines = iter_lines(sock)

        try:
            request_line = next(lines).decode("ascii")
        except StopIteration:
            raise ValueError("Request line missing.")

        try:
            method, path, _ = request_line.split(" ")
        except ValueError:
            raise ValueError(f"Malformed request line {request_line!r}.")

        headers = {}
        for line in lines:
            try:
                name, _, value = line.decode("ascii").partition(":")
                headers[name.lower()] = value.lstrip()
            except ValueError:
                raise ValueError(f"Malformed header line {line!r}.")

        return cls(method=method.upper(), path=path, headers=headers)

روی سوکت متصل‌شده اجرا می‌شود و خطوطی مثل این را چاپ می‌کند:

ConsoleRequest(method='GET', path='/', headers={'host': 'localhost:9000', 'user-agent': 'curl/7.54.0', 'accept': '*/*'})

چون from_socket در شرایط خاصی می‌تواند استثنا پرتاب کند، ممکن است سرور با درخواست نامعتبر الان کرش کند. برای مدیریت این‌ها، فراخوانی from_socket را در try-except می‌گذاریم و وقتی درخواست بدی بگیریم به کلاینت پاسخ «400 Bad Request» می‌فرستیم:

pythonBAD_REQUEST_RESPONSE = b"""\

with socket.socket() as server_sock:

یک ثابت SERVER_ROOT تعریف می‌کنیم تا نشان دهد سرور فایل‌ها را از کجا سرو کند و یک تابع serve_file:

pythonimport mimetypes
import os
import socket
import typing

SERVER_ROOT = os.path.abspath("www")

FILE_RESPONSE_TEMPLATE = """\
HTTP/1.1 200 OK
Content-type: {content_type}
Content-length: {content_length}

""".replace("\n", "\r\n")


def serve_file(sock: socket.socket, path: str) -> None:
    """با گرفتن یک سوکت و مسیر نسبی یک فایل (نسبت به
    SERVER_SOCK)، اگر فایل وجود داشت آن را به سوکت بفرست. اگر
    فایل وجود نداشت، پاسخ «404 Not Found» بفرست.
    """
    if path == "/":
        path = "/index.html"

    abspath = os.path.normpath(os.path.join(SERVER_ROOT, path.lstrip("/")))
    if not abspath.startswith(SERVER_ROOT):
        sock.sendall(NOT_FOUND_RESPONSE)
        return

    try:
        with open(abspath, "rb") as f:
            stat = os.fstat(f.fileno())
            content_type, encoding = mimetypes.guess_type(abspath)
            if content_type is None:
                content_type = "application/octet-stream"

            if encoding is not None:
                content_type += f"; charset={encoding}"

            response_headers = FILE_RESPONSE_TEMPLATE.format(
                content_type=content_type,
                content_length=stat.st_size,
            ).encode("ascii")

            sock.sendall(response_headers)
            sock.sendfile(f)
    except FileNotFoundError:
        sock.sendall(NOT_FOUND_RESPONSE)
        return

serve_file سوکت کلاینت و مسیر فایل را می‌گیرد. سعی می‌کند آن مسیر را به یک فایل واقعی داخل SERVER_ROOT تبدیل کند و اگر فایل بیرون از ریشهٔ سرور resolve شد، پاسخ «not found» می‌فرستد. بعد سعی می‌کند فایل را باز کند، نوع mime و اندازه‌اش را با os.fstat بفهمد، هدرهای پاسخ را بسازد و با فراخوان سیستمی sendfile فایل را به سوکت بنویسد. اگر فایل روی دیسک نبود، پاسخ «not found» می‌فرستد.
