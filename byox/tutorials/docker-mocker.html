Mocker — داکر تقلیدی با ۱۰۰٪ پایتون

⚙ زبان: Python 📁 دسته: داکر ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی پروژهٔ «mocker: A proof-of-concept imitation of Docker, written in 100% Python» نوشتهٔ «آنتونی شاو (Anthony Shaw)» است — یک تقلید اثبات‌مفهوم (proof-of-concept) از داکر که کاملاً در پایتون نوشته شده و از فضاهای نام هسته (Kernel Namespaces)، سی‌گروپ‌ها (cgroups) و فضاهای نام شبکه / iproute2 لینوکس استفاده می‌کند. نسخه کامل و به‌روز را از مخزن اصلی بخوانید.
↗ مشاهده منبع اصلی

مقدمه: Mocker چیست و چرا؟

Mocker یک تقلید اثبات‌مفهوم (proof-of-concept) از داکر است که با ۱۰۰٪ پایتون نوشته شده و برای ایزوله‌سازی کانتینرها (containers) از فضاهای نام هستهٔ لینوکس (Kernel Namespaces)، سی‌گروپ‌ها (cgroups) و فضاهای نام شبکه / iproute2 استفاده می‌کند. این پروژه حاصل یک سخنرانی در رویداد Docker meetup سیدنی در ۱۸ اکتبر است؛ جایی که نویسنده قصد داشت مفاهیم اصلیِ فضاهای نام، سی‌گروپ‌ها و فضاهای نام شبکه، قالب تصویر داکر (همان رابط برنامه‌نویسی جدید) و این واقعیت را نشان دهد که داکر بسیار فراتر از همین امکانات هسته‌ای است.

انگیزهٔ نوشتن این پروژه در بخش «Why?» خود مخزن این‌گونه شرح داده شده است:

مدام جمله‌هایی می‌شنوم مانند «داکر در اصل همان سی‌گروپ‌هاست» یا «داکر همان chroot عظیم‌تری است»، که کاملاً نادرست است. من قرار است در میت‌آپ داکر سیدنی در ۱۸ اکتبر دربارهٔ برخی از مفاهیم اصلی فضاهای نام هسته، سی‌گروپ‌ها و فضاهای نام شبکه سخنرانی کنم و یک پیاده‌سازی ساده برای نشان‌دادن نحوهٔ کار ایزوله‌سازی کانتینر، قالب تصویر داکر (رابط برنامه‌نویسی جدید) و همچنین این‌که داکر چقدر فراتر از این قابلیت‌های اصلی هسته است، به ذهنم رسید.

منابع تکمیلی معرفی‌شده در README:

  • ویدیوی ضبط‌شدهٔ سخنرانی در PyCon AU 2017 دربارهٔ Mocker
  • پست وبلاگی دربارهٔ استفاده از این کتابخانه‌ها (Hackernoon)

نکتهٔ مهم این است که نویسنده صراحتاً می‌گوید این پروژه را در دو روز نوشته و نباید آن را جدی گرفت؛ کدها صرفاً برای آموزش و نمایش مفاهیم هستند و نقاط ضعف خودشان را نیز دارند (بخش «محدودیت‌ها» را ببینید).

نصب و اجرا

پروژه فقط روی لینوکس کار می‌کند و روی CentOS 7 و Ubuntu 14 تست شده است. وابستگی‌های آن در فایل requirements.txt آمده است:

textrequests
docopt
terminaltables
nsenter
snakeoil
pychroot
cgroups
pyroute2
colorama

نقش هر کدام از این وابستگی‌ها در این پروژه:

  • requests — کلاینت HTTP برای ارتباط با رجیستری (registry) داکر و دریافت توکن، مانیفست (manifest) و لایه‌های تصویر (image layers).
  • docopt — پردازش آرگومان‌های خط فرمان بر اساس متن راهنمای Usage.
  • terminaltables — رسم جدول ASCII برای دستور mocker images.
  • nsenter — ورود به فضای نام فرایندهای دیگر (برای دستور mocker run).
  • snakeoil — ابزارهای وابسته (مثلاً log.info در ماژول cgroups).
  • pychroot — بسته‌بندی پایتونیِ فراخوانی chroot.
  • cgroups — ساخت سی‌گروپ و محدودکردن CPU و حافظه.
  • pyroute2 — مدیریت رابط‌های شبکه، پل‌ها (bridges) و فضاهای نام شبکه از پایتون.
  • colorama — خروجی رنگی ترمینال (برای لاگ).

فایل setup.py بسته را به‌صورت یک بستهٔ نصب‌شدنی Mocker تعریف می‌کند و اسکریپت قابل‌اجرای scripts/mocker را ثبت می‌کند:

py#!/usr/bin/env python

from distutils.core import setup
import mocker

setup(
    name='Mocker',
    version=mocker.__version__,
    description='Python example implementation of the Docker engine',
    author='Anthony Shaw',
    author_email='gward@python.net',
    url='https://www.python.org/sigs/distutils-sig/',
    packages=['distutils', 'distutils.command'],
    scripts=['scripts/mocker'])

اسکریپت نصب‌شده صرفاً ماژول پایتون را با همهٔ آرگومان‌های خط فرمان اجرا می‌کند:

shell#!/bin/sh
python -m mocker $1

در ریشهٔ مخزن هم فایل mocker.py وجود دارد که همان نقطهٔ ورود مستقل است و می‌توان آن را مستقیماً اجرا کرد؛ مثلاً ./mocker.py pull hello-world یا ./mocker.py run library/hello-world.

معماری و ساختار مخزن

ساختار مخزن (در شاخهٔ master) ساده و جمع‌وجور است:

معماری کد بر پایهٔ یک الگوی سادهٔ فرمان است: کلاس پایهٔ BaseDockerCommand فقط یک متد run() تعریف می‌کند و هر دستور (pull، images، run) یک زیرکلاس است که آن را پیاده‌سازی می‌کند. کلاس پایه:

pyclass BaseDockerCommand(object):
    def run(*args):
        raise NotImplementedError()

همهٔ داده‌های محلی (مانیفست‌ها، لایه‌ها و محتوای استخراج‌شدهٔ تصاویر) در پوشهٔ ~/mocker ذخیره می‌شوند؛ این مسیر در ماژول mocker/__init__.py به‌صورت ثابت سراسری _base_dir_ تعریف شده است و در صورت نبودن، ساخته می‌شود.

رابط خط فرمان (CLI) با docopt

برخلاف داکرِ واقعی که از یک دیمن (daemon) استفاده می‌کند، CLI این پروژه بسیار ساده است: متن راهنمای Usage در mocker/__init__.py تعریف شده و کتابخانهٔ docopt آن را به‌صورت خودکار پردازش می‌کند:

py__doc__ = """Mocker.

Usage:
  mocker pull <name>[<tag>]
  mocker run <name>
  mocker images
  mocker (-h | --help)
  mocker --version

Options:
  -h --help     Show this screen.
  --version     Show version.
"""

سه دستور اصلی عبارت‌اند از: mocker pull <name>[<tag>] برای کشیدن تصویر (pull) از رجیستری عمومی داکر، mocker run <name> برای اجرای یک تصویرِ دانلودشده، و mocker images برای نمایش فهرست تصاویر محلی. نقطهٔ ورود یعنی فایل mocker.py در ریشهٔ مخزن، آرگومان‌ها را با docopt تجزیه می‌کند، کلاسِ متناظر با دستور را انتخاب و نمونه‌سازی می‌کند و متد run() آن را صدا می‌زند:

py#!/usr/bin/python
from docopt import docopt

import mocker
from mocker.base import BaseDockerCommand
from mocker.pull import PullCommand
from mocker.images import ImagesCommand
from mocker.run import RunCommand


if __name__ == '__main__':
    arguments = docopt(mocker.__doc__, version=mocker.__version__)
    command = BaseDockerCommand
    if arguments['pull']:
        command = PullCommand
    elif arguments['images']:
        command = ImagesCommand
    elif arguments['run']:
        command = RunCommand

    cls = command(**arguments)
    cls.run(**arguments)

توجه کنید که docopt بر اساس متن Usage، کلیدهای آرگومان را دقیقاً با همان نام‌های درون پرانتز زاویه‌ای (مثل <name>) در دیکشنری ورودی قرار می‌دهد؛ به همین دلیل کلاس‌های فرمان، فیلدها را از روی همین کلیدها می‌خوانند.

# با استفاده از colorama برای رنگ‌بندی کمی تغییر داده شده است


class ColorizingStreamHandler(logging.StreamHandler):
    color_map = {
        logging.DEBUG: colorama.Style.DIM + colorama.Fore.CYAN,
        logging.WARNING: colorama.Fore.YELLOW,
        logging.ERROR: colorama.Fore.RED,
        logging.CRITICAL: colorama.Back.RED,
    }

    def __init__(self, stream, color_map=None):
        logging.StreamHandler.__init__(self,
                                       colorama.AnsiToWin32(stream).stream)
        if color_map is not None:
            self.color_map = color_map

    @property
    def is_tty(self):
        isatty = getattr(self.stream, 'isatty', None)
        return isatty and isatty()

    def format(self, record):
        message = logging.StreamHandler.format(self, record)
        if self.is_tty:
            # روی traceback رنگ اعمال نکن
            parts = message.split('\n', 1)
            parts[0] = self.colorize(parts[0], record)
            message = '\n'.join(parts)
        return message

    def colorize(self, message, record):
        try:
            return (self.color_map[record.levelno] + message +
                    colorama.Style.RESET_ALL)
        except KeyError:
            return message

log = logging.getLogger()
handler = ColorizingStreamHandler(sys.stdout)
formatter = logging.Formatter('%(message)s')
handler.setFormatter(formatter)
log.addHandler(handler)
log.setLevel(logging.INFO)

کلاینت رجیستری: mocker pull

دستور pull در فایل mocker/pull.py پیاده‌سازی شده است. این کلاس عملاً یک کلاینت سادهٔ رجیستری (registry client) است که با پروتکل Registry HTTP API v2 داکر کار می‌کند: ابتدا به‌صورت ناشناس از سرور auth.docker.io توکن می‌گیرد (با محدودهٔ repository:library/<image>:pull)، سپس مانیفست تصویر را از registry-1.docker.io/v2 دریافت می‌کند، آن را به‌صورت JSON در ~/mocker کش (cache) می‌کند و در نهایت همهٔ لایه‌های یکتا را با جریان‌سازی (streaming) دانلود کرده و محتوای هر لایه (بایگانی tar) را در پوشهٔ layers/contents استخراج می‌کند:

pyimport requests
import os, platform
import json
import tarfile
from mocker import _base_dir_
from .base import BaseDockerCommand


class PullCommand(BaseDockerCommand):
    registry_base = 'https://registry-1.docker.io/v2'

    def __init__(self, *args, **kwargs):
        self.image = kwargs['<name>']
        self.library = 'library'  # todo - کتابخانه‌های تعریف‌شده توسط کاربر
        self.tag = kwargs['<tag>'] if kwargs['<tag>'] is not None else 'latest'

    def auth(self, library, image):
        # درخواست توکن v2
        token_req = requests.get(
            'https://auth.docker.io/token?service=registry.docker.io&scope=repository:%s/%s:pull'
            % (library, image))
        return token_req.json()['token']

    def get_manifest(self):
        # دریافت مانیفست تصویر
        print("Fetching manifest for %s:%s..." % (self.image, self.tag))

        manifest = requests.get('%s/%s/%s/manifests/%s' %
                                (self.registry_base, self.library, self.image, self.tag),
                                headers=self.headers)

        return manifest.json()

    def run(self, *args, **kwargs):
        # ورود ناشناس
        self.headers = {'Authorization': 'Bearer %s' % self.auth(self.library,
                                                                 self.image)}
        # دریافت مانیفست
        manifest = self.get_manifest()

        # ذخیره‌سازی مانیفست
        image_name_friendly = manifest['name'].replace('/', '_')
        with open(os.path.join(_base_dir_,
                               image_name_friendly+'.json'), 'w') as cache:
            cache.write(json.dumps(manifest))
        # ذخیره لایه‌ها در یک پوشهٔ جدید
        dl_path = os.path.join(_base_dir_, image_name_friendly, 'layers')
        if not os.path.exists(dl_path):
            os.makedirs(dl_path)

        # دریافت هر لایهٔ یکتا
        layer_sigs = [layer['blobSum'] for layer in manifest['fsLayers']]
        unique_layer_sigs = set(layer_sigs)

        # ساخت پوشه‌ای برای محتوای تصویر
        contents_path = os.path.join(dl_path, 'contents')
        if not os.path.exists(contents_path):
            os.makedirs(contents_path)

        # دانلود همهٔ اجزا
        for sig in unique_layer_sigs:
            print('Fetching layer %s..' % sig)
            url = '%s/%s/%s/blobs/%s' % (self.registry_base, self.library,
                                         self.image, sig)
            local_filename = os.path.join(dl_path, sig) + '.tar'

            r = requests.get(url, stream=True, headers=self.headers)
            with open(local_filename, 'wb') as f:
                for chunk in r.iter_content(chunk_size=1024):
                    if chunk:
                        f.write(chunk)

            # فهرست بخشی از محتوا
            with tarfile.open(local_filename, 'r') as tar:
                for member in tar.getmembers()[:10]:
                    print('- ' + member.name)
                print('...')

                tar.extractall(str(contents_path))

نکات فنی مهم دربارهٔ این کلاینت:

  • شناسهٔ هر لایه از فیلد blobSum (هش sha256) در آرایهٔ fsLayers مانیفست گرفته می‌شود و لایه‌های تکراری با set() حذف می‌شوند.
  • دانلود هر لایه به‌صورت جریان‌های ۱۰۲۴ بایتی انجام می‌شود و فایل tar آن در پوشهٔ layers نگهداری می‌شود.
  • به‌جای نگهداشتن جداگانهٔ لایه‌ها، همهٔ آن‌ها پشت‌سرهم در یک پوشهٔ واحد layers/contents استخراج می‌شوند؛ یعنی همان «تصویر فشرده/یکپارچه‌شده» (squashed image) که نویسنده در محدودیت‌ها به آن اشاره کرده است.

ذخیره‌سازی تصاویر: mocker images و ساختار پوشه

دستور images در فایل mocker/images.py پیاده‌سازی شده است. این کلاس محتوای پوشهٔ ~/mocker را می‌خواند، برای هر مانیفست JSONِ دانلودشده یک ردیف می‌سازد و مجموع حجم لایه‌های آن را محاسبه و با کتابخانهٔ terminaltables به‌صورت جدول ASCII نمایش می‌دهد:

pyimport os
import json
from terminaltables import AsciiTable

from mocker import _base_dir_
from .base import BaseDockerCommand


class ImagesCommand(BaseDockerCommand):
    registry_base = 'https://registry-1.docker.io/v2'

    def __init__(self, *args, **kwargs):
        pass

    def list_images(self):
        images = [['name', 'version', 'size', 'file']]

        for image_file in os.listdir(_base_dir_):
            if image_file.endswith('.json'):
                with open(os.path.join(_base_dir_, image_file), 'r') as json_f:
                    image = json.loads(json_f.read())
                image_base = os.path.join(_base_dir_, image_file.replace('.json', ''), 'layers')
                size = sum(os.path.getsize(os.path.join(image_base, f)) for f in
                           os.listdir(image_base)
                           if os.path.isfile(os.path.join(image_base, f)))
                images.append([image['name'], image['tag'], sizeof_fmt(size), image_file])
        return images

    def run(self, *args, **kwargs):
        images = self.list_images()
        table = AsciiTable(images)
        print(table.table)


def sizeof_fmt(num, suffix='B'):
    ''' اعتبار: http://stackoverflow.com/questions/1094841/reusable-library-to-get-human-readable-version-of-file-size '''
    for unit in ['','Ki','Mi','Gi','Ti','Pi','Ei','Zi']:
        if abs(num) < 1024.0:
            return "%3.1f%s%s" % (num, unit, suffix)
        num /= 1024.0
    return "%.1f%s%s" % (num, 'Yi', suffix)

اجرای کانتینر: mocker run

قلب پروژه در فایل mocker/run.py قرار دارد. دستور run طبق README این مراحل را انجام می‌دهد:

  • ایجاد یک آداپتور اترنت مجازی (virtual ethernet) به نام veth0 در فضای نام ریشه (root namespace)
  • ایجاد یک فضای نام شبکه (network namespace) برای «کانتینر»
  • پل‌کردن آداپتور veth1 در فضای نام شبکهٔ جدید با آدرس 10.0.0.3/24
  • تنظیم مسیر پیش‌فرض (default route) به 10.0.0.1
  • ایجاد یک سی‌گروپ (cgroup) برای فرایندها
  • Chroot به پوشهٔ تصویر استخراج‌شده (بدون عکس فوری — که مطلوب نیست)
  • اجرای دستور Cmd انتخاب‌شده توسط تصویر داکر، تنظیم متغیرهای محیطی و نوشتن خروجی در /tmp/stdout

کد کامل فایل mocker/run.py:

pyimport os
import uuid
import json
from pprint import pprint
import subprocess
import traceback
from pyroute2 import IPDB, NetNS, netns
from cgroups import Cgroup
from cgroups.user import create_user_cgroups

from mocker import _base_dir_, log
from .base import BaseDockerCommand
from .images import ImagesCommand
from .pull import PullCommand


try:
    from pychroot import Chroot
except ImportError:
    print('warning: missing chroot options')


class RunCommand(BaseDockerCommand):
    def __init__(self, *args, **kwargs):
        pass

    def run(self, *args, **kwargs):
        images = ImagesCommand().list_images()
        image_name = kwargs['<name>']
        ip_last_octet = 103 # TODO : قابل تنظیم

        file = [i[3] for i in images if i[0] == image_name]
        if (file == []):
            kwargs['pull'] = True
            kwargs['<name>'] = kwargs['<name>'].split("/")[1]
            PullCommand(*args, **kwargs).run()
            images = ImagesCommand().list_images()
            file = [i[3] for i in images if i[0] == image_name]
            
        match = file[0]

        target_file = os.path.join(_base_dir_, match)
        with open(target_file) as tf:
            image_details = json.loads(tf.read())
        # تنظیم جزئیات محیط
        state = json.loads(image_details['history'][0]['v1Compatibility'])

        # استخراج اطلاعات این کانتینر
        env_vars = state['config']['Env']
        start_cmd = subprocess.list2cmdline(state['config']['Cmd'])
        working_dir = state['config']['WorkingDir']

        id = uuid.uuid1()

        # نام نسبتاً یکتا
        name = 'c_' + str(id.fields[5])[:4]

        # مک نسبتاً یکتا
        mac = str(id.fields[5])[:2]

        layer_dir = os.path.join(_base_dir_, match.replace('.json', ''), 'layers', 'contents')

        with IPDB() as ipdb:
            veth0_name = 'veth0_'+name
            veth1_name = 'veth1_'+name
            netns_name = 'netns_'+name
            bridge_if_name = 'bridge0'

            existing_interfaces = ipdb.interfaces.keys()

            # ساخت یک رابط مجازی جدید
            with ipdb.create(kind='veth', ifname=veth0_name, peer=veth1_name) as i1:
                i1.up()
                if bridge_if_name not in existing_interfaces:
                    ipdb.create(kind='bridge', ifname=bridge_if_name).commit()
                i1.set_target('master', bridge_if_name)

            # ایجاد یک فضای نام شبکه
            netns.create(netns_name)

            # انتقال رابط پل به فضای نام جدید
            with ipdb.interfaces[veth1_name] as veth1:
                veth1.net_ns_fd = netns_name

            # استفاده از این فضای نام شبکه به‌عنوان پایگاه‌داده
            ns = IPDB(nl=NetNS(netns_name))
            with ns.interfaces.lo as lo:
                lo.up()
            with ns.interfaces[veth1_name] as veth1:
                veth1.address = "02:42:ac:11:00:{0}".format(mac)
                veth1.add_ip('10.0.0.{0}/24'.format(ip_last_octet))
                veth1.up()
            ns.routes.add({
                'dst': 'default',
                'gateway': '10.0.0.1'}).commit()

            try:
                # ساخت پوشهٔ cgroup برای این کاربر
                user = os.getlogin()
                create_user_cgroups(user)

                # ابتدا cgroup را می‌سازیم و محدودیت cpu و حافظه آن را تنظیم می‌کنیم
                cg = Cgroup(name)
                cg.set_cpu_limit(50)  # TODO : این‌ها را به‌صورت گزینهٔ خط فرمان دریافت کن
                cg.set_memory_limit(500)

                # سپس تابعی می‌سازیم که فرایند را به cgroup اضافه کند
                def in_cgroup():
                    try:
                        pid = os.getpid()
                        cg = Cgroup(name)
                        for env in env_vars:
                            log.info('Setting ENV %s' % env)
                            os.putenv(*env.split('=', 1))

                        # تنظیم فضای نام شبکه
                        netns.setns(netns_name)

                        # افزودن فرایند به cgroup
                        cg.add(pid)

                        os.chroot(layer_dir)
                        if working_dir != '':
                            log.info("Setting working directory to %s" % working_dir)
                            os.chdir(working_dir)
                    except Exception as e:
                        traceback.print_exc()
                        log.error("Failed to preexecute function")
                        log.error(e)
                cmd = start_cmd
                log.info('Running "%s"' % cmd)
                process = subprocess.Popen(cmd, preexec_fn=in_cgroup, shell=True)
                process.wait()
                print(process.stdout)
                log.error(process.stderr)
            except Exception as e:
                traceback.print_exc()
                log.error(e)
            finally:
                log.info('Finalizing')
                NetNS(netns_name).close()
                netns.remove(netns_name)
                ipdb.interfaces[veth0_name].remove()
                log.info('done')

نکتهٔ جالب در ابتدای متد run: اگر تصویرِ خواسته‌شده از قبل دانلود نشده باشد، خودِ دستور run به‌صورت خودکار یک PullCommand اجرا می‌کند و سپس اجرا را ادامه می‌دهد (شبیه رفتار داکر که تصویر را در صورت نبودن می‌کشد).

شبکه: پل، veth و فضای نام شبکه

بخش شبکه با کتابخانهٔ pyroute2 (پیاده‌سازی پایتونیِ netlink و iproute2) انجام می‌شود و همان الگوی کلاسیک داکر است:

  1. یک جفت veth (کابل مجازی دوطرفه) با نام‌های یکتای veth0_<name> و veth1_<name> ساخته می‌شود؛ سر اول در فضای نام ریشه بالا می‌آید و به پل bridge0 متصل می‌شود (در صورت نبودن، خود پل با kind='bridge' ساخته می‌شود).
  2. یک فضای نام شبکهٔ یکتا با netns.create(netns_name) ساخته می‌شود.
  3. سر دوم veth با تنظیم veth1.net_ns_fd = netns_name به داخل فضای نام جدید منتقل می‌شود.
  4. در فضای نام جدید: رابط loopback (lo) بالا می‌آید، به veth1 یک آدرس مک (MAC) ساختگی و آدرس IP یکتای 10.0.0.<last_octet>/24 اختصاص داده می‌شود و مسیر پیش‌فرض به سمت گیت‌وی 10.0.0.1 اضافه می‌شود.
  5. در پایان (finally): فضای نام شبکه بسته و حذف می‌شود و veth0 از پل جدا و حذف می‌شود.

نکات این بخش:

  • همهٔ آماده‌سازی‌ها (متغیرهای محیطی، ورود به فضای نام شبکه، افزودن به سی‌گروپ، chroot و تغییر مسیر کاری) در تابع in_cgroup انجام می‌شوند که به‌عنوان preexec_fn به subprocess.Popen داده می‌شود؛ یعنی دقیقاً قبل از اجرای فرمان اصلی داخل همان فرایند فرزند اجرا می‌شود.
  • متغیرهای محیطی (Env) از مانیفست تصویر خوانده می‌شوند و با os.putenv تنظیم می‌شوند (مثلاً مسیر PATH در نمونهٔ hello-world).
  • os.chroot(layer_dir) ریشهٔ سیستم فایل را به پوشهٔ محتوای استخراج‌شده تغییر می‌دهد — همان «chroot روی تصویر یکپارچه» که ذکر شد؛ import کتابخانهٔ pychroot هم فقط اختیاری است و در صورت نبودن، یک پیام هشدار چاپ می‌شود.
  • دستور اجرایی (Cmd) از state['config']['Cmd'] مانیفست گرفته و با subprocess.list2cmdline به رشته تبدیل می‌شود.
  • محدودیت‌های CPU و حافظه در کد با TODO علامت‌گذاری شده‌اند تا به‌صورت گزینهٔ خط فرمان دریافت شوند.

محدودیت‌ها (Caveats)

نویسنده در README صادقانه این محدودیت‌ها را فهرست کرده است:

  1. این پروژه را در دو روز نوشته است؛ آن را جدی نگیرید.
  2. فقط روی لینوکس کار می‌کند (تست‌شده روی CentOS 7 و Ubuntu 14).
  3. کانتینر nginx را هم امتحان کنید —
  4. پیاده‌سازی شبکه نیمه‌کاره است؛ هنوز باید نگاشت آدرس شبکه (NAT) آن کامل شود (در کد خبری از iptables نیست).
  5. برخی تصاویر را امتحان کرده و با فرمان شروع (start command) آن‌ها مشکل داشته است؛ ظاهراً پشتهٔ لایه‌ها را درست سوار نمی‌کند. به‌جای استفاده از mount عکس فوری btrfs، روی تصویرِ یکپارچه‌شدهٔ دانلودشده chroot انجام می‌دهد؛ یعنی هیچ snapshot/overlayfs در کار نیست.
نکتهٔ آموزشی: مقایسهٔ این پروژه با داکرِ واقعی، دقیقاً همان هدف نویسنده است: نشان دادن اینکه داکر «فقط cgroups نیست» و «فقط chroot نیست»؛ هستهٔ داکر ترکیبی از فضاهای نام هسته، سی‌گروپ‌ها، سیستم‌های فایل لایه‌ای (overlayfs/btrfs)، شبکه (veth/پل/NAT/iptables) و یک کلاینت/سرور رجیستری پیچیده است — و حتی همهٔ این‌ها هم بخش کوچکی از داکرِ کامل هستند.
