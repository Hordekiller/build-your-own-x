۱. چرا Scope و Digest؟

هر چیزی در AngularJS به دور دو مفهوم می‌چرخد: Scope (مدلی که DOM به آن وصل است) و Digest (مکانیزمی که تغییرات مدل را پیدا و به DOM منتقل می‌کند). در این بخش، این دو را از صفر می‌سازیم — با همان دقت و رویکرد Angular واقعی، اما در محیط تست جاوااسکریپت خالص (بدون DOM).

روش آموزش: مقاله به‌سبک TDD نوشته شده: اول یک رفتار را توصیف می‌کند (تست)، بعد پیاده‌سازی آن را می‌آورد. اگر کد را دنبال کنید، تست‌ها را با Mocha/Jasmine اجرا خواهید کرد.

۲. Watch ها: اشتراک در تغییرات

با $watch یک تابع «نظاره‌گر» ثبت می‌شود که مقدار فعلی را برمی‌گرداند. با $digest این نظاره‌گرها را صدا می‌زنیم و اگر مقدار عوض شده بود، شنونده‌ها را خبر می‌کنیم:

jsScope.prototype.$watch = function(watchFn, listenerFn) {
  const watcher = {
    watchFn: watchFn,
    listenerFn: listenerFn || function() {},
    last: initWatchVal, // مقدار ویژهٔ «هنوز ارزیابی نشده»
  };
  this.$$watchers.push(watcher);
};

Scope.prototype.$digest = function() {
  let dirty;
  do {
    dirty = this.$$digestOnce();
  } while (dirty);
};

Scope.prototype.$$digestOnce = function() {
  let self = this;
  let dirty = false;
  this.$$watchers.forEach(function(watcher) {
    const newValue = watcher.watchFn(self);
    const oldValue = watcher.last;
    // فقط اگر تغییر کرده باشد خبر بده
    if (newValue !== oldValue) {
      watcher.last = newValue;
      watcher.listenerFn(newValue, oldValue, self);
      dirty = true;
    }
  });
  return dirty;
};

نکتهٔ مهم: حلقهٔ do…while یعنی تا وقتی تغییری پیدا شد، دوباره بررسی کن — چون ممکن است یک listener خودش scope را تغییر دهد. به این رفتار «dirty checking» می‌گوییم.

۳. هشدار loop: جلوگیری از بی‌نهایت‌شدن

اگر یک listener مدام مقدار را عوض کند، digest هرگز تمام نمی‌شود. Angular محدودیت TTL دارد ($digestTtl):

jsScope.prototype.$digest = function() {
  let ttl = 10; // حداکثر دورها
  let dirty;
  do {
    dirty = this.$$digestOnce();
    if (dirty && !(ttl--)) {
      throw 'ده دورهٔ digest بدون رسیدن به ثبات!';
    }
  } while (dirty);
};

۴. مقایسه با مرجع (Value-based) و عمق (Deep)

در Angular می‌توانید تعیین کنید مقایسه «مقداری» باشد (برای اعداد و رشته‌ها پیش‌فرض) یا «مرجع‌محور» (برای اشیا) یا حتی عمیق (مقایسهٔ بازگشتی ساختار شیء). مقاله هر سه حالت را با $$watchValueFn و الگوریتم $$areEqual پیاده می‌کند:

jsScope.prototype.$watch = function(watchFn, listenerFn, valueEq) {
  const watcher = {
    watchFn: watchFn,
    listenerFn: listenerFn || function() {},
    valueEq: !!valueEq, // مقایسهٔ عمیق یا مرجع
    last: initWatchVal,
  };
  this.$$watchers.push(watcher);
};

Scope.prototype.$$digestOnce = function() {
  let self = this;
  let dirty = false;
  this.$$watchers.forEach(function(watcher) {
    const newValue = watcher.watchFn(self);
    const oldValue = watcher.last;
    // مقایسه با معیار مناسب
    if (!self.$$areEqual(newValue, oldValue, watcher.valueEq)) {
      watcher.last = (watcher.valueEq ? _.cloneDeep(newValue) : newValue);
      watcher.listenerFn(newValue, oldValue, self);
      dirty = true;
    }
  });
  return dirty;
};

Scope.prototype.$$areEqual = function(newValue, oldValue, valueEq) {
  if (valueEq) {
    return _.isEqual(newValue, oldValue); // مقایسهٔ عمیق
  }
  return newValue === oldValue; // مقایسهٔ مرجع
};

چرا deep watch خطرناک است؟ چون مقایسهٔ عمیق برای هر watcher گران است و با ساختارهای بزرگ، digest کند می‌شود — Angular فقط وقتی از آن استفاده کنید هزینهٔ آن را می‌پردازید.

۵. ارزیابی نکردن و NaaN: نگه‌داشتن مقدار «بی‌مقدار»

یک جزئیات مهم: در اولین digest باید listener حتماً صدا زده شود حتی اگر مقدار اولیهٔ watchFn برابر undefined باشد. Angular با یک مقدار ویژهٔ initWatchVal این را حل می‌کند (و همین ترفند باعث می‌شود NaaN هم درست کار کند چون NaaN با خودش برابر نیست):

jsfunction initWatchVal() {} // یک مقدار «نشانه» که به هیچ چیز برابر نیست

۶. $eval، $evalAsync و $apply

بخش پایانی مقاله سه روش مهم اجرای کد در scope را اضافه می‌کند:

jsScope.prototype.$eval = function(expr, locals) {
  // اجرای فوری تابع/عبارت در context خود scope
  return expr(this, locals);
};

Scope.prototype.$evalAsync = function(expr) {
  // اجرای تاخیری: در تابع $applyAsyncQueue و قبل از digest بعدی
  if (!this.$$phase && !this.$$asyncQueue.length) {
    setTimeout(function() {
      // وقتی صف خالی بود، digest اجرا کن
      if (scope.$$asyncQueue.length) scope.$digest();
    }, 0);
  }
  this.$$asyncQueue.push({ scope: this, expr: expr });
};

Scope.prototype.$apply = function(expr) {
  // اجرای کد «بیرون از چرخهٔ آنگولار» (مثلاً در رویداد مرورگر)
  try {
    this.$eval(expr);
  } finally {
    this.$digest(); // همیشه digest را اجرا کن
  }
};

دلیل وجود $apply: هر تغییری که خارج از «زون» Angular رخ دهد (مثل setTimeout یا کتابخانهٔ خارجی) توسط digest دیده نمی‌شود؛ $apply آن را وارد چرخه می‌کند.

۷. جمع‌بندی

  • Scope یک مدل ساده است + مکانیزم watch/digest که می‌توانید کامل‌ترش کنید؛ همهٔ «جادوی» Angular از همین حلقهٔ dirty checking می‌آید.
  • مقایسهٔ مرجع در مقابل مقایسهٔ عمیق، تعادل بین دقت و سرعت است.
  • قسمت‌های بعدی این سری به scope های فرزند، رویدادها و دستورها (directives) می‌پردازند.
