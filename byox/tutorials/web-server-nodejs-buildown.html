وب سرور خودت را از صفر در Node.js بساز (Build Your Own Web Server)

⚙ زبان: Node.js ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی کتاب آنلاین «Build Your Own Web Server From Scratch In Node.JS» از جیمز اسمیت (James Smith) است — آموزش کامل برنامه‌نویسی شبکه، پروتکل HTTP و WebSocket با کدنویسی یک وب سرور از صفر در Node.js، در دو بخش و ۱۳ فصل.
↗ مشاهده منبع اصلی

۱. مقدمه — این کتاب چیست؟

بیشتر مردم هر روز از HTTP استفاده می‌کنند، اما تعداد کمی از کارکرد درونی آن سر در می‌آورند. این کتاب از سری «Build Your Own X» عمیق می‌رود و اصول را از صفر آموزش می‌دهد تا درک روشن‌تری از ابزارها و فناوری‌هایی که به آن‌ها تکیه داریم به دست آوریم:

  • برنامه‌نویسی شبکه.
  • پروتکل‌ها و ارتباطات.
  • HTTP با جزئیات کامل.

کتاب در دو بخش است: بخش اول یک سرور HTTP پایه می‌سازد (۷ فصل) و بخش دوم برنامه‌ها و توسعه‌ها را پوشش می‌دهد (۶ فصل: محتوای پویا، فایل‌ها، Range Request، کش، فشرده‌سازی و WebSocket).

۲. مرور HTTP و یک سرور TCP ساده

کتاب با مرور پروتکل HTTP شروع می‌کند: درخواست و پاسخ، متدها، کدهای وضعیت و سربرگ‌ها — سپس به برنامه‌نویسی شبکه می‌پردازد. اولین پروژه، یک سرور TCP خام است که فقط اتصال می‌گیرد و داده را به‌صورت خام می‌فرستد و می‌گیرد:

javascriptconst net = require('net');

// یک سرور TCP ساده: به هر اتصال سلام می‌کند
const server = net.createServer((socket) => {
    console.log('کلاینت وصل شد');

    socket.on('data', (data) => {
        console.log('دریافت:', data.toString());
        socket.write('سلام از سرور!\r\n');
    });

    socket.on('close', () => console.log('اتصال بسته شد'));
});

server.listen(8000, () => console.log('سرور روی پورت 8000'));

فصل بعدی Promise و رویدادها است: مدل رویدادمحور Node (Event Loop)، فراخوانی‌ها (callbacks)، وعده‌ها و async/await — چون سرورهای شبکه ذاتاً ناهمگام‌اند. سپس با همین ابزار یک پروتکل شبکه ساده روی TCP تعریف می‌شود تا ببینیم پروتکل‌ها چگونه «قالب پیام» و «ماشین حالت» دارند.

۳. معناشناسی و نحو HTTP

قبل از نوشتن سرور HTTP، باید HTTP را درست بشناسیم. این فصل نحو و معناشناسی HTTP را به‌طور کامل باز می‌کند:

  • ساختار درخواست: خط درخواست (METHOD path HTTP/version)، سربرگ‌ها (Header: value) و بدنه (اختیاری، با Content-Length).
  • ساختار پاسخ: خط وضعیت (HTTP/version status reason)، سربرگ‌ها و بدنه.
  • متدها: GET، POST، HEAD و...؛ کدهای وضعیت: 200، 404، 301 و...؛ سربرگ‌های کلیدی: Host، Content-Type، Content-Length و... .
  • نگهداری اتصال: Connection: keep-alive و مرز دقیق پیام‌ها — جایی که بیشتر سرورهای تازه‌کار می‌شکنند، چون نمی‌دانند یک درخواست کجا تمام می‌شود.

۴. کدنویسی یک سرور HTTP پایه

حالا نوبت پیاده‌سازی است: روی سرور TCP قبلی، پارسر درخواست، سازنده پاسخ و مسیریابی ساده می‌نشینند:

javascriptconst net = require('net');

const server = net.createServer((socket) => {
    let buf = '';

    socket.on('data', (data) => {
        buf += data.toString();

        // یک درخواست کامل وقتی تمام می‌شود که \r\n\r\n ببینیم
        const headerEnd = buf.indexOf('\r\n\r\n');
        if (headerEnd === -1) return; // هنوز کامل نیست؛ صبر کن

        const requestLine = buf.slice(0, buf.indexOf('\r\n'));
        const [method, path, version] = requestLine.split(' ');

        console.log(`${method} ${path}`);

        const body = 'Hello, World!';
        const response =
            'HTTP/1.1 200 OK\r\n' +
            `Content-Length: ${body.length}\r\n` +
            'Content-Type: text/plain\r\n' +
            '\r\n' +
            body;

        socket.write(response);
        socket.end();
    });
});

server.listen(8000, () => console.log('سرور HTTP روی پورت 8000'));

مطابق سنت «ساخت از صفر»، این پیاده‌سازی http خودِ Node را کنار می‌گذارد و از net پایه استفاده می‌کند تا همه لایه‌ها دست‌ساز باشد — سپس همان منطق با کتابخانه استاندارد مقایسه می‌شود.

۵. بخش دوم: توسعه‌ها

بخش دوم، سرور پایه را به یک سرور واقعی نزدیک می‌کند، فصل به فصل:

  1. محتوای پویا و جریان (Streaming): تولید پاسخ‌ها در لحظه به‌جای رشته‌های از پیش ساخته؛ معرفی Stream API در Node (شبیه خط لوله: readable.pipe(writable)).
  2. ورودی/خروجی فایل و مدیریت منابع: سرو فایل‌ها از دیسک، MIME Typeها و مدیریت صحیح خطا و اتصال‌های قطع‌شده.
  3. درخواست‌های Range: پشتیبانی از سربرگ Range و پاسخ 206 Partial Content — همان چیزی که ویدیوهای پخش‌شونده به آن وابسته‌اند.
  4. کش HTTP: سربرگ‌های Cache-Control، ETag و Last-Modified برای جلوگیری از ارسال دوباره محتوای بدون تغییر.
  5. فشرده‌سازی: پشتیبانی از Accept-Encoding و پاسخ gzip با Stream API — فشرده‌سازی «در حال جریان» بدون نگه‌داشتن کل فایل در حافظه.
  6. WebSocket و همزمانی: ارتقای دست‌ساز اتصال از HTTP به WebSocket (دست دادن با Upgrade، قاب‌بندی فریم‌ها با ماسک و) و مدیریت همزمانی اتصال‌های باز.
javascript// سرو فایل از دیسک با جریان: حافظه را اشغال نمی‌کند
const fs = require('fs');
const path = require('path');

function serveFile(socket, filePath) {
    const full = path.join(__dirname, 'public', filePath);
    const stat = fs.statSync(full);

    socket.write('HTTP/1.1 200 OK\r\n');
    socket.write(`Content-Length: ${stat.size}\r\n`);
    socket.write('Content-Type: text/html; charset=utf-8\r\n');
    socket.write('\r\n');

    // فایل را قطعه‌قطعه به سمت کلاینت جریان بده
    const stream = fs.createReadStream(full);
    stream.pipe(socket);
}
نکته: متن کامل کتاب (شامل ۱۳ فصل با تمرین و نسخه کامل کد) قابل خرید است؛ نسخه وبِ فصل‌های بخش اول رایگان و در دسترس است. اگر جاوااسکریپت بلد نیستید، «Eloquent JavaScript» منبع پیشنهادی خود کتاب است.
