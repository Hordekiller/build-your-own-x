۱. مقدمه: جست‌وجو به‌صورت هندسه

در سری مقاله‌های بویتر، هدف این است که موتورهای جست‌وجوی واقعی را از صفر بسازیم و بفهمیم. این قسمت به مدل فضای برداری (Vector Space Model) اختصاص دارد: هر سند را به‌صورت یک بردار در فضای «واژه‌ها» تصور می‌کنیم، پرس‌وجوی کاربر هم یک بردار است، و «ربط» یعنی نزدیکیِ زاویه‌ایِ این دو بردار — که با کسینوس زاویه بین بردارها (cosine similarity) سنجیده می‌شود. به زبان ساده: دو سندِ شبیه، در جهت‌های نزدیک‌به‌هم از مبدأ دراز می‌کشند.

ایدهٔ اصلی: به‌جای جست‌وجوی «کلمه در کلمه»، متن را به مختصاتِ هندسی تبدیل می‌کنیم و «شباهت» را با زاویهٔ بین بردارها حساب می‌کنیم — مدلی که پایهٔ بیشتر موتورهای کلاسیک است.

۲. ساخت واژه‌نامه: تابع concordance

اولین قدم، ساختن واژه‌نامه (vocabulary) است: تابعی که محتوای همهٔ فایل‌های یک پوشه را می‌خواند، آن‌ها را به واژه‌ها می‌شکند و یک نگاشت «واژه → شماره» می‌سازد. این شماره در واقع همان «دیمانسیون» بردار است — بعداً برای هر سند، یک بردار با همین ابعاد می‌سازیم. بویتر این تابع را concordance() می‌نامد:

pythonimport os, re

def concordance(path):
    """خواندن همهٔ فایل‌های پوشه و ساخت واژه‌نامه (واژه → شماره)"""
    words = {}
    for f in os.listdir(path):
        text = open(os.path.join(path, f), 'r').read().lower()
        for word in re.findall(r'\w+', text):
            words.setdefault(word, len(words))   # هر واژه جدید یک دیمانسیون جدید
    return words

۳. بردارِ هر سند: شمارش واژه‌ها

حالا برای هر فایل، یک بردار می‌سازیم که در دیمانسیون مربوط به هر واژه، تعدادِ دفعاتِ حضور آن واژه در فایل را دارد. نتیجه یک «ماتریس سند×واژه» است: شدت حضور هر واژه در هر سند. بویتر کد کامل این مرحله را قدم‌به‌قدم نشان می‌دهد (خواندن دوبارهٔ فایل‌ها، شمارش با شمارنده و پر کردن بردارها) — دقت کنید که این بار از واژه‌نامهٔ ساخته‌شده استفاده می‌کنیم تا همهٔ بردارها «هم‌ابعاد» باشند.

pythondef build_vectors(path, concord):
    """برای هر فایل، یک بردارِ شمارش واژه بساز"""
    vectors = {}
    files = os.listdir(path)
    for f in files:
        counts = {}
        text = open(os.path.join(path, f), 'r').read().lower()
        for word in re.findall(r'\w+', text):
            counts[word] = counts.get(word, 0) + 1
        vec = [0] * len(concord)
        for word, count in counts.items():
            vec[concord[word]] = count
        vectors[f] = vec
    return vectors

۴. رتبه‌بندی با فاصلهٔ کسینوسی

نقطهٔ اوج آموزش: تابعی که «شباهتِ کسینوسی» دو بردار را حساب می‌کند — حاصل‌ضرب نقطه‌ایِ بردارها تقسیم بر حاصل‌ضرب اندازهٔ (norm) آن‌ها:

pythonfrom math import sqrt, acos

def dot(vec_a, vec_b):
    return sum(a * b for a, b in zip(vec_a, vec_b))

def norm(vec):
    return sqrt(sum(x * x for x in vec))

def cosine_similarity(vec_a, vec_b):
    """شباهت کسینوسی: ۱ یعنی هم‌جهت (بسیار شبیه)، ۰ یعنی بی‌رابطه"""
    if norm(vec_a) == 0 or norm(vec_b) == 0:
        return 0.0
    return dot(vec_a, vec_b) / (norm(vec_a) * norm(vec_b))

def cosine_distance(vec_a, vec_b):
    """فاصلهٔ کسینوسی = ۱ - شباهت؛ عدد کوچک‌تر یعنی ربط بیشتر"""
    return 1.0 - cosine_similarity(vec_a, vec_b)

سپس برای یک پرس‌وجو: اول بردارِ پرس‌وجو را (در همین فضا، با همین واژه‌نامه) می‌سازیم، بعد فاصلهٔ کسینوسی آن را با بردارِ هر سند حساب می‌کنیم و نتایج را به‌ترتیب این فاصله مرتب می‌کنیم — سندی که کمترین فاصله (بزرگ‌ترین شباهت) را دارد، رتبهٔ اول می‌گیرد.

۵. الگوریتم اصلاح‌شده: IDf برای خنثی‌کردن واژه‌های بی‌ارزش

نسخهٔ اول ساده، مشکل معروفی دارد: واژه‌های پرتکرارِ بی‌معنی («the»، «and»، «of») بردارها را به هم نزدیک می‌کنند و کلمات کلیدیِ کمیاب را زیر سایه می‌برند. راه حل مقاله‌ای که بویتر «الگوریتم اصلاح‌شده» می‌نامد، اعمال وزنِ IDF است: واژه‌ای که در همهٔ فایل‌ها هست، اطلاعات کمی دارد و وزنش کم می‌شود؛ واژه‌ای که فقط در چند فایل است، «نشانه» است و وزنش زیاد می‌شود. در کد اصلاح‌شده، قبل از محاسبهٔ شباهت، هر درایهٔ بردار در IDFِ وزنِ همان واژه ضرب می‌شود؛ اثر عملی این است که نتایجِ معنادار به صدرِ رتبه‌بندی می‌آیند.

pythonimport math

def calculate_idf(vectors, concord):
    """وزن هر واژه: لگاریتمِ نسبتِ اسنادِ دارای واژه به کل اسناد (برعکس)"""
    n = len(vectors)
    idf = {}
    for word, idx in concord.items():
        docs_having = sum(1 for v in vectors.values() if v[idx] > 0)
        idf[word] = math.log(n / docs_having)
    return idf

def apply_idf(vectors, idf, concord):
    """ضرب کردن IDF در بردارها — واژه‌های رایج کمرنگ و کمیاب‌ها پررنگ می‌شوند"""
    result = {}
    for fname, vec in vectors.items():
        result[fname] = [vec[i] * idf[word] for word, i in concord.items()]
    return result
چرا «فضای برداری»؟ چون هر واژه یک «محور» است و هر سند یک نقطه/بردار در آن فضا. سندها به‌صورت هندسه قابل مقایسه می‌شوند — و این همان چیزی است که دهه‌ها موتورهای جست‌وجوی کلاسیک (مثل Lucene) روی آن ساخته شده‌اند.

۶. جمع‌بندی و قدم بعدی

این آموزش نشان می‌دهد موتور جست‌وجو چطور از «تطبیق کلمه» به «مقایسهٔ هندسی» می‌رسد: واژه‌نامه، بردارِ سند، شباهت کسینوسی و در نهایت وزن‌دهی IDF برای کیفیت. برای فهم عمیق‌ترِ امتیازدهی، آموزش «TF-IDF» همین مجموعه را بخوانید و برای نسخهٔ «جست‌وجوی آموختنی»، مقالهٔ «یادگیری جست‌وجوی متنی از بازخورد» مرجع بعدی شماست.
