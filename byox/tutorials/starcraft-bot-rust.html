رباتی برای استارکرافت در Rust، C یا هر زبان دیگری

مقدمه

استارکرافت: برود وار (StarCraft: Brood War). این بازی برای من خیلی مهم است! و حدس می‌زنم برای بسیاری از شما هم همین‌طور باشد. آن‌قدر مهم که نمی‌دانم اصلاً باید به صفحهٔ آن در ویکی‌پدیا لینک بدهم یا نه.

مدتی پیش هالت (Halt) به من پیام خصوصی (PM) فرستاد و پیشنهاد یادگیری زبان راست (Rust) را داد. مثل هر آدم معمولی، تصمیم گرفتیم با نوشتن «سلام دنیا» شروع کنیم: یک کتابخانهٔ پویا (dynamic library) برای ویندوز که بتواند در فضای آدرس‌دهی استارکرافت بارگذاری شود و واحدها (units) را مدیریت کند.

مقالهٔ زیر روند یافتن راه‌حل‌ها و استفاده از فناوری‌ها و تکنیک‌هایی را توصیف می‌کند که به شما امکان می‌دهند چیزهای جدیدی دربارهٔ راست و اکوسیستم آن یاد بگیرید. شاید هم الهام بگیرید که رباتی را با زبان موردعلاقهٔ خودتان پیاده‌سازی کنید — چه C، چه C++، چه روبی (Ruby)، پایتون و غیره.

حین خواندن این مقاله، قطعاً گوش‌دادن به سرود کرهٔ جنوبی ارزشش را دارد:

▶ تماشای «سرود استارکرافت» (Starcraft OST) در یوتیوب

ویدیوی «سرود استارکرافت» (Starcraft OST) که نویسنده در مقاله جاسازی کرده است؛ ما ویدیو را میزبانی نمی‌کنیم و فقط لینک اصلی یوتیوب را گذاشته‌ایم.

BWAPI

این بازی تقریباً ۲۰ ساله است و همچنان محبوب است؛ مسابقات حتی در سال ۲۰۱۷ هم جمعیت زیادی را در آمریکا جذب می‌کرد، جایی که نبرد استادان بزرگ «جِیدونگ» (Jaedong) در برابر «بیسو» (Bisu) برگزار شد. علاوه بر بازیکنان انسان، ماشین‌های بی‌شرم (soulless machines) هم در نبردهای SC شرکت می‌کنند! و این به لطف BWAPI ممکن شده است. لینک‌های مفیدتر.

بیش از یک دهه است که جامعه‌ای از توسعه‌دهندگان ربات حول این بازی وجود دارد. علاقه‌مندان ربات می‌سازند و در مسابقات مختلف شرکت می‌کنند. بسیاری از آن‌ها هوش مصنوعی (AI) و یادگیری ماشین (machine learning) مطالعه می‌کنند. BWAPI توسط دانشگاه‌ها برای آموزش دانشجویان استفاده می‌شود. حتی یک کانال توییچ (Twitch) وجود دارد که چنین مسابقاتی را پخش می‌کند.

پس، یک تیم از هواداران، بک‌اند (back-end) استارکرافت را سال‌ها پیش مهندسی معکوس (reverse engineering) کردند و یک API به زبان C++ توسعه دادند که به شما امکان می‌دهد ربات بسازید، در فرایند بازی تزریق (injection) انجام دهید و انسان‌های بیچاره را سلطه کنید.

همان‌طور که اغلب اتفاق می‌افتد، پیش از ساختن خانه لازم است سنگ معدن استخراج شود؛ برای ساختن ابزارِ ساخت ربات، باید یک API پیاده‌سازی کرد. راست (Rust) چه پیشنهادی دارد؟

FFI (واسط توابع خارجی)

کار با زبان‌های دیگر از راست بسیار ساده است. برای این کار یک FFI (واسط توابع خارجی — Foreign Function Interface) وجود دارد. بگذارید گزیدهٔ کوتاهی از مستندات را بیاورم.

تصور کنید یک کتابخانهٔ snappy داریم که فایل هدر snappy-c.h را دارد و این فایل شامل اعلان توابع است.

بیایید با استفاده از cargo یک پروژه بسازیم:

shell$ cargo new --bin snappy
     Created binary (application) `snappy` project
$ cd snappy
snappy$ tree
.
├── Cargo.toml
└── src
    └── main.rs

1 directory, 2 files

Cargo ساختار فایل استاندارد پروژه را ایجاد کرده است.

در Cargo.toml وابستگی به libc را مشخص می‌کنیم:

toml[dependencies]
libc = "0.2"

فایل src/main.rs به این شکل خواهد بود:

rustextern crate libc; // برای وارد کردن انواع سی؛ در مورد ما برای size_t
use libc::size_t;

#[link(name = "snappy")] // نام کتابخانه را برای لینک‌کردن تابع مشخص می‌کند
extern {
    // اعلان تابعی را می‌نویسیم که می‌خواهیم وارد کنیم؛
    // در C این اعلان به این شکل است:
    // size_t snappy_max_compressed_length(size_t source_length);
    fn snappy_max_compressed_length(source_length: size_t) -> size_t;
}

fn main() {
    let x = unsafe { snappy_max_compressed_length(100) };
    println!("max compressed length of a 100 byte buffer: {}", x);
}

بیایید پروژه را بسازیم و اجرا کنیم:

shellsnappy$ cargo build
...
snappy$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.02s
     Running `target/debug/snappy`
max compressed length of a 100 byte buffer: 148

می‌توانید فقط cargo run را صدا بزنید؛ این دستور قبل از اجرا، cargo build را هم صدا می‌زند. گزینهٔ دیگر این است که پروژه را بسازید و مستقیم باینری را صدا بزنید:

shellsnappy$ ./target/debug/snappy
max compressed length of a 100 byte buffer: 148

اگر کتابخانهٔ snappy نصب شده باشد، کد کامپایل خواهد شد (برای اوبونتو باید بستهٔ libsnappy-dev را نصب کنید).

shellsnappy$ ldd target/debug/snappy
    ...
    libsnappy.so.1 => /usr/lib/x86_64-linux-gnu/libsnappy.so.1 (0x00007f8de07cf000)

همان‌طور که می‌بینید، باینری ما به کتابخانهٔ مشترک (shared library) libsnappy لینک شده است. و فراخوانی snappy_max_compressed_length در کد ما، فراخوانی تابعی از همین کتابخانه است.

rust-bindgen

خیلی خوب می‌شد اگر می‌توانستیم FFI خودمان را خودکار تولید کنیم. خوشبختانه، ابزاری به نام rust-bindgen در جعبه‌ابزار یک معتاد راست وجود دارد. این ابزار قادر است بایندینگ‌های FFI را برای کتابخانه‌های C (و تا حدودی C++) تولید کند.

نصب:

shell$ cargo install bindgen

rust-bindgen چه شکلی است؟ فایل‌های هدر C/C++ را می‌گیریم، ابزار bindgen را به آن‌ها نشان می‌دهیم و خروجی، کد راست تولیدشده با اعلان‌های مناسب است تا بتوانیم از ساختارها و توابع C استفاده کنیم. این چیزی است که bindgen برای snappy تولید می‌کند:

shell$ bindgen /usr/include/snappy-c.h | grep -C 1 snappy_max_compressed_length
extern "C" {
    pub fn snappy_max_compressed_length(source_length: usize) -> usize;
}

معلوم می‌شود که bindgen نمی‌تواند با هدرهای BWAPI کنار بیاید و حجم عظیمی کد غیرقابل‌استفاده تولید می‌کند (به دلیل توابع عضو مجازی (virtual member functions)، std::string در API عمومی و غیره). ماجرا این است که BWAPI به زبان C++ نوشته شده است. استفاده از C++ حتی از پروژه‌های C++ هم عموماً دشوار است. وقتی کتابخانه ساخته شد، بهتر است با همان لینکر (linker) (همان نسخه) لینک شود؛ فایل‌های هدر باید با همان کامپایلر (همان نسخه) تجزیه شوند. همهٔ این عوامل ممکن است روی نتیجه اثر بگذارند. Mangling مثلاً که هنوز در GNU GCC نمی‌تواند بدون خطا پیاده‌سازی شود. این عوامل آن‌قدر قابل‌توجه‌اند که حتی gtest هم نتوانست بر آن‌ها غلبه کند. و در مستندات آمده است: بهتر است gtest را به‌عنوان بخشی از پروژه با همان کامپایلر و همان لینکر بسازید.

BWAPI-C

زبان C زبان میانجی (lingua franca) مهندسی نرم‌افزار است. اگر rust-bindgen برای زبان C خوب کار می‌کند، چرا BWAPI را برای C پیاده‌سازی نکنیم و بعد از API آن استفاده کنیم؟ ایدهٔ خوبی است!

بله، این ایدهٔ خوبی است — تا وقتی که به درون BWAPI نگاه کنید و تعداد کلاس‌ها و متدهایی را ببینید که باید پیاده‌سازی کنید. به‌خصوص همهٔ این چیدمان‌های حافظه (memory layouts)، کدهای asm، وصله‌کردن حافظه (memory patching) و دیگر «وحشت‌ها»یی که وقت آن‌ها را نداریم. لازم است از راه‌حل موجود به‌طور کامل استفاده شود.

اما به هر حال باید بر mangling، کد C++، وراثت (inheritance) و توابع عضو مجازی غلبه کنیم.

در C++ دو ابزار قدرتمند وجود دارد که برای حل مسئله‌مان استفاده خواهیم کرد: اشاره‌گرهای ناشفاف (opaque pointers) و extern "C".

extern "C" {} به کد C++ اجازه می‌دهد خودش را زیر نقاب C «ماسک» کند. این کار تولید نام توابع بدون mangling را ممکن می‌سازد.

اشاره‌گرهای ناشفاف به ما اجازه می‌دهند نوع را پاک کنیم و بدون ارائهٔ پیاده‌سازی، به «نوعی نامعین» اشاره‌گر بسازیم. چون این فقط اعلانِ یک نوع است، نمی‌توان از این نوع به‌صورت مقدار (by value) استفاده کرد؛ فقط از طریق اشاره‌گر.

تصور کنیم این کد C++ را داریم:

cppnamespace cpp {

struct Foo {
    int bar;

    virtual int get_bar() {
        return this->bar;
    }
};

} // namespace cpp

می‌توانیم آن را به یک هدر C تبدیل کنیم:

cextern "C" {

typedef struct Foo_ Foo; // اشاره‌گر ناشفاف به Foo

// فراخوانی cpp::Foo::get_bar
int Foo_get_bar(Foo* self);

}

و این بخش C++ است که حلقهٔ اتصال بین هدر C و پیاده‌سازی C++ خواهد بود:

cppint Foo_get_bar(Foo* self) {
    // اشاره‌گر ناشفاف را به cpp::Foo مشخص تبدیل کن و متد ::get_bar را صدا بزن
    return reinterpret_cast<cpp::Foo*>(self)->get_bar();
}

لازم نبود همهٔ متدهای کلاس‌ها این‌طور پردازش شوند. در BWAPI کلاس‌هایی وجود دارند که می‌توانید خودتان با فیلدهای همین ساختارها پیاده‌سازی کنید؛ مثلاً typedef struct Position { int x; int y; } Position; و متدهایی مثل Position::get_distance.

کلاس‌هایی هم بودند که مجبور بودم به‌شکلی خاص با آن‌ها رفتار کنم. مثلاً AIModule باید اشاره‌گر به یک کلاس C++ با مجموعهٔ مشخصی از توابع عضو مجازی باشد. با این حال، این هدر و این پیاده‌سازی است.

پس از چند ماه کار سخت، ۵۵۴ متد و یک دوجین کلاس، کتابخانهٔ کراس‌پلتفرم BWAPI-C متولد شد که به شما اجازه می‌دهد در C ربات بسازید. محصول جانبی این کار، امکان کراس‌کامپایل (cross-compilation) و امکان پیاده‌سازی API در هر زبان دیگری بود که از FFI و قرارداد فراخوانی cdecl پشتیبانی می‌کند.

نکته: اگر کتابخانه می‌نویسید، لطفاً API آن را در C بنویسید.

مهم‌ترین ویژگی BWAPI-C، گسترده‌ترین یکپارچگی ممکن با زبان‌های برنامه‌نویسی دیگر است. پایتون، روبی، راست، PHP، جاوا و بسیاری دیگر قادرند با C کار کنند؛ پس اگر پیچ‌وخم‌ها را هموار کنید و wrapperهای خودتان را پیاده‌سازی کنید، می‌توانید با کمک آن‌ها هم ربات بنویسید.

نوشتن ربات در C

این بخش اصول کلی سازمان داخلی ماژول‌های استارکرافت را توصیف می‌کند.

۲ نوع ربات وجود دارد: ماژول (module) و کلاینت (client). بیایید به مثال نوشتن یک ماژول نگاه کنیم.

ماژول یک کتابخانهٔ پویا است. اصل کلی بارگذاری کتابخانه‌های پویا را می‌توان اینجا دید. ماژول باید ۲ تابع export کند: newAIModule و gameInit.

gameInit آسان است. این تابع برای انتقال اشاره‌گر به بازی جاری فراخوانی می‌شود. این اشاره‌گر بسیار مهم است، چون در درون BWAPI یک متغیر سراسری استاتیک وجود دارد که در برخی بخش‌های کد از آن استفاده می‌شود. بگذارید gameInit را تعریف کنیم:

cDLLEXPORT void gameInit(void* game) {
    BWAPIC_setGame(game);
}

newAIModule کمی پیچیده‌تر است. باید اشاره‌گر به کلاس C++ برگرداند که یک جدول متد مجازی با نام‌هایی مثل onXXXXX دارد؛ این متدها در رویدادهای خاص بازی فراخوانی می‌شوند. بگذارید ساختار ماژول را اعلان کنیم:

ctypedef struct ExampleAIModule
{
    const AIModule_vtable* vtable_;

    const char* name;
} ExampleAIModule;

فیلد اول باید اشاره‌گر به جدول متدها باشد (یک‌جور جادو است). این هم تابع newAIModule:

cDLLEXPORT void* newAIModule() {
    ExampleAIModule* const module = (ExampleAIModule*) malloc( sizeof(ExampleAIModule) );
    module->name = "ExampleAIModule";
    module->vtable_ = &module_vtable;

    return createAIModuleWrapper( (AIModule*) module );
}

createAIModuleWrapper یک ترفند جادویی دیگر است که اشاره‌گر C را به اشاره‌گر کلاس C++ با توابع عضو مجازی تبدیل می‌کند.

module_vtable یک متغیر استاتیک روی جدول متدهاست؛ مقادیر متدها با اشاره‌گر به توابع سراسری پر می‌شوند:

cstatic AIModule_vtable module_vtable = {
    onStart,
    onEnd,
    onFrame,
    onSendText,
    onReceiveText,
    onPlayerLeft,
    onNukeDetect,
    onUnitDiscover,
    onUnitEvade,
    onUnitShow,
    onUnitHide,
    onUnitCreate,
    onUnitDestroy,
    onUnitMorph,
    onUnitRenegade,
    onSaveGame,
    onUnitComplete
};

void onEnd(AIModule* module, bool isWinner) { }
void onFrame(AIModule* module) {}
void onSendText(AIModule* module, const char* text) {}
void onReceiveText(AIModule* module, Player* player, const char* text) {}
void onPlayerLeft(AIModule* module, Player* player) {}
void onNukeDetect(AIModule* module, Position target) {}
void onUnitDiscover(AIModule* module, Unit* unit) {}
void onUnitEvade(AIModule* module, Unit* unit) {}
void onUnitShow(AIModule* module, Unit* unit) {}
void onUnitHide(AIModule* module, Unit* unit) {}
void onUnitCreate(AIModule* module, Unit* unit) {}
void onUnitDestroy(AIModule* module, Unit* unit) {}
void onUnitMorph(AIModule* module, Unit* unit) {}
void onUnitRenegade(AIModule* module, Unit* unit) {}
void onSaveGame(AIModule* module, const char* gameName) {}
void onUnitComplete(AIModule* module, Unit* unit) {}

اگر به نام توابع و امضاهایشان نگاه کنید، مشخص است در چه شرایطی و با چه آرگومان‌هایی باید فراخوانی شوند. در مثال همهٔ توابع را خالی گذاشتم، به‌جز:

cvoid onStart(AIModule* module) {
    ExampleAIModule* self = (ExampleAIModule*) module;
    Game* game = BWAPIC_getGame();
    Game_sendText(game, "Hello from bwapi-c!");
    Game_sendText(game, "My name is %s", self->name);
}

این تابع وقتی فراخوانی می‌شود که بازی اجرا شود. آرگومان آن اشاره‌گر به ماژول جاری است. BWAPIC_getGame اشاره‌گر سراسری به بازی را برمی‌گرداند که با فراخوانی BWAPIC_setGame تنظیمش کردیم. پس بیایید یک مثال کارآمد از کراس‌کامپایل یک ماژول را نشان بدهیم:

دکمه‌ها را فشار دهید و بازی را اجرا کنید. اطلاعات بیشتر دربارهٔ کامپایل و اجرا در سایت BWAPI و در BWAPI-C موجود است.

bwapi-sys

در اکوسیستم راست روش مشخصی برای نام‌گذاری بسته‌هایی که به کتابخانه‌های بومی (native) لینک می‌شوند وجود دارد. هر بستهٔ foo-sys دو کارکرد مهم را انجام می‌دهد:

  • با کتابخانهٔ بومی libfoo لینک می‌شود؛
  • اعلان‌هایی برای توابع کتابخانهٔ libfoo فراهم می‌کند. اما فقط اعلان‌ها! انتزاعات سطح بالا در کرِیت‌های *-sys فراهم نمی‌شوند.

برای اینکه بستهٔ *-sys بتواند با موفقیت لینک شود، باید به cargo بگویید کتابخانهٔ بومی را جست‌وجو کند و/یا کتابخانه را از سورس بسازد.

برای اینکه بستهٔ *-sys اعلان‌ها را فراهم کند، یا باید خودتان آن‌ها را بنویسید یا با bindgen تولید کنید. باز هم bindgen. تلاش شمارهٔ دو =)

تولید بایندینگ‌ها فوق‌العاده آسان است:

shellbindgen BWAPI.h -o lib.rs \
  --opaque-type ".+_" \
  --blacklist-type "std.*|__.+|.+_$|Game_v(Send|Print|Draw).*|va_list|.+_t$" \
  --no-layout-tests \
  --no-derive-debug \
  --raw-line "#![allow(improper_ctypes, non_snake_case)]" \
  -- -I../submodules/bwapi-c/include

sed -i -r -- 's/.+\s+(.+)_;/pub struct \1;/' lib.rs

BWAPI.h فایلی است با همهٔ هدرهای C از BWAPI-C.

مثلاً bindgen قبلاً چنین اعلان‌هایی را برای توابع بالا تولید کرده است:

rustextern "C" {
    /// BWAPIC_setGame باید از gameInit فراخوانی شود تا BWAPI::BroodwarPtr مقداردهی شود
    pub fn BWAPIC_setGame(game: *mut Game);
}
extern "C" {
    pub fn BWAPIC_getGame() -> *mut Game;
}

دو استراتژی وجود دارد: نگه‌داشتن کد تولیدشده در مخزن، و تولید کد در لحظهٔ ساخت (build). هر دو رویکرد مزایا و معایب خودشان را دارند.

خوشحالم که با bwapi-sys آشنا می‌شوید؛ یک قدم کوچک دیگر به سمت هدفمان.

یادتان هست که قبلاً دربارهٔ کراس‌پلتفرم صحبت کردم؟ nlinker به پروژه پیوست و یک استراتژی زیرکانه پیاده‌سازی کرد. اگر هاست هدف ویندوز باشد، BWAPIC از قبل ساخته‌شده از GitHub دانلود می‌شود. و برای بقیهٔ اهداف، BWAPI-C را از سورس برای OpenBW می‌سازیم (کمی بعد درباره‌اش صحبت می‌کنم).

bwapi-rs

حالا بایندینگ‌ها را داریم و می‌توانیم انتزاعات سطح بالا را تعریف کنیم. دو نوع برای کار داریم: مقادیر خالص (pure values) و اشاره‌گرهای ناشفاف.

با مقادیر خالص همه‌چیز ساده است. بیایید رنگ‌ها را مثال بزنیم. باید استفاده از آن‌ها را در کد راست راحت کنیم تا بتوانیم رنگ‌ها را به‌شکلی راحت و طبیعی به کار ببریم:

rustgame.draw_line(CoordinateType::Screen, (10, 20), (30, 40), Color::Red);
                                                                  ^^^

پس برای استفادهٔ راحت لازم است enum را با ثابت‌های C++ تعریف کنیم، اما به‌شکلی اصطلاحی (idiomatic) برای راست، و متدهای تبدیل به bwapi_sys::Color را با استفاده از std::convert::From تعریف کنیم:

rust// نسخهٔ FFI
#[repr(C)]
#[derive(Copy, Clone)]
pub struct Color {
    pub color: ::std::os::raw::c_int,
}

// نسخهٔ اصطلاحی
#[derive(PartialEq, PartialOrd, Copy, Clone)]
pub enum Color {
    Black = 0,
    Brown = 19,
...

برای راحتی‌تان می‌توانید از کرِیت enum-primitive-derive استفاده کنید.

استفاده از اشاره‌گرهای ناشفاف هم آسان است. بیایید از الگوی Newtype استفاده کنیم:

rustpub struct Player(*mut sys::Player);

یعنی Player نوعی ساختار با یک فیلد خصوصی است — یک اشاره‌گر خام ناشفاف از C. و این‌جا راه تعریف Player::color است:

rustimpl Player {

    // پس متد به‌صورت Player::getColor در bwapi-sys اعلان شده است
    //extern "C" {
    //    pub fn Player_getColor(self_: *mut Player) -> Color;
    //}

    pub fn color(&self) -> Color {
        // bwapi_sys::Player_getColor - تابع پوششی (wrapper) از BWAPI-C
        // self.0 - اشاره‌گر ناشفاف
        let color = unsafe { bwapi_sys::Player_getColor(self.0) };
        color.into() // تبدیل bwapi_sys::Color -> Color
    }
}

حالا می‌توانیم اولین ربات خودمان را در راست بنویسیم!

ساخت ربات در Rust

به‌عنوان اثبات مفهوم (proof of concept)، ربات شبیه به یک کشورِ معروف خواهد بود: کل وظیفه، استخدام کارگر و جمع‌آوری مواد معدنی (minerals) است.

بیایید با توابع لازم gameInit و newAIModule شروع کنیم:

rust#[no_mangle]
pub unsafe extern "C" fn gameInit(game: *mut void) {
    bwapi_sys::BWAPIC_setGame(game as *mut bwapi_sys::Game);
}

#[no_mangle]
pub unsafe extern "C" fn newAIModule() -> *mut void {
    let module = ExampleAIModule { name: String::from("ExampleAIModule") };
    let result = wrap_handler(Box::new(module));

    result
}

#[no_mangle] همان کارکرد extern "C" در C++ را انجام می‌دهد. درون wrap_handler همهٔ جادو رخ می‌دهد: جایگزینی جدول توابع مجازی و «ماسک‌کردن» کلاس C++.

تعریف ساختار ماژول حتی از C ساده‌تر و شیک‌تر است:

ruststruct ExampleAIModule {
    name: String,
}

بیایید چند متد برای رندر آمار و دادن دستورها اضافه کنیم:

rustimpl ExampleAIModule {
    fn draw_stat(&mut self) {
        let game = Game::get();
        let message = format!("Frame {}", game.frame_count());
        game.draw_text(CoordinateType::Screen, (10, 10), &message);
    }
    fn give_orders(&mut self) {
        let player = Game::get().self_player();

        for unit in player.units() {

            match unit.get_type() {
                UnitType::Terran_SCV |
                UnitType::Zerg_Drone |
                UnitType::Protoss_Probe => {
                    if !unit.is_idle() {
                        continue;
                    }

                    if unit.is_carrying_gas() || unit.is_carrying_minerals() {
                        unit.return_cargo(false);
                        continue;
                    }

                    if let Some(mineral) = Game::get()
                        .minerals()
                        .min_by_key(|m| unit.distance_to(m))
                    {
                        // به مواد معدنی بیشتری نیاز داریم!
                        unit.right_click(&mineral, false);
                    }
                }

                UnitType::Terran_Command_Center => {
                    unit.train(UnitType::Terran_SCV);
                }

                UnitType::Protoss_Nexus => {
                    unit.train(UnitType::Protoss_Probe);
                }

                UnitType::Zerg_Hatchery |
                UnitType::Zerg_Lair |
                UnitType::Zerg_Hive => {
                    unit.train(UnitType::Zerg_Drone);
                }

                _ => {}
            };
        }
    }
}

برای تبدیل نوع ExampleAIModule به یک ماژول واقعی باید آن را به رویدادهای onXXXX پاسخگو کنید. برای این کار باید نوع EventHandler را پیاده‌سازی کنید که مشابه جدول مجازی AIModule_vtable در C است:

rustimpl EventHandler for ExampleAIModule {
    fn on_start(&mut self) {
        Game::get().send_text(&format!("Hello from Rust! My name is {}", self.name));
    }
    fn on_end(&mut self, _is_winner: bool) {}
    fn on_frame(&mut self) {
        self.draw_stat();
        self.give_orders();
    }
    fn on_send_text(&mut self, _text: &str) {}
    fn on_receive_text(&mut self, _player: &mut Player, _text: &str) {}
    fn on_player_left(&mut self, _player: &mut Player) {}
    fn on_nuke_detect(&mut self, _target: Position) {}
    fn on_unit_discover(&mut self, _unit: &mut Unit) {}
    fn on_unit_evade(&mut self, _unit: &mut Unit) {}
    fn on_unit_show(&mut self, _unit: &mut Unit) {}
    fn on_unit_hide(&mut self, _unit: &mut Unit) {}
    fn on_unit_create(&mut self, _unit: &mut Unit) {}
    fn on_unit_destroy(&mut self, _unit: &mut Unit) {}
    fn on_unit_morph(&mut self, _unit: &mut Unit) {}
    fn on_unit_renegade(&mut self, _unit: &mut Unit) {}
    fn on_save_game(&mut self, _game_name: &str) {}
    fn on_unit_complete(&mut self, _unit: &mut Unit) {}
}

▶ تماشای ویدیوی اجرای ربات در یوتیوب

ویدیوی اجرای ربات که نویسنده در مقاله جاسازی کرده است؛ ما ویدیو را میزبانی نمی‌کنیم و فقط لینک اصلی یوتیوب را گذاشته‌ایم.

OpenBW

این‌ها حتی فراتر رفتند. آن‌ها تصمیم گرفتند نسخهٔ متن‌باز SC:BW بنویسند! و در این کار خوب‌اند. یکی از اهدافشان پیاده‌سازی تصاویر HD بود، اما SC:Remastered از آن‌ها جلو زد = ( در این لحظه می‌توانید از API آن‌ها برای نوشتن ربات استفاده کنید (بله، در C++ هم)، اما شگفت‌انگیزترین قابلیت، امکان مشاهدهٔ رپلی‌ها (replays) مستقیم در مرورگر است.

جمع‌بندی

یک مسئلهٔ حل‌نشده در پیاده‌سازی وجود داشت: ما یگانه بودن مراجع (references) را کنترل نمی‌کنیم؛ پس وجود &mut و & به همان ناحیه، هنگام اصلاح شیء به رفتار تعریف‌نشده (undefined behavior) منجر می‌شود. یک‌جور دردسر. هالت تلاش کرد بایندینگ‌های اصطلاحی پیاده‌سازی کند، اما نتوانست راه‌حلی پیدا کند. همچنین اگر می‌خواهید این کار را کامل کنید، باید با دقت API C++ را «زیرورو کنید» و اصلاح‌کننده‌های const را درست قرار دهید.

از کار روی این پروژه واقعاً لذت بردم؛ روزها (하루 종일 — تمام روز) رپلی‌ها را تماشا می‌کردم و عمیقاً در فضای بازی غرق می‌شدم. این بازی یک فروکردن شگفت‌انگیز (놀라운) در جهان هستی ایجاد کرد. هیچ بازی از نظر محبوبیت با SC: BW قابل مقایسه (비교할 수 없다 — غیرقابل‌مقایسه) نیست و تأثیر آن بر سیاست کرهٔ جنوبی (대한민국 정치) غیرقابل‌تصور بود. احتمالاً (아마도) پروگِیمرها در کره به‌اندازهٔ بازیگران نقش اول درام‌های کره‌ای که در ساعت پربیننده پخش می‌شوند محبوب‌اند. همچنین (또한)، اگر در کره پروگِیمر باشید، می‌توانید به یک یگان ویژهٔ ارتش بپیوندید.

نکته: نویسنده در پاراگراف بالا عمداً بخش‌هایی را به زبان کر‌ه‌ای نوشته تا به بازی ادای احترام کند؛ ترجمهٔ هر عبارت کر‌ه‌ای در داخل پرانتز آورده شده است.
