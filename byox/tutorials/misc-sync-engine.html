مشکل همگام‌سازی داده

یادداشت‌بردار، تقویم، لیست خرید — همه این‌ها «دیتای مشترک» دارند که روی چند دستگاه باید یکسان باشد. راه اول: پوش‌اندن دلتاها به سرور مرکزی (مانند CRDT ساده). مشکل: وقتی دو دستگاه آفلاین تغییراتی می‌دهند، بعداً چه کسی برنده است؟ پاسخ CRDTهاست: ادغام بدون درگیری و همیشه سازگار.

CRDT چیست؟

CRDT (نوع دادهٔ تکرارشوندهٔ همگرا) ساختاری است که هر دستگاه کپی محلی خودش را دارد؛ تغییرات به شکل صریح «جابه‌جا» با نسخه و شناسهٔ دستگاه نگه داشته می‌شوند و ادغام‌کردن دو حالت همیشه نتیجهٔ یکسان می‌دهد — مهم نیست چقدر باهم در تعارض آمده باشند. متنی که در Google Docs هم‌زمان چند نفر ویرایش می‌کنند، نمونهٔ آن است.

Yjs: CRDT آماده

Yjs یک کتابخانهٔ CRDT برای JS است که متن، آرایه و Map را پشتیبانی می‌کند. ایدهٔ این آموزش: یک «موتور همگام‌سازی» که سرور Node فقط «مرکز رویداد» است؛ یعنی فقط تغییرات را بین کلاینت‌ها پخش می‌کند (relay) بدون اینکه بداند محتوا چیست:

JavaScriptconst Y = require('yjs');
const ws = require('ws');

// یک سند مشترک در سرور
const doc = new Y.Doc();

// وقتی کلاینتی تغییر فرستاد، به بقیه بده
function handleMessage(conn, data) {
  Y.applyUpdate(doc, data);          // ادغام تغییر در سرور
  broadcast(doc);                    // پخش وضعیت جدید برای همه
}

// کلاینت تازه‌وصل‌شده: وضعیت کامل را می‌گیرد نه دلتا
function onConnect(conn) {
  conn.send(Y.encodeStateAsUpdate(doc));   // state sync
}

الگوی `state sync + update sync` همان پروتکل Yjs است: اول وضعیت کامل، بعد فقط دلتاها — دقیقاً مانند راه‌اندازی اولیهٔ همگام‌سازی.

چرا جذاب است؟

با این موتور، همگام‌سازی آفلاین-اول (offline-first) برای هر اپلیکیشنی ممکن می‌شود: تغییرات روی دستگاه محلی ذخیره، و به‌محض وصل شدن وصل می‌شوند و ادغام می‌شوند. بدون CRDT باید مشکل «برندهٔ آخرین نوشتن» و نسخه‌بندی پیچیده را دستی حل می‌کردید.
