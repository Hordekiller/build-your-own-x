مدیریت فایل‌های dotfiles با nistow

⚙ زبان: Nim 📁 دسته: ابزار خط فرمان ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی مقاله «Day 6: Manage your dotfiles easily with nistow» نوشته «xmonader» (مجموعه آموزش‌های Nim Days) است. نسخه کامل و به‌روز را از سایت اصلی بخوانید.
↗ مشاهده منبع اصلی

مقدمه

امروز ابزاری می‌سازیم تا فایل‌های dotfiles خود را به‌آسانی مدیریت کنیم.

چیدمان فایل‌های dotfiles

text        i3
        `-- .config
            `-- i3
                `-- config

پس در اینجا یک دایرکتوری به نام i3 در بالاترین سطح داریم که «نام برنامه» (APP_NAME) را نشان می‌دهد و زیر آن درختی از مسیرهای پیکربندی قرار دارد. اینجا به این معناست که قرار است فایل config نسبت به «دایرکتوری مقصد» (destination directory) به مسیر .config/i3/config لینک شود.

نکته: دایرکتوری خانه (Home) مقصد پیش‌فرض است.

چه انتظاری داریم؟

shell➜  ~ nistow --help
    Stow 0.1.0
        -h | --help     : show help
        -v | --version  : show version
        --verbose       : verbose messages
        -s | --simulate : simulate stow operation
        -f | --force    : override old links
        -a | --app      : application path to stow
        -d | --dest     : destination to stow to
  • پرچم --simulate برای شبیه‌سازی روی سیستم فایل بدون لینک‌سازی واقعی استفاده می‌شود.
  • --app دایرکتوری برنامه‌ای است که با چیدمان dotfiles توصیف‌شده در بالا سازگار است.
  • --dest مقصدی است که فایل‌ها زیر آن سمبلینک (symlink) می‌شوند؛ پیش‌فرض آن دایرکتوری خانه است.
shellnistow --app=/home/striky/wspace/dotfiles/localdir --dest=/tmp/tmpconf --verbose

پیاده‌سازی

nimproc writeHelp() = 
    echo """
Stow 0.1.0 (Manage your dotfiles easily)

Allowed arguments:
    -h | --help     : show help
    -v | --version  : show version
    --verbose       : verbose messages
    -s | --simulate : simulate stow operation
    -f | --force    : override old links
    -a | --app      : application path to stow
    -d | --dest     : destination to stow to

    """

writeHelp یک رویهٔ (proc) ساده است که رشتهٔ راهنما را روی خروجی استاندارد (stdout) می‌نویسد.

nimproc writeVersion() =
    echo "Stow version 0.1.0"

برای نوشتن نسخه.

nimproc cli*() =

نقطهٔ ورود (entry point) برنامهٔ خط فرمان ما.

nim  var 
    simulate, verbose, force: bool = false
    app, dest: string = ""

این متغیرها گزینه‌های مختلفی را نشان می‌دهند که در برنامه اجازه می‌دهیم.

nim  if paramCount() == 0:
    writeHelp()
    quit(0)

اگر هیچ آرگومانی پاس داده نشود، رشتهٔ راهنما را می‌نویسیم و طبق اصطلاح Nim با «exit» یا «quit» و با «کد خروج» (exit status) صفر از برنامه خارج می‌شویم.

nim  for kind, key, val in getopt():
    case kind
    of cmdLongOption, cmdShortOption:
        case key
        of "help", "h": 
            writeHelp()
            quit()
        of "version", "v":
            writeVersion()
            quit()
        of "simulate", "s": simulate = true
        of "verbose": verbose = true
        of "force", "f": force = true
        of "app", "a": app = val
        of "dest", "d": dest = val 
        else:
          discard
    else:
      discard

در اینجا رشتهٔ خط فرمان را با استفاده از getopt تجزیه (parse) می‌کنیم.

nim  for kind, key, val in getopt():
    case kind
    of cmdLongOption, cmdShortOption:

پس برای فرمان --app=/home/striky/dotfiles/i3 -f، نوع (kind) مربوط به --app برابر cmdLongOption و نوع مربوط به -f برابر cmdShortOption است؛ کلید (key) برای --app برابر app و برای -f برابر f است؛ مقدار (val) برای --app برابر /home/striky/dotfiles/i3 است و برای -f در تجزیهٔ ما true قرار می‌گیرد؛ زیرا بیشتر شبیه یک سوییچ بولی (boolean) است — اگر وجود داشته باشد یعنی می‌خواهیم آن را true کنیم.

nim  if dest.isNilOrEmpty():
    dest = getHomeDir()

در اینجا مقصد پیش‌فرض (dest) را روی دایرکتوری خانه قرار می‌دهیم.

nim  if app.isNilOrEmpty():
    echo "Make sure to provide --app flags"
    quit(1)

در اینجا اگر app تنظیم نشده باشد، با «کد خطا» (exit status) ۱ از برنامه خارج می‌شویم.

nim  try:
    stow(getLinkableFiles(appPath=app, dest=dest), simulate=simulate, verbose=verbose, force=force)
  except ValueError:
    echo "Error happened: " & getCurrentExceptionMsg()

در اینجا تلاش می‌کنیم همهٔ فایل‌های قابل لینک در دایرکتوری app را به دایرکتوری dest لینک کنیم و همهٔ گزینه‌هایی را که از آرگومان‌های خط فرمان جمع‌آوری کرده‌ایم — یعنی simulate، verbose و force — پاس می‌دهیم؛ و همه را در try/except می‌پیچیم تا خطا به کاربر نمایش داده شود.

nimwhen isMainModule:
  cli()

اگر این ماژول، ماژول اصلی (main module) باشد، نقطهٔ ورود خود یعنی cli را صدا می‌زنیم.

بازگشت به stow و getLinkableFiles

خیلی خب! برگردیم به stow و getLinkableFiles.

با getLinkableFiles شروع می‌کنیم. چیدمان dotfiles را به خاطر دارید؟

nim    # appPath: دایرکتوری فایل‌های dotfiles برنامه
    #     انتظار داریم دایرکتوری این سلسله‌مراتب را داشته باشد.
    #     i3
    #     `-- .config
    #         `-- i3
    #         `-- config

می‌خواهیم همهٔ فایل‌های موجود در آن را با مسیر کامل بگیریم؛ فایل لینکِ هر یک دقیقاً همان مسیر است، فقط نام appPath با مسیر dest جایگزین می‌شود:

text[/home/striky/wspace/dotfiles/i3]/.config/i3/config -> [/home/striky]/.config/i3/config
__________________appPath________                      _____dest____
nimtype
  LinkInfo = tuple[original:string, dest:string]

نوعی ساده برای نمایش مسیر اصلی و محلی که باید به آن سمبلینک ساخته شود.

nimproc getLinkableFiles*(appPath: string, dest: string=expandTilde("~")): seq[LinkInfo] =

    # فایل‌های قابل لینک را در یک برنامهٔ مشخص جمع‌آوری می‌کند.

    # appPath: دایرکتوری فایل‌های dotfiles برنامه
    #     انتظار داریم دایرکتوری این سلسله‌مراتب را داشته باشد.
    #     i3
    #     `-- .config
    #         `-- i3
    #         `-- config

    # dest: مقصد فایل‌های لینک : پیش‌فرض خانهٔ کاربر است.

getLinkableFiles رویه‌ای است که appPath و dest را می‌گیرد و یک seq از LinkInfo برمی‌گرداند که این تبدیل را برای هر فایل انجام می‌دهد:

text[/home/striky/wspace/dotfiles/i3]/A_FILE_PATH -> [/home/striky]A_FILE_PATH
__________________apppath________                _____dest____
nim  var appPath = expandTilde(appPath)
  if not dirExists(appPath):
    raise newException(ValueError, fmt("App path {appPath} doesn't exist."))
  var linkables = newSeq[LinkInfo]()
  for filepath in walkDirRec(appPath, yieldFilter={pcFile}):
    let linkpath = filepath.replace(appPath, dest)
    var linkInfo : LinkInfo = (original:filepath, dest:linkpath)
    linkables.add(linkInfo)
  return linkables

در اینجا با استفاده از walkDirRec روی دایرکتوری appPath پیمایش می‌کنیم و در آرگومان yieldFilter مشخص می‌کنیم که به pcFile — یعنی «مؤلفهٔ مسیرِ فایل» — علاقه‌مندیم؛ به‌عبارتی فقط ورودی‌هایی از نوع فایل معمولی (regular file).

رویهٔ stow

nimproc stow(linkables: seq[LinkInfo], simulate: bool=true, verbose: bool=true, force: bool=false) = 
    # لینک‌های نمادین و دایرکتوری‌های مربوطه را می‌سازد

    # linkables فهرستی از تاپل‌ها (filepath, linkpath) است : List[Tuple[file_path, link_path]]
    # simulate شبیه‌سازی را بدون هیچ اثری روی سیستم فایل انجام می‌دهد: bool
    # verbose پیام‌های لاگ را نمایش می‌دهد: bool

  for linkinfo in linkables:
    let (filepath, linkpath) = linkinfo
    if verbose:
      echo(fmt("Will link {filepath} -> {linkpath}"))

    if not simulate:
      createDir(parentDir(linkpath))
      if not fileExists(linkpath):
        createSymlink(filepath, linkpath)
      else:
        if force:
          removeFile(linkpath)
          createSymlink(filepath, linkpath)
        else:
          if verbose:
            echo(fmt("Skipping linking {filepath} -> {linkpath}"))

stow رویهٔ بسیار ساده‌ای است؛ فهرستی از LinksInfo می‌گیرد که همهٔ اطلاعات (نام فایل اصلی و مقصد سمبلینک) را دارد و سمبلینک‌سازی را انجام می‌دهد — فقط به شرطی که شبیه‌سازی نباشد — و اگر verbose فعال باشد، پیام‌ها را چاپ می‌کند.
