بازسازی گیت با روبی (Rebuilding Git in Ruby)

چرا گیت را با روبی بازسازی کنیم؟

گیت ابزاری قدرتمند است که هر روز استفاده می‌کنیم، اما تا به حال فکر کرده‌اید «جادوی» آن چطور کار می‌کند؟ مستندات داخلی گیت ترسناک، ناقص و بی‌مثال‌اند؛ کندوکاو در پیاده‌سازی واقعی آن هم اگر با C آشنا نباشید سخت است. برداشتن موتورِ یک سیستم و سرهم کردن دوبارهٔ آن، یکی از بهترین راه‌های فهمیدنِ سیستم است. این مقاله همین کار را با روبی انجام می‌دهد: پیاده‌سازی گیت برای توسعه‌دهندگان Rails که روبی را بهتر از C می‌شناسند.

نتیجهٔ نهایی RGit است که این کارها را انجام می‌دهد: اجرای دستورها از طریق نسخهٔ شخصیِ rgit، ایجاز مخزن (init)، مرحله‌بندی فایل‌ها (add) و ثبت عکس فوری (commit).

قدم ۱ — دستورهای گیت و فلسفهٔ یونیکس

گیت به‌صورت مدولار ساخته شده و از «فلسفهٔ یونیکس» پیروی می‌کند: ابزارهای کوچک و تیز. هر دستور یک فایل اسکریپت مجزاست و دستور سطح بالا فقط به آن‌ها پراکسی می‌کند. کافیست کنوانسیون نام‌گذاری را رعایت کنیم تا دستور دلخواه خودمان را بسازیم:

ruby#!/usr/bin/env ruby
# bin/rgit
command, *args = ARGV

if command.nil?
  $stderr.puts "Usage: rgit <command> [<args>]"
  exit 1
end

path_to_command = File.expand_path("../rgit-#{command}", __FILE__)
if !File.exist? path_to_command
  $stderr.puts "No such command"
  exit 1
end

exec path_to_command, *args

این اسکریپت یکی از سه کار را می‌کند: نمایش راهنما اگر زیردستوری داده نشده، خطا اگر اسکریپتی برای زیردستور وجود نداشته باشد، یا اجرای زیردستور. به‌عنوان شهروند خوب یونیکس، پیام‌های خطا به stderr می‌روند و کد خروج غیرصفر برمی‌گردانیم.

قدم ۲ — ایجاز مخزن (init)

گیت همهٔ داده و فرادادهٔ خود را در پوشه‌ای به‌نام .git در ریشهٔ مخزن نگه می‌دارد. ساختار هدف:

ترمینال.rgit
├── HEAD
├── config
├── objects
│   ├── info
│   └── pack
└── refs
    ├── heads
    └── tags

HEAD فایلی است با مقدار ثابت ref: refs/heads/master و بقیهٔ درخت هم پوشه‌های خالی‌اند. «بیشترِ این ساخت را فراخوانی‌های پشت‌سرهمِ Dir.mkdir تشکیل می‌دهد»:

ruby#!/usr/bin/env ruby
# bin/rgit-init
RGIT_DIRECTORY = ".rgit".freeze
OBJECTS_DIRECTORY = "#{RGIT_DIRECTORY}/objects".freeze
REFS_DIRECTORY = "#{RGIT_DIRECTORY}/refs".freeze

if Dir.exists? RGIT_DIRECTORY
  $stderr.puts "Existing RGit project"
  exit 1
end

def build_objects_directory
  Dir.mkdir OBJECTS_DIRECTORY
  Dir.mkdir "#{OBJECTS_DIRECTORY}/info"
  Dir.mkdir "#{OBJECTS_DIRECTORY}/pack"
end

def build_refs_directory
  Dir.mkdir REFS_DIRECTORY
  Dir.mkdir "#{REFS_DIRECTORY}/heads"
  Dir.mkdir "#{REFS_DIRECTORY}/tags"
end

def initialize_head
  File.open("#{RGIT_DIRECTORY}/HEAD", "w") do |file|
    file.puts "ref: refs/heads/master"
  end
end

Dir.mkdir RGIT_DIRECTORY
build_objects_directory
build_refs_directory
initialize_head

$stdout.puts "RGit initialized in #{RGIT_DIRECTORY}"

قدم ۳ — افزودن به ناحیهٔ مرحله‌بندی (add)

مرحله‌بندی فایل چند گام دارد: ساخت SHA از روی محتوای فایل، ساخت بلاب با فشرده‌سازی محتوا، ذخیرهٔ بلاب به‌صورت objects/<دو کاراکتر اول sha>/<بقیهٔ sha>، و ثبت sha و مسیر در ایندکس.

ایندکس واقعی گیت فایلی باینری با هدر DIRC و فرادادهٔ زیاد (ctime، mtime، mode، uid، gid و...) است و به همین دلیل «مشتی کاراکتر بی‌معنی» به نظر می‌رسد. مقاله برای سادگی و خوانایی، قالب متنی ساده را برمی‌گزیند:

ruby# قالب ایندکس RGit
<SHA> <path>
<SHA> <path>
<SHA> <path>
ruby#!/usr/bin/env ruby
# bin/rgit-add
require "digest"
require "zlib"
require "fileutils"

RGIT_DIRECTORY = ".rgit".freeze
OBJECTS_DIRECTORY = "#{RGIT_DIRECTORY}/objects".freeze
INDEX_PATH = "#{RGIT_DIRECTORY}/index"

path = ARGV.first
if path.nil?
  $stderr.puts "No path specified"
  exit 1
end

file_contents = File.read(path)
sha = Digest::SHA1.hexdigest file_contents
blob = Zlib::Deflate.deflate file_contents
object_directory = "#{OBJECTS_DIRECTORY}/#{sha[0..1]}"
FileUtils.mkdir_p object_directory
blob_path = "#{object_directory}/#{sha[2..-1]}"

File.open(blob_path, "w") { |file| file.print blob }
File.open(INDEX_PATH, "a") { |file| file.puts "#{sha} #{path}" }

بعد از rgit add bin/rgit، انبار اشیاء یک بلاب فشرده دارد و ایندکس یک خط مثل b302dd6f8cd2b385b170e78c14503342c0ba6ae8 bin/rgit.

قدم ۴ — ثبت عکس فوری (commit)

بلاب‌ها محتوای یک فایل در یک زمان‌اند. برای عکس برداشتن از کل پروژه، گیت برای هر دایرکتوری یک شیء «tree» می‌سازد: درخت‌ها نمایانگر پوشه‌ها و بلاب‌ها نمایانگر فایل‌ها، و کل این ساختار به یک شیء «commit» گره می‌خورد. دستور commit سه کار می‌کند:

  1. ساختن ساختار tree/blob
  2. ساخت شیء commit که به آن ساختار اشاره می‌کند
  3. به‌روزرسانی شاخهٔ فعلی برای اشاره به این commit

چون ساخت اشیاء کار رایجی است، به کلاس کمکی استخراج شده است:

ruby# lib/rgit/object
require "fileutils"

module RGit
  class Object
    def initialize(sha)
      @sha = sha
    end

    def write(&block)
      object_directory = "#{OBJECTS_DIRECTORY}/#{sha[0..1]}"
      FileUtils.mkdir_p object_directory
      object_path = "#{object_directory}/#{sha[2..-1]}"
      File.open(object_path, "w", &block)
    end

    private
    attr_reader :sha
  end
end

سپس خود دستور commit: اول ایندکس را به ساختار هشِ درختی تبدیل می‌کند، بعد این ساختار را به‌صورت بازگشتی به اشیاء tree روی دیسک تبدیل کرده و sha هرکدام را در والدش ثبت می‌کند؛ پیام commit را با ویرایشگر کاربر ($VISUAL) می‌گیرد؛ و در پایان، شاخهٔ فعلی (که از HEAD خوانده می‌شود) را به commit جدید اشاره می‌دهد و ایندکس را خالی می‌کند:

ruby#!/usr/bin/env ruby
# bin/rgit-commit — خلاصه‌شده
def index_tree
  index_files.each_with_object({}) do |line, obj|
    sha, _, path = line.split
    segments = path.split("/")
    segments.reduce(obj) do |memo, s|
      if s == segments.last
        memo[segments.last] = sha
        memo
      else
        memo[s] ||= {}
        memo[s]
      end
    end
  end
end

def build_tree(name, tree)
  sha = Digest::SHA1.hexdigest(Time.now.iso8601 + name)
  object = RGit::Object.new(sha)
  object.write do |file|
    tree.each do |key, value|
      if value.is_a? Hash
        dir_sha = build_tree(key, value)
        file.puts "tree #{dir_sha} #{key}"
      else
        file.puts "blob #{value} #{key}"
      end
    end
  end
  sha
end

def build_commit(tree:)
  # پیام از طریق ویرایشگر $VISUAL گرفته می‌شود
  sha = Digest::SHA1.hexdigest(Time.now.iso8601 + "user")
  object = RGit::Object.new(sha)
  object.write do |file|
    file.puts "tree #{tree}"
    file.puts "author user"
    file.puts
    file.puts message
  end
  sha
end

نتیجه: برای یافتن وضعیت فعلی، از HEAD شاخهٔ فعلی را می‌یابیم؛ شاخه به آخرین commit اشاره می‌کند؛ commit به شیء tree ریشه اشاره می‌کند؛ و آن tree به tree های زیرپوشه و بلاب‌های فایل‌ها. این ساختارِ اشیاءِ اشاره‌کننده به هم، همان چیزی است که گیت را قدرتمند می‌کند: با تغییر چند فایل اشاره‌گر، به هر نقطه‌ای از تاریخچه می‌رویم.

چرا این کار ارزشش را دارد؟

  • ساختار واقعی .git، ایندکس و اشیاء را با مثال‌های واقعی روبی می‌بینید — نه فقط تئوری
  • فلسفهٔ «ابزارهای کوچک و تیز» گیت را در عمل تجربه می‌کنید
  • درک می‌کنید که چرا گیت می‌تواند با تغییر چند فایل اشاره‌گر، در تاریخچه جابه‌جا شود

اگر می‌خواهید عمیق‌تر بروید، کد کامل RGit در github.com/JoelQ/rgit موجود است.
