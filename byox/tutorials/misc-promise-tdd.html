پیاده‌سازی پرامیس‌ها از صفر (به روش TDD)

↗ مشاهده منبع اصلی

چرا TDD برای این پروژه؟

پرامیس دارای رفتارهای دقیق و مشخصی است (یک‌بار settle، زنجیره، خطا). تست‌نویسی قبل از کد، دقیقاً مشخص می‌کند که «چه رفتاری باید داشته باشیم» و به ما اجازه می‌دهد بدون حدس‌زدن، پیاده‌سازی کنیم. این آموزش با `jest` یا یک تست‌رانر ساده کار می‌کند.

اولین تست: resolve و then

اولین تست‌های ما رفتار پایه را مشخص می‌کنند: یک پرامیس با resolve مقدار می‌گیرد؛ و then آن مقدار را می‌گیرد:

JavaScript// تست: پرامیس ساخته شده و resolve می‌شود
test('resolve مقدار را می‌دهد', () => {
  const p = new MyPromise((resolve) => resolve(42));
  return p.then(value => {
    expect(value).toBe(42);
  });
});

test('then زنجیره‌ای کار می‌کند', () => {
  const p = new MyPromise((resolve) => resolve(2));
  return p
    .then(v => v * 10)
    .then(v => v + 1)
    .then(v => {
      expect(v).toBe(21);
    });
});

حالا کد مینیمال را می‌نویسیم تا این تست‌ها سبز شوند: state، settle و then با زنجیره.

تست‌های reject و catch

مرحلهٔ بعدی خطاهاست: reject مقدار خطا را می‌دهد، catch آن را می‌گیرد و throw در executor باعث reject می‌شود:

JavaScript// روش رد شدن را با همان ساختار settle پیاده می‌کنیم
test('reject باعث فراخوانی catch می‌شود', () => {
  const p = new MyPromise((resolve, reject) => reject(new Error('بد')));

  return p.catch(err => {
    expect(err.message).toBe('بد');
  });
});

test('throw در executor مساوی reject است', () => {
  const p = new MyPromise(() => {
    throw new Error('منفجر شد');
  });
  return expect(p).rejects.toThrow('منفجر شد');
});

برای پاس شدن، `constructor` باید با try/catch آرگومان executor را اجرا کند و `catch` را روی `then(undefined, onRejected)` تعریف کنیم.

پیاده‌سازی نهایی (خلاصه)

با این تست‌ها، پیاده‌سازی خاکستری روشن می‌شود: یک object با سه حالت، یک آرایهٔ handlers و یک `settle` که فقط یک باr فراخوانی می‌شود:

JavaScriptclass MyPromise {
  static PENDING = 'pending';
  static FULFILLED = 'fulfilled';
  static REJECTED = 'rejected';

  constructor(executor) {
    this.state = MyPromise.PENDING;
    this.value = undefined;
    this.handlers = [];
    const resolve = v => this.settle(MyPromise.FULFILLED, v);
    const reject = r => this.settle(MyPromise.REJECTED, r);
    try { executor(resolve, reject); } catch (e) { reject(e); }
  }

  settle(state, value) {
    if (this.state !== MyPromise.PENDING) return;
    this.state = state;
    this.value = value;
    this.handlers.forEach(h => h());
  }

  then(onF, onR) {
    return new MyPromise((resolve, reject) => {
      this.handlers.push(() => {
        const handler = this.state === MyPromise.FULFILLED ? onF : onR;
        try {
          const r = handler ? handler(this.value) : this.value;
          if (r instanceof MyPromise) r.then(resolve, reject);
          else resolve(r);
        } catch (e) { reject(e); }
      });
    });
  }

  catch(onR) { return this.then(undefined, onR); }
}

نکتهٔ مهم: تست‌ها ابتدا نوشته می‌شوند، بعد کد; و هر مرحله فقط «به‌قدر کافی» برای سبز شدن پیاده‌سازی می‌شود.

جمع‌بندی

این آموزش نشان می‌دهد که TDD فقط برای پروژه‌های بزرگ نیست — حتی برای فاخته‌های الگوریتمی هم بهترین راه برای دقیق‌شدن است. پس از اتمام، تست‌های رفتار ناهمگام (setTimeout و میکروتسک) را هم می‌توانید اضافه کنید.
