مدیر پنجره در اکوسیستم X11

در X11، سرور X فقط «نقاشی» و ورودی را مدیریت می‌کند؛ چیدمان پنجره‌ها به مدیر پنجره (Window Manager) واگذار می‌شود. مدیر پنجره به‌عنوان یک کلاینت خاص، حدود پنجره‌ها را تغییر می‌دهد، titlebar ترسیم می‌کند و کلیدها را تفسیر می‌کند. برنامه‌های عادی هیچ اطلاعی از چیدمان به‌علت دکوراسیون‌ها ندارند.

این آموزش با یک مدیر پنجرهٔ ساده شروع می‌شود که پنجره‌ها را ترسیم و جابه‌جا می‌کند و بعداً ویژگی‌هایی مثل تایلینگ (tiling) و focus را اضافه می‌کند.

رویدادها و اتصال به سرور

همهٔ کارها از طریق پروتکل X (با xcb در C) انجام می‌شود. مدیر پنجره باید به رویدادهای `MapRequest` (وقتی پنجره جدیدی می‌خواهد دیده شود) و `ConfigureRequest` (وقتی پنجره می‌خواهد اندازه/موقعیت بگیرد) گوش دهد:

C++// حلقهٔ اصلی رویدادهای مدیر پنجره
while ((e = xcb_wait_for_event(conn))) {
    switch (e->response_type & ~0x80) {
        case XCB_MAP_REQUEST:
            map_request(conn, (xcb_map_request_event_t*)e);
            break;
        case XCB_CONFIGURE_REQUEST:
            configure_request(conn, (xcb_configure_request_event_t*)e);
            break;
        case XCB_KEY_PRESS:
            handle_key(conn, (xcb_key_press_event_t*)e);
            break;
    }
    free(e);
}

// نمایش و جای‌گذاری پنجرهٔ جدید
void map_request(xcb_connection_t* c, xcb_map_request_event_t* e) {
    xcb_configure_window(c, e->window,
        XCB_CONFIG_WINDOW_X | XCB_CONFIG_WINDOW_Y |
        XCB_CONFIG_WINDOW_WIDTH | XCB_CONFIG_WINDOW_HEIGHT,
        (uint32_t[]){ 0, 0, SCR_W, SCR_H });
    xcb_map_window(c, e->window);
    xcb_flush(c);
}

به این صورت، هر برنامهٔ جدید خودکار به‌اندازهٔ تمام صفحه بزرگ می‌شود — رفتار پایهٔ مدیران پنجرهٔ تایلینگ.

اعلان‌های EWMH و دسکتاپ مدرن

فساً به تنهایی کافی نیست؛ برای اینکه محیط‌های دسکتاپ متوجه مدیر پنجره شوند، باید پروتکل EWMH رعایت شود: اعلام `_NET_SUPPORTED`، `_NET_NUMBER_OF_DESKTOPS` و مواردی مشابه. همچنین تعامل با `_NET_WM_STATE` برای پنجره‌های تمام‌صفحه.

این بخش در قسمت دوم آموزش به‌طور کامل پوشش داده می‌شود؛ و بعد از آن پروژه آمادهٔ استفاده در یک دسکتاپ واقعی می‌شود.
