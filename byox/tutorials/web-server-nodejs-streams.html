یک وب سرور را از صفر با NodeJS Streams کدنویسی کنیم

مقدمه

در این پست، به سراغ مبانی می‌رویم و یک وب سرور ساده را از صفر با NodeJS می‌سازیم. در این مسیر، ساختار درخواست‌ها و پاسخ‌های HTTP را مرور می‌کنیم و با Stream API نود آشنا می‌شویم.

اول، ماژول داخلی http نود را به‌سرعت مرور می‌کنیم. بعد، ساختار کلی یک درخواست و پاسخ HTTP را بررسی می‌کنیم. سپس با ماژول داخلی net، یک سرور TCP سطح پایین می‌سازیم و سعی می‌کنیم آن را به یک وب سرور قابل استفاده تبدیل کنیم.

لازم به ذکر است که همهٔ کدهای این مقاله هرگز نباید در برنامه‌های تولیدی استفاده شوند؛ فقط جنبهٔ آموزشی دارند.

نگاهی سریع به ماژول http داخلی نود

NodeJS همراه با یک سرور HTTP ساده ارائه می‌شود. این سرور به ما اجازه می‌دهد روی هر پورتی گوش دهیم و یک تابع callback ارائه دهیم که در هر درخواست ورودی فراخوانی می‌شود.

تابع callback دو آرگومان دریافت می‌کند: یک شیء Request و یک شیء Response. شیء Request با خصوصیات مفیدی دربارهٔ درخواست پر شده و از شیء Response برای ارسال پاسخ به کلاینت استفاده می‌شود. مثال «Hello World» با سرور http نود:

JavaScriptconst http = require('http');
const server = http.createServer();
server.on('request', (req, res) => {
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
  res.setHeader('Content-Type','text/plain');
  res.end('Hello World!');
});
server.listen(3000);

این کار یک وب سرور راه می‌اندازد که روی پورت 3000 گوش می‌دهد. وقتی درخواستی بیاید، پیامی با تاریخ فعلی و سپس متد و URL درخواست لاگ می‌شود. این داده‌ها از پارامتر req می‌آید — شیء Request که توسط نود ساخته شده. این شیء خصوصیتی به نام .socket نیز دارد که سوکت TCP سطح پایین‌تر است.

در کد بالا، این که به یک شیء مرتب با req.method و req.url دسترسی داریم یعنی شخص دیگری به جای ما زحمتِ پارس‌کردن متن درخواست و تبدیلش به یک شیء مرتب را کشیده است. در بخش بعد، به ساختار یک درخواست HTTP نگاه می‌کنیم تا سرنخ‌هایی برای پارس‌کردنش به دست آوریم.

تجزیهٔ HTTP

در این‌جا یک نمونه درخواست HTTP است:

HTTPPOST /posts/42/comments HTTP/1.1\r\n
Host: www.my-api.com\r\n
Accept: application/json\r\n
Authorization: Bearer N2E5NTU2MzQ5MGQ4N2UzNjIxOTY2ZDU1M2YwNjA3OGFjYjgyMjU4NQ\r\n
Accept-Encoding: gzip, deflate, br\r\n
Content-Type: application/json\r\n
Content-Length: 28\r\n
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10.13; rv:58.0)\r\n
\r\n
{"text":"this is a comment"}
  • هر خط با \r\n جدا می‌شود.
  • خط اول «خط درخواست» (request line) نام دارد؛ از سه نشانهٔ جدا شده با فاصله تشکیل شده: متد درخواست (POST)، URI درخواست (/posts/42/comments) و نسخهٔ پروتکل (HTTP/1.1).
  • هر خط بعدی یک هدر درخواست است؛ از یک فیلد و مقدارش که با : جدا شده‌اند تشکیل می‌شود.
  • خطی فقط با \r\n هست که پایان هدرها را نشان می‌دهد. هر چیزی بعد از آن بدنهٔ درخواست است.
  • در این درخواست، بدنه یک سند JSON است که با هدر Content-Type هماهنگ است و طولش ۲۸ بایت است که با هدر Content-Length مطابقت دارد.

و این یک نمونه پاسخ HTTP است:

HTTPHTTP/1.1 200 OK\r\n
Server: nginx/1.9.4\r\n
Date: Fri, 20 Apr 2017 16:19:42 GMT\r\n
Content-Type: application/json\r\n
Content-Length: 141\r\n
\r\n
{
  "id": "8fh924b42o",
  "text": "this is a comment",
  "createdAt": "2017-04-20T16:19:42.840Z",
  "updatedAt": "2017-04-20T16:19:42.840Z"
}
  • مثل درخواست، هر خط با \r\n جدا می‌شود.
  • خط اول «خط وضعیت» (status line) نام دارد: نسخهٔ HTTP، کد وضعیت (200) و عبارت دلیل (OK).
  • هر خط بعدی یک هدر پاسخ است با همان ساختار هدرهای درخواست.
  • یک خط خالی پایان هدرها و شروع بدنه را نشان می‌دهد.
  • بدنه یک سند JSON با ۱۴۱ بایت است که با مقادیر هدرها مطابقت دارد.

دریافت و پارس‌کردن درخواست HTTP

NodeJS ماژول داخلی net را برای ساخت یک سرور TCP استریمی فراهم کرده. «استریمی» یعنی سرور می‌تواند داده را در طول زمان ارسال و دریافت کند و از Stream API نود استفاده می‌کند.

جایی که سرور http رویداد request را با اشیاء Request و Response منتشر می‌کرد، سرور TCP رویداد connection را با یک شیء Socket منتشر می‌کند. اشیاء Socket از نوع Duplex Streams هستند؛ یعنی هم قابل خواندن‌اند و هم قابل نوشتن.

اگر به سرور TCP خودمان درخواست HTTP بفرستیم، خواندن از Socket متن درخواست را به ما می‌دهد. دو راه برای خواندن از یک readable stream هست: اشتراک در رویداد data یا فراخواندن متد .read(). بگذارید اولی را ببینیم:

JavaScriptconst net = require('net');
const server = net.createServer();
server.on('connection', handleConnection);
server.listen(3000);

function handleConnection(socket) {
  socket.on('data', (chunk) => {
    console.log('Received chunk:\n', chunk.toString());
  });
  socket.write('HTTP/1.1 200 OK\r\nServer: my-web-server\r\nContent-Length: 0\r\n\r\n');
}

این کد را در فایلی به نام server.js بگذارید و از خط فرمان با node server.js اجرایش کنید. در ترمینال دیگر، با cURL یک درخواست ساده به سرورتان بفرستید:

Bashcurl -v localhost:3000/some/url

خروجی با جزئیات از cURL می‌بینید که هدرهای درخواست و پاسخ را نشان می‌دهد و در ترمینال نود چیزی شبیه این دیده می‌شود:

ConsoleReceived chunk:
GET /some/url HTTP/1.1
Host: localhost:3000
User-Agent: curl/7.54.0
Accept: */*

بگذارید یک درخواست POST با داده بفرستیم:

Bashcurl -v -XPOST -d'hello=world' localhost:3000/some/url

اگر بدنهٔ درخواست طولانی‌تر بود، آن را در چند chunk دریافت می‌کردید. اما یک وب سرور همیشه لازم نیست بدنهٔ درخواست را پردازش کند. اغلب بخش هدر برای شروع پردازش درخواست کافی است. چون داریم یک وب سرور عمومی می‌نویسیم، باید راهی پیدا کنیم که به محض رسیدن به رشتهٔ \r\n\r\n در ورودی، دریافت داده را از سوکت متوقف کنیم.

این کار با متد .read() سوکت راحت‌تر انجام می‌شود، چون کنترل می‌کنیم چه زمانی کشیدن داده از استریم را متوقف کنیم. کدی برای این کار:

JavaScriptconst net = require('net');
const server = net.createServer();
server.on('connection', handleConnection);
server.listen(3000);

function handleConnection(socket) {
  // یک بار مشترک رویداد readable بشو تا بتوانیم .read() را صدا بزنیم
  socket.once('readable', function() {
    // بافر برای نگه‌داشتن دادهٔ ورودی
    let reqBuffer = new Buffer('');
    // بافر موقت برای خواندن chunk ها
    let buf;
    let reqHeader;
    while(true) {
      // خواندن داده از سوکت
      buf = socket.read();
      // اگر داده‌ای نبود متوقف شو
      if (buf === null) break;

      // افزودن دادهٔ جدید به بافر درخواست
      reqBuffer = Buffer.concat([reqBuffer, buf]);

      // آیا به \r\n\r\n رسیده‌ایم؟ یعنی پایان هدر
      let marker = reqBuffer.indexOf('\r\n\r\n')
      if (marker !== -1) {
        // اگر رسیده‌ایم، ممکن است بعد از آن داده باشد؛ به خاطر بسپار
        let remaining = reqBuffer.slice(marker + 4);
        // هدر همهٔ چیزهایی است که خوانده‌ایم، تا قبل از \r\n\r\n
        reqHeader = reqBuffer.slice(0, marker).toString();
        // دادهٔ اضافه را دوباره به استریم سوکت برمی‌گردانیم
        socket.unshift(remaining);
        break;
      }
    }
    console.log(`Request header:\n${reqHeader}`);

    // ارسال یک پاسخ عمومی
    socket.end('HTTP/1.1 200 OK\r\nServer: my-custom-server\r\nContent-Length: 0\r\n\r\n');
  });
}

کد کمی طولانی‌تر است چون به منطقی برای تصمیم‌گیری دربارهٔ زمان توقف خواندن از استریم نیاز داریم. این به ما اجازه می‌دهد هدر را از بدنه جدا کنیم. بخش کلیدی خط socket.unshift است که هر دادهٔ اضافه‌ای را که خوانده بودیم دوباره به استریم readable برمی‌گرداند؛ بنابراین می‌توانیم همین سوکت را در صورت لزوم به کاربر بدهیم تا از آن بخواند.

کد کامل وب سرور پایه

اینجا کد کامل وب سرور پایهٔ ماست که همهٔ چیزهایی که دیدیم را کنار هم می‌گذارد. سرورمان تابعی به نام createWebServer(requestHandler) در معرض دید قرار می‌دهد که یک هندلر به شکل (req, res) => void می‌گیرد — دقیقاً مثل وب سرور پایهٔ نود. کامنت‌های کد توضیح می‌دهند هر گام چه می‌کند:

JavaScriptconst net = require('net');

function createWebServer(requestHandler) {
  const server = net.createServer();
  server.on('connection', handleConnection);
  
  function handleConnection(socket) {
    // یک بار مشترک رویداد readable شو تا بتوانیم .read() را صدا بزنیم
    socket.once('readable', function() {
      // بافر برای نگه‌داشتن دادهٔ ورودی
      let reqBuffer = new Buffer('');
      // بافر موقت برای خواندن chunk ها
      let buf;
      let reqHeader;
      while(true) {
        // خواندن داده از سوکت
        buf = socket.read();
        // اگر داده‌ای نبود متوقف شو
        if (buf === null) break;
  
        // افزودن دادهٔ جدید به بافر درخواست
        reqBuffer = Buffer.concat([reqBuffer, buf]);
  
        // آیا به \r\n\r\n رسیده‌ایم؟ یعنی پایان هدر
        let marker = reqBuffer.indexOf('\r\n\r\n')
        if (marker !== -1) {
          // ممکن است بعد از آن داده باشد؛ به خاطر بسپار
          let remaining = reqBuffer.slice(marker + 4);
          // هدر همهٔ آن چیزی است که خوانده‌ایم تا قبل از \r\n\r\n
          reqHeader = reqBuffer.slice(0, marker).toString();
          // برگرداندن دادهٔ اضافه به استریم readable سوکت
          socket.unshift(remaining);
          break;
        }
      }
      
      /* کارهای مربوط به درخواست */
      // شروع پارس‌کردن هدر
      const reqHeaders = reqHeader.split('\r\n');
      // خط اول خاص است
      const reqLine = reqHeaders.shift().split(' ');
      // خطوط بعدی هر کدام یک هدرند؛ از آن‌ها یک شیء می‌سازیم
      const headers = reqHeaders.reduce((acc, currentHeader) => {
        const [key, value] = currentHeader.split(':');
        return {
          ...acc,
          [key.trim().toLowerCase()]: value.trim()
        };
      }, {});
      // این شیء به callback هندل درخواست فرستاده می‌شود
      const request = {
        method: reqLine[0],
        url: reqLine[1],
        httpVersion: reqLine[2].split('/')[1],
        headers,
        // کاربر این وب سرور می‌تواند مستقیم از سوکت بخواند تا بدنهٔ درخواست را بگیرد
        socket
      };

      /* کارهای مربوط به پاسخ */
      // مقادیر اولیه
      let status = 200, statusText = 'OK', headersSent = false, isChunked = false;
      const responseHeaders = {
        server: 'my-custom-server'
      };
      function setHeader(key, value) {
        responseHeaders[key.toLowerCase()] = value;
      }
      function sendHeaders() {
        // فقط یک بار انجامش بده :)
        if (!headersSent) {
          headersSent = true;
          // افزودن هدر تاریخ
          setHeader('date', new Date().toGMTString());
          // فرستادن خط وضعیت
          socket.write(`HTTP/1.1 ${status} ${statusText}\r\n`);
          // فرستادن هر کدام از هدرهای بعدی
          Object.keys(responseHeaders).forEach(headerKey => {
            socket.write(`${headerKey}: ${responseHeaders[headerKey]}\r\n`);
          });
          // افزودن \r\n پایانی که هدرها را از بدنه جدا می‌کند
          socket.write('\r\n');
        }
      }
      const response = {
        write(chunk) {
          if (!headersSent) {
            // اگر هدر content-length وجود ندارد، Transfer-Encoding chunked را مشخص کن
            if (!responseHeaders['content-length']) {
              isChunked = true;
              setHeader('transfer-encoding', 'chunked');
            }
            sendHeaders();
          }
          if (isChunked) {
            const size = chunk.length.toString(16);
            socket.write(`${size}\r\n`);
            socket.write(chunk);
            socket.write('\r\n');
          }
          else {
            socket.write(chunk);
          }
        },
        end(chunk) {
          if (!headersSent) {
            // طول کامل پاسخ را می‌دانیم؛ بگذار تنظیمش کنیم
            if (!responseHeaders['content-length']) {
              // فرض می‌کنیم chunk بافر است نه رشته!
              setHeader('content-length', chunk ? chunk.length : 0);
            }
            sendHeaders();
          }
          if (isChunked) {
            if (chunk) {
              const size = (chunk.length).toString(16);
              socket.write(`${size}\r\n`);
              socket.write(chunk);
              socket.write('\r\n');
            }
            socket.end('0\r\n\r\n');
          }
          else {
            socket.end(chunk);
          }
        },
        setHeader,
        setStatus(newStatus, newStatusText) { status = newStatus, statusText = newStatusText },
        // متد راحتی برای ارسال JSON از طریق سرور
        json(data) {
          if (headersSent) {
            throw new Error('Headers sent, cannot proceed to send JSON');
          }
          const json = new Buffer(JSON.stringify(data));
          setHeader('content-type', 'application/json; charset=utf-8');
          setHeader('content-length', json.length);
          sendHeaders();
          socket.end(json);
        }
      };
      
      // ارسال درخواست به هندلر!
      requestHandler(request, response);
    });
  }

  return {
    listen: (port) => server.listen(port)
  };
}

const webServer = createWebServer((req, res) => {
  // این همان کد اولیه‌مان با ماژول http است :)
  console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
  res.setHeader('Content-Type','text/plain');
  res.end('Hello World!');
});

webServer.listen(3000);

همان‌طور که در ابتدای پست گفته شد، این کد سرور هیچ جایی در تولید ندارد؛ فقط برای یادگیری استریم‌ها و بافرهاست.

بیشتر کدها خودتوضیح‌دهنده‌اند: درخواست را با قوانین بخش قبل پارس و پاسخ را ارسال می‌کنیم. تنها بخش جدید، Transfer-Encoding: chunked است که وقتی طول پاسخ را از قبل نمی‌دانیم لازم است. می‌توانید دربارهٔ chunked transfer encoding در ویکی‌پدیا بیشتر بخوانید.

نتیجه‌گیری

با استفاده از بلوک‌های ساختمان سطح پایین‌تر مثل net، Stream و Buffer، توانستیم یک سرور HTTP ابتدایی بر پایهٔ یک سرور TCP و کمی منطق پارس بسازیم. در این مسیر، کمی دربارهٔ نحوهٔ کار درخواست‌ها و پاسخ‌های HTTP، و همچنین مبانی استریم‌ها و بافرهای readable و writable یاد گرفتیم.
