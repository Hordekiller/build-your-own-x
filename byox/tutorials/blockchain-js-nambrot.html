مقدمه

با تمام هیاهویی که پیرامون بلاک‌چین‌ها (blockchains) و ارزهای دیجیتال (cryptocurrencies) وجود دارد، تصمیم گرفتم کمی بیشتر دربارهٔ آن‌ها یاد بگیرم. و چه راهی بهتر از این که خودتان تلاش کنید آن‌ها را بسازید؟ در ادامه، توضیحی قدم‌به‌قدم از نحوهٔ کار یک بلاک‌چین و چگونگی ساخت آن از اصول اولیه خواهید یافت. در هر قدم از مراحل زیر، می‌توانید نسخهٔ معادل دمو را در آدرس blockchain-step${N}.nambrot.com ببینید و نسخهٔ نهایی در blockchain.nambrot.com در دسترس است.

سلب مسئولیت (disclaimer): نویسنده از برخی جنبه‌ها که این بلاک‌چین برای اهداف آموزشی از واقعیت فاصله می‌گیرد، آزادانه چشم‌پوشی کرده است.

نگاهی به ساختار و معماری مخزن

گام ۱: زنجیره‌ای از بلاک‌ها؟

برای درک نحوهٔ کار بلاک‌چین‌ها، از خودِ نام شروع می‌کنیم. بلاک‌چین؟ زنجیره‌ای از بلاک‌ها؟

یک تصور غلط رایج این است که بلاک‌چین یک زنجیرهٔ منفرد از بلاک‌هاست؛ در حالی که در واقعیت، بیشتر شبیه به یک درخت از بلاک‌هاست. بنابراین در هر لحظه، زنجیره‌های متعددی از بلاک‌ها وجود دارند که هر کدام با اشاره به والد (parent) خود ساخته می‌شوند. این اشاره‌کردن از طریق هش‌ها (hashes) انجام می‌شود که بر اساس داده‌های درون بلاک محاسبه می‌شوند (یعنی هش والد، داده‌های تراکنش و سایر موارد مهم).

با اشاره‌کردن از طریق هش بلاک‌ها، می‌توانیم ترتیب خاصی برای بلاک‌ها اعمال کنیم. یعنی با فرض یک زنجیره از بلاک‌ها، نمی‌توانید بلاکی را در وسط زنجیره بردارید و داده‌هایش را تغییر دهید؛ زیرا این کار هش آن را تغییر می‌دهد و به‌تبع آن، هش همهٔ بلاک‌هایی که از آن بلاک منشعب شده‌اند نیز تغییر می‌کند.

این قطعه‌کد برگرفته از بخش گام ۱ فایل README.md مخزن است (نسخهٔ آموزشی ساده‌شده):

jsclass Block {
  constructor(blockchain, parentHash, nonce = sha256(new Date().getTime().toString()).toString()) {
    this.blockchain = blockchain;
    this.nonce = nonce;
    this.parentHash = parentHash;
    this.hash = sha256(this.nonce + this.parentHash).toString()
  }

اگر به کد نگاه کنید، می‌بینید که جنبهٔ همتا‌به‌همتا (P2P) بلاک‌چین‌ها چگونه وارد بازی می‌شود: به محض اینکه یک نود تصمیم بگیرد بلاکی را «استخراج» کرده، می‌تواند آن بلاک را به همهٔ نودهای دیگر پخش (broadcast) کند؛ آن‌ها می‌توانند آن را تأیید کنند و سپس آن را به درخت خودشان نیز اضافه کنند.

گام ۲: خب پس «بلاک‌چینِ» اصلی چیست؟

لینک دموی گام ۲

در گام ۱ دیدیم که در یک زنجیره از بلاک‌ها، بلاک آخر عملاً همهٔ داده‌های زنجیرهٔ اجداد خود را معتبر می‌سازد؛ زیرا هر تغییری در داده‌های بالادست زنجیره، ناگزیر هش بلاک آخر را تغییر می‌دهد. همهٔ این‌ها عالی است؛ اما منظور مردم از «بلاک‌چینِ» اصلی چیست؟

طبق تعریف، «بلاک‌چینِ» اصلی فقط بلندترین زنجیرهٔ موجود در درخت است. بنابراین ممکن است زنجیره‌ای در برهه‌ای از زمان بلندترین باشد و سپس زنجیرهٔ دیگری جای آن را بگیرد. بیایید بلندترین زنجیره را در درخت بصری‌سازی کنیم. این قطعه‌کد برگرفته از بخش گام ۲ فایل README.md است:

jsclass Blockchain {
  longestChain() {
    const blocks = values(this.blocks)
    const maxByHeight = maxBy(prop('height'))
    const maxHeightBlock = reduce(maxByHeight, blocks[0], blocks)
    const getParent = (x) => {
      if (x === undefined) {
        return false
      }

      return [x, this.blocks[x.parentHash]]
    }
    return reverse(unfold(getParent, maxHeightBlock))
  }
}

بنابراین با توجه به یک درخت، بلندترین زنجیره نمایانگر دید فعلی ما از این است که کدام تاریخچه از بلاک‌ها — و در نتیجه کدام بازنمایی از داده‌ها — را معتبر می‌دانیم.

نسخهٔ کامل و نهایی این متد در فایل src/models/Blockchain.js با نام longestChain() پیاده‌سازی شده است؛ دو متد کمکی maxHeightBlock() و createGenesisBlock() نیز در کنار آن قرار دارند (کد نهایی این فایل را در بخش «کد نهایی مدل‌ها» ببینید).

گام ۳: هرج‌ومرجِ آزاد ممنوع

لینک دموی گام ۳

اگر بلاک‌چین‌های واقعی مثل گام ۲ کار می‌کردند، به هرج‌ومرجی آزاد بدل می‌شدند؛ جایی که نودها می‌توانند خودسرانه از زنجیرهٔ بلاک‌ها ایجاد انشعاب (fork) کنند و عملاً تعداد بی‌نهایت بلاک به آن اضافه کنند تا بلندترین زنجیره شده و در نتیجه «بلاک‌چینِ اصلی» شوند (همان‌طور که در GIF بالا دیدید). این به آن معناست که هر کسی می‌تواند تاریخچه را تغییر دهد و عملاً داده‌های گذشته را دستکاری کند. چگونه از این وضعیت جلوگیری کنیم؟

با سخت‌کردن افزودن بلاک از طریق یک معمای محاسباتی. به‌جای پذیرفتن هر بلاک دلخواه، بخشی از قوانین اجماع (consensus) یک بلاک‌چین تعیین می‌کند کدام بلاک‌ها معتبرند و کدام‌ها معتبر نیستند. در این مورد، می‌خواهیم افزودن بلاک را پرهزینه (resource-intensive) کنیم. رایج‌ترین راه برای این کار — و احتمالاً قابل‌تحسین‌ترین بخش مقالهٔ اصلی بیت‌کوین — ترکیب آن با اثبات کار (proof-of-work / POW) است. اثبات کار به ما اطمینان می‌دهد که نودهایی که می‌خواهند بلاک‌هایی به درخت اضافه کنند، باید ثابت کنند تلاش قابل‌توجهی صرف کرده‌اند. چون هش SHA256 یک بلاک (امیدواریم) واقعاً تصادفی باشد، می‌توانیم مقرر کنیم که هش باید به تعداد معینی «0» ختم شود (در بیت‌کوین، شرط این است که هش با تعداد معینی «0» آغاز شود). این قطعه‌کد از بخش گام ۳ فایل README.md است:

jsclass Block {
  isValid() {
    return this.parentHash === 'root' ||
      (this.hash.substr(-DIFFICULTY) === "0".repeat(DIFFICULTY) &&
      this.hash === sha256(this.nonce + this.parentHash).toString())
  }

  setNonce(nonce) {
    this.nonce = nonce
    this._setHash()
  }

  _setHash() {
    this.hash = sha256(this.nonce + this.parentHash).toString()
  }
}

تعداد واقعی «0»ها در بلاک‌چین‌های دنیای واقعی به‌صورت پویا و بر اساس سرعتی که اخیراً بلاک‌ها به آن اضافه شده‌اند محاسبه می‌شود. یک ماینر (استخراج‌کننده) باید نانس‌های (nonces) متعددی را امتحان کند به این امید که سرانجام یکی از آن‌ها هشی تولید کند که به {DIFFICULTY} عدد «0» ختم می‌شود.

اثبات کار همان چیزی است که بلاک‌چین را «امن» می‌کند، آن را غیرمتمرکز (decentralized) می‌سازد و منشأ حملهٔ بدنام خرجِ دوبارهٔ ۵۱٪ (51% double-spend attack) است. زمانی که بلاکی روی بلاک‌چین (بلندترین زنجیرهٔ بلاک‌ها) جای می‌گیرد، مهاجم باید اثبات کار آن بلاک و همهٔ بلاک‌های پس از آن را دوباره انجام دهد. مثال آن خرجِ دوباره است: یک تراکنش به بلاکی اضافه کنید، اما سپس با استخراج زنجیرهٔ جایگزینی از والد همان بلاک، آن را «نامعتبر» کنید. با این حال، بدون داشتن ۵۱٪ از قدرت محاسباتی شبکه، مهاجم همیشه از سایر نودهای شبکه که می‌خواهند بلاک‌هایی را از بلاک‌چین مشروع فعلی اضافه کنند، عقب خواهد ماند. بنابراین امنیت بلاک‌چین متکی بر این است که قدرت محاسباتی میان اشخاص منفرد متمرکز نشود.

گام ۴: چه چیزی را استخراج کنم؟

لینک دموی گام ۴

پس این سؤال مطرح می‌شود که چرا ماینرها باید همهٔ این تلاش را برای افزودن یک بلاک صرف کنند؟ مگر این که بازی سرگرم‌کننده‌ای برایشان باشد؛ معمولاً این‌جا صحبت از انگیزه‌های اقتصادی به میان می‌آید. برای این که بلاک‌چین توسط ماینرها امن بماند، پروتکل به ماینرها پاداش استخراج (mining reward) می‌دهد که در حال حاضر معادل ۱۲.۵ بیت‌کوین است. سایر نودها بلاک ماینر با این پاداش به خودش را می‌پذیرند؛ به شرطی که سایر قوانین پروتکلی که در بالا بحث کردیم را بگذراند. بیایید دربارهٔ مکانیک خاصِ اینکه ماینر چگونه پاداش را به خودش می‌دهد صحبت کنیم؛ چیزی که به مفهومی از مالکیت (ownership) و راهی برای گنجاندن چنین مالکیتی در یک بلاک نیاز دارد.

برای درک مالکیت، به درک سطح بالایی از رمزنگاری کلید عمومی (public-key encryption) نیاز دارید که فراتر از حیطهٔ این آموزش است (این ویدیو به‌نظر توضیح غیرفنی خوبی است). تنها چیزی که برای این‌جا باید بدانید این است که موارد زیر ممکن هستند:

  1. راهی برای تولید دو چیز وجود دارد: یک کلید عمومی (public key) و یک کلید خصوصی (private key). کلید خصوصی را محرمانه نگه دارید.
  2. همان‌طور که از نامش برمی‌آید، کلید عمومی چیزی است که می‌توانید به‌طور عمومی به سایر طرف‌ها اعلام کنید.
  3. برای اثبات این که شما کسی بوده‌اید که کلید عمومی را تولید کرده‌اید، می‌توانید یک پیام (یا دادهٔ دلخواه) مشخص را با کلید خصوصی خود امضا کنید. دیگران می‌توانند امضای شما (که مختص همان پیام است)، خود پیام و کلید عمومی شما را بگیرند و تأیید کنند که امضا واقعاً از سوی کسی است که بر کلید خصوصی تسلط دارد (زیرا بدون کلید خصوصی هیچ راهی برای امضای رضایت‌بخش پیام وجود ندارد).
  4. با کلید عمومی می‌توانید یک پیام (داده) را رمزگذاری کنید به‌طوری که فقط صاحب کلید خصوصی بتواند آن را رمزگشایی کند.

به‌طور خلاصه، مالکیت مفهوم تسلط بر چیزی است؛ در این مورد، شما کلید عمومی را «مالک» هستید و می‌توانید چنین مالکیتی را با امضای داده‌ها با کلید خصوصی خود اثبات کنید. بنابراین، برای دریافت پاداش استخراج — یعنی اعلام مالکیت بر آن — کافی است ماینر کلید عمومی خود را در بلاک قرار دهد. آن کلید عمومی در بیت‌کوین با نام آدرس کیف پول (wallet address) نیز شناخته می‌شود (ساده‌سازی مفرط).

پس بیایید فقط یک فیلد به نام coinbaseBeneficiary به بلاک اضافه کنیم که کلید عمومی ماینر را در خود دارد و آن را به محتوای محاسبهٔ هش اضافه کنیم. این قطعه‌کد از بخش گام ۴ فایل README.md است:

jsclass Block {
  isValid() {
    return this.parentHash === 'root' ||
      (this.hash.substr(-DIFFICULTY) === "0".repeat(DIFFICULTY) &&
      this.hash === this._calculateHash())
  }

  createChild(coinbaseBeneficiary) {
    return new Block({
      blockchain: this.blockchain,
      parentHash: this.hash,
      height: this.height + 1,
      coinbaseBeneficiary
    })
  }

  _calculateHash() {
    return sha256(this.nonce + this.parentHash + this.coinbaseBeneficiary).toString()
  }
}

بنابراین، یک سکه فقط «مالکیت بر یک کلید عمومی است که با کلید خصوصی همراه است». با پیمایش در طول یک زنجیره از بلاک‌ها، می‌توانید جمع کنید که هر کلید عمومی چند سکه مالک است. در واقعیت، این‌ها با نام خروجی‌های تراکنش خرج‌نشده (Unspent Transaction Outputs / UTXOs) شناخته می‌شوند؛ بخش تراکنش‌ها به‌زودی خواهد آمد. برای این که هر بار که می‌خواهیم بفهمیم یک آدرس چند سکه در اختیار دارد، مجبور نباشیم زنجیرهٔ بلاک‌ها را پیمایش کنیم، آن دانش را با هر بلاک در یک استخر UTXO (UTXO pool) «کش» می‌کنیم. هر وقت بلاکی به والدش اضافه می‌کنیم، استخر UTXO والد را برمی‌داریم و سکه‌های ذی‌نفع کوین‌بیس (coinbase beneficiary) را به آن اضافه می‌کنیم. این قطعه‌کدها از بخش گام ۴ فایل README.md هستند:

jsclass UTXOPool {
  constructor(utxos = {}) {
    this.utxos = utxos
  }

  addUTXO(publicKey, amount) {
    if (this.utxos[publicKey]) {
      this.utxos[publicKey].amount += amount
    } else {
      const utxo = new UTXO(publicKey, amount)
      this.utxos[publicKey] = utxo
    }
  }

  clone() {
    return new UTXOPool(clone(this.utxos))
  }
}

class Blockchain {
  _addBlock(block) {
    if (!block.isValid())
      return
    if (this.containsBlock(block))
      return

    // بررسی اینکه والد عملاً وجود دارد و ارتفاع اعلام‌شده درست است
    const parent = this.blocks[block.parentHash];
    if (parent === undefined && parent.height + 1 !== block.height )
      return

    // اضافه‌کردن سکهٔ کوین‌بیس به استخر والد
    const newUtxoPool = parent.utxoPool.clone();
    newUtxoPool.addUTXO(block.coinbaseBeneficiary, 12.5)
    block.utxoPool = newUtxoPool;

    this.blocks[block.hash] = block;
    rerender()
  }
}

از این طریق، شما باید شروع به دیدن این نکته نیز کنید که بلاک‌چین چگونه به‌عنوان یک دفتر کل (ledger) عمل می‌کند؛ اما همچنین چگونه ذاتاً بی‌ثبات است. یک انشعاب در بلاک‌چین، استخرهای UTXO متفاوتی و در نتیجه ادعاهای متفاوتی بر روی سکه‌ها را به وجود می‌آورد (به همین دلیل است که ایمن‌سازی اجماع تا این اندازه مهم است) — همان‌طور که در GIF زیر می‌بینید. به همین دلیل است که معمولاً توصیه می‌شود تعداد معینی بلاک صبر کنید تا بتوانید تراکنشی را «تسویه‌شده» (settled) فرض کنید؛ در غیر این صورت، یک انشعاب می‌تواند چیزی را که شما فرض می‌کردید وضعیت دفتر کل است، باطل کند.

jsclass Transaction {
  constructor(inputPublicKey, outputPublicKey, amount) {
    this.inputPublicKey = inputPublicKey
    this.outputPublicKey = outputPublicKey
    this.amount = amount
    this._setHash()
  }

  _setHash() {
    this.hash = this._calculateHash()
  }

  _calculateHash() {
    return sha256(this.inputPublicKey + this.outputPublicKey + this.amount).toString()
  }
}

یک تراکنش صرفاً اعلامیه‌ای برای انتقال مالکیت از یک کلید عمومی به کلید عمومی دیگر است؛ بنابراین تنها چیزی که باید در یک تراکنش ثبت کنیم، کلید عمومی‌ای است که سکه دارد، کلید عمومی مقصد و مقدار سکه‌ای است که می‌خواهیم انتقال دهیم. jsclass UTXOPool {
  handleTransaction(transaction) {

      return

رمزنگاری: تولید کلید، امضا و تأیید امضا

هستهٔ رمزنگاری پروژه در فایل src/crypto.js قرار دارد. این فایل از کتابخانهٔ elliptic با منحنی بیضوی secp256k1 (همان منحنی‌ای که بیت‌کوین استفاده می‌کند) برای امضای دیجیتال (ECDSA) استفاده می‌کند. سه تابع اصلی را صادر می‌کند: generatePair() برای تولید جفت‌کلید، sign(message, privateKey) برای امضای یک پیام با کلید خصوصی، و verifySignature(message, signature, publicKey) برای تأیید امضا با کلید عمومی. کد کامل و دقیق این فایل:

jsimport elliptic from "elliptic";
const ec = new elliptic.ec("secp256k1");

export function generatePair() {
  const keypair = ec.genKeyPair();
  window.keypair = keypair;
  return {
    publicKey: keypair.getPublic("hex"),
    privateKey: keypair.getPrivate("hex")
  };
}

export function sign(message, privateKey) {
  try {
    const keypair = ec.keyFromPrivate(privateKey, "hex");
    return keypair.sign(message).toDER("hex");
  } catch (error) {
    return "invalid signature";
  }
}

export function verifySignature(message, signature, publicKey) {
  try {
    const keypair = ec.keyFromPublic(publicKey, "hex");
    return ec.verify(message, signature, keypair);
  } catch (error) {
    return false;
  }
}

همان‌طور که در خروجی مشاهده می‌شود، امضاها در قالب DER هگزادسیمال تولید می‌شوند و تأیید امضا با همان کلید عمومیِ ورودیِ تراکنش انجام می‌شود. این فایل همان چیزی است که Transaction.hasValidSignature() در فایل src/models/Transaction.js از آن استفاده می‌کند. در رابط کاربری، کامپوننت src/components/Signature.js جریان امضاکردن را شبیه‌سازی می‌کند: کاربر کلید خصوصیِ متناظر با کلید عمومیِ فرستنده را انتخاب می‌کند، امضا روی پیامِ «هش تراکنش» محاسبه می‌شود و صحت آن بلافاصله با verifySignature بررسی می‌شود.

نکته: در دنیای واقعی، امضای هش تراکنش همان چیزی است که «اثبات مالکیت» سکه‌ها را ممکن می‌کند؛ هیچ‌کس بدون کلید خصوصی نمی‌تواند امضای معتبری تولید کند و هر تغییری در دادهٔ تراکنش، امضای قبلی را باطل می‌کند.

لایهٔ شبکه: پیام‌رسانی بین نودها

جنبهٔ همتا‌به‌همتای پروژه در دو فایل پیاده‌سازی شده است: src/network.js (کلاینت) و src/server.js (سرور). الگوی پیام‌رسانی، انتشار/اشتراک (publish/subscribe) روی یک کانال واحد است: هر نود پیامی را با یک «نوع» روی کانال منتشر می‌کند (publish) و سرور آن را به همهٔ نودهای دیگر بازپخش می‌کند؛ نودها بر اساس نوع پیام تصمیم می‌گیرند به آن گوش دهند (subscribe) یا نه. کد کامل و دقیق این دو فایل:

js// src/network.js — لایهٔ انتشار/اشتراک کلاینت

  socket.on('channel', function(data){
    if (data.type === type) {
      callback(data.payload)
    }
  })
}

export const publish = (type, payload) => {
  socket.emit('channel', { type, payload })
}

سرور یک پیام‌رسان متمرکزِ نسبتاً ساده است: هر پیامی که روی کانال channel دریافت کند، به همهٔ کلاینت‌های متصل بازپخش می‌کند. این یعنی عملاً یک گذرگاه (pub/sub) کوچک است که نودها را به هم وصل می‌کند (در نسخهٔ مرورگریِ دمو، هر تب باز برنامه یک نود است؛ با بازکردن چند تب، چند نود شبیه‌سازی می‌شوند).

در سطح مدل‌ها، پیام‌های شبکه‌ای زیر ردوبدل می‌شوند:

  • BLOCKS_BROADCAST — پخش بلاک‌های یک بلاک‌چین مشخص؛ نودهای دیگر بلاک را پس از اعتبارسنجی به درخت خود اضافه می‌کنند.
  • TRANSACTION_BROADCAST — پخش یک تراکنش؛ نودهای دیگر آن را در pendingTransactions خود ثبت می‌کنند.
  • REQUEST_BLOCKS — درخواست دریافت بلاک‌های یک بلاک‌چین؛ نودِ تازه‌وارد در هنگام ساخت بلاک‌چین آن را می‌فرستد و پاسخ آن نیز خودِ یک پیام BLOCKS_BROADCAST است.
  • BLOCKCHAIN_BROADCAST / BLOCKCHAIN_BROADCAST_REQUEST — اعلامِ وجود بلاک‌چین‌ها بین نودها.

به‌عنوان نمونه، بخشی از سازندهٔ کلاس Blockchain در فایل src/models/Blockchain.js نشان می‌دهد که چگونه بلاک‌چین به این پیام‌ها گوش می‌دهد و بلافاصله درخواست بلاک‌ها را منتشر می‌کند:

jsimport sha256 from "crypto-js/sha256";
import UTXOPool from "./UTXOPool";
import { map } from "ramda";
import { transactionFromJSON } from "./Transaction";

const DIFFICULTY = 2;

class Block {
  constructor(opts) {
    const {
      blockchain,
      parentHash,
      height,
      coinbaseBeneficiary,
      nonce,
      utxoPool,
      transactions
    } = {
      coinbaseBeneficiary: "root",
      nonce: "",
      utxoPool: new UTXOPool(),
      transactions: {},
      ...opts
    };
    this.blockchain = blockchain;
    this.nonce = nonce;
    this.parentHash = parentHash;
    this.height = height;
    this.coinbaseBeneficiary = coinbaseBeneficiary;
    this.utxoPool = utxoPool;
    this.transactions = map(transactionFromJSON)(transactions);
    this._setHash();
    // فقط برای اهداف نمایش بصری
    this.expanded = true;
  }

  isRoot() {
    return this.parentHash === "root";
  }
  isValid() {
    return (
      this.isRoot() ||
      (this.hash.substr(-DIFFICULTY) === "0".repeat(DIFFICULTY) &&
        this.hash === this._calculateHash())
    );
  }

  createChild(coinbaseBeneficiary) {
    const block = new Block({
      blockchain: this.blockchain,
      parentHash: this.hash,
      height: this.height + 1,
      utxoPool: this.utxoPool.clone(),
      coinbaseBeneficiary
    });

    // برای سهولت کار، به ماینر اجازه می‌دهیم بلافاصله سکه‌های کوین‌بیس را خرج کند
    block.utxoPool.addUTXO(coinbaseBeneficiary, 12.5);

    return block;
  }

  addTransaction(transaction) {
    if (!this.isValidTransaction(transaction)) return;
    this.transactions[transaction.hash] = transaction;
    this.utxoPool.handleTransaction(transaction, this.coinbaseBeneficiary);
    this._setHash();
  }

  isValidTransaction(transaction) {
    return (
      this.utxoPool.isValidTransaction(transaction) &&
      transaction.hasValidSignature()
    );
  }

  addingTransactionErrorMessage(transaction) {
    if (!transaction.hasValidSignature()) return "Signature is not valid";
    return this.utxoPool.addingTransactionErrorMessage(transaction);
  }

  setNonce(nonce) {
    this.nonce = nonce;
    this._setHash();
  }

  combinedTransactionsHash() {
    if (Object.values(this.transactions).length === 0)
      return "No Transactions in Block";
    return sha256(
      Object.values(this.transactions)
        .map(tx => tx.hash)
        .join("")
    );
  }

  toJSON() {
    return {
      hash: this.hash,
      nonce: this.nonce,
      parentHash: this.parentHash,
      height: this.height,
      coinbaseBeneficiary: this.coinbaseBeneficiary,
      transactions: map(transaction => transaction.toJSON(), this.transactions)
    };
  }

  _setHash() {
    this.hash = this._calculateHash();
  }

  _calculateHash() {
    return sha256(
      this.nonce +
        this.parentHash +
        this.coinbaseBeneficiary +
        this.combinedTransactionsHash()
    ).toString();
  }
}

export default Block;

export function blockFromJSON(blockchain, data) {
  return new Block({
    ...data,
    blockchain
  });
}

src/models/Blockchain.js

jsimport Block from "./Block";
import { blockFromJSON } from "./Block";
import { transactionFromJSON } from "./Transaction";
import { rerender } from "../store";
import { publish, subscribeTo } from "../network";
import { maxBy, reduce, unfold, reverse, values, prop } from "ramda";

class Blockchain {
  constructor(name) {
    this.name = name;
    this.genesis = null;
    this.blocks = {};

    this.pendingTransactions = {};

    this.createGenesisBlock();

    subscribeTo("BLOCKS_BROADCAST", ({ blocks, blockchainName }) => {
      if (blockchainName === this.name) {
        blocks.forEach(block => this._addBlock(blockFromJSON(this, block)));
      }
    });

    subscribeTo("TRANSACTION_BROADCAST", ({ transaction, blockchainName }) => {
      if (blockchainName === this.name) {
        this.pendingTransactions[transaction.hash] = transactionFromJSON(transaction);
      }
    });

    publish("REQUEST_BLOCKS", { blockchainName: this.name });
    subscribeTo("REQUEST_BLOCKS", ({ blockchainName }) => {
      if (blockchainName === this.name)
        publish("BLOCKS_BROADCAST", {
          blockchainName,
          blocks: Object.values(this.blocks).map(b => b.toJSON())
        });
    });
  }

  maxHeightBlock() {
    const blocks = values(this.blocks);
    const maxByHeight = maxBy(prop("height"));
    const maxHeightBlock = reduce(maxByHeight, blocks[0], blocks);
    return maxHeightBlock;
  }

  longestChain() {
    const getParent = x => {
      if (x === undefined) {
        return false;
      }

      return [x, this.blocks[x.parentHash]];
    };
    return reverse(unfold(getParent, this.maxHeightBlock()));
  }

  createGenesisBlock() {
    const block = new Block({
      blockchain: this,
      parentHash: "root",
      height: 1,
      nonce: this.name
    });
    this.blocks[block.hash] = block;
    this.genesis = block;
  }

  containsBlock(block) {
    return this.blocks[block.hash] !== undefined;
  }

  addBlock(newBlock) {
    this._addBlock(newBlock);
    publish("BLOCKS_BROADCAST", {
      blocks: [newBlock.toJSON()],
      blockchainName: this.name
    });
  }

  _addBlock(block) {
    if (!block.isValid()) return;
    if (this.containsBlock(block)) return;

    // بررسی اینکه والد عملاً وجود دارد و ارتفاع اعلام‌شده درست است
    const parent = this.blocks[block.parentHash];
    if (parent === undefined && parent.height + 1 !== block.height) return;

    const isParentMaxHeight = this.maxHeightBlock().hash === parent.hash;

    // کلون‌کردن استخر UTXO والد و هم‌زمان‌سازی آن با بلاک
    const newUtxoPool = parent.utxoPool.clone();
    block.utxoPool = newUtxoPool;

    // افزودن سکهٔ کوین‌بیس به استخر
    block.utxoPool.addUTXO(block.coinbaseBeneficiary, 12.5);

    // اعمال‌مجدد تراکنش‌ها برای اعتبارسنجی آن‌ها
    const transactions = block.transactions;
    block.transactions = {};
    let containsInvalidTransactions = false;

    Object.values(transactions).forEach(transaction => {
      if (block.isValidTransaction(transaction)) {
        block.addTransaction(transaction);

        // اگر تراکنش در لیست در انتظار بلاک‌چین داشتیم و در بلندترین ارتفاع هستیم، آن را حذف کن
        if (isParentMaxHeight && this.pendingTransactions[transaction.hash])
          delete this.pendingTransactions[transaction.hash];
      } else {
        containsInvalidTransactions = true;
      }
    });

    // اگر تراکنش‌های نامعتبری پیدا کردیم، بلاک را اضافه نکن
    if (containsInvalidTransactions) return;

    this.blocks[block.hash] = block;
    rerender();
  }
}
export default Blockchain;

jsimport sha256 from "crypto-js/sha256";
import { verifySignature } from "../crypto";

export default class Transaction {
  constructor(inputPublicKey, outputPublicKey, amount, fee, signature) {
    this.inputPublicKey = inputPublicKey;
    this.outputPublicKey = outputPublicKey;
    this.amount = amount;
    this.fee = fee;
    this.signature = signature;
    this._setHash();
  }

  hasValidSignature() {
    return (
      this.signature !== undefined &&
      verifySignature(this.hash, this.signature, this.inputPublicKey)
    );
  }

  toJSON() {
    return {
      inputPublicKey: this.inputPublicKey,
      outputPublicKey: this.outputPublicKey,
      amount: this.amount,
      fee: this.fee,
      hash: this.hash,
      signature: this.signature
    };
  }

  _setHash() {
    this.hash = this._calculateHash();
  }

  _calculateHash() {
    return sha256(
      this.inputPublicKey + this.outputPublicKey + this.amount + this.fee
    ).toString();
  }
}

  return new Transaction(
    transaction.inputPublicKey,
    transaction.outputPublicKey,
    transaction.amount,
    transaction.fee,
    transaction.signature
  );
}

import { clone } from 'ramda';
import UTXO from './UTXO';

export default class UTXOPool {
  constructor(utxos = {}) {
    this.utxos = utxos
  }

  addUTXO(publicKey, amount) {
    if (this.utxos[publicKey]) {
      this.utxos[publicKey].amount += amount
    } else {
      const utxo = new UTXO(publicKey, amount)
      this.utxos[publicKey] = utxo
    }
  }

  handleTransaction(transaction, feeReceiver) {
    if (!this.isValidTransaction(transaction))
      return
    const inputUTXO = this.utxos[transaction.inputPublicKey];
    inputUTXO.amount -= transaction.amount
    inputUTXO.amount -= transaction.fee
    if (inputUTXO.amount === 0)
      delete this.utxos[transaction.inputPublicKey]
    this.addUTXO(transaction.outputPublicKey, transaction.amount)
    this.addUTXO(feeReceiver, transaction.fee)
  }

  isValidTransaction(transaction) {
    const { inputPublicKey, amount, fee } = transaction
    const utxo = this.utxos[inputPublicKey]
    return utxo !== undefined && utxo.amount >= (amount + fee) && amount > 0
  }

  addingTransactionErrorMessage(transaction) {
    const { inputPublicKey, amount, fee } = transaction
    const utxo = this.utxos[inputPublicKey]
    if (utxo === undefined)
      return "No UTXO was associated with this public key"
    if (amount <= 0)
      return "Amount has to be at least 0"
    if (utxo.amount < amount + fee)
      return `UTXO associated with this public key (${utxo.amount}) does not cover desired amount (${amount}) and fee (${fee})`
  }

  clone() {
    return new UTXOPool(clone(this.utxos))
  }
}

    case "BLOCKCHAIN_BROADCAST":

          const blockchain = new Blockchain(name);
          state.blockchains.push(blockchain);
        }
      });

      state.identities[identity.publicKey] = identity;
      break;

      break;
