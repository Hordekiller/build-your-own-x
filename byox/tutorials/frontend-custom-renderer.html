ساخت رندرکننده سفارشی React — سخنرانی سوفی آلپرت در React Conf 2019

⚙ زبان: JavaScript 🎥 ویدیو (React Conf 2019) ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه معرفی و مرور فارسی ویدیوی «Building a Custom React Renderer» — سخنرانی سوفی آلپرت (Sophie Alpert)، مدیر سابق تیم React در فیسبوک — در React Conf 2019 است. او با استفاده از بستهٔ react-reconciler یک رندرکنندهٔ کامل (React DOM مینیاتوری) را روی صحنه می‌سازد.

۱. دربارهٔ سخنرانی

سوفی آلپرت در این سخنرانی نشان می‌دهد چطور با بستهٔ رسمی react-reconciler یک رندرکنندهٔ سفارشی React بسازیم. او «مغز» React (الگوریتم مقایسه و زمان‌بندی) را همان‌طور که هست نگه می‌دارد و فقط «دست‌ها» را عوض می‌کند: یک HostConfig که می‌گوید نودها چطور ساخته، به‌روزرسانی و حذف شوند. خروجی کارش React DOM Mini است — یک رندرکنندهٔ کامل برای DOM که کامپوننت‌های واقعی React را اجرا می‌کند.

نکته: کد سخنرانی و پروژهٔ تمرینی در مخزن zaki-yama-labs و نمونه‌های مشابه (مثل react-dom-mini) در گیت‌هاب موجود است — برای تمرین عملی عالی است.

۳. ایدهٔ اصلی: HostConfig چیست؟

هر رندرکنندهٔ React از دو بخش تشکیل شده: reconciler (که تصمیم می‌گیرد «چه چیزی عوض شود») و renderer (که تصمیم را «اعمال» می‌کند). رابط بین این دو دقیقاً HostConfig است. در سخنرانی، سوفی با پاس دادن یک شیء از توابع به react-reconciler یک رندرکننده می‌سازد:

js// نقطهٔ ورود: ساخت reconciler با توابع پلتفرم خودمان
let reconciler = ReactReconciler({
  // «حالت جهش»: محیط ما مثل DOM است (appendChild و removeChild دارد)
  supportsMutation: true,

  // ساخت یک نود در محیط هدف
  createInstance(type, props, rootContainerInstance, hostContext, internalInstanceHandle) {
    const el = document.createElement(type);
    return el;
  },

  // ساخت نود متنی
  createTextInstance(text) {
    return document.createTextNode(text);
  },

  // الحاق نودها
  appendChildToContainer(container, child) {
    container.appendChild(child);
  },
  appendChild(parent, child) {
    parent.appendChild(child);
  },
  appendInitialChild(parent, child) {
    parent.appendChild(child);
  },

  // حذف و جابه‌جایی
  removeChildFromContainer(container, child) {
    container.removeChild(child);
  },
  removeChild(parent, child) {
    parent.removeChild(child);
  },
  insertInContainerBefore(container, child, before) {
    container.insertBefore(child, before);
  },
  insertBefore(parent, child, before) {
    parent.insertBefore(child, before);
  },

  // به‌روزرسانی: محاسبه و اعمال تغییرات props
  prepareUpdate(instance, type, oldProps, newProps) {
    // تفاوت‌ها را محاسبه کن؛ اگر چیزی نبود null برگردان
    return computeDiff(oldProps, newProps);
  },
  commitUpdate(instance, updatePayload, type, oldProps, newProps) {
    applyUpdatePayload(instance, updatePayload);
  },

  // توابع کمکی قراردادی
  shouldSetTextContent() { return false; },
  getChildHostContext() { return {}; },
  getPublicInstance(instance) { return instance; },
  getRootHostContext() { return {}; },
  prepareForCommit() {},
  resetAfterCommit() {},
  finalizeInitialChildren() {},
});

وقتی این توابع آماده شوند، رندرکننده را با دو فراخوانی به حرکت درمی‌آوریم: createContainer (ساخت ریشه) و updateContainer (شروع رندر):

jsconst root = reconciler.createContainer(domElement, false);
reconciler.updateContainer(<App />, root, null, () => console.log('رندر کامل شد'));

۴. چرا این سخنرانی مهم است؟

  • می‌فهمید React Native، React Three Fiber و ده‌ها رندرکنندهٔ دیگر چطور با یک «مغز» مشترک کار می‌کنند.
  • کدهای واقعی رندرکننده‌های تولیدی (مثل react-dom) بسیار پیچیده‌اند؛ این نسخهٔ مینیمال فقط لایهٔ مفهومی را نگه می‌دارد.
  • بعد از این ویدیو، مقالهٔ «Learn you some custom React renderers» از HackerNoon را بخوانید تا کد مکتوب همان کار را هم ببینید.
