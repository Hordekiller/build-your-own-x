Hack the Virtual Memory — فصل ۰: رشته‌های C و /proc (Holberton)

⚙ زبان: C 🖥 لینوکس + GDB ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور قسمت اول از سری «Hack the Virtual Memory» در وبلاگ دانشگاه Holberton است که با نگاه «هکری» حافظهٔ مجازی لینوکس را با C و GDB واکاوی می‌کند.
↗ مشاهده منبع اصلی

۱. ایدهٔ سری

«Hack the Virtual Memory» یک سری مقالهٔ آموزشی است که حافظهٔ مجازی را «دستکاری‌شونده» نشان می‌دهد: به‌جای درس‌های تئوری خشک، ما حافظهٔ یک فرایند واقعی در حال اجرا را با ابزارهای لینوکس باز می‌کنیم و تغییرش می‌دهیم. فصل ۰، ساده و در عین حال شگفت‌انگیز، با رشته‌های C و فایل‌سیستم /proc شروع می‌شود.

۲. نقشه‌ی حافظهٔ یک فرایند

هر فرایند لینوکس یک «فضای آدرس مجازی» دارد که بخش‌های استاندارد دارد: text (کد برنامه)، data (متغیرهای سراسری)، stack (پشته) و heap (تخصیص دینامیک). متغیرهای رشتهٔ C بسته به نحوهٔ تعریف، در بخش‌های مختلف می‌نشینند:

  • رشتهٔ لیترال (مثل "hello") در بخش text (فقط‌خواندنی).
  • آرایهٔ سراسری (مثل char s[] = "…" در سطح global) در بخش data.
  • متغیر محلی روی stack.

۳. پنجره‌ای به حافظه: /proc/pid/mem

نکتهٔ کلیدی: لینوکس حافظهٔ هر فرایند را از طریق فایل /proc/<pid>/mem در معرض دید می‌گذارد. با خواندن این فایل (مثل یک فایل معمولی) و با کمک /proc/<pid>/maps (نقشهٔ بخش‌ها)، می‌توانیم محتوای حافظهٔ یک فرایند زنده را ببینیم و حتی بازنویسی کنیم:

c// خواندن یک کاراکتر از حافظه‌ی یک فرایند زنده
int read_byte(pid_t pid, long addr) {
    char path[64];
    snprintf(path, sizeof path, "/proc/%d/mem", pid);

    int fd = open(path, O_RDONLY);
    char byte;
    pread(fd, &byte, 1, addr);   // خواندن یک بایت از آدرس داده‌شده
    close(fd);
    return byte;
}

اگر همان برنامه با ptrace یا attach متوقف نشود، باز کردن /proc/pid/mem ممکن است خطای EIO بدهد — این خودش یک درس مهم دربارهٔ مجوزها و حالت متوقف فرایند است.

۴. هک واقعی: تغییر رشته در یک فرایند زنده

مثال معروف فصل: برنامه‌ای یک رشته را روی صفحه می‌نویسد و چاپ می‌کند؛ ما آدرس آن رشته را در نقشهٔ حافظه پیدا می‌کنیم، سپس با نوشتن در /proc/pid/mem محتوای آن را عوض می‌کنیم — و دفعهٔ بعدی که برنامه چاپ می‌کند، رشتهٔ ما را می‌بینید:

c// تغییر یک بایت از رشته‌ی فرایند زنده
int write_byte(pid_t pid, long addr, char value) {
    char path[64];
    snprintf(path, sizeof path, "/proc/%d/mem", pid);

    int fd = open(path, O_WRONLY);
    pwrite(fd, &value, 1, addr);
    close(fd);
    return 0;
}

برای پیدا کردن آدرس دقیق، از GDB کمک می‌گیریم: x/s آدرس رشته را نشان می‌دهد و p/x آدرس‌های متغیرها را.

۵. چه چیزهایی یاد می‌گیریم؟

  • تفاوت واقعی بخش‌های حافظه (stack / data / text) با مشاهدهٔ مستقیم.
  • کاربرد عملی /proc و مفاهیم PID و مجوزها.
  • مفهوم آدرس‌های مجازی در برابر فیزیکی — چرا آدرس‌ها در maps «مجازی»اند.
  • ابزارهایی که توسعه‌دهندگان دیباگر و ابزارهای هک حافظه استفاده می‌کنند.
نکتهٔ تکمیلی: این سری ادامه‌های دیگری هم دارد (آدرس‌های مجازی، malloc داخلی و…)؛ فصل ۰ به‌خاطر سادگی و شیرینی، بهترین دروازهٔ ورود به دنیای مدیریت حافظهٔ لینوکس است.
