موتور جست‌وجو چطور کار می‌کند؟

هر موتور جست‌وجو دو فاز دارد: نمایه‌سازی (indexing) و پرس‌وجو (query). در نمایه‌سازی، هر سند به «توکن» شکسته می‌شود (کلمات) و نقشهٔ معکوس «کلمه → اسناد» ساخته می‌شود؛ در پرس‌وجو، کلمات عبارت جست‌وجو در این نقشه پیدا و اسناد حاوی همه‌شان بازگردانده می‌شوند.

توکن‌سازی و پایگاه داده

بن در این سری از SQLite استفاده می‌کند: جدول اسناد + جدول واژه‌ها + جدول پیوند (کلمه به سند با شمارش). توکن‌سازی یعنی جداسازی کلمات و حذف نویسه‌های تزئینی:

PHPfunction tokenise($text) {
    // جدا کردن کلمات ساده (با حفظ حالت)
    $words = str_word_count(strtolower($text), 1);
    // حذف کلمات توقف (stop words) مثل «و، با، به»
    $stop = ['the', 'and', 'for', 'php'];
    return array_diff($words, $stop);
}

حذف stop words باعث می‌شود رایج‌ترین کلمه‌ها پرونده‌های غول‌آسا نسازند و نتیجه هم دقیق‌تر شود.

نمایه‌سازی اسناد

PHPforeach ($documents as $doc) {
    $docId = insertDocument($db, $doc['url'], $doc['title']);

    foreach (tokenise($doc['body']) as $word) {
        $wordId = getOrCreateWord($db, $word);
        // ردیف پیوند: کلمه—سند با تعداد تکرار
        incrementLink($db, $wordId, $docId);
    }
}

جدول `links` با (word_id, doc_id, count) قلب «اندیس معکوس» است — فرمت شفافی که موتورهای تجاری با فرمت‌های فشرده‌تر دارند.

پرس‌وجو

جست‌وجو با JOIN بین واژه‌ها و پیوندها انجام می‌شود و با شمارش و ترتیب‌دهی، مرتب‌ترین نتیجه می‌آید. رتبه‌بندی سادهٔ TF (بسامد تکرار کلمه در سند) حتی بدون IDF هم نتایج خوبی می‌دهد:

SQLSELECT d.url, SUM(l.count) AS score
FROM words w
JOIN links  l ON l.word_id = w.id
JOIN docs   d ON d.id = l.doc_id
WHERE w.word IN ('php', 'search')
GROUP BY d.id
ORDER BY score DESC
LIMIT 10;

بعد از این پیاده‌سازی ۱۰۰ خطی، مفاهیم BM25، PageRank و indexing توزیع‌شده دیگر رمزآلود نیستند — همهٔ آن‌ها ارتقاهای همین پایه‌اند.
