یک موتور قالب — فصل «۵۰۰ خط یا کمتر» (A Template Engine)

منبع اصلی: این صفحه ترجمهٔ فارسی فصل «A Template Engine» از کتاب 500 Lines or Less (aosabook) اثر ند بتچلدر (Ned Batchelder) — نگه‌دارندهٔ coverage.py. نسخه کامل و به‌روز را از سایت اصلی بخوانید.
↗ مشاهده منبع اصلی

۱. چرا موتور قالب؟

بیشتر برنامه‌ها «منطق زیاد و متنِ ثابتِ کم» دارند و زبان‌های برنامه‌نویسی برای همین ساخته شده‌اند. ولی بعضی کارها برعکس‌اند: منطق کم و حجم عظیمی متن — مشهورترین نمونه، تولید HTML در برنامه‌های وب است. خیلی کم پیش می‌آید صفحه‌ای کاملاً ثابت باشد؛ معمولاً فقط نام کاربر یا فهرست محصولات پویاست. راهِ «رشته‌های ثابت + جایگزینی» به سرعت به هم‌ریختگی می‌رسد: HTML تکه‌تکه در کد پایتون گم می‌شود و طراحِ فرانت‌اند باید کد پایتون را ویرایش کند. راه‌حل، قالب‌ها هستند: فایلی که بیشترش HTML ثابت است و فقط بخش‌های پویا با علامت‌گذاری خاص وارد می‌شوند:

html<p>Welcome, {{user_name}}!</p>
<p>Products:</p>
<ul>
{% for product in product_list %}
    <li>{{ product.name }}:
        {{ product.price|format_price }}</li>
{% endfor %}
</ul>

زبان قالب زبان‌های معمول را «وارونه» می‌کند: متن ثابت، پیش‌فرض است و کدِ پویا با علامت خاص وارد می‌شود (در برنامه‌نویسی معمول، کد پیش‌فرض است و متنِ ثابت داخل string literal). اما برای اجرا به یک موتور قالب نیاز داریم: تابعی که قالب (ساختار و متن ثابت) و یک کانتکست (دادهٔ پویا) را می‌گیرد و رشتهٔ نهایی HTML را تولید می‌کند.

۲. نحوِ زبانی که می‌سازیم

نحو بر پایهٔ Django است: {{expr}} برای درج داده؛ نقطه برای همهٔ دسترسی‌های داده ({{product.price}} یعنی هم attribute، هم کلیدِ دیکشنری — و اگر مقدار callable بود خودکار صدا زده می‌شود)؛ فیلترها با | ({{story.subject|slugify|lower}})؛ شرط {% if %}/ {% endif %}؛ حلقهٔ {% for x in list %}/{% endfor %}؛ و کامنت {# ... #}.

۳. تفسیر یا کامپایل؟

دو رویکرد بزرگ وجود دارد. تفسیر: تجزیه‌گر ساختار دادهٔ نمایانگر قالب می‌سازد و موتورِ رندر اعلامی روی آن راه می‌رود (سبک Django). کامپایل: تجزیه‌گر، کدِ مستقیماً اجراشدنی تولید می‌کند (سبک Jinja2 و Mako). فصل، رویکرد کامپایل را انتخاب می‌کند: قالب به یک تابع پایتونی ترجمه می‌شود. دلیلش عملی است: این موتور برای تولید گزارش‌های HTMLِ coverage.py نوشته شده — قالب‌ها کم‌اند ولی بارها اجرا می‌شوند؛ هزینهٔ کامپایل یک‌بار پرداخت می‌شود و هر اجرا چندین بار سریع‌تر از تفسیر است. (و راستش، «نوشتن برنامه‌ای که برنامه می‌نویسد» خیلی هم سرگرم‌کننده است!)

کد پایتونی که تولید می‌شود، چیزی شبیه این است (برای خوانایی اندکی نرمال شده):

pythondef render_function(context, do_dots):
    c_user_name = context['user_name']
    c_product_list = context['product_list']
    c_format_price = context['format_price']

    result = []
    append_result = result.append
    extend_result = result.extend
    to_str = str

    extend_result([
        '<p>Welcome, ',
        to_str(c_user_name),
        '!</p>\n<p>Products:</p>\n<ul>\n'
    ])
    for c_product in c_product_list:
        extend_result([
            '\n    <li>',
            to_str(do_dots(c_product, 'name')),
            ':\n        ',
            to_str(c_format_price(do_dots(c_product, 'price'))),
            '</li>\n'
        ])
    append_result('\n</ul>\n')
    return ''.join(result)
میکرو-بهینه‌سازی‌های آموزنده: داده‌های کانتکست در ابتدای تابع به متغیرهای محلی (با پیشوند c_) استخراج می‌شوند چون جست‌وجوی محلی از سراسری سریع‌تر است؛ append/extend از روی آرایه یک‌بار گرفته می‌شوند تا زمان‌های بعد صرفِ attribute lookup نشود؛ و str به یک نام محلی کوتاه می‌شود. این‌ها فقط بعد از آزمایش زمان‌بندی اضافه شده‌اند.

۴. کلاس CodeBuilder

هستهٔ موتور، کلاس Templite است («قالبِ لایت!»). برای ساخت کد پایتون از یک کمکی به نام CodeBuilder استفاده می‌کند که خط اضافه می‌کند، تورفتگی را مدیریت می‌کند و در پایان، از کدِ ساخته‌شده مقدار نهایی می‌گیرد:

pythonclass CodeBuilder(object):
    """ساخت راحتِ کد منبع"""

    def __init__(self, indent=0):
        self.code = []
        self.indent_level = indent

    def add_line(self, line):
        """افزودن یک خط؛ تورفتگی و newline خودکار اضافه می‌شود."""
        self.code.extend([" " * self.indent_level, line, "\n"])

    INDENT_STEP = 4  # طبق PEP8!

    def indent(self):
        """افزایش تورفتگی سطرهای بعدی."""
        self.indent_level += self.INDENT_STEP

    def dedent(self):
        """کاهش تورفتگی سطرهای بعدی."""
        self.indent_level -= self.INDENT_STEP

    def add_section(self):
        """افزودن یک بخش: CodeBuilder تودرتو برای پر شدنِ بعدی."""
        section = CodeBuilder(self.indent_level)
        self.code.append(section)
        return section

    def __str__(self):
        return "".join(str(c) for c in self.code)

    def get_globals(self):
        """اجرای کد و برگرداندن دیکشنری تعریف‌شده‌ها."""
        assert self.indent_level == 0
        python_source = str(self)
        global_namespace = {}
        exec(python_source, global_namespace)
        return global_namespace

نکتهٔ طراحی خوب: CodeBuilder هیچ دانشی از موتور قالب ندارد — فقط «خط کد می‌سازد»؛ و get_globals با exec کد را اجرا و تعریف‌ها را برمی‌گرداند، بدون این‌که بداند تابع چه نامی دارد.

۵. کامپایل در سازندهٔ Templite

کلاس Templite دو فاز دارد. سازنده (با آرگومان‌های *contexts — ادغام چند دیکشنری) همهٔ کارِ کامپایل را انجام می‌دهد و متد render فقط اجرا می‌کند. نقشهٔ راه:

  1. باز کردن کد: def render_function(context, do_dots): و بعد از آن یک بخشِ prologue (vars_code) که هنوز خالی است — بعداً که همهٔ نام‌ها را شناختیم پر می‌شود؛ به‌همراه خط‌های ثابتِ result/append/extend/to_str.
  2. یک تابع درونی flush_output (کلوزر روی buffer و code) که قطعه‌های خروجیِ بافر شده را به‌صورت یک خطِ append_result(...) یا extend_result([...]) به کد اضافه می‌کند.
  3. تجزیه با یک رگکس: re.split(r"(?s)({{.*?}}|{%.*?%}|{#.*?#})", text) — پرچم (?s) یعنی نقطه با newline هم تطبیق می‌کند و .*? یعنی کوتاه‌ترین تطبیق (lazy). خروجی لیستی از قطعه‌های literal و تگ است.
  4. حلقه روی تگ‌ها: کامنت را نادیده بگیر؛ {{expr}} → خطِ to_str(کد_عبارت)؛ {% if %} → خطِ if ...: + indent؛ {% for x in expr %} → خطِ for c_x in ...: + indent؛ {% end %} → dedent؛ و literalها با repr() بافر می‌شوند. پشتهٔ ops_stack هم خطاهای «end ناهماهنگ» را می‌گیرد.
  5. در پایان: پر کردن prologue با خط‌های c_var = context['var'] برای همهٔ نام‌های all_vars - loop_vars؛ سپس return ''.join(result)؛ و در نهایت self._render_function = code.get_globals()['render_function'].

۶. کامپایل عبارت‌ها: فیلترها و نقطه‌ها

متد _expr_code به‌صورت بازگشتی عبارت قالب را به عبارت پایتون ترجمه می‌کند: فیلترها (|) به «فراخوانی تابعِ فیلتر روی مقدار قبلی» تبدیل می‌شوند (c_upper(c_name)) و نام فیلترها به all_vars اضافه می‌شوند؛ نقطه‌ها به فراخوانیِ do_dots(x, 'y', 'z') تبدیل می‌شوند (چون مشخص نیست در زمان کامپایل attribute است یا کلید)؛ و نام ساده، با پیشوندِ c_.

pythondef _expr_code(self, expr):
    """تبدیل عبارتِ قالب به عبارتِ پایتون."""
    if "|" in expr:
        pipes = expr.split("|")
        code = self._expr_code(pipes[0])
        for func in pipes[1:]:
            self._variable(func, self.all_vars)
            code = "c_%s(%s)" % (func, code)
    elif "." in expr:
        dots = expr.split(".")
        code = self._expr_code(dots[0])
        args = ", ".join(repr(d) for d in dots[1:])
        code = "do_dots(%s, %s)" % (code, args)
    else:
        self._variable(expr, self.all_vars)
        code = "c_%s" % expr
    return code

۷. رندر: فقط اجرا

چون کارِ سخت در کامپایل انجام شده، render ساده است: کانتکستِ کل (ادغام کانتکست سازنده و کانتکست این رندر) را می‌سازد و render_function را صدا می‌زند. معنای نقطه‌ها در زمان اجرا با _do_dots تعیین می‌شود:

pythondef render(self, context=None):
    render_context = dict(self.context)
    if context:
        render_context.update(context)
    return self._render_function(render_context, self._do_dots)

def _do_dots(self, value, *dots):
    """ارزیابی در زمان اجرای عبارت‌های نقطه‌دار."""
    for dot in dots:
        try:
            value = getattr(value, dot)
        except AttributeError:
            value = value[dot]
        if callable(value):
            value = value()
    return value

۸. تست و چیزهایی که حذف شده‌اند

با موتور، یک مجموعه‌تست کامل همراه است: خودِ موتور ۲۵۲ خط و تست‌ها ۲۷۵ خط («کدِ خوب‌تست‌شده معمولاً تست‌هایش از محصولش بیشتر است»). عمداً حذف شده‌اند: ارث‌بری و includeِ قالب، تگ‌های سفارشی، escaping خودکار، آرگومان برای فیلترها، else/elif، حلقهٔ چندمتغیره و کنترل فاصلهٔ سفید. با این‌حال همین موتورِ ساده، واقعاً موتورِ تولید گزارش‌های HTML در coverage.py است!

۹. جمع‌بندی

در ۲۵۲ خط، یک موتور قالبِ ساده اما توانا ساختیم. ایدهٔ اصلی، در یک جمله: قالب را به یک تابع پایتونی کامپایل کن، بعد تابع را اجرا کن. این فصل همچنین نمونهٔ فوق‌العاده‌ای از «تولید کد» (code generation) است — تکنیکی که اساس کامپایلرهای زبان‌های برنامه‌نویسی است.

کپیرایت: فصل «A Template Engine» اثر ند بتچلدر (Ned Batchelder) است و در کتاب «500 Lines or Less» (aosabook.org) منتشر شده. این صفحه فقط ترجمهٔ فارسی آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسنده اصلی است. برای مشاهده اصل مطلب به سایت اصلی مراجعه کنید.
