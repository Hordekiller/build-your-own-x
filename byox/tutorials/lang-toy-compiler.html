چرا Flex و Bison؟

قبل از اینکه همه چیز را دستی بنویسیم، خوب است بدانیم ابزارهای کلاسیک «ساخت کامپایلر» چطور کار می‌کنند. Flex lexer تولید می‌کند (متن ورودی را به token تبدیل می‌کند) و Bison parser و تولیدکنندهٔ پارسر (که گرامر را با LALR parsing تحلیل می‌کند). این آموزش، با این دو ابزار، یک کامپایلر کوچک با خروجی اسمبلی می‌سازد.

بخش اول: فایل Flex

فایل lexer در Flex با سه بخش تعریف می‌شود: declarations، rules (قواعد بازگشتی)، و کدهای اضافه. برای مثال تعریف tokenهای ریاضی:

Flex%{
#include "parser.hpp"   // تعریف token ها از Bison
%}

DIGIT   [0-9]
NUMBER  {DIGIT}+

%%

"+"   { return PLUS; }
"-"   { return MINUS; }
"*"   { return MULT; }
"/"   { return DIV; }
{NUMBER}  { yylval.num = atoi(yytext); return NUMBER; }
[ \t\n]   { /* نادیده‌گرفتن فاصله‌ها */ }
.         { yyerror("کاراکتر نامعتبر"); }

%%

int yywrap(void) { return 1; }   // پایان فایل

بخش دوم: گرامر Bison

سرعت عمل Bison به‌خاطر گرامرهای LALR است؛ در اینجا یک اکسپرژن ساده تعریف می‌شود و با هر کاهش (reduction)، کد اسمبلی متناظر تولید می‌شود — همین اتصالِ «گرامر↔کد» اصل کار کامپایلر است:

Bison%token NUMBER
%left PLUS MINUS
%left MULT DIV

%%

expr: expr PLUS expr   { $$ = gen_add($1, $3); }
    | expr MULT expr   { $$ = gen_mult($1, $3); }
    | NUMBER           { $$ = gen_number($1); }
    ;

%%

int gen_number(int n) {
  printf("push %d\n", n);   // کد اسمبلی برای عدد
  return 0;
}

توجه کنید که عبارت‌ها با %left اولویت‌بندی می‌شوند — این هم‌ارز است با آنچه در parser دستی با Pratt انجام می‌دهیم.

گام‌های بعدی

پس از ماشین‌حساب، مقاله به افزودن متغیرها، شرط‌ها و توابع اشاره می‌کند. به‌طور کلی مسیر این‌گونه است: (۱) ساخت lexer با Flex، (۲) تعریف گرامر و AST، (۳) تولید کد اسمبلی در actions، (۴) کامپایل و اجرای testها.

جمع‌بندی

این مقاله نشان می‌دهد که ابزارهای قدیمی (Flex/Bison) هنوز بهترین راه برای ساخت سریع lexer/parser هستند؛ اگر به «دستی‌سازی» علاقه دارید بعداً به آموزش‌هایی مثل acwj بروید — اما اگر فقط می‌خواهید کامپایلر بسازید، این روش سریع‌ترین نقطهٔ شروع است.
