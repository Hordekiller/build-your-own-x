Kernel 201 — نوشتن درایور صفحه‌کلید و صفحه‌نمایش (ارجون سری‌داران)

منبع اصلی: این صفحه ترجمهٔ فارسی و مرور مقالهٔ «Kernel 201 — Let's write a Kernel with keyboard and screen support» از ارجون سری‌داران است — ادامهٔ Kernel 101 که پشتیبانی صفحه‌کلید و صفحه‌نمایش را به هسته اضافه می‌کند.

۱. هدف مقاله

کرنل Kernel 101 فقط یک پیام چاپ می‌کرد. این مقاله همان کرنل را می‌گیرد و دو قابلیت واقعی به آن می‌دهد: چاپ روی صفحه با کنترل کامل (اسکرول، رنگ، مکان‌نما) و خواندن صفحه‌کلید با وقفه. این یعنی اولین بار است که هستهٔ ما با سخت‌افزار تعامل واقعی دارد: از طریق درگاه‌های I/O و وقفه‌ها.

۲. درگاه‌های I/O: خواندن و نوشتن با in/out

سخت‌افزار x86 از طریق «درگاه» (port) با CPU حرف می‌زند — آدرس‌های ویژه‌ای که با دستورهای in و out قابل دسترس‌اند. دو درگاه مهم: 0x3F8 (سریال) برای خروجی و 0x60 برای صفحه‌کلید. مثال: چاپ یک کاراکتر در درگاه سریال:

c// نوشتن در درگاه سریال COM1
#define PORT_SERIAL 0x3F8

void serial_write(char c) {
    __asm__ volatile (
        "outb %0, %1"        // خروجی بایت c به درگاه PORT_SERIAL
        : : "a"(c), "Nd"(PORT_SERIAL)
    );
}

۳. صفحه‌نمایش: پرش به خط بعد و اسکرول

مانیتور VGA حالت متن، خودش اسکرول نمی‌کند؛ هسته باید با محاسبهٔ آدرس «خط بعدی» در حافظهٔ 0xB8000 و پاک کردن خط آخر، اسکرول را مدیریت کند. حرکت مکان‌نما هم با دو درگاه مخصوص (0x3D4/0x3D5) انجام می‌شود:

c// حرکت مکان‌نما با فرستادن آدرس ۱۶ بیتی به کنترل‌کننده‌ی VGA
void move_cursor(int row, int col) {
    unsigned short pos = row * 80 + col;

    outb(0x3D4, 14);            // رجیستر «بایت بالایی» را انتخاب کن
    outb(0x3D5, (pos >> 8) & 0xFF);  // بایت بالا
    outb(0x3D4, 15);            // رجیستر «بایت پایینی»
    outb(0x3D5, pos & 0xFF);    // بایت پایین
}

۴. صفحه‌کلید با وقفه

کلیدها با وقفهٔ IRQ1 می‌رسند. هسته باید یک IDT (جدول توصیفگر وقفه) بسازد و هندلری تعریف کند که کد کلید (scancode) را از درگاه 0x60 بخواند و به کاراکتر ترجمه کند. هر کلید دو کد دارد: فشار (مثل 0x1E برای A) و رهاسازی (با بیت 0x80). یک تکهٔ جدول ترجمهٔ کیبورد QWERTY:

c// ترجمه‌ی scancode به کاراکتر (قسمتی از جدول)
unsigned char keyboard_map[128] = {
    0,  27, '1', '2', '3', '4', '5', '6', '7', '8',
    '9', '0', '-', '=', '\b',
    '\t', 'q', 'w', 'e', 'r', 't', 'y', 'u', 'i', 'o',
    'p', '[', ']', '\n',
    0,                      // Ctrl
    'a', 's', 'd', 'f', 'g', 'h', 'j', 'k', 'l', ';',
    '\'', '`',
    0, '\\', 'z', 'x', 'c', 'v', 'b', 'n', 'm', ',',
    '.', '/', 0, '*',
    0, ' ',                 // Space
    // ...
};

۵. اجرا

مثل Kernel 101، با grub-mkrescue یک ISO می‌سازیم و در QEMU اجرا می‌کنیم. حالا اگر کلیدی بزنید، کاراکتر آن روی صفحه ظاهر می‌شود — و وقتی به انتهای صفحه برسید، متن به‌درستی اسکرول می‌شود:

bashmake          # ساخت kernel
grub-mkrescue -o os.iso kernel_dir
qemu-system-i386 -cdrom os.iso
نکتهٔ تکمیلی: این مقاله بهترین پل برای گذار از «هستهٔ نمایشی» به «هستهٔ تعاملی» است؛ قدم بعدی طبیعی، زمان‌بندی و multitasking است (مثل آموزش جیمز مولی در همین مجموعه).
