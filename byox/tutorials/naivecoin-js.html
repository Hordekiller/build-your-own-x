انگیزه (Motivation)

ارزهای دیجیتال و قراردادهای هوشمند (smart-contracts) روی بستر بلاک‌چین، ساده‌ترین مفاهیم برای درک نیستند؛ چیزهایی مانند کیف پول‌ها (wallets)، آدرس‌ها، اثبات کار بلاک‌ها (block proof-of-work)، تراکنش‌ها و امضاهای آن‌ها، وقتی در یک بافت وسیع‌تر قرار بگیرند معنادارتر می‌شوند. این پروژه که از naivechain الهام گرفته شده است، تلاشی است برای ارائهٔ هرچه موجزتر و ساده‌تر یک پیاده‌سازی از ارز دیجیتال.

ارز دیجیتال چیست؟

از ویکی‌پدیا: ارز دیجیتال (cryptocurrency) یک دارایی دیجیتال است که به‌عنوان واسطهٔ مبادله طراحی شده است؛ با استفاده از رمزنگاری، تراکنش‌ها امن می‌شوند و ایجاد واحدهای اضافی ارز کنترل می‌شود.

مفاهیم کلیدی نایوکوین (Key concepts)

  • مؤلفه‌ها (Components):
    • سرور HTTP
    • نود (Node)
    • بلاک‌چین
    • اپراتور (Operator)
    • ماینر (Miner)
  • رابط API مبتنی بر HTTP برای کنترل همه‌چیز
  • همگام‌سازی بلاک‌چین و تراکنش‌ها
  • اثبات کار ساده (سختی هر ۵ بلاک افزایش می‌یابد)
  • ایجاد آدرس‌ها با رویکرد قطعی (deterministic) با استفاده از EdDSA
  • پایستگی (persist) داده‌ها در یک پوشه
توجه: naivechain از websocket برای ارتباط p2p استفاده می‌کند، اما در این پیاده‌سازی برای ساده‌کردن درک تبادل پیام‌ها، آن را کنار گذاشته‌ایم و فقط به ارتباط REST اتکا می‌کنیم.

jsconst HttpServer = require('./httpServer');

const Operator = require('./operator');
const Miner = require('./miner');

module.exports = function naivecoin(host, port, peers, logLevel, name) {
    host = process.env.HOST || host || 'localhost';
    port = process.env.PORT || process.env.HTTP_PORT || port || 3001;
    peers = (process.env.PEERS ? process.env.PEERS.split(',') : peers || []);
    peers = peers.map((peer) => { return { url: peer }; });
    logLevel = (process.env.LOG_LEVEL ? process.env.LOG_LEVEL : logLevel || 6);    
    name = process.env.NAME || name || '1';

    require('./util/consoleWrapper.js')(name, logLevel);

    console.info(`Starting node ${name}`);

    let blockchain = new Blockchain(name);
    let operator = new Operator(name, blockchain);
    let miner = new Miner(blockchain, logLevel);
    let node = new Node(host, port, peers, blockchain);
    let httpServer = new HttpServer(node, blockchain, operator, miner);

    httpServer.listen(host, port);
};

بلاک‌چین

بلاک‌چین دو نوع اطلاعات را نگه می‌دارد: فهرست بلاک‌ها (یک لیست پیوندی / linked list) و فهرست تراکنش‌ها (یک هش‌مپ / hash map).

بلاک‌چین مسئول این کارهاست:

  • تأیید بلاک‌های رسیده؛
  • تأیید تراکنش‌های رسیده؛
  • همگام‌سازی فهرست تراکنش‌ها؛
  • همگام‌سازی فهرست بلاک‌ها.

بلاک‌چین یک لیست پیوندی است که در آن، هش بلاک بعدی بر اساس هش بلاک قبلی به‌علاوهٔ داده‌های داخل خودِ بلاک محاسبه می‌شود:

یک بلاک تنها در صورتی به فهرست بلاک‌ها اضافه می‌شود که:

  1. بلاک، آخرین بلاک باشد (ایندکس قبلی + ۱)؛
  2. بلاک قبلی درست باشد (هش قبلی == block.previousHash)؛
  3. هش درست باشد (هش محاسبه‌شدهٔ بلاک == block.hash)؛
  4. سطح دشواری چالش اثبات کار درست باشد (دشواریِ ایندکسِ n بلاک‌چین < دشواری بلاک)؛
  5. همهٔ تراکنش‌های داخل بلاک معتبر باشند؛
  6. مجموع تراکنش‌های خروجی برابر مجموع تراکنش‌های ورودی + ۵۰ سکه باشد که پاداش ماینر بلاک است؛
  7. بررسی شود که در آن بلاک خرجِ دوباره (double spending) وجود نداشته باشد؛
  8. فقط ۱ تراکنش کارمزد (fee) و ۱ تراکنش پاداش (reward) وجود داشته باشد.

یک تراکنش داخل بلاک در صورتی معتبر است که:

  1. هش تراکنش درست باشد (هش محاسبه‌شدهٔ تراکنش == transaction.hash)؛
  2. امضای همهٔ تراکنش‌های ورودی درست باشد (امضای دادهٔ تراکنش را می‌توان با کلید عمومی آدرس تأیید کرد)؛
  3. مجموع تراکنش‌های ورودی بزرگ‌تر از تراکنش‌های خروجی باشد تا جایی برای کارمزد تراکنش باقی بماند؛
  4. تراکنش از قبل در بلاک‌چین نباشد؛
  5. همهٔ تراکنش‌های ورودی در بلاک‌چین خرج‌نشده (unspent) باشند.

برای جزئیات بیشتر دربارهٔ نحوهٔ کار بلاک‌چین می‌توانید این پست را از پروژهٔ naivechain بخوانید.

«تراکنش‌ها» فهرستی از تراکنش‌های تأییدنشده است و هیچ چیز خاصی دربارهٔ آن وجود ندارد. در این پیاده‌سازی، فهرست تراکنش‌ها فقط تراکنش‌های تأییدنشده را در خود دارد؛ به محض اینکه یک تراکنش تأیید شود، بلاک‌چین آن را از این فهرست حذف می‌کند:

text[
    transaction 1,
    transaction 2,
    transaction 3
]

یک تراکنش تنها در صورتی به فهرست تراکنش‌ها اضافه می‌شود که:

  1. از قبل در فهرست تراکنش‌ها نباشد؛
  2. هش تراکنش درست باشد (هش محاسبه‌شدهٔ تراکنش == transaction.hash)؛
  3. امضای همهٔ تراکنش‌های ورودی درست باشد (امضای دادهٔ تراکنش را می‌توان با کلید عمومی آدرس تأیید کرد)؛
  4. مجموع تراکنش‌های ورودی بزرگ‌تر از تراکنش‌های خروجی باشد تا جایی برای کارمزد تراکنش باقی بماند؛
  5. تراکنش از قبل در بلاک‌چین نباشد؛
  6. همهٔ تراکنش‌های ورودی در بلاک‌چین خرج‌نشده باشند.

ماژول Blockchain: lib/blockchain/index.js

کلاس Blockchain دو «پایگاه داده» (فایل‌های JSON) باز می‌کند: blocks.json برای بلاک‌ها و transactions.json برای تراکنش‌های تأییدنشده؛ از یک EventEmitter نیز استفاده می‌کند تا بقیهٔ مؤلفه‌ها (مثلاً نود برای پخش همگانی) پس از تغییر داده‌ها مطلع شوند. کد کامل lib/blockchain/index.js. سازندهٔ کلاس، متد init و متد addBlock:

jsclass Blockchain {
    constructor(dbName) {
        this.blocksDb = new Db('data/' + dbName + '/' + BLOCKCHAIN_FILE, new Blocks());
        this.transactionsDb = new Db('data/' + dbName + '/' + TRANSACTIONS_FILE, new Transactions());

        // INFO: در این پیاده‌سازی پایگاه داده یک فایل است و هر بار داده ذخیره می‌شود
        // فایل بازنویسی می‌شود؛ احتمالاً برای کارایی بهتر باید پایگاه داده محکم‌تری استفاده شود
        this.blocks = this.blocksDb.read(Blocks);
        this.transactions = this.transactionsDb.read(Transactions);

        // برخی بخش‌ها از emitter استفاده می‌کنند تا پس از تغییر داده‌ها عمل کنند
        this.emitter = new EventEmitter();
        this.init();
    }

    init() {
        // اگر بلاک‌چین خالی بود، بلاک جنسیس ساخته می‌شود
        if (this.blocks.length == 0) {
            console.info('Blockchain empty, adding genesis block');
            this.blocks.push(Block.genesis);
            this.blocksDb.write(this.blocks);
        }

        // حذف تراکنش‌هایی که در بلاک‌چین هستند
        console.info('Removing transactions that are in the blockchain');
        R.forEach(this.removeBlockTransactionsFromTransactions.bind(this), this.blocks);
    }

    addBlock(newBlock, emit = true) {
        // فقط در صورتی بلاک اضافه می‌شود که معتبر باشد (باید با بلاک قبلی مقایسه شود)
        if (this.checkBlock(newBlock, this.getLastBlock())) {
            this.blocks.push(newBlock);
            this.blocksDb.write(this.blocks);

            // پس از افزودن بلاک، تراکنش‌های این بلاک از فهرست تراکنش‌های در انتظار حذف می‌شوند
            this.removeBlockTransactionsFromTransactions(newBlock);

            console.info(`Block added: ${newBlock.hash}`);
            console.debug(`Block added: ${JSON.stringify(newBlock)}`);
            if (emit) this.emitter.emit('blockAdded', newBlock);

            return newBlock;
        }
    }

متدهای checkBlock و checkTransaction دقیقاً همان قوانین هشت‌گانه و شش‌گانهٔ بالا را پیاده می‌کنند و در صورت نقض هر کدام، به‌ترتیب خطاهای BlockAssertionError یا TransactionAssertionError پرتاب می‌کنند. همچنین با replaceChain امکان جایگزینی کل زنجیره (زمانی که زنجیرهٔ بلندتری از یک همتا دریافت شود) فراهم شده است؛ ابتدا صحت زنجیرهٔ جدید با checkChain بررسی و سپس بلاک‌های جدید یکی‌یکی اضافه می‌شوند.

تراکنش‌های خرج‌نشده (UTXO)

مفهوم UTXO (خروجی تراکنش خرج‌نشده) در نایوکوین یک فایل جدا ندارد؛ محاسبهٔ آن متد getUnspentTransactionsForAddress در همان lib/blockchain/index.js است. این متد خروجی‌های همهٔ تراکنش‌های (تأییدشده و تأییدنشده) را لیست می‌کند، سپس خروجی‌هایی را که به‌عنوان ورودیِ یک تراکنش دیگر خرج شده‌اند حذف می‌کند؛ به این ترتیب امکان «زنجیرهٔ تراکنش» (transaction chain) فراهم می‌شود:

            index++;
        }, transaction.data.outputs);

        // ساخت فهرستی از همهٔ ورودی‌های تراکنش که برای یک آدرس پیدا شده‌اند (یا همه)            
        R.forEach((txInput) => {
            if (address && txInput.address != address) return;

            txInputs.push({
                transaction: txInput.transaction,
                index: txInput.index,
                amount: txInput.amount,
                address: txInput.address
            });
        }, transaction.data.inputs);
    };

    // هم تراکنش‌های داخل بلاک و هم تراکنش‌های تأییدنشده را در نظر می‌گیرد (امکان‌پذیری زنجیره تراکنش)
    let txOutputs = [];
    let txInputs = [];
    R.forEach(R.pipe(R.prop('transactions'), R.forEach(selectTxs)), this.blocks);
    R.forEach(selectTxs, this.transactions);

    // هر دو فهرست را بررسی و خروجی‌هایی را می‌یابیم که ورودی متناظر ندارند
    let unspentTransactionOutput = [];
    R.forEach((txOutput) => {
        if (!R.any((txInput) => txInput.transaction == txOutput.transaction && txInput.index == txOutput.index, txInputs)) {
            unspentTransactionOutput.push(txOutput);
        }
    }, txOutputs);

    return unspentTransactionOutput;
}

ماژول Transaction: lib/blockchain/transaction.js

کلاس Transaction متد اصلی check() را دارد که قوانین اعتبارسنجی تراکنش (هش، امضای ورودی‌ها، موازنهٔ ورودی/خروجی و کارمزد) را اجرا می‌کند. کد کامل lib/blockchain/transaction.js:

jsclass Transaction {
    construct() {
        this.id = null;
        this.hash = null;
        this.type = null;
        this.data = {
            inputs: [],
            outputs: []
        };
    }

    toHash() {
        // INFO: پیاده‌سازی‌های متفاوتی از الگوریتم هش وجود دارد، برای مثال: https://en.bitcoin.it/wiki/Hashcash
        return CryptoUtil.hash(this.id + this.type + JSON.stringify(this.data));
    }

    check() {
        // بررسی اینکه هش تراکنش درست است
        let isTransactionHashValid = this.hash == this.toHash();

        if (!isTransactionHashValid) {
            console.error(`Invalid transaction hash '${this.hash}'`);
            throw new TransactionAssertionError(`Invalid transaction hash '${this.hash}'`, this);
        }

        // بررسی اینکه امضای همهٔ تراکنش‌های ورودی درست است (داده تراکنش با کلید عمومی آدرس امضا شده است)
        R.map((txInput) => {
            let txInputHash = CryptoUtil.hash({
                transaction: txInput.transaction,
                index: txInput.index,
                address: txInput.address
            });
            let isValidSignature = CryptoEdDSAUtil.verifySignature(txInput.address, txInput.signature, txInputHash);

            if (!isValidSignature) {
                console.error(`Invalid transaction input signature '${JSON.stringify(txInput)}'`);
                throw new TransactionAssertionError(`Invalid transaction input signature '${JSON.stringify(txInput)}'`, txInput);
            }
        }, this.data.inputs);


        if (this.type == 'regular') {
            // بررسی اینکه مجموع تراکنش‌های ورودی بزرگ‌تر از خروجی‌هاست تا جایی برای کارمزد تراکنش باقی بماند
            let sumOfInputsAmount = R.sum(R.map(R.prop('amount'), this.data.inputs));
            let sumOfOutputsAmount = R.sum(R.map(R.prop('amount'), this.data.outputs));

            let negativeOutputsFound = 0;
            let i = 0;
            let outputsLen = this.data.outputs.length;

            // بررسی خروجی‌های منفی
            for (i = 0; i < outputsLen; i++) {
                if (this.data.outputs[i].amount < 0) {
                    negativeOutputsFound++;
                }
            }

            let isInputsAmountGreaterOrEqualThanOutputsAmount = R.gte(sumOfInputsAmount, sumOfOutputsAmount);

            if (!isInputsAmountGreaterOrEqualThanOutputsAmount) {
                console.error(`Invalid transaction balance: inputs sum '${sumOfInputsAmount}', outputs sum '${sumOfOutputsAmount}'`);
                throw new TransactionAssertionError(`Invalid transaction balance: inputs sum '${sumOfInputsAmount}', outputs sum '${sumOfOutputsAmount}'`, { sumOfInputsAmount, sumOfOutputsAmount });
            }

            let isEnoughFee = (sumOfInputsAmount - sumOfOutputsAmount) >= Config.FEE_PER_TRANSACTION; // 1 چون کارمزد 1 ساتوشی به ازای هر تراکنش است

            if (!isEnoughFee) {
                console.error(`Not enough fee: expected '${Config.FEE_PER_TRANSACTION}' got '${(sumOfInputsAmount - sumOfOutputsAmount)}'`);
                throw new TransactionAssertionError(`Not enough fee: expected '${Config.FEE_PER_TRANSACTION}' got '${(sumOfInputsAmount - sumOfOutputsAmount)}'`, { sumOfInputsAmount, sumOfOutputsAmount, FEE_PER_TRANSACTION: Config.FEE_PER_TRANSACTION });
            }
            if (negativeOutputsFound > 0) {
                console.error(`Transaction is either empty or negative, output(s) caught: '${negativeOutputsFound}'`);
                throw new TransactionAssertionError(`Transaction is either empty or negative, output(s) caught: '${negativeOutputsFound}'`);
            }
        }

        return true;
    }

    static fromJson(data) {
        let transaction = new Transaction();
        R.forEachObjIndexed((value, key) => { transaction[key] = value; }, data);
        transaction.hash = transaction.toHash();
        return transaction;
    }
}

تولید secret از رمز عبور (با PBKDF2)، ساخت جفت‌کلید با الگوریتم EdDSA (ed25519)، امضا و تأیید امضا. کد کامل lib/util/cryptoEdDSAUtil.js:

jsconst crypto = require('crypto');
const elliptic = require('elliptic');
const EdDSA = elliptic.eddsa;

const SALT = '0ffaa74d206930aaece253f090c88dbe6685b9e66ec49ad988d84fd7dff230d1';

class CryptoEdDSAUtil {
    static generateSecret(password) {
        let secret = crypto.pbkdf2Sync(password, SALT, 10000, 512, 'sha512').toString('hex');
        console.debug(`Secret: \n${secret}`);
        return secret;
    }

    static generateKeyPairFromSecret(secret) {
        // ساخت جفت‌کلید از secret
        let keyPair = ec.keyFromSecret(secret); // رشته hex، آرایه یا Buffer        
        console.debug(`Public key: \n${elliptic.utils.toHex(keyPair.getPublic())}`);
        return keyPair;
    }

    static signHash(keyPair, messageHash) {
        let signature = keyPair.sign(messageHash).toHex().toLowerCase();
        console.debug(`Signature: \n${signature}`);
        return signature;
    }

    static verifySignature(publicKey, signature, messageHash) {
        let key = ec.keyFromPublic(publicKey, 'hex');
        let verified = key.verify(messageHash, signature);
        console.debug(`Verified: ${verified}`);
        return verified;
    }

    static toHex(data) {
        return elliptic.utils.toHex(data);
    }
}

class Db {
    constructor(filePath, defaultData) {
        this.filePath = filePath;
        this.defaultData = defaultData;
    }

    read(prototype) {
        if (!fs.existsSync(this.filePath)) return this.defaultData;

        var fileContent = fs.readFileSync(this.filePath);

        fs.writeFileSync(this.filePath, JSON.stringify(data));
    }
}

متد generateAddress آدرس‌ها را به‌صورت قطعی — بر اساس secret یا آخرین کلید خصوصی — تولید می‌کند. کد کامل lib/operator/wallet.js:

jsclass Wallet {
    constructor() {
        this.id = null;
        this.passwordHash = null;
        this.secret = null;
        this.keyPairs = [];
    }

    generateAddress() {
        // اگر secret برابر null باشد یعنی کیف پول تازه ساخته شده است
        if (this.secret == null) {
            this.generateSecret();
        }

        let lastKeyPair = R.last(this.keyPairs);
        
        // تولید seed بعدی بر اساس اولین secret یا یک secret جدید از آخرین جفت‌کلید
        let seed = (lastKeyPair == null ?  this.secret : CryptoEdDSAUtil.generateSecret(R.propOr(null, 'secretKey', lastKeyPair)));
        let keyPairRaw = CryptoEdDSAUtil.generateKeyPairFromSecret(seed);
        let newKeyPair = {
            index: this.keyPairs.length + 1,
            secretKey: CryptoEdDSAUtil.toHex(keyPairRaw.getSecret()),
            publicKey: CryptoEdDSAUtil.toHex(keyPairRaw.getPublic())
        };
        this.keyPairs.push(newKeyPair);
        return newKeyPair.publicKey;
    }

    generateSecret() {
        this.secret = CryptoEdDSAUtil.generateSecret(this.passwordHash);
        return this.secret;
    }

    static fromPassword(password) {
        let wallet = new Wallet();
        wallet.id = CryptoUtil.randomId();
        wallet.passwordHash = CryptoUtil.hash(password);
        return wallet;
    }
}

        // فایل بازنویسی می‌شود؛ احتمالاً برای کارایی بهتر باید پایگاه داده محکم‌تری استفاده شود
        this.wallets = this.db.read(Wallets);

    createTransaction(walletId, fromAddressId, toAddressId, amount, changeAddressId) {
        let utxo = this.blockchain.getUnspentTransactionsForAddress(fromAddressId);
        let wallet = this.getWalletById(walletId);

        if (wallet == null) throw new ArgumentError(`Wallet not found with id '${walletId}'`);

        let secretKey = wallet.getSecretKeyByAddress(fromAddressId);

        if (secretKey == null) throw new ArgumentError(`Secret key not found with Wallet id '${walletId}' and address '${fromAddressId}'`);

        let tx = new TransactionBuilder();
        tx.from(utxo);
        tx.to(toAddressId, amount);
        tx.change(changeAddressId || fromAddressId);
        tx.fee(Config.FEE_PER_TRANSACTION);
        tx.sign(secretKey);        

        return Transaction.fromJson(tx.build());
    }
}

TransactionBuilder: lib/operator/transactionBuilder.js

این کلاس زنجیره‌ای (fluent) ورودی‌های UTXO، آدرس مقصد، مبلغ باقی‌مانده و کارمزد را می‌گیرد و در متد build() ورودی‌ها را امضا کرده و خروجی‌ها (مقصد + باقی‌مانده) را می‌سازد. کد کامل lib/operator/transactionBuilder.js:

js    from(listOfUTXO) {
        this.listOfUTXO = listOfUTXO;
        return this;
    }

    to(address, amount) {
        this.outputAddress = address;
        this.totalAmount = amount;
        return this;
    }

    change(changeAddress) {
        this.changeAddress = changeAddress;
        return this;
    }

    fee(amount) {
        this.feeAmount = amount;
        return this;
    }

    sign(secretKey) {
        this.secretKey = secretKey;
        return this;
    }

    build() {
        // بررسی اطلاعات لازم
        if (this.listOfUTXO == null) throw new ArgumentError('It\'s necessary to inform a list of unspent output transactions.');
        if (this.outputAddress == null) throw new ArgumentError('It\'s necessary to inform the destination address.');
        if (this.totalAmount == null) throw new ArgumentError('It\'s necessary to inform the transaction value.');

        // محاسبه مبلغ باقی‌مانده
        let totalAmountOfUTXO = R.sum(R.pluck('amount', this.listOfUTXO));
        let changeAmount = totalAmountOfUTXO - this.totalAmount - this.feeAmount;

        // برای هر ورودی تراکنش، هش ورودی محاسبه و داده امضا می‌شود
        let self = this;
        let inputs = R.map((utxo) => {
            let txiHash = CryptoUtil.hash({
                transaction: utxo.transaction,
                index: utxo.index,
                address: utxo.address
            });
            utxo.signature = CryptoEdDSAUtil.signHash(CryptoEdDSAUtil.generateKeyPairFromSecret(self.secretKey), txiHash);
            return utxo;
        }, this.listOfUTXO);

        let outputs = [];

        // افزودن گیرنده هدف
        outputs.push({
            amount: this.totalAmount,
            address: this.outputAddress
        });

        // افزودن مبلغ باقی‌مانده
        if (changeAmount > 0) {
            outputs.push({
                amount: changeAmount,
                address: this.changeAddress
            });
        } else {
            throw new ArgumentError('The sender does not have enough to pay for the transaction.');
        }        

        // مقدار باقی‌مانده، کارمزدی است که خالق بلاک جمع می‌کند        

        return Transaction.fromJson({
            id: CryptoUtil.randomId(64),
            hash: null,
            type: this.type,
            data: {
                inputs: inputs,
                outputs: outputs
            }
        });
    }

ماینر (Miner)

ماینر فهرست تراکنش‌های در انتظار (pending) را می‌گیرد و یک بلاک جدید شامل آن تراکنش‌ها می‌سازد. طبق پیکربندی، هر بلاک حداکثر ۲ تراکنش دارد.

مراحل مونتاژ یک بلاک جدید:

  1. از فهرست تراکنش‌های تأییدنشده، تراکنش‌های کاندیدایی انتخاب می‌شوند که نه هنوز در بلاک‌چین هستند و نه قبلاً انتخاب شده‌اند؛
  2. دو تراکنش اول از فهرست تراکنش‌های کاندیدا گرفته می‌شود؛
  3. یک تراکنش جدید شامل کارمزد (به آدرس ماینر، ۱ ساتوشی به ازای هر تراکنش) اضافه می‌شود؛
  4. یک تراکنش پاداش شامل ۵۰ سکه به آدرس ماینر اضافه می‌شود؛
  5. برای این بلاک اثبات کار انجام می‌شود.

ماژول Miner: lib/miner/index.js

متد mine() ابتدا با متد استاتیک generateNextBlock بلاک پایه را می‌سازد و سپس محاسبهٔ سنگین اثبات کار را در یک thread جداگانه (کتابخانهٔ threads) اجرا می‌کند تا سرور در حین ماینینگ مسدود نشود. کد کامل lib/miner/index.js:

            /*eslint-disable */

            const Miner = require(input.__dirname);

اثبات کار (Proof-of-work)

اثبات کار با محاسبهٔ ۱۴ مقدار hex اول برای یک هش تراکنش مشخص انجام می‌شود و nonce افزایش می‌یابد تا به حداقل سطح دشواری مورد نیاز برسد. دشواری هر ۵ بلاک، با یک مقدار نمایی (توان ۵) افزایش می‌یابد. در حدود بلاک هفتادم، با این پیکربندی، تولید یک بلاک جدید حدود ۵۰ ثانیه طول می‌کشد. همهٔ این مقادیر قابل تنظیم‌اند:

jsconst difficulty = this.blockchain.getDifficulty();
do {
    block.timestamp = new Date().getTime() / 1000;
    block.nonce++;
    block.hash = block.toHash();
    blockDifficulty = block.getDifficulty();
} while (blockDifficulty >= difficulty);

this.blockchain.getDifficulty() مقدار hex دشواری ایندکس فعلی بلاک‌چین را برمی‌گرداند. این مقدار با توان رساندن دشواری اولیه به ۵، هر ۵ بلاک محاسبه می‌شود.

block.getDifficulty() مقدار hexِ ۱۴ بایت اول هش بلاک را برمی‌گرداند و آن را با دشواریِ پذیرفته‌شدهٔ فعلی مقایسه می‌کند.

وقتی هش تولیدشده به سطح دشواری مورد نظر برسد، بلاک همان‌گونه که هست برگردانده می‌شود. حلقهٔ اثبات کار در proveWorkFor پیاده‌سازی شده است:

js    /* istanbul ignore next */
    static proveWorkFor(jsonBlock, difficulty) {
        let blockDifficulty = null;
        let start = process.hrtime();
        let block = Block.fromJson(jsonBlock);

        // INFO: هر ارز دیجیتال روش متفاوتی برای اثبات کار دارد، این یک دنباله هش ساده است

        // حلقه‌ای که nonce را افزایش می‌دهد تا هش با دشواری مورد نظر پیدا شود
        do {
            block.timestamp = new Date().getTime() / 1000;
            block.nonce++;
            block.hash = block.toHash();
            blockDifficulty = block.getDifficulty();
        } while (blockDifficulty >= difficulty);
        console.info(`Block found: time '${process.hrtime(start)[0]} sec' dif '${difficulty}' hash '${block.hash}' nonce '${block.nonce}'`);
        return block;
    }

نود (Node)

نود فهرستی از همتاهای متصل را نگه می‌دارد و همهٔ تبادل داده‌ها بین نودها را انجام می‌دهد، شامل:

  1. دریافت همتایان جدید و بررسی اینکه با آن‌ها چه کند؛
  2. دریافت بلاک‌های جدید و بررسی اینکه با آن‌ها چه کند؛
  3. دریافت تراکنش‌های جدید و بررسی اینکه با آن‌ها چه کند.

نود همهٔ اطلاعات دریافتی را دوباره پخش (rebroadcast) می‌کند، مگر اینکه با آن کاری انجام نداده باشد؛ مثلاً اگر همتا/تراکنش/بلاک‌چین را از قبل داشته باشد.

یک مسئولیت اضافه، گرفتن تعداد تأییدها (confirmations) برای یک تراکنش مشخص است. این کار را با پرسیدن از هر نود دربارهٔ وجود داشتن یا نداشتن آن تراکنش در بلاک‌چین خودش انجام می‌دهد.

کلاس Node با superagent درخواست‌های HTTP/REST به همتاها می‌فرستد و با اتصال به رویدادهای بلاک‌چین، بلاک‌ها و تراکنش‌های جدید را بین همتاها پخش می‌کند. کد کامل lib/node/index.js:

        this.blockchain.emitter.on('blockAdded', (block) => {

        });

            this.broadcast(this.sendTransaction, newTransaction);
        });

            this.broadcast(this.sendLatestBlock, R.last(blocks));
        });
    }

js    checkReceivedBlocks(blocks) {
        const receivedBlocks = blocks.sort((b1, b2) => (b1.index - b2.index));
        const latestBlockReceived = receivedBlocks[receivedBlocks.length - 1];
        const latestBlockHeld = this.blockchain.getLastBlock();

        // اگر بلاک‌چین دریافتی از بلاک‌چین ما بلندتر نباشد، کاری نکن
        if (latestBlockReceived.index <= latestBlockHeld.index) {
            console.info('Received blockchain is not longer than blockchain. Do nothing');
            return false;
        }

        console.info(`Blockchain possibly behind. We got: ${latestBlockHeld.index}, Peer got: ${latestBlockReceived.index}`);
        if (latestBlockHeld.hash === latestBlockReceived.previousHash) { // می‌توانیم بلاک دریافتی را به زنجیره‌مان الحاق کنیم
            console.info('Appending received block to our chain');
            this.blockchain.addBlock(latestBlockReceived);
            return true;
        } else if (receivedBlocks.length === 1) { // باید زنجیره را از همتایمان بپرسیم
            console.info('Querying chain from our peers');
            this.broadcast(this.getBlocks);
            return null;
        } else { // بلاک‌چین دریافتی از بلاک‌چین فعلی طولانی‌تر است
            console.info('Received blockchain is longer than current blockchain');
            this.blockchain.replaceChain(receivedBlocks);
            return true;
        }
    }

تست‌ها با mocha (و ضمیمهٔ mocha-steps) و supertest نوشته شده‌اند؛ اسکریپت تست در package.json به این صورت تعریف شده است: "test": "_mocha -u bdd --colors test/". فایل test/integrationTest.js یک تست یکپارچه‌سازی سرتاسری است: دو نود را راه‌اندازی می‌کند، کیف پول و آدرس می‌سازد، بلاک ماین می‌کند، تراکنش ایجاد می‌کند، تأییدها و موجودی‌ها را بررسی می‌کند، همگام‌سازی نودها را می‌سنجد و در انتها خطاهای پیش‌بینی‌شده (رمز عبور غلط، موجودی ناکافی و...) را نیز می‌آزماید. ابتدای این فایل — ساخت مؤلفه‌ها و اولین گام‌ها — به این شکل است:

jsrequire('mocha-steps');
const supertest = require('supertest');
const assert = require('assert');
const HttpServer = require('../lib/httpServer');
const Blockchain = require('../lib/blockchain');
const Operator = require('../lib/operator');
const Miner = require('../lib/miner');
const Node = require('../lib/node');
const fs = require('fs-extra');

const logLevel = 0;

require('../lib/util/consoleWrapper.js')('integrationTest', logLevel);

describe('Integration Test', () => {
    const name1 = 'integrationTest1';
    const name2 = 'integrationTest2';

    const createNaivecoin = (name, host, port, peers, removeData = true) => {
        if (removeData) fs.removeSync('data/' + name + '/');
        let blockchain = new Blockchain(name);
        let operator = new Operator(name, blockchain);
        let miner = new Miner(blockchain, logLevel);
        let node = new Node(host, port, peers, blockchain);
        let httpServer = new HttpServer(node, blockchain, operator, miner);
        return httpServer.listen(host, port);
    };

    const walletPassword = 't t t t t';
    let context = {};

    step('start server 1', () => {
        return createNaivecoin(name1, 'localhost', 3001, [])
            .then((httpServer) => {
                context.httpServer1 = httpServer;
            });
    });

    step('create wallet', () => {
        return Promise.resolve()
            .then(() => {
                return supertest(context.httpServer1.app)
                    .post('/operator/wallets')
                    .send({ password: walletPassword })
                    .expect(201);
            }).then((res) => {
                context.walletId = res.body.id;
            });
    });

تست‌ها داده‌های خود را در پوشهٔ data/ می‌سازند و پس از پایان، آن‌ها را پاک می‌کنند.
