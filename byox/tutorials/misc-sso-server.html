مشکل SSO

چند اپلیکیشن در سازمان: ایمیل، تقویم، سیستم داخلی. کاربر نخواسته برای هر کدام دوباره وارد شود. راه‌حل: یک سرور مرکزی احراز هویت؛ کاربر یک بار login می‌کند و بقیهٔ اپ‌ها به‌صورت خودکار او را می‌شناسند.

در ساده‌ترین شکل (که در این آموزش آمده): سرور SSO یک session نگه می‌دارد، اپلیکیشن‌ها با یک «توکن تصادفی» به آن وصل می‌شوند، و لیست اپ‌های مجاز هم نزد سرور ثبت شده است.

جریان ورود

وقتی کاربر به اپ B می‌رود و session ندارد، به سرور SSO ریدایرکت می‌شود. اگر آنجا هم session نداشت، فرم login می‌بیند؛ بعد از ورود موفق، سرور با یک کوکی به اپ B برمی‌گرداند و B باید این توکن را نزد سرور تأیید کند:

JavaScript// در سرور SSO: اعتبارسنجی توکنی که اپ ارسال می‌کند
app.post('/validate', (req, res) => {
  const { appId, token } = req.body;

  // این اپ مجاز است؟ توکن معتبر است؟
  const session = sessions[token];
  if (!apps.includes(appId) || !session) {
    return res.status(401).json({ error: 'نامعتبر' });
  }

  // فقط شناسهٔ کاربر را برمی‌گردانیم، نه رمز!
  res.json({ ok: true, userId: session.userId });
});

نکتهٔ امنیتی مهم: اپ‌ها فقط token را رد و بدل می‌کنند؛ رمز عبور و اطلاعات اضافه هرگز برای آن‌ها ارسال نمی‌شود.

طرف اپلیکیشن

هر اپ می‌داند SSO در کجا زندگی می‌کند (منطقهٔ مشترک دامنه یا کوکی). منطق اپ ساده است: اگر session کاربر را نداریم، به SSO ریدایرکت شو؛ با `app.validate` وضعیت را چک کن:

JavaScript// در هر اپ: middleware برای چک کردن ورود
function requireSSO(req, res, next) {
  if (req.cookies.sso_token) {
    // توکن را نزد سرور SSO تأیید کن
    return ssoServer.validate(req.cookies.sso_token)
      .then(userId => { req.userId = userId; next(); })
      .catch(() => res.redirect(`${SSO_URL}/login?next=${req.path}`));
  }
  res.redirect(`${SSO_URL}/login?next=${req.path}`);
}

پارامتر `next` مهم است: بعد از ورود، کاربر به همان صفحه‌ای برمی‌گردد که می‌خواست، نه همیشه به خانه.

مرزهای ساده‌سازی

این راه‌حل برای یادگیری، عالی است؛ ولی برای تولید: توکن‌ها باید امضا شوند (HMAC/JWT)، session باید در Redis ماندگار شود، جریان باید ضد CSRF و ضد timing attack باشد، و بهتر است از استانداردهای OIDC/SAML استفاده کنید. با فهمیدن همین نسخهٔ ساده، خواندن مستندات OIDC خیلی راحت‌تر می‌شود.
