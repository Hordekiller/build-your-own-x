۱. چرا Redux را از صفر بسازیم؟

Redux در هستهٔ خود فقط سه مفهوم دارد: یک شیء واحد برای state، تابع خالص (reducer) که state را تغییر می‌دهد و تابع dispatch که اکشن‌ها را به reducer می‌رساند. تمام API آن (getState، subscribe، combineReducers، createStore و…) فقط همین سه ایده را سرو می‌کنند. با ساختن خودمان می‌فهمیم که نه جادو دارد، نه پیچیدگی خاصی.

۲. اولین پیاده‌سازی: فروشگاه دستی

مقاله با یک «فروشگاه» (store) دست‌ساز شروع می‌کند: یک شیء state و تابعی که آن را عوض می‌کند. سپس می‌خواهیم همهٔ تغییرات state فقط از یک مسیر عبور کند — این همان dispatch است:

js// ابتدا بدون Redux: state پراکنده و بی‌قاعده
let state = { count: 0 };
function increment() { state = { ...state, count: state.count + 1 }; }

// حالا با اکشن: هر تغییر state یک شیء توصیفی دارد
function dispatch(action) {
  state = reducer(state, action);
}

// و reducer یک تابع خالص است: (state قبلی + اکشن) → state جدید
function reducer(state = { count: 0 }, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'DECREMENT':
      return { ...state, count: state.count - 1 };
    default:
      return state;
  }
}

dispatch({ type: 'INCREMENT' }); // state.count: 1
dispatch({ type: 'DECREMENT' }); // state.count: 0

به این نکات دقت کنید: reducer هیچ‌وقت state را دستکاری نمی‌کند (شیء جدید برمی‌گرداند) و برای یک ورودی یکسان، همیشه خروجی یکسان می‌دهد — همین «خلوص» است که تست‌پذیری و قابلیت بازپخش (time-travel) را ممکن می‌کند.

۳. ساختن createStore

حالا همین ایده را بسته‌بندی می‌کنیم: یک تابع createStore که state را درون یک closure نگه می‌دارد و API استاندارد Redux را برمی‌گرداند:

jsfunction createStore(reducer, initialState) {
  let state = initialState;
  const listeners = [];

  return {
    // خواندن state فعلی
    getState() {
      return state;
    },

    // ارسال اکشن: reducer اجرا، state عوض و شنونده‌ها خبردار می‌شوند
    dispatch(action) {
      state = reducer(state, action);
      listeners.forEach((listener) => listener());
      return action;
    },

    // ثبت شنوندهٔ تغییرات؛ تابع حذف‌اشتراک برمی‌گرداند
    subscribe(listener) {
      listeners.push(listener);
      return () => {
        const index = listeners.indexOf(listener);
        if (index > -1) listeners.splice(index, 1);
      };
    },
  };
}

// استفاده
const store = createStore(reducer);
store.subscribe(() => console.log('count:', store.getState().count));
store.dispatch({ type: 'INCREMENT' });

این دقیقاً همان چیزی است که Redux هست — کل کتابخانه در همین حد خلاصه می‌شود؛ بقیه ابزارها (bindActionCreators، applyMiddleware و…) فقط آسایش توسعه‌دهنده‌اند.

۴. ترکیب reducerها

در برنامهٔ واقعی state بزرگ است؛ به‌جای یک reducer غول‌پیکر، چند reducer کوچک داریم که هر کدام فقط بخش خودشان را مدیریت می‌کنند و combineReducers آن‌ها را کنار هم می‌گذارد:

jsfunction combineReducers(reducers) {
  return (state = {}, action) => {
    const nextState = {};
    for (const key in reducers) {
      // هر reducer فقط کلید مربوط به خودش را به‌روز می‌کند
      nextState[key] = reducers[key](state[key], action);
    }
    return nextState;
  };
}

const appReducer = combineReducers({
  count: counterReducer,
  user: userReducer,
});

۵. پیوند با React

بخش پایانی مقاله نشان می‌دهد چطور این store را به یک کامپوننت React وصل کنیم: با store.subscribe رندر را به‌روزرسانی می‌کنیم و با store.dispatch اکشن می‌فرستیم:

jsclass Counter extends React.Component {
  componentDidMount() {
    // هر تغییر state → رندر دوباره
    this.unsubscribe = store.subscribe(() => this.forceUpdate());
  }

  componentWillUnmount() {
    this.unsubscribe();
  }

  render() {
    return (
      <div>
        <span>{store.getState().count}</span>
        <button onClick={() => store.dispatch({ type: 'INCREMENT' })}>+</button>
      </div>
    );
  }
}

پکیج react-redux دقیقاً همین اتصال را (با بهینه‌سازی انتخاب‌های selector) برای شما انجام می‌دهد.

۶. جمع‌بندی

  • Redux = state واحد + reducer خالص + dispatch؛ کل چارچوب در چند ده خط جاوااسکریپت ساده است.
  • خلوص reducer مهم‌ترین ویژگی است: باعث پیش‌بینی‌پذیری، تست‌پذیری و قابلیت بازپخش (با ابزارهایی مثل Redux DevTools) می‌شود.
  • بعد از این آموزش، کد منبع Redux (فقط چند فایل کوچک) را بخوانید؛ متوجه می‌شوید چقدر به همین نسخهٔ ساده شبیه است.
