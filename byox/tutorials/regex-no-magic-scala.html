بدون جادو: عبارت باقاعده

⚙ زبان: Scala ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی مقاله «No Magic: Regular Expressions» (بخش ۱ از ۳) از راسل کوهن (مه ۲۰۱۴) است — ساخت یک موتور عبارت باقاعده در کمتر از ۲۰۰ خط کد. کد کامل در مخزن گیت‌هاب راسل کوهن موجود است.
↗ مشاهده منبع اصلی

مقدمه

تا همین اواخر، عبارت‌های باقاعده برای من جادویی به نظر می‌رسیدند. هیچ‌وقت نمی‌فهمیدم چگونه می‌شود تعیین کرد که آیا یک رشته با یک عبارت باقاعده معین مطابقت دارد یا نه. حالا می‌دانم! این است روش پیاده‌سازی یک موتور عبارت باقاعده ابتدایی در کمتر از ۲۰۰ خط کد.

مشخصات

پیاده‌سازی عبارت‌های باقاعده کامل نسبتاً طاقت‌فرساست و بدتر از آن، چیز زیادی به شما یاد نمی‌دهد. نسخه‌ای که پیاده می‌کنیم همین‌قدر هست که بدون ملالت یاد بگیرید. زبان عبارت باقاعده ما این‌ها را پشتیبانی می‌کند:

جدول.    با هر کاراکتری مطابقت بده
|    با «abc» یا «cde» مطابقت بده
+    با یک یا چند مورد از الگوی قبلی
*    با صفر یا چند مورد از الگوی قبلی
( )  برای گروه‌بندی

اگرچه این مجموعه کوچکی از گزینه‌هاست، باز هم می‌توانیم regexهای بامزه‌ای بسازیم؛ مثلاً m(t|n| )|b برای مطابقت زیرنویس‌های «جنگ ستارگان» بدون مطابقت «پیشتازان فضا»، یا (..)* مجموعه همه رشته‌های با طول زوج.

برنامه حمله

عبارت‌های باقاعده را در ۳ فاز ارزیابی می‌کنیم:

  1. عبارت باقاعده را به یک درخت نحو تجزیه کن
  2. درخت نحو را به یک ماشین حالت تبدیل کن
  3. ماشین حالت را روی رشته‌مان ارزیابی کن

برای ارزیابی عبارت‌های باقاعده از یک ماشین حالت به نام NFA استفاده می‌کنیم (بعداً بیشتر درباره‌اش). در سطح بالا، NFA نماینده regex ماست. با مصرف ورودی‌ها از حالتی به حالت دیگر در NFA می‌رویم. اگر به جایی برسیم که نتوانیم یک انتقال مجاز را دنبال کنیم، عبارت باقاعده با رشته مطابقت ندارد.

این رویکرد ابتدا توسط کن تامپسون، یکی از نویسندگان اصلی یونیکس، نشان داده شد. در مقاله ۱۹۶۸ خودش (CACM) پیاده‌سازی یک ویرایشگر متن را شرح می‌دهد و یک ارزیاب عبارت باقاعده هم در آن گنجانده است. تنها تفاوت این است که مقاله او با کد ماشین ۷۰۹۴ نوشته شده. اوضاع قبلاً خیلی جدی‌تر بود.

این الگوریتم ساده‌سازی شیوه ارزیابی عبارت‌های باقاعده توسط موتورهای غیر-بک‌ترکینگ مثل RE2 است که در زمان اثبات‌پذیر خطی اجرا می‌شوند. تفاوت قابل‌توجهی با موتورهای regex موجود در پایتون و جاوا دارد که از backtracking استفاده می‌کنند: با ورودی‌های خاص روی رشته‌های کوچک عملاً تا ابد اجرا می‌شوند. موتور ما در O(طول ورودی × طول عبارت) اجرا می‌شود.

رویکرد من تقریباً استراتژی‌ای را دنبال می‌کند که راس کاکس در پست عالی وبلاگش ترسیم کرده.

نمایش یک عبارت باقاعده

بیایید یک قدم به عقب برگردیم و درباره اینکه چگونه یک عبارت باقاعده را نمایش دهیم فکر کنیم. قبل از اینکه امیدوار باشیم یک عبارت باقاعده را ارزیابی کنیم، باید آن را به ساختار داده‌ای تبدیل کنیم که کامپیوتر بتواند روی آن کار کند. در حالی که رشته‌ها ساختار خطی دارند، عبارت‌های باقاعده سلسله‌مراتب طبیعی دارند.

رشته abc|(c|(de)) را در نظر بگیرید. اگر آن را به‌صورت رشته نگه دارید، باید در هنگام ارزیابی عبارت بین مجموعه‌های مختلف پرانتز به‌جلو‌وعقب پرش کنید و backtracking کنید. یک راه‌حل تبدیل آن به یک درخت است که کامپیوتر به‌آسانی می‌تواند آن را پیمایش کند. مثلاً b+a به شکل یک درخت می‌شود.

برای نمایش درخت، می‌خواهیم سلسله‌مراتبی از کلاس‌ها بسازیم. مثلاً کلاس Or ما باید دو زیردرخت داشته باشد تا دو طرفش را نشان دهد. طبق مشخصات، ۴ مؤلفه مختلف regex را باید تشخیص دهیم: +، *، | و کاراکترهای تحت‌اللفظی مثل .، a و b. علاوه بر این، باید بتوانیم نشان دهیم که یک عبارت از دیگری پیروی می‌کند. کلاس‌های ما این‌ها هستند:

scalaabstract class RegexExpr

// ., a, b
case class Literal(c: Char) extends RegexExpr

// a|b
case class Or(expr1: RegexExpr, expr2: RegexExpr) extends RegexExpr

// ab -> Concat(a,b); abc -> Concat(a, Concat(b, c))
case class Concat(first: RegexExpr, second: RegexExpr) extends RegexExpr

// a*
case class Repeat(expr: RegexExpr) extends RegexExpr

// a+
case class Plus(expr: RegexExpr) extends RegexExpr

تحلیل یک عبارت باقاعده

برای رسیدن از رشته به نمایش درختی، از فرآیند تبدیل‌ای به نام «تحلیل» (parsing) استفاده می‌کنیم. قرار نیست درباره ساخت تحلیل‌گرها با جزئیات زیاد صحبت کنم. بلکه به‌اندازه‌ای می‌دهم که اگر خواستید تحلیل‌گر خودتان را بنویسید راهنمایتان کند. اینجا مرور می‌کنم چگونه عبارت‌های باقاعده را با کتابخانه ترکیب‌کننده‌های تحلیل‌گر (parser combinator) اسکالا تحلیل کردم.

کتابخانه تحلیل اسکالا به ما اجازه می‌دهد با فقط نوشتن مجموعه قواعدی که زبان‌مان را توصیف می‌کنند، یک تحلیل‌گر بنویسیم. متأسفانه از نمادهای زیادی استفاده می‌کند، اما امیدوارم بتوانید از پشت آن نویز، اصل ماجرا را ببینید.

هنگام پیاده‌سازی یک تحلیل‌گر باید ترتیب عمل‌ها را در نظر بگیریم. همان‌طور که «اولویت عملگرها» به حساب (محاسبات) اعمال می‌شود، مجموعه متفاوتی از قواعد هم برای عبارت‌های باقاعده اعمال می‌شود. می‌توانیم این را به‌صورت رسمی‌تر با ایده «اِتصال» عملگر به کاراکترهای کنارش بیان کنیم. عملگرهای مختلف با قدرت‌های مختلفی «اتصال» می‌گیرند — به‌عنوان قیاس، در عبارت‌هایی مثل 5+6*4، * محکم‌تر از + اتصال می‌گیرد. در عبارت‌های باقاعده، * محکم‌تر از | اتصال می‌گیرد. اگر این را به‌صورت درخت نمایش دهیم، ضعیف‌ترین عملگرها در بالا قرار می‌گیرند.

نتیجه می‌گیریم که باید اول ضعیف‌ترین عملگرها را تحلیل کنیم و بعد عملگرهای قوی‌تر را. هنگام تحلیل، می‌توانید تصورش کنید: عملگری را بیرون بکشید، به درخت اضافه کنید، و بعد روی دو بخش باقی‌مانده رشته بازگشت کنید.

در عبارت‌های باقاعده ترتیب قدرت اتصال این است:

جدولکاراکتر تحت‌اللفظی و پرانتز      (قوی‌ترین)
+ و *
الحاق — «a» بعد از «b» است
|                                    (ضعیف‌ترین)

چون ۴ سطح قدرت اتصال داریم، به ۴ نوع عبارت متفاوت نیاز داریم. آن‌ها را (تا حدی خودسرانه) نام‌گذاری کردیم: lit، lowExpr (+ و *)، midExpr (الحاق) و highExpr (|). بریم سراغ کد. اول یک تحلیل‌گر برای ابتدایی‌ترین سطح، یک کاراکتر منفرد:

scalaobject RegexParser extends RegexParsers {
    def charLit: Parser[RegexExpr] = ("""\w""".r | ".") ^^ {
        char => Literal(char.head)
    }

یک لحظه برای توضیح این نحو صبر کنیم. این یک تحلیل‌گر تعریف می‌کند که یک RegexExpr می‌سازد. سمت راست می‌گوید: «چیزی را پیدا کن که با \w (هر کاراکتر واژه‌ای) یا یک نقطه مطابقت داشته باشد. اگر پیدا کردی، آن را به Literal تبدیل کن.

پرانتزها باید در پایین‌ترین سطح تحلیل‌گر تعریف شوند چون قوی‌ترین اتصال را دارند. اما باید بتوانید هر چیزی را داخل پرانتز بگذارید. می‌توانیم این را با کد زیر انجام دهیم:

scala    def parenExpr: Parser[RegexExpr] = "(" ~> highExpr <~ ")"
    def lit: Parser[RegexExpr] = charLit | parenExpr

اینجا * و + را تعریف می‌کنیم:

scala    def repeat: Parser[RegexExpr] = lit <~ "*"
        ^^ { case l => Repeat(l) }
    def plus: Parser[RegexExpr] = lit <~ "+"
        ^^ { case p => Plus(p) }
    def lowExpr: Parser[RegexExpr] = repeat | plus | lit

بعد، الحاق را تعریف می‌کنیم، سطح بعدی:

scala    def concat: Parser[RegexExpr] = rep(lowExpr)
        ^^ { case list => listToConcat(list)}
    def midExpr: Parser[RegexExpr] = concat | lowExpr

در نهایت، or را تعریف می‌کنیم:

scala    def or: Parser[RegexExpr] = midExpr ~ "|" ~ midExpr
        ^^ { case l ~ "|" ~ r => Or(l, r)}

و در آخر، highExpr را تعریف می‌کنیم. highExpr یک or است، ضعیف‌ترین عملگر اتصال، یا اگر or نبود، یک midExpr:

scala    def highExpr: Parser[RegexExpr] = or | midExpr

و در نهایت، کمی کد کمکی برای تمامش کردن:

scala    def listToConcat(list: List[RegexExpr]): RegexExpr = list match {
        case head :: Nil => head
        case head :: rest => Concat(head, listToConcat(rest))
    }

    def apply(input: String): Option[RegexExpr] = {
        parseAll(highExpr, input) match {
            case Success(result, _) => Some(result)
            case failure : NoSuccess => None
        }
    }
}

تمام شد! با این کد اسکالا می‌توانید برای هر عبارت باقاعده‌ای که با مشخصات مطابقت دارد درخت‌های تحلیل تولید کنید. ساختارهای داده حاصل درخت‌اند.

حالا که می‌توانیم عبارت‌های باقاعده‌مان را به درخت‌های نحو تبدیل کنیم، در میانه راه ارزیابی آن‌ها هستیم. مراحل بعدی در بخش ۲ و ۳ مقاله شرح داده شده‌اند: تبدیل درخت نحو به یک NFA و سپس ارزیابی آن NFA روی رشته‌های داده‌شده — با همین رویکرد الگوریتم‌های RE2 و ساخت تامپسون که اینجا ارجاع شد.

کپیرایت: این صفحه ترجمه فارسی مقاله «No Magic: Regular Expressions» اثر راسل کوهن (Russell Cohen) است. تمام حقوق محتوا و کدها متعلق به نویسنده اصلی است. برای مشاهده اصل مطلب (و بخش‌های ۲ و ۳) به سایت اصلی مراجعه کنید.
