مقدمه

اسلک (Slack) پلتفرم فوق‌العاده‌ای برای همکاری تیمی است؛ و نه‌تنها این، بلکه یکی از بهترین رابط‌های برنامه‌نویسی (API) را برای ساخت چت‌بات‌ها (Chatbot) دارد. چت‌بات‌ها در همهٔ اندازه‌ها وجود دارند؛ از رباتی که یادآوری می‌کند شیر بخرید تا رباتی که به شما کمک می‌کند پول بفرستید یا دریافت کنید.

در این نوشته، شما را در ساخت یک ربات اسلک (Slack Bot) حداقلی با پس‌زمینهٔ پایتون همراهی می‌کنم. ایده این است که رباتی در اسلک راه‌اندازی کنیم که وقتی به آن سلام کنید، جواب سلام دهد؛ وقتی راه افتاد و در حال اجرا شد، می‌توانیم تنها با کدنویسی منطق اضافه، توانایی‌های ربات را گسترش دهیم.

دقیقهٔ ۱: اسلک (Slack)

پیش از شروع کدنویسی ربات، بیایید چرخهٔ زندگی ربات‌های اسلک را بفهمیم:

  1. اگر با اسلک تازه‌کار هستید، بدانید که یک پلتفرم پیام‌رسان با تمرکز بر همکاری تیمی است. اسلک به شما اجازه می‌دهد برنامه‌های سفارشی بسازید، از جمله ربات‌ها (نوعی پلتفرم پیام‌رسان به‌عنوان سرویس؛ Messaging Platform as a Service). شما بخش پشتیبان (backend) برنامه را روی سرور خودتان اجرا می‌کنید تا منطق تجاری (business logic) پردازش شود.
  2. برای شروع، باید عضو یک تیم اسلک باشید و برای ساخت اپلیکیشن اسلک (Slack App) جدید، امتیاز مدیر (admin privilege) داشته باشید. اگر عضو هیچ تیم اسلکی نیستید، می‌توانید یک تیم بسازید.
  3. برای تیم اسلک یک اپلیکیشن اسلک می‌سازیم و سپس یک کاربر ربات (Bot User) به اپ اضافه می‌کنیم.
  4. برای پردازش درخواست‌های کاربر ربات، یک برنامهٔ وب REST پشتیبان مبتنی بر جنگو (Django) می‌سازیم.
  5. چون پس‌زمینه را روی سیستم محلی خودمان اجرا می‌کنیم، از ngrok برای تونل‌زنی (tunneling) شبکهٔ محلی و دریافت یک آدرس اینترنتی (url) عمومی استفاده می‌کنیم.
  6. وقتی پس‌زمینه آماده شد، می‌توانیم آدرس نقطهٔ پایانی (endpoint) را برای تأیید نشانی توسط چالش (url verification by challenge) به اسلک ارائه دهیم. نخستین بار که یک endpoint ارائه می‌دهید، اسلک یک درخواست POST چالش با یک توکن (token) محرمانه می‌فرستد. برای تکمیل موفقیت‌آمیز چالش، باید درخواست را همراه با همان رازِ چالش بازگردانید (فقط کافی است پیام دریافتی را منعکس — echo — کنید). این کار برای یک endpoint مشخص فقط یک‌بار انجام می‌شود.
  7. پس از تأیید، می‌توانیم در رویدادها (events) عضو (subscribe) شویم تا اسلک برای هر کدام که بخواهیم پیامی به پس‌زمینهٔ ما بفرستد. این بهترین بخش ماجراست: برای دریافت رویدادهای جدید لازم نیست اسلک را استعلام (poll) کنید؛ اسلک کارهای سنگین را خودش انجام می‌دهد؛ همین موضوع این کار را نمونهٔ استفادهٔ بسیار مناسبی برای AWS Lambda می‌سازد. فهرست بلندبالای رویدادها را می‌توانید اینجا ببینید.
  8. بعد از راه‌اندازی اپلیکیشن اسلک و آماده‌بودن پس‌زمینه برای پردازش رویدادها، می‌توانیم منطق ربات را بنویسیم تا در واکنش به یک رویداد، کار مشخصی انجام دهد. در این‌جا وقتی کاربری سلام می‌کند، ربات ما با یک پیام سلام پاسخ می‌دهد.

بیایید شیرجه بزنیم به ساخت ربات…

دقیقهٔ ۲: ساخت اپلیکیشن اسلک (Create a Slack App)

با ساخت اپلیکیشن اسلک از اینجا شروع کنید؛ روی ساخت اپ (Create App) کلیک کنید. سپس مراحل ساخت اپ را ادامه دهید؛ نامی برایش انتخاب کنید و تیم اسلک را برگزینید.

سپس به صفحهٔ پیکربندی اپ (App configuration) هدایت می‌شوید؛ برای اینکه ربات ما راه بیفتد و اجرا شود، باید کارهای زیر را انجام دهید:

  1. ساخت کاربر ربات (Bot User)
  2. نصب اپلیکیشن اسلک روی تیم
  3. تأیید پس‌زمینه (Back End)
  4. عضو شدن در رویدادها (Subscribe to Events)

در پنل سمت چپ روی کاربر ربات (Bot User) کلیک کنید، یک نام کاربری برای ربات انتخاب کنید و کلید «همیشه ربات من را آنلاین نشان بده» (Always Show My Bot as Online) را روشن کنید. چون قرار است فقط از Events API استفاده کنیم، در غیر این صورت ربات آنلاین نمایش داده نمی‌شود. برای ساخت «ربات سلام» ما روی افزودن کاربر ربات (Add Bot User) کلیک کنید.

دقیقهٔ ۳: نصب اپلیکیشن اسلک روی تیم (Install Slack App to Team)

حالا در پنل سمت چپ روی نصب اپ (Install App) کلیک کنید و اپ را روی تیم اسلک خود نصب کنید.

بعد از نصب، توکن دسترسی OAuth کاربر ربات (Bot User OAuth Access Token) را دریافت خواهید کرد؛ این توکن را یادداشت کنید؛ بعداً هنگام پیکربندی اپ جنگو به آن نیاز داریم. این توکن مانند گذرواژه‌ای است که ربات ما با آن با تیم اسلک ارتباط برقرار می‌کند. در ادامهٔ این آموزش از این توکن با نام SLACK_BOT_USER_TOKEN یاد خواهیم کرد.

دقیقهٔ ۴: اعتبارنامه‌های کلاینت اسلک (Slack Client Credentials)

همچنین اعتبارنامه‌های اپ (App Credentials) را از بخش اطلاعات پایه (Basic Information) در پنل سمت چپ یادداشت کنید. این اعتبارنامه‌ها به ما اجازه می‌دهند با API اسلک صحبت کنیم؛ بنابراین هر بار که پیامی به اسلک می‌فرستیم، باید شناسهٔ کلاینت (Client ID / CLIENT_ID) و راز کلاینت (Client Secret / CLIENT_SECRET) خودمان را بفرستیم تا در اسلک شناسایی شویم. به همین ترتیب می‌توانیم تأیید کنیم که پیامِ دریافتی واقعاً از سمت اسلک ارسال شده است؛ با بررسی اینکه توکن تأیید (Verification Token / VERIFICATION_TOKEN) داخل پیام با توکن موجود در اعتبارنامه‌های اپ یکی است.

حالا باید چهار مقدار کلیدی در دست داشته باشیم:

  1. شناسهٔ کلاینت — SLACK_CLIENT_ID
  2. راز کلاینت — SLACK_CLIENT_SECRET
  3. توکن تأیید — SLACK_VERIFICATION_TOKEN
  4. توکن کاربر ربات — SLACK_BOT_USER_TOKEN

در پیکربندی اپلیکیشن اسلک فقط یک گام آخر داریم: ارائهٔ نقطهٔ پایانی (endpoint) REST API ربات‌مان به اسلک و تأیید گرفتن آن.

پیش از آن‌که ربات را تأیید کنیم و در رویدادها عضو شویم، باید اپ جنگو را در حال اجرا داشته باشیم.

دقیقهٔ ۵: آماده‌سازی محیط (Environment Setup)

از پایتون 3.5 و بسته‌های زیر استفاده خواهیم کرد:

  1. جنگو (Django)
  2. چارچوب REST جنگو (Django REST Framework)
  3. کلاینت اسلک برای پایتون (Slack Client for Python)
  4. API رویدادهای اسلک (Slack Events API)

برای محیط مجازی (virtual environment) از conda و برای مدیریت بسته‌ها از pip استفاده می‌کنیم. بیایید برای پروژه‌مان یک محیط مجازی جدید به نام slack_bot با نسخهٔ پایتون 3.5.x بسازیم و محیط مجازی را فعال کنیم.

shellconda create -n slack_bot python==3.5
# ویندوز
activate slack_bot
# مک‌اواس، لینوکس
source activate slack_bot

حالا بسته‌های لازم را نصب می‌کنیم:

shellpip install django

pip install slackclient

pip install slackeventsapi

دقیقهٔ ۷: پیکربندی تنظیمات جنگو (Configure Django Settings)

چارچوب REST با نمای API (API View) داخلی و رابط API قابل مرور (browseable API) خود، ساخت نقطه‌های پایانی (endpoint) API را آسان می‌کند. بیایید چارچوب REST را به‌عنوان وابستگی (dependency) به تنظیمات جنگو اضافه کنیم. همچنین باید اپلیکیشن خودمان یعنی events را هم به‌عنوان وابستگی اضافه کنیم. دو خطی که در ادامه آمده را در فایل slack/settings.py اضافه کنید.

py# slack/settings.py
INSTALLED_APPS = [

    'django.contrib.contenttypes',
    'django.contrib.sessions',

دقیقهٔ ۸: ساخت یک نقطهٔ پایانی API (Create an API endpoint)

حالا که سرور اپلیکیشن ما راه افتاده و در حال اجراست، باید یک نقطهٔ پایانی برای اسلک بسازیم تا پیام‌های رویداد را به آن بفرستد. با چارچوب REST جنگو (Django Rest Framework / DRF) یک نمای API به شکل زیر می‌سازیم:

py# events/views.py
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status
from django.conf import settings

SLACK_VERIFICATION_TOKEN = getattr(settings, 'SLACK_VERIFICATION_TOKEN', None)

class Events(APIView):
    def post(self, request, *args, **kwargs):
        slack_message = request.data
        if slack_message.get('token') != SLACK_VERIFICATION_TOKEN:
            return Response(status=status.HTTP_403_FORBIDDEN)
        return Response(status=status.HTTP_200_OK)

در کد بالا، بسته‌های پایتون موردنیاز را وارد (import) می‌کنیم، توکنِ ذخیره‌شده در پیکربندی را بازیابی می‌کنیم و سپس یک نمای API تعریف می‌کنیم تا درخواست POST را مدیریت کند.

در تابع POST بررسی می‌کنیم که آیا توکن داخل پیام با توکن تأیید کاربر ربات ما مطابقت دارد یا نه؛ این کار برای اعتبارسنجی این است که درخواستِ دریافتی واقعاً از سمت اسلک آمده است. اگر مطابقت داشت، پیام «OK» می‌فرستیم وگرنه به درخواست‌کننده اعلام می‌کنیم که از دسترسی به سرور ما «منع شده» (Forbidden) است.

دقیقهٔ ۹: پیکربندی مسیرهای جنگو (Configure Django Routes)

نکته: اگر در برنامه‌های وب تازه‌کار هستید، بدانید که مسیریابی (routing) روشی است که با آن به سرور وب می‌گوییم وقتی به یک آدرس (URL) درخواستی می‌رسد، کدام تابع فراخوانی شود. وقتی آدرس با یک پیام درخواست مواجه شود، تابع متناظر فراخوانی می‌شود و پیامِ درخواست‌کننده به‌عنوان پارامتر به تابع پاس داده می‌شود.

برای اتصال کلاس Events API به آدرس http://localhost:8000/events/، خطوط زیر را در slack/urls.py اضافه کنید.

py# slack/urls.py
from django.conf.urls import url
from django.contrib import admin
from events.views import Events                                    #

urlpatterns = [
    url(r'^admin/', admin.site.urls),
    url(r'^events/', Events.as_view()),                            #
]

آدرس سرور را در مرورگر باز کنید؛ رابط API قابل مرور (browsable API interface) را خواهید دید.

نکته: معمولاً برای هر اپ یک فایل مسیریابی جداگانه می‌سازیم و آن را در مسیریابی پروژه ثبت می‌کنیم. برای ساده نگه‌داشتن کد، آدرس اپ events را در فایل مسیریابی پروژه تعریف کرده‌ام.

دقیقهٔ ۱۰: چالش تأیید آدرس اسلک (Slack URL Verification Challenge)

برای ارائهٔ نقطهٔ پایانی API به اسلک، باید منطقی کدنویسی کنیم تا اسلک بتواند نقطهٔ پایانی ما را تأیید کند و آن را با کاربر ربات اسلک مرتبط سازد. در کلاس Events API کد زیر را اضافه کنید.

pyfrom rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status
from django.conf import settings

SLACK_VERIFICATION_TOKEN = getattr(settings, 'SLACK_VERIFICATION_TOKEN', None)


class Events(APIView):
    def post(self, request, *args, **kwargs):

        slack_message = request.data
        
        if slack_message.get('token') != SLACK_VERIFICATION_TOKEN:
            return Response(status=status.HTTP_403_FORBIDDEN)

        # چالش تأیید آدرس
        if slack_message.get('type') == 'url_verification':        #
            return Response(data=slack_message,                    #
                            status=status.HTTP_200_OK)             #

        return Response(status=status.HTTP_200_OK)

کاری که این‌جا می‌کنیم این است که بررسی می‌کنیم آیا درخواست، تأیید نشانی (url verification) است؛ اگر بود، همان پیام را عیناً به عقب برمی‌گردانیم.

        slack_message = request.data

        if slack_message.get('token') != SLACK_VERIFICATION_TOKEN:
            return Response(status=status.HTTP_403_FORBIDDEN)

        # چالش تأیید آدرس
        if slack_message.get('type') == 'url_verification':
            return Response(data=slack_message,
                            status=status.HTTP_200_OK)
        # ربات سلام
        if 'event' in slack_message:                              #4
            event_message = slack_message.get('event')            #
            
            # پیام خودِ ربات را نادیده بگیر
            if event_message.get('subtype') == 'bot_message':     #5
                return Response(status=status.HTTP_200_OK)        #
            
            # پردازش پیام کاربر
            user = event_message.get('user')                      #6
            text = event_message.get('text')                      #
            channel = event_message.get('channel')                #
            bot_text = 'Hi <@{}> :wave:'.format(user)             #
            if 'hi' in text.lower():                              #7
                Client.api_call(method='chat.postMessage',        #8
                                channel=channel,                  #
                                text=bot_text)                    #
                return Response(status=status.HTTP_200_OK)        #9

        return Response(status=status.HTTP_200_OK)

کارهایی که انجام دادیم به این شرح است:

  1. بستهٔ کلاینت اسلک (Slack Client) را وارد کردیم.
  2. توکن کاربر ربات اسلک را از تنظیمات بازیابی کردیم.
  3. یک نمونهٔ (instance) Client ساختیم تا پاسخ ربات را به اسلک پست (post) کند.
  4. اگر دادهٔ رویداد (event data) در پیام دریافتی موجود بود، پیام را پردازش می‌کنیم.
  5. پیامی که ربات در یک کانال پست می‌کند، دوباره به‌عنوان بخشی از دریافت‌کنندگان به خودِ ربات هم می‌رسد؛ بنابراین پیامِ ربات باید توسط ربات نادیده گرفته شود.
  6. اگر پیام از یک کاربر باشد، رویداد را پردازش می‌کنیم. شناسهٔ کاربر (user id)، شناسهٔ کانال (channel id) و پیامِ کاربر به ربات را استخراج می‌کنیم و سپس پیام سلام ربات را با نام کاربر می‌سازیم.
  7. اگر پیام کاربر شامل واژهٔ سلام hi بود، اقدام به پست کردن پیام سلام می‌کنیم.
  8. برای پست کردن پیام پاسخ ربات در کانال، API کلاینت اسلک را از طریق chat.postMessage فراخوانی می‌کنیم.
  9. پس از پست شدن پیام، به رویداد اسلک پاسخ OK می‌دهیم.

در این‌جا تصویری از منطق ربات می‌بینید:

دقیقهٔ ۱۲: تونل‌زنی با ngrok (Tunneling with ngrok)

حالا باید ربات خود را در یک دامنهٔ عمومی در دسترس قرار دهیم تا اسلک بتواند فراخوانی‌های سرویس (service calls) را انجام دهد. یکی از راه‌های انجام این کار در سیستم محلی، استفاده از یک سرویس تونل‌زنی مثل ngrok است؛ بروید و ngrok را برای سیستمتان نصب کنید.

وقتی ngrok را راه‌اندازی کردید:

۱. سرور جنگو را با این دستور اجرا کنید:

shellpython manage.py runserver 0.0.0.0:8000

۲. از ngrok استفاده کنید تا پورت جنگو را به یک دامنهٔ عمومی متصل کنید، به این شکل:

shellngrok http 8000

ngrok یک آدرس عمومی می‌سازد و درخواست‌ها را به سرور شما هدایت می‌کند؛ پس از اتصال موفق، چیزی شبیه به تصویر زیر می‌بینید:

برای دسترسی به API ربات به آدرس http://<your-unique-id>.ngrok.io/events/ بروید.

دقیقهٔ ۱۳: ارائهٔ آدرس به اسلک (Submitting URL to Slack)

به داشبورد اپلیکیشن‌های اسلک بروید، اپ خود را انتخاب کنید و با دادن آدرس ngrok در رویدادها عضو شوید.

آدرس شما باید از پسِ چالش تأیید (verification challenge) بربیاید.

سپس به پایین اسکرول کنید و برای «پیام کانال» (channel message) و «پیام مستقیم» (direct message) عضو شوید.

دقیقهٔ ۱۴: همین و بس (That's All Folks)

ربات شما الان راه افتاده و در حال اجراست؛ بروید و در چت اسلک به آن سلام کنید.
