چگونه یک موتور regex از صفر بسازیم

مقدمه

در این مقاله یک موتور عبارت باقاعده ساده می‌سازیم که بتواند از الگوی [a-zA-Z][a-zA-Z0-9_.]+@[a-zA-Z0-9]+.[a-zA-Z]{2,} (که در آن . به‌جای «هر کاراکتر»، تحت‌اللفظی است) برای بررسی اعتبار آدرس‌های ایمیل استفاده کند. از زبان گولنگ استفاده می‌کنیم. مقاله به ۳ بخش تقسیم شده است:

  • تحلیل (Parsing)
  • ساخت ماشین حالت (Building the state machine)
  • مطابقت (Matching)

تحلیل (Parsing)

به خودی خود، یک رشته regex فقط یک رشته است. باید آن را به چیزی تبدیل کنیم که ساختار داشته باشد؛ مثلاً:

توکن‌ها// رشته regex اصلی
"[a-zA-Z0-9_]+@[a-zA-Z0-9]+.[a-zA-Z]{2,}"
// توکن‌های regex
Repeat(1, بی‌نهایت):
   Range(a, b,...z, A, B,...,Z, 0,...,9, _)
Literal(@)
Repeat(1, بی‌نهایت):
   Range(a, b,...z, A, B,...,Z, 0,...,9)
Literal(.)
Repeat(2, بی‌نهایت):
   Range(a, b,...z, A, B,...,Z)

ایده اصلی هنگام تحلیل یک رشته regex ساده است: به دنبال کاراکترهایی می‌گردیم که معانی ویژه دارند مثل * + ? () [] {} و سعی می‌کنیم با کمک آن‌ها توکن بسازیم. ابتدا چند نوع و ثابت تعریف می‌کنیم:

gotype tokenType uint8 // <1>
const ( // <2>
   group         tokenType = iota
   bracket       tokenType = iota
   or            tokenType = iota
   repeat        tokenType = iota
   literal       tokenType = iota
   groupUncaptured tokenType = iota
)
type token struct { // <3>
   tokenType tokenType
   // محتوای مورد نیاز برای هر توکن متفاوت خواهد بود
   // پس باید با نوع انعطاف‌پذیر باشیم
   value     interface{}
}
type parseContext struct { // <4>
   // اندیس کاراکتری که در حال پردازش آن
   // در رشته regex هستیم
   pos    int
   tokens []token
}
  1. فقط یک نام مستعار نوع برای کاراکتر است.
  2. ثابت‌های مشخص‌کننده نوع توکنی که با آن کار می‌کنیم؛ مثل enum.
  3. ساختار اصلی توکن؛ یک نوع و یک مقدار دارد که بسته به نوع، می‌تواند هر چیزی باشد.
  4. parseContext به ما کمک می‌کند موقعیت‌هایمان را پیگیری کنیم و توکن‌های تحلیل‌شده تاکنون را نگه دارد.

حالا الگوریتم تحلیل ما:

gofunc parse(regex string) *parseContext {
   ctx := &parseContext{
      pos:    0,
      tokens: []token{},
   }
   for ctx.pos < len(regex) {
      process(regex, ctx)
      ctx.pos++
   }
   return ctx
}
  • روی هر کاراکتر حلقه می‌زنیم و آن را پردازش می‌کنیم تا به پایان رشته regex برسیم.

حالا نگاهی به متد process بیندازیم. کمی درگیرتر است؛ قدم‌به‌قدم بررسی‌اش می‌کنیم.

gofunc process(regex string, ctx *parseContext) {
    ch := regex[ctx.pos]
    if ch == '(' { // <1>
        groupCtx := &parseContext{
            pos:    ctx.pos,
            tokens: []token{},
        }
        parseGroup(regex, groupCtx)
        ctx.tokens = append(ctx.tokens, token{
            tokenType: group,
            value:     groupCtx.tokens,
        })
    } else if ch == '[' { // <2>
        parseBracket(regex, ctx)
    } else if ch == '|' { // <3>
        parseOr(regex, ctx)
    } else if ch == '*' || ch == '?' || ch == '+' { // <4>
        parseRepeat(regex, ctx)
    } else if ch == '{' { // <5>
        parseRepeatSpecified(regex, ctx)
    } else { // <6>
        // لیترال
        t := token{
            tokenType: literal,
            value:     ch,
        }
        ctx.tokens = append(ctx.tokens, t)
    }
}

همان‌طور که گفتیم، سعی می‌کنیم کاراکترهایی را که می‌شناسیم مطابقت دهیم و از آن‌ها برای تحلیل توکن‌ها استفاده کنیم.

  1. اگر کاراکتر فعلی ( باشد، با گروه سر و کار داریم و سعی می‌کنیم چند کاراکتر بعد را به‌عنوان گروه تحلیل کنیم.
  2. اگر [ باشد، عبارت براکتی است.
  3. اگر | باشد، عبارت جایگزینی (Or) است.
  4. کاراکترهای * (ستاره کلین)، + و ? همگی تکرار را نشان می‌دهند. ? یعنی اختیاری؛ از نظر تکرار یعنی کاراکتر حداکثر یک‌بار تکرار می‌شود.
  5. آکولاد هم تکرار را مشخص می‌کند: a* == a{0,}، a+ == a{1,}، a? == a{0,1}.
  6. اگر هیچ‌کدام نبود، آن را لیترال در نظر می‌گیریم. توجه داشته باشید این یک پیاده‌سازی ساده‌شده است؛ موارد زیادی برای در نظر گرفتن وجود دارد. این الگوریتم ساده‌شده همچنین کاراکترهای escape را در نظر نمی‌گیرد (یعنی \a به‌عنوان الحاق دو لیترال \ و a تلقی می‌شود).

حالا هر تابع تعریف‌شده را بررسی می‌کنیم. با تحلیل عبارت‌های گروهی (1) شروع می‌کنیم:

gofunc parseGroup(regex string, ctx *parseContext) {
   ctx.pos += 1 // از پرانتز باز رد شو
   for regex[ctx.pos] != ')' {
      process(regex, ctx)
      ctx.pos += 1
   }
}
  • هر کاراکتر را مثل متد parse پردازش می‌کنیم تا به پرانتز بسته برسیم. مدیریت خطا را پوشش نمی‌دهیم؛ اگر اندیس از مرز خارج شود به‌هرحال panic می‌کند.

آن کد اضافه اطراف parseGroup در تابع process چه می‌کند؟ یک context مخصوص هر گروه می‌سازیم تا بتوانیم همه توکن‌های داخل یک گروه خاص را کنار هم بسته‌بندی کنیم بی‌آنکه با context سطح بالا درگیر شویم. بعد از پایان تحلیل گروه، همه توکن‌های تحلیل‌شده را در یک توکن جدید از نوع group می‌بندیم و به فهرست توکن سراسری اضافه می‌کنیم.

حالا ببینیم چگونه عبارت‌های براکتی (2) را تحلیل کنیم. این کل تابع است:

gofunc parseBracket(regex string, ctx *parseContext) {
    ctx.pos++ // از براکت باز رد شو
    var literals []string
    for regex[ctx.pos] != ']' { // <1>
        ch := regex[ctx.pos]
        if ch == '-' { // <2>
            next := regex[ctx.pos+1] // <3-1>
            prev := literals[len(literals)-1][0] // <3-1>
            literals[len(literals)-1] = fmt.Sprintf("%c%c", prev, next) // <3-2>
            ctx.pos++  // برای مصرف کاراکتر next
        } else { // <4>
            literals = append(literals, fmt.Sprintf("%c", ch))
        }
        ctx.pos++ // <5>
    }
    literalsSet := map[uint8]bool{}
    for _, l := range literals { // <6>
        for i := l[0]; i <= l[len(l)-1]; i++ { // <7>
            literalsSet[i] = true
        }
    }
    ctx.tokens = append(ctx.tokens, token{ // <8>
        tokenType: bracket,
        value:     literalsSet,
    })
}
  1. مثل گروه، تا براکت بسته (]) پیش می‌رویم.
  2. بررسی می‌کنیم آیا - است، چون نشان‌دهنده بازه است (مثل a-zK-Z2-8).
  3. وقتی نشان بازه بود: کاراکتر بعدی و کاراکتر قبلی (آخرین عضو فهرست لیترال‌ها) را می‌گیریم و به‌صورت دو کاراکتر کنار هم ذخیره می‌کنیم.
  4. اگر نبود، لیترال منفرد است و به فهرست اضافه می‌شود.
  5. به کاراکتر بعدی می‌رویم.
  6. فهرست literals هم لیترال دارد و هم بازه، و ممکن است تکراری باشند (مثل [a-me-s]). روی مقادیر ذخیره‌شده رد می‌شویم و هر لیترال را به literalsSet اضافه می‌کنیم؛ مجموعه‌ها ذاتاً تکراری ندارند. در گولنگ از map استفاده می‌کنیم چون مجموعه بومی ندارد.
  7. همه کاراکترهای بین اول و آخر مقدار ذخیره‌شده را اضافه می‌کنیم. در لیترال‌های منفرد فقط خود لیترال اضافه می‌شود؛ در بازه‌ها همه از اول تا آخر (شامل).
  8. در نهایت توکن براکت را به فهرست توکن‌ها اضافه می‌کنیم.

در نوبت بعدی parseOr است که جایگزینی‌ها (3) را تحلیل می‌کند:

gofunc parseOr(regex string, ctx *parseContext) {
    // <1:start>
    rhsContext := &parseContext{
        pos:    ctx.pos,
        tokens: []token{},
    }
    rhsContext.pos += 1 // از | رد شو
    for rhsContext.pos < len(regex) && regex[rhsContext.pos] != ')' {
        process(regex, rhsContext)
        rhsContext.pos += 1
    }
    // <1:end>
    // دو طرف عبارت OR
    left := token{
        tokenType: groupUncaptured,
        value:     ctx.tokens, // <2>
    }
    right := token{ // <3>
        tokenType: groupUncaptured,
        value:     rhsContext.tokens,
    }
    ctx.pos = rhsContext.pos // <4>
    ctx.tokens = []token{{ // <5>
        tokenType: or,
        value:     []token{left, right},
    }}
}
  1. عملیات جایگزینی نحو <left>|<right> دارد. تا وقتی به | برسیم، همه چیز سمت چپ آن را تحلیل کرده‌ایم. حالا وقت تحلیل سمت راست است؛ کدی تقریباً همانند تحلیل گروه‌ها. context خالی مخصوص سمت راست می‌سازیم و همه توکن‌ها را در آن جمع می‌کنیم، تا پایان رشته regex یا برخورد با پرانتز بسته.
  2. سمت چپ شامل همه توکن‌های موجود در context اصلی است.
  3. برای سمت راست، همه توکن‌های جمع‌شده در rhsContext را می‌گیریم. برای هر دو از نوع groupUncaptured استفاده می‌کنیم — نوعی که برای نشان دادن یک دسته توکن ساخته شده.
  4. موقعیت context اصلی را به‌روز می‌کنیم.
  5. توکن جایگزینی را می‌سازیم و به context اصلی اضافه می‌کنیم. نکته مهم: توکن‌های قدیمی را در context اصلی نگه نمی‌داریم چون از قبل داخل توکن جایگزینی‌اند.

حالا تکرارها (4):

goconst repeatInfinity = -1
func parseRepeat(regex string, ctx *parseContext) {
    ch := regex[ctx.pos]
    var min, max int
    if ch == '*' {
        min = 0
        max = repeatInfinity
    } else if ch == '?' {
        min = 0
        max = 1
    } else {
        // ch == '+'
        min = 1
        max = repeatInfinity
    }
    // باید آخرین توکن را با داده شمارنده بپیچیم
    // تا بدانیم min و max روی چه چیزی اعمال می‌شوند
    lastToken := ctx.tokens[len(ctx.tokens)-1]
    ctx.tokens[len(ctx.tokens)-1] = token{
        tokenType: repeat,
        value: repeatPayload{
            min:   min,
            max:   max,
            token: lastToken,
        },
    }
}
  • ایده پایه این است که هر نماد اینجا حداقل و حداکثر تعداد تکرار مشخصی دارد. repeatInfinity مقدار -1 است اما آن را بی‌نهایت در نظر می‌گیریم.
  • بعد از تعیین مرزها، آخرین توکن تحلیل‌شده را می‌گیریم (چون نمادهای تکرار همیشه سمت راست توکن هستند)، آن را در یک توکن repeat با مرزهای مناسب می‌پیچیم و در همان موقعیت فهرست توکن ذخیره می‌کنیم.

عبارت تکرار دیگر کد کمی طولانی‌تر دارد اما ایده همان است (5):

gofunc parseRepeatSpecified(regex string, ctx *parseContext) {
    // +1 چون آکولاد باز { را رد می‌کنیم
    start := ctx.pos + 1
    // تا رسیدن به انتهای آکولادها پیش برو
    for regex[ctx.pos] != '}' {
        ctx.pos++
    }
    boundariesStr := regex[start:ctx.pos] // <1>
    pieces := strings.Split(boundariesStr, ",") // <2>
    var min, max int
    if len(pieces) == 1 { // <3>
        if value, err := strconv.Atoi(pieces[0]); err != nil {
            panic(err.Error())
        } else {
            min = value
            max = value
        }
    } else if len(pieces) == 2 { // <4>
        if value, err := strconv.Atoi(pieces[0]); err != nil {
            panic(err.Error())
        } else {
            min = value
        }
        if pieces[1] == "" {
            max = repeatInfinity
        } else if value, err := strconv.Atoi(pieces[1]); err != nil {
            panic(err.Error())
        } else {
            max = value
        }
    } else {
        panic(fmt.Sprintf("برای شمارنده باید 1 یا 2 مقدار مشخص شود: '%s'", boundariesStr))
    }
    // <5>
    lastToken := ctx.tokens[len(ctx.tokens)-1]
    ctx.tokens[len(ctx.tokens)-1] = token{
        tokenType: repeat,
        value: repeatPayload{
            min:   min,
            max:   max,
            token: lastToken,
        },
    }
}
  1. رشته مرزها را می‌گیریم؛ همه‌چیز بین {}.
  2. آن را با جداکننده کاما تکه‌تکه می‌کنیم.
  3. اگر فقط یک عضو بود (مثل {1})، تعداد تکرار دقیق است و min و max یکی‌اند.
  4. اگر دو عضو بود، اولی min و دومی max است (مثل {3,7}). اگر عضو دوم نبود ({3,})، حداقل سه تکرار لازم است و سقف ندارد؛ یعنی repeatInfinity.
  5. حالا که مرزها را داریم، آخرین توکن تحلیل‌شده را برمی‌داریم، در توکن repeat با مرزهای مناسب می‌پیچیم و ذخیره می‌کنیم.

با این کار مراحل تحلیل یک رشته regex تمام می‌شود. در بخش بعد می‌آموزیم چگونه از آن توکن‌ها یک ماشین حالت بسازیم.

ساخت ماشین حالت

در این بخش می‌آموزیم چگونه از توکن‌های تحلیل‌شده یک ماشین حالت بسازیم؛ اما اول ببینیم ماشین حالت چیست.

ماشین حالت متناهی چیست؟

ماشین حالت متناهی (FSM) یا اتوماتای متناهی (FA) ماشینی انتزاعی است که از مجموعه‌ای متناهی از حالت‌ها، یک حالت اولیه، حالت‌های پایانی و انتقال‌هایی بین این حالت‌ها تشکیل شده. FA دو نوع دارد: اتوماتای متناهی قطعی (DFA) و اتوماتای متناهی نادترمینیستی (NFA).

بررسی پذیرش این‌گونه انجام می‌شود:

  1. همیشه از حالت شروع هستیم.
  2. اولین کاراکتر رشته ورودی را می‌گیریم و می‌بینیم آیا انتقال متناظری هست: اگر بود به آن حالت می‌رویم و با کاراکتر بعدی ادامه می‌دهیم؛ اگر نبود، رشته پذیرفته نمی‌شود.
  3. تا پایان رشته تکرار می‌کنیم و بررسی می‌کنیم آیا در حالت پایانی هستیم.
  4. بودن در حالت پایانی یعنی رشته پذیرفته شده.

در DFA، با یک حالت و ورودی یکسان، همیشه به همان حالت هدف می‌روی. قطعی است.

در NFA، با یک حالت و ورودی یکسان می‌توانی به حالت‌های مختلف بروی؛ نادترمینیستی است. epsilon یعنی ورودی خالی. این NFA هم فقط رشته‌های abd و ace را می‌پذیرد؛ اما با مقدار epsilon می‌توانی وارد چند حالت شوی.

در بخش‌های بعد فهرست توکن‌های تحلیل‌شده را می‌گیریم و از آن‌ها یک epsilon-NFA می‌سازیم. وقتی NFA آماده شد، باید از هر حالت رد شویم و سعی کنیم یک‌به‌یک کاراکتر از رشته ورودی مصرف کنیم و ببینیم به حالت پایانی می‌رسیم یا نه.

از عبارت باقاعده تا epsilon-NFA

قدم قبلی فهرستی از توکن‌ها به ما می‌دهد. این‌ها را به یک epsilon-NFA تبدیل می‌کنیم. برای این کار از الگوریتمی به نام «ساخت تامپسون» استفاده می‌کنیم که الگوریتمی برای ساخت و ترکیب چند NFA در یک NFA است.

برای نمایش حالت NFA از این ساختار ساده استفاده می‌کنیم:

gotype state struct {
    start       bool
    terminal    bool
    transitions map[uint8][]*state
}
  1. start نشان می‌دهد آیا این حالت نقطه ورود است.
  2. terminal نشان می‌دهد آیا حالت نهایی است. رسیدن به این حالت یعنی ورودی با regex مطابقت دارد.
  3. transitions نقشه‌ای است که در آن یک کاراکتر به فهرستی از حالت‌های مختلف نگاشت می‌شود.
  • حالت شروع (صورتی) و حالت پایانی (آبی) داریم.
  • برای هر توکن یک NFA جدا می‌سازیم و این NFAها با انتقال‌های اپسیلون در هم الحاق می‌شوند. آخرین حالت NFA قبلی به اولین حالت NFA بعدی وصل می‌شود.
  • یک انتقال اپسیلون از حالت شروع به اولین حالت (s1) NFAهای الحاق‌شده هست و یکی هم از آخرین حالت NFAهای الحاق‌شده به حالت پایانی.

همان چیز در کد:

goconst epsilonChar uint8 = 0 // کاراکتر خالی
func toNfa(ctx *parseContext) *state {
    startState, endState := tokenToNfa(&ctx.tokens[0]) // <1>
    for i := 1; i < len(ctx.tokens); i++ { // <2>
        startNext, endNext := tokenToNfa(&ctx.tokens[i]) // <3>
        endState.transitions[epsilonChar] = append(
            endState.transitions[epsilonChar],
            startNext,
        ) // <4>
        endState = endNext // <5>
    }
    start := &state{ // <6>
        transitions: map[uint8][]*state{
            epsilonChar: {startState},
        },
        start: true,
    }
    end := &state{ // <7>
        transitions: map[uint8][]*state{},
        terminal:    true,
    }
    endState.transitions[epsilonChar] = append(
        endState.transitions[epsilonChar],
        end,
    ) // <8>
    return start // <9>
}
  1. اولین توکن را می‌گیریم و به NFA تبدیل می‌کنیم. tokenToNfa یک NFA از توکن می‌سازد و حالت شروع و پایان آن را برمی‌گرداند.
  2. روی بقیه توکن‌ها رد می‌شویم.
  3. برای هر توکن tokenToNfa را صدا می‌زنیم و حالت شروع و پایان را نگه می‌داریم.
  4. حالت پایان فراخوانی قبلی را به حالت شروع NFA جدید وصل می‌کنیم.
  5. حالت پایان را ذخیره می‌کنیم چون در تکرار بعدی به کار می‌آید.
  6. حالت شروع را می‌سازیم؛ با انتقال اپسیلون به حالت شروع اولین NFA.
  7. حالت پایانی را می‌سازیم.
  8. حالت پایان آخرین NFA حالا انتقال اپسیلون به حالت پایانی دارد.
  9. در نهایت حالت شروع را برمی‌گردانیم چون نقطه ورود است.

حالا که طرح کلی ساخت NFA را داریم، ببینیم هر توکن چگونه به NFA تبدیل می‌شود:

go// برمی‌گرداند (start, end)
func tokenToNfa(t *token) (*state, *state) {
    start := &state{
        transitions: map[uint8][]*state{},
    }
    end := &state{
        transitions: map[uint8][]*state{},
    }
    switch t.tokenType {
    case literal:
    case or:
    case bracket:
    case group, groupUncaptured:
    case repeat:
    default:
        panic("نوع توکن ناشناخته")
    }
    return start, end
}
  • کد بالا اسکلت tokenToNfa است؛ هر نوع توکن و نحوه مدیریتش را در ادامه می‌بینیم.
  • به‌طور کلی حالت‌های خالی start و end می‌سازیم، منطقی در switch انجام می‌شود و آن‌ها را برمی‌گردانیم.

لیترال‌ها

با لیترال‌ها شروع می‌کنیم چون ساده‌ترین‌اند. برای رفتن از start به end به انتقال ch نیاز داریم؛ ch یک کاراکتر منفرد است.

gocase literal:
    ch := t.value.(uint8)
    start.transitions[ch] = []*state{end}

t.value به مقداری اشاره می‌کند که هنگام تحلیل در ساختار token ذخیره کردیم.

جایگزینی (or)

Or یعنی انتخاب بین دو مسیر متفاوت. به یاد بیاورید در فاز تحلیل، مقدار توکن or دارای دو طرف چپ و راست بود؛ هرکدام NFA متفاوتی را نشان می‌دهند. برای ساخت NFA جایگزینی نیاز داریم:

  • انتقال اپسیلون از حالت شروع به شروع هر دو NFA چپ و راست
  • انتقال اپسیلون از پایان هر دو NFA به حالت پایان
gocase or:
    values := t.value.([]token)
    left := values[0]
    right := values[1]
    s1, e1 := tokenToNfa(&left) // <1>
    s2, e2 := tokenToNfa(&right) // <1>
    start.transitions[epsilonChar] = []*state{s1, s2} // <2>
    e1.transitions[epsilonChar] = []*state{end} // <3>
    e2.transitions[epsilonChar] = []*state{end} // <3>
  1. هر دو NFA چپ و راست ساخته می‌شوند.
  2. حالت شروع با انتقال اپسیلون به شروع هر دو NFA وصل می‌شود.
  3. حالت پایان هر NFA با انتقال اپسیلون به حالت پایان NFA جایگزینی وصل می‌شود.

عبارت براکتی

عبارت‌های براکتی را می‌توان جایگزینی بزرگ در نظر گرفت؛ مثلاً [a-c0-2x] یعنی a|b|c|0|1|2|x. تفاوت کوچک این است که با لیترال‌ها سر و کار داریم نه NFAهای دلخواه، پس به‌سادگی برای هر لیترال یک انتقال از حالت شروع به حالت پایان می‌سازیم.

gocase bracket:
    literals := t.value.(map[uint8]bool)
    for l := range literals { // <1>
        start.transitions[l] = []*state{end} // <2>
    }
  1. از هر لیترال براکت رد می‌شویم.
  2. انتقالی از start به end اضافه می‌کنیم.

گروه‌ها

برای تبدیل گروه به NFA، همه NFAهای منفرد ساخته‌شده از توکن‌های داخل گروه را الحاق می‌کنیم. این کار را قبلاً در تابع toNFA دیده‌ایم؛ کد همان است:

go// در موتور ما تفاوتی بین
// group و groupUncaptured نیست
case group, groupUncaptured:
    tokens := t.value.([]token)
    start, end = tokenToNfa(&tokens[0])
    for i := 1; i < len(tokens); i++ {
        ts, te := tokenToNfa(&tokens[i])
        end.transitions[epsilonChar] = append(
            end.transitions[epsilonChar],
            ts,
        )
        end = te
    }

تکرار

از میان همه نمونه‌های پوشش‌داده‌شده، فهم تکرار شاید سخت‌ترین باشد؛ قدم‌به‌قدم می‌رویم و سعی می‌کنیم راه‌حل عمومی‌ای پیدا کنیم که همه حالت‌های تکرار را پوشش دهد. در همه مثال‌های پیش‌رو، A هر NFA دلخواه است.

با ستاره (بستن کلین)، بعلاوه و علامت سوال (اختیاری) شروع می‌کنیم. در هر سه مثال حداقل و حداکثر رخدادهای متناظر هم مشخص شده.

  • هر مثال انتقال اپسیلون از حالت شروع به شروع A و از پایان A به حالت پایان دارد؛ یعنی تکرار دقیقاً یک‌بار NFA A.
  • * یعنی A را می‌توان نادیده گرفت یا هر تعداد بار تکرار کرد: برای نادیده‌گرفتن، انتقال اپسیلون مستقیم از حالت شروع به حالت پایان اضافه شده (عبور کامل از A)؛ برای تکرار بی‌نهایت، انتقال اپسیلون از حالت پایان به شروع A.
  • + یعنی حداقل یک‌بار تکرار و بدون سقف: برای برآوردن حداقل یک، انتقال اپسیلون را از مثال * حذف می‌کنیم؛ حالا راهی برای دور زدن A نیست.
  • ? یعنی یا نادیده‌گرفتن یا دقیقاً یک‌بار: خیلی شبیه * است و فقط انتقال اپسیلون از حالت پایان به شروع A حذف شده.

نکات:

  1. اگر حداقل صفر است، انتقال اپسیلون از حالت شروع به حالت پایان اضافه کن.
  2. اگر حداکثر بی‌نهایت است، انتقال اپسیلون از حالت پایان به شروع A اضافه کن.

حالا حالت تعداد تکرار دقیق:

به‌سادگی همان NFA A را m بار الحاق می‌کنیم.

اگر حداقل مشخص باشد اما سقف بی‌نهایت:

باز هم NFA A را m بار الحاق می‌کنیم چون حداقل تعداد تکرار است؛ اما انتقال اپسیلون از حالت پایان به شروع آخرین نمونه A هم اضافه می‌کنیم.

حالت پایانی: هم حداقل و هم حداکثر مشخص و حداکثر بی‌نهایت نیست:

A باید m بار تکرار شود، پس آن را m بار الحاق می‌کنیم. (n-m) تکرار باقی‌مانده کاملاً اختیاری است؛ پس از رسیدن به حداقل، باید بتوانیم به حالت پایان برویم. برای پایان زودهنگام، از حالت شروع هر نمونه A یک انتقال اپسیلون به حالت پایان اضافه می‌کنیم.

حالا ببینیم چگونه کدنویسی شده:

gocase repeat:
    p := t.value.(repeatPayload)
    if p.min == 0 { // <1>
        start.transitions[epsilonChar] = []*state{end}
    }
    var copyCount int // <2>
    if p.max == repeatInfinity {
        if p.min == 0 {
            copyCount = 1
        } else {
            copyCount = p.min
        }
    } else {
        copyCount = p.max
    }
    from, to := tokenToNfa(&p.token) // <3>
    start.transitions[epsilonChar] = append( // <4>
        start.transitions[epsilonChar],
        from,
    )

    for i := 2; i <= copyCount; i++ { // <5>
        s, e := tokenToNfa(&p.token)
        // پایان قبلی را به شروع این یکی وصل کن
        to.transitions[epsilonChar] = append( // <6>
            to.transitions[epsilonChar],
            s,
        )

        // حالت‌های ورود و خروج NFA قبلی را دنبال کن
        from = s // <7>
        to = e   // <7>
        // بعد از حداقل تکرارهای لازم
        // بقیه باید اختیاری باشند؛ پس به شروع
        // هر NFA انتقال اپسیلون اضافه کن
        // تا در صورت نیاز نادیده گرفته شوند
        if i > p.min { // <8>
            s.transitions[epsilonChar] = append(
                s.transitions[epsilonChar],
                end,
            )
        }
    }
    to.transitions[epsilonChar] = append( // <9>
        to.transitions[epsilonChar],
        end,
    )

    if p.max == repeatInfinity { // <10>
        end.transitions[epsilonChar] = append(
            end.transitions[epsilonChar],
            from,
        )
    }
  1. اگر حداقل صفر است، انتقال اپسیلون از حالت شروع به حالت پایان لازم است.
  2. copyCount حداکثر تعداد دفعاتی است که باید از p.token NFA بسازیم: اگر سقف بی‌نهایت و حداقل صفر باشد، ۱ است چون حداقل یک نسخه لازم است؛ اگر سقف بی‌نهایت و حداقل غیرصفر باشد، مقدار min (حداقل p.min بار لازم است)؛ اگر سقف بی‌نهایت نباشد، مقدار max.
  3. مثل گروه، باید چند NFA الحاق کنیم؛ پس با ساخت اولین نسخه شروع می‌کنیم.
  4. حالت شروع به شروع این NFA جدید وصل می‌شود.
  5. بقیه تکرارها را پیمایش می‌کنیم.
  6. گام واقعی الحاق؛ جایی که پایان NFA قبلی به شروع NFA فعلی وصل می‌شود.
  7. شروع و پایان NFA فعلی را ذخیره می‌کنیم.
  8. بعد از ساخت حداقل تعداد NFAهای لازم، بقیه باید اختیاری باشند؛ پس از شروع هر NFA اختیاری، انتقال اپسیلون به حالت پایان اضافه می‌کنیم.
  9. پایان آخرین NFA را به حالت پایان وصل کن.
  10. اگر سقف بی‌نهایت است، انتقال اپسیلون از حالت پایان به شروع آخرین NFA اضافه کن.

مطابقت

قطعه پایانی موتور regex ما منطق مطابقت است. ایده پایه: هر کاراکتر رشته آزمون را به ترتیب به حالت فعلی NFA می‌دهیم تا به پایان رشته برسیم. اگر کل رشته تمام شد و در حالت پایانی بودیم، یعنی رشته با regex مطابقت دارد.

در حین پیمایش رشته از یک نشانگر/مکان‌نما به موقعیت خاصی در رشته استفاده می‌کنیم. علاوه بر هر اندیس از رشته، نشانگر ما می‌تواند به آغاز رشته (پیش از مطابقت) و پایان رشته (بعد از مصرف همه کاراکترها) هم اشاره کند.

در کد این ثابت‌ها و متد کمکی را داریم:

goconst (
    startOfText uint8 = 1
    endOfText   uint8 = 2
)
func getChar(input string, pos int) uint8 {
    if pos >= len(input) {
        return endOfText
    }
    if pos < 0 {
        return startOfText
    }
    return input[pos]
}

و کد مطابقت:

gofunc (s *state) check(input string, pos int) bool { // <1>
    ch := getChar(input, pos) // <2>
    if ch == endOfText && s.terminal { // <3>
        return true
    }
    if states := s.transitions[ch]; len(states) > 0 { // <4>
        nextState := states[0]
        if nextState.check(input, pos+1) { // <5>
            return true
        }
    }
    for _, state := range s.transitions[epsilonChar] { // <6>
        if state.check(input, pos) { // <7>
            return true
        }
        if ch == startOfText && state.check(input, pos+1) { // <8>
            return true
        }
    }
    return false // <9>
}
  1. (s *state) فقط راهی برای افزودن تابع به ساختار state در گولنگ است؛ ربطی به الگوریتم ندارد.
  2. کاراکتر فعلی مورد بررسی را می‌گیریم؛ یا کاراکتر معتبر از رشته است، یا startOfText یا endOfText.
  3. اگر در پایان رشته و در حالت پایانی باشیم، یعنی مطابقت دارد؛ true برمی‌گردانیم.
  4. برای کاراکتر فعلی بررسی می‌کنیم آیا انتقالی مشخص شده.
  5. اگر انتقال وجود داشت، حالت بعدی را می‌گیریم، نشانگر را یک‌قدم جلو می‌بریم و بررسی می‌کنیم. اگر موفق بود true برمی‌گردانیم.
  6. اگر انتقال کاراکتری نبود، انتقال‌های خالی/اپسیلون را بررسی می‌کنیم.
  7. برای همه این انتقال‌ها حالت بعدی را با همان ورودی و موقعیت می‌آزماییم؛ چون انتقال خالی است نیازی به افزایش موقعیت نیست.
  8. احتمال دارد در شروع متن گیر کنیم و هیچ‌وقت پیشرفت نکنیم؛ این شرط جلوی آن را می‌گیرد.
  9. اگر هیچ‌چیز مطابقت نکرد، شکست است و false برمی‌گردانیم.
