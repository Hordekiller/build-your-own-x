نوشتن یک فریم‌ورک MiniTest

⚙ زبان: Nim ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور «Day 8: MiniTest» از سری NimDays است که یک فریم‌ورک تست کوچک با قدرت ماکروهای Nim می‌سازد.
↗ مشاهده منبع اصلی

یک فریم‌ورک تست چه اجزایی دارد؟

حداقل اجزای هر فریم‌ورک تست: ثبت‌نام تست‌ها، اجرای هر تست به‌صورت ایزوله، مقایسهٔ انتظار با نتیجه (assertion)، خلاصهٔ نتایج و خروجی غیرصفر در صورت شکست. فریم‌ورک‌های پیشرفته‌تر fixture (برپایی/مصرف) و suite دارند.

در این آموزش، یک MiniTest در Nim می‌سازیم که سینتکسی شبیه RSpec دارد — با کمک macroها.

وضعیت توصیفی با ماکرو

ایدهٔ اصلی: یک ماکرو `describe` بلوک‌های تست را جمع می‌کند و هنگام اجرا، فقط تست‌هایی که نامشان از خط فرمان آمده اجرا می‌شوند. هر تست یک closure ساده است:

Nimimport macros

# ثبت تست ها: آرایه‌ای از نام + بدنه
var tests: seq[(string, proc())]

macro describe(name: static[string], body: untyped): untyped =
  # کارهای ماکرو: جمع کردن تست‌ها با AST
  result = newStmtList()
  for child in body:
    if child.kind == nnkCall and child[0].repr == "test":
      let testName = child[1].repr
      let body = child[2].repr
      # ... تولید کد ثبت تست

describe "محاسبات ریاضی":
  test "جمع ساده":
    check(1 + 1 == 2)
  test "ضرب":
    check(2 * 3 == 6)

ماکروهای Nim AST را در زمان کامپایل می‌بینند؛ به همین دلیل می‌توانیم «زبان‌هایی روی زبان» (DSL) بسازیم بدون اینکه اجرای برنامه کند شود.

اجرا و گزارش

بخش اجرا تست‌ها را یکی‌یکی صدا می‌زند، خطاها را می‌گیرد و در پایان خلاصه می‌دهد:

Nimvar passed = 0
var failed = 0

for (name, body) in tests:
  try:
    body()
    passed.inc
    echo "✓ ", name
  except CatchableError as e:
    failed.inc
    echo "✗ ", name, " — ", e.msg
    echo "  ", getCurrentException().trace

echo ""
echo passed, " قبول، ", failed, " شکست"
if failed > 0:
  quit(1)   # برای CI مهم است!

همان `quit(1)` است که در پایپ‌لاین‌های CI کار ابزارهایی مثل pytest را تحقق می‌بخشد: شاید هیچ کلمه‌ای چاپ نشود ولی خروجی صفر/غیرصفر همه‌چیز را می‌گوید.

جمع‌بندی

شگفت‌انگیز است که با حدود ۵۰ خط کد، یک فریم‌ورک تست داستانی (describe/it) ساخته‌اید. دفعهٔ بعد که از RSpec یا Jest استفاده می‌کنید، می‌دانید پشت صحنه چه خبر است — و Nim این را با ماکروها تر و تمیز نشان می‌دهد.
