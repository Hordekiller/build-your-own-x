بیت‌تورنت (BitTorrent) چیست؟

بیت‌تورنت یک پروتکل به‌اشتراک‌گذاری فایل همتا‌به‌همتا (peer-to-peer) است. این پروتکل به کاربران امکان می‌دهد بدون وجود هیچ سرور مرکزی به‌عنوان واسطه، فایل‌ها را به‌طور مستقیم در اینترنت با یکدیگر به اشتراک بگذارند.

برای این منظور، فایل‌ها به قطعات کوچک با اندازه یکسان تقسیم می‌شوند. هر کلاینت یا همتا در شبکه می‌تواند یا یک قطعه را درخواست کند (اگر آن را ندارد) یا یک قطعه را ارسال کند (اگر همتای دیگری آن را درخواست کند). همتاها می‌توانند همزمان از چند همتای دیگر قطعه بگیرند و بفرستند تا وقتی همه همتاها فایل کامل را داشته باشند. به همتایی که قطعاتی برای ارسال دارد «seeder» (بذرپاش) و به همتایی که هنوز در حال درخواست قطعه است «leecher» (دانه‌خوار) گفته می‌شود.

نبودِ یک سرور مرکزی به این معناست که هزینه پهنای باندِ به‌اشتراک‌گذاری محتوا برای تولیدکننده اولیه کاهش می‌یابد. در ابتدا تنها یک seeder وجود خواهد داشت؛ اما به محض اینکه همتاهای دیگر فایل‌ها را دریافت کنند، آن‌ها نیز seeder می‌شوند. این پروتکل به محتوای پرطرفدارتر تمایل دارد: هرچه همتاهای بیشتری فایلی را بخواهند، همتاهای بیشتری هم آن فایل را برای به‌اشتراک‌گذاری خواهند داشت؛ عرضه با تقاضا رشد می‌کند. از این نظر این روش مقاوم‌تر نیز هست، چون شبکه در برابر خرابی یک سیستم مقاوم می‌شود و وقتی چندین seeder وجود داشته باشد، هیچ نقطه شکست واحدی ندارد.

محتوای کم‌طرفدار اگر تنها تعداد کمی seeder داشته باشد، دانلودش دشوار یا کند خواهد بود. فایل‌های کوچک نیز ممکن است کندتر از سرور سنتی دانلود شوند، چون سربار زمانی مشخصی برای پیدا کردن همتاها وجود دارد. نبودِ سرور مرکزی همچنین می‌تواند به وضعیتی منجر شود که تقریباً همه همتاهای شبکه کامل باشند اما همه یک قطعه یکسان را نداشته باشند (البته این حالت به دلیل الگوریتم‌های انتخاب قطعه برای درخواست، باید نادر باشد).

تاریخچه

شبکه‌های همتا‌به‌همتا با ایجاد نپستر (Napster) در سال ۱۹۹۹ توسط شان فنینگ (Shawn Fanning) فراگیر شدند. نپستر یک فهرست متمرکز از فایل‌های انتخاب‌شده روی رایانه هر کاربر نگهداری می‌کرد و سپس به کاربران اجازه می‌داد فایل‌ها را جستجو کرده و مستقیم از یکدیگر دانلود کنند.

پروتکل بیت‌تورنت در سال ۲۰۰۱ توسط برام کوهن (Bram Cohen) ساخته شد و بهبودهای متعددی نسبت به سیستم نپستر داشت. فهرست متمرکز واحد فایل‌ها را حذف کرد و آن را با فهرست‌هایی جایگزین نمود که هر کسی می‌توانست میزبان آن‌ها باشد (به‌نام «tracker»). همچنین فایل‌ها را به قطعاتی تقسیم کرد که هر کدام می‌توانست از کلاینت‌های مختلف دانلود شود، به‌جای اینکه کل فایل از یک همتای واحد گرفته شود (قطعات ترکیب‌شده با استفاده از هش‌ها اعتبارسنجی می‌شوند). بهبودهای بعدی پروتکل نیاز به tracker را کاملاً حذف کرده‌اند.

مانند نپستر، بیت‌تورنت نیز به‌شدت برای به‌اشتراک‌گذاری غیرقانونی فایل استفاده شد و هر دو مفهوم حقوقی منفی دارند. اما برخلاف نپستر، نبودِ یک مرجع متمرکز باعث شده است در برابر تعطیل شدن بسیار مقاوم‌تر باشد.

امروزه این پروتکل همچنان برای به‌اشتراک‌گذاری فایل میان کاربران عادی و همچنین برای تحویل محتوا استفاده می‌شود (پروژه‌های مختلف نرم‌افزار متن‌باز و همچنین بازی‌ها) و نیز برای توزیع داخلی کد جدید به سرورها (فیسبوک و توییتر). دیگر سیستم‌های پرطرفداری که از شبکه‌های همتا‌به‌همتا استفاده می‌کنند عبارت‌اند از ارزهای دیجیتال مختلف (بیت‌کوین، اتریوم) و بازارهای غیرمتمرکز (OpenBazaar).

اجزاء

مشخصات اولیه پروتکل تعدادی مؤلفه را شرح می‌داد:

  • فایل تورنت: فایل کوچک و ساده‌ای که ابرداده‌های پایه درباره یک فایل واحد یا گروهی از فایل‌های موجود در تورنت را نگه می‌دارد. مشخص می‌کند فایل چگونه باید به قطعات تقسیم شود و همچنین کدام trackerها این تورنت را ردیابی می‌کنند.
  • یک ترکر (tracker): سرور متمرکزی که فهرستی از تورنت‌ها را به همراه فهرست متناظر همتاها برای هر یک نگهداری می‌کند. معروف‌ترین نمونه، The Pirate Bay است.
  • کلاینت: برنامه‌ای که می‌تواند فایل‌های تورنت جدید بسازد یا فایل‌های موجود را باز کند. به trackerهای مشخص‌شده متصل می‌شود و شروع به ارسال یا دریافت بخش‌هایی از فایل می‌کند. چند نمونه: Vuze، Transmission، uTorrent و Deluge.

افزوده‌های اخیر به پروتکل به این معناست که دیگر نه فایل تورنت لازم است و نه tracker — نتیجه‌اش حذف کامل هرگونه تمرکز است.

محدوده

هدف این پروژه، درک بهتر جزئیات فنی پروتکل بیت‌تورنت بود. از نظر عمق تحقیق، دوست دارم به نقطه‌ای برسم که ایده خوبی از آنچه نمی‌دانم داشته باشم. بیت‌تورنت در واقع موضوع فوق‌العاده‌ای است چون حوزه‌های مختلفی را پوشش می‌دهد: HTTP، TCP، کدگذاری سفارشی، هش‌کردن رمزنگاری، ورودی/خروجی فایل و (اختیاری) چندنخی بودن. از C# استفاده کردم چون زبانی است که بیشتر از همه با آن آشنا هستم. اساساً نسخه 1.0 پروتکل را ساختم؛ هرچند پیش از آنکه بتوان در دنیای واقعی آزمایشش کرد، افزودنی‌های بیشتری لازم است (بخش «تحقیقات بیشتر» را ببینید).

  • اعداد صحیح: i32768e — با i شروع و به e ختم می‌شوند. چون می‌توانند تعداد بایت‌های یک فایل را نمایش دهند و برخی فایل‌ها بزرگ‌تر از 2.14 گیگابایت هستند، این‌ها را به‌صورت long ذخیره می‌کنیم.
  • دیکشنری‌ها: d3:key5:valuee — با d شروع و به e ختم می‌شوند و فهرستی از کلیدها و مقادیر متناوب دارند. همه کلیدها باید رشته‌های UTF-8 معتبر باشند. دیکشنری باید بر اساس کلید مرتب شود (بایت‌های خام UTF-8). آن‌ها را به‌صورت Dictionary<string,object> ذخیره می‌کنیم. دیکشنری‌ها در C# قابل مرتب‌سازی نیستند، پس تنها هنگام ذخیره در فایل، کلیدها را مرتب می‌کنیم.

رمزگشایی

متد Decode() ما یک آرایه بایت می‌گیرد. قرار است آن را یک‌بایت‌-یک‌بایت تجزیه کنیم، پس یک iterator می‌سازیم و آن را به اولین بایت می‌بریم. سپس DecodeNextObject() را صدا می‌زنیم که نوع شیء بعدی را ارزیابی می‌کند و تابع رمزگشایی مربوطه را فراخوانی می‌کند. این بخش را در یک تابع جدا کرده‌ایم تا بتوانیم اشیاء داخل لیست‌ها یا دیکشنری‌های تودرتو را به‌صورت بازگشتی پردازش کنیم.

cs
using System;
using System.Text;
using System.Linq;
using System.Collections.Generic;
using System.IO;

namespace BitTorrent
{
    public static class BEncoding
    {
        private static byte DictionaryStart  = System.Text.Encoding.UTF8.GetBytes("d")[0]; // عدد ASCII کاراکتر «d» (۱۰۰)
        private static byte DictionaryEnd    = System.Text.Encoding.UTF8.GetBytes("e")[0]; // عدد ASCII کاراکتر «e» (۱۰۱)
        private static byte ListStart        = System.Text.Encoding.UTF8.GetBytes("l")[0]; // عدد ASCII کاراکتر «l» (۱۰۸)
        private static byte ListEnd          = System.Text.Encoding.UTF8.GetBytes("e")[0]; // عدد ASCII کاراکتر «e» (۱۰۱)
        private static byte NumberStart      = System.Text.Encoding.UTF8.GetBytes("i")[0]; // عدد ASCII کاراکتر «i» (۱۰۵)
        private static byte NumberEnd        = System.Text.Encoding.UTF8.GetBytes("e")[0]; // عدد ASCII کاراکتر «e» (۱۰۱)
        private static byte ByteArrayDivider = System.Text.Encoding.UTF8.GetBytes(":")[0]; // عدد ASCII کاراکتر «:» (۵۸)

        public static object Decode(byte[] bytes)
        {
            IEnumerator<byte> enumerator = ((IEnumerable<byte>)bytes).GetEnumerator();
            enumerator.MoveNext();

            return DecodeNextObject(enumerator);
        }
        private static object DecodeNextObject(IEnumerator<byte> enumerator)
        {
            if (enumerator.Current == DictionaryStart)
                return DecodeDictionary(enumerator);            

            if (enumerator.Current == ListStart)
                return DecodeList(enumerator);            

            if (enumerator.Current == NumberStart)                       
                return DecodeNumber(enumerator);

            return DecodeByteArray(enumerator);
        }
    }
}

همچنین یک متد برای رمزگشایی یک فایل (مثل فایل تورنت) می‌سازیم.

cs
public static object DecodeFile(string path)
{
    if (!File.Exists(path))
        throw new FileNotFoundException("unable to find file: " + path);

    byte[] bytes = File.ReadAllBytes(path);

    return BEncoding.Decode(bytes);
}

اعداد (Numbers)

اگر بدانیم شیء بعدی یک عدد است، تا رسیدن به کاراکتری که پایان عدد را نشان می‌دهد (e) در آرایه جلو می‌رویم و در طول مسیر بایت‌ها را جمع می‌کنیم. سپس این بایت‌ها را به string و بعد string را به long تبدیل می‌کنیم. از long استفاده می‌کنیم چون برخی اعداد، تعداد بایت‌های یک فایل را نشان می‌دهند که می‌تواند بزرگ‌تر از حداکثر مقدار int باشد.

cs
private static long DecodeNumber(IEnumerator enumerator)
{
    List<byte> bytes = new List<byte>();

    // تا رسیدن به پرچم پایان، بایت‌ها را جمع می‌کنیم
    while (enumerator.MoveNext())
    {
        if (enumerator.Current == NumberEnd)
            break;
        
        bytes.Add(enumerator.Current);
    }

    string numAsString = Encoding.UTF8.GetString(bytes.ToArray());

    return Int64.Parse(numAsString);
}

رشته‌ها (Strings)

برای رشته‌ها (آرایه‌های بایت) باید دو بخش جداگانه را تجزیه کنیم: اول عددی که طول آرایه بایت را نشان می‌دهد و بعد خود بایت‌ها. پس اول تا رسیدن به کاراکتری که پایان عدد طول را نشان می‌دهد تکرار می‌کنیم. از حلقه do..while استفاده می‌کنیم چون به اولین کاراکتر نیاز داریم. سپس، همان‌طور که برای رمزگشایی اعداد انجام دادیم، بایت‌ها را به string و بعد string را به int تبدیل می‌کنیم تا طول را به‌دست آوریم. طول، تعداد بایت‌های آرایه را نشان می‌دهد؛ می‌توانیم در آرایه جلو برویم تا بایت‌های لازم را داشته باشیم.

cs
private static byte[] DecodeByteArray(IEnumerator<byte> enumerator)
{
    List<byte> lengthBytes = new List<byte>();

    // اسکن تا رسیدن به جداکننده
    do
    {
        if( enumerator.Current == ByteArrayDivider )
            break;

        lengthBytes.Add(enumerator.Current);
    }
    while (enumerator.MoveNext());

    string lengthString = System.Text.Encoding.UTF8.GetString(lengthBytes.ToArray());

    int length;
    if (!Int32.TryParse(lengthString, out length))
        throw new Exception("unable to parse length of byte array");

    // حالا خود آرایه بایت را می‌خوانیم
    byte[] bytes = new byte[length];

    for (int i = 0; i < length; i++)
    {
        enumerator.MoveNext();
        bytes[i] = enumerator.Current;
    }

    return bytes;
}

لیست‌ها (Lists)

برای لیست‌ها کافی است تا رسیدن به کاراکتر پایان، شیء بعدی را برداریم. نیازی به دانستن نوع اشیاء داخل لیست نیست؛ فقط می‌خوریمشان. مشخصات تعیین نمی‌کند که همه آیتم‌ها باید یک نوع باشند و در پیاده‌سازی ما هم بررسی نمی‌کنیم.

cs
private static List<object> DecodeList(IEnumerator<byte> enumerator)
{
    List<object> list = new List<object>();

    // تا رسیدن به پرچم پایان، اشیاء را رمزگشایی می‌کنیم
    while (enumerator.MoveNext())
    {
        if( enumerator.Current == ListEnd )
            break;

        list.Add(DecodeNextObject(enumerator));
    }

    return list;
}

دیکشنری‌ها (Dictionaries)

دیکشنری‌ها تقریباً به همان شکل مدیریت می‌شوند؛ تنها تفاوتش این است که هر بار دو شیء برمی‌داریم (یک کلید و یک مقدار) و آن‌ها را در دیکشنری می‌گذاریم. کلیدها باید رشته‌های UTF-8 معتبر باشند.

آیتم‌های دیکشنری باید بر اساس بایت‌های خام UTF-8 کلید مرتب شوند. مهم است که دوباره بررسی کنیم دیکشنری ورودی درست مرتب شده است، چون بعداً باید فرایند رمزگشایی را معکوس کنیم و خروجی‌ای یکسان با ورودی تولید کنیم. اگر دیکشنری ورودی درست مرتب نشده باشد، اطلاعات مرتب‌سازی (نادرست) را از دست می‌دهیم و در نتیجه قادر به انجام این کار نخواهیم بود.

cs
private static Dictionary<string,object> DecodeDictionary(IEnumerator<byte> enumerator)
{            
    Dictionary<string,object> dict = new Dictionary<string,object>();
    List<string> keys = new List<string>();

    // تا رسیدن به پرچم پایان، اشیاء را رمزگشایی می‌کنیم
    while (enumerator.MoveNext())
    {
        if( enumerator.Current == DictionaryEnd )
            break;

        // همه کلیدها رشته‌های UTF8 معتبر هستند
        string key = Encoding.UTF8.GetString(DecodeByteArray(enumerator));
        enumerator.MoveNext();
        object val = DecodeNextObject(enumerator);

        keys.Add(key);
        dict.Add(key, val);
    }

    // بررسی می‌کنیم دیکشنری ورودی درست مرتب شده است
    // در غیر این صورت نمی‌توانیم کدگذاری یکسانی تولید کنیم
    var sortedKeys = keys.OrderBy(x => BitConverter.ToString(Encoding.UTF8.GetBytes(x)));
    if (!keys.SequenceEqual(sortedKeys))
        throw new Exception("error loading dictionary: keys not sorted");

    return dict;
}

رمزگذاری

حالا این فرایند را معکوس می‌کنیم تا بتوانیم از ساختارهای C# خروجی BEncoded بسازیم. برای تولید آرایه بایت از یک MemoryStream استفاده می‌کنیم. از متدی به نام EncodeNextObject() استفاده می‌کنیم که نوع شیء فعلی را شناسایی و متد کدگذاری مربوطه را صدا می‌زند؛ این به ما امکان رمزگذاری بازگشتی می‌دهد.

cs
public static byte[] Encode(object obj)
{
    MemoryStream buffer = new MemoryStream();

    EncodeNextObject(buffer, obj);

    return buffer.ToArray();
}

public static void EncodeToFile(object obj, string path)
{
    File.WriteAllBytes(path, Encode(obj));
}

private static void EncodeNextObject(MemoryStream buffer, object obj)
{
    if (obj is byte[])                
        EncodeByteArray(buffer, (byte[])obj);
    else if (obj is string)
        EncodeString(buffer, (string)obj);
    else if (obj is long)
        EncodeNumber(buffer, (long)obj);
    else if (obj.GetType() == typeof(List<object>))
        EncodeList(buffer, (List<object>)obj);
    else if (obj.GetType() == typeof(Dictionary<string,object>))
        EncodeDictionary(buffer, (Dictionary<string,object>)obj);
    else
        throw new Exception("unable to encode type " + obj.GetType());
}

private static void EncodeDictionary(MemoryStream buffer, Dictionary<string,object> input)

}

قطعه‌ها و بلاک‌ها

فایل‌های موجود در تورنت در یک لیست قرار می‌گیرند و سپس به تکه‌های هم‌اندازه به نام «قطعه» (piece) تقسیم می‌شوند (به‌جز احتمالاً آخرین قطعه). یکپارچگی هر قطعه با هش SHA1 بایت‌های آن قطعه (که در فایل تورنت یافت می‌شود) قابل اعتبارسنجی است.

بلاک‌ها واحدهای کوچک‌تری نسبت به قطعه‌ها هستند. قطعه‌ها ممکن است برای انتقال میان همتاها خیلی بزرگ باشند، پس این تکه‌های کوچک‌تر داده‌اند که واقعاً منتقل می‌شوند. هیچ اندازه مشخصی برای بلاک تعیین نشده است؛ پس ممکن است کلاینت ما از اندازه‌ای متفاوت با یک همتا استفاده کند. مهم نیست اندازه متفاوتی داشته باشیم، چون بلاک‌ها با ایندکس قطعه، یک offset بایتی و یک طول درخواست می‌شوند. بلاک‌ها تنها وقتی می‌توانند درخواست یا ارسال شوند که کل قطعه اعتبارسنجی شده باشد و مشخصاً یک قطعه فقط وقتی قابل اعتبارسنجی است که همه بلاک‌های داخل آن به‌طور کامل به‌دست آمده باشند.

خواندن و نوشتن

همان‌طور که در نمودار زیر می‌بینید، بلاک‌ها و قطعه‌ها اهمیتی نمی‌دهند که یک فایل کجا تمام می‌شود و فایل بعدی کجا شروع می‌شود — هر تعداد فایل می‌تواند داخل یک قطعه قرار بگیرد.

cs
public byte[] Read(long start, int length)
{
    long end = start + length;
    byte[] buffer = new byte[length];

    for (int i=0; i<Files.Count; i++)
    {                
        if ((start < Files[i].Offset && end < Files[i].Offset) ||
            (start > Files[i].Offset + Files[i].Size && end > Files[i].Offset + Files[i].Size))
            continue;

        string filePath = DownloadDirectory + Path.DirectorySeparatorChar + FileDirectory + Files[i].Path;

        if (!File.Exists(filePath))
            return null;

        long fstart = Math.Max(0, start - Files[i].Offset);
        long fend = Math.Min(end - Files[i].Offset, Files[i].Size);
        int flength = Convert.ToInt32(fend - fstart);
        int bstart = Math.Max(0, Convert.ToInt32(Files[i].Offset - start));

        using (Stream stream = new FileStream(filePath, FileMode.Open, FileAccess.Read, FileShare.ReadWrite))
        {                    
            stream.Seek(fstart, SeekOrigin.Begin);
            stream.Read(buffer, bstart, flength);
        }
    }

    return buffer;
}

public void Write(long start, byte[] bytes)
{
    long end = start + bytes.Length;

    for (int i = 0; i < Files.Count; i++)
    {                
        if ((start < Files[i].Offset && end < Files[i].Offset) ||
            (start > Files[i].Offset + Files[i].Size && end > Files[i].Offset + Files[i].Size))
            continue;

        string filePath = DownloadDirectory + Path.DirectorySeparatorChar + FileDirectory + Files[i].Path;

        string dir = Path.GetDirectoryName(filePath);
        if (!Directory.Exists(dir))
            Directory.CreateDirectory(dir);

        lock (fileWriteLocks[i])
        {
            using (Stream stream = new FileStream(filePath, FileMode.OpenOrCreate, FileAccess.ReadWrite))
            {
                long fstart = Math.Max(0, start - Files[i].Offset);
                long fend = Math.Min(end - Files[i].Offset, Files[i].Size);
                int flength = Convert.ToInt32(fend - fstart);
                int bstart = Math.Max(0, Convert.ToInt32(Files[i].Offset - start));

                stream.Seek(fstart, SeekOrigin.Begin);
                stream.Write(bytes, bstart, flength);
            }
        }
    }
}

اعتبارسنجی

اعتبارسنجی هر قطعه نسبتاً ساده است. یک نکته مهم: اگر همه بلاک‌های یک قطعه را به‌دست آورده باشیم ولی اعتبارسنجی شکست بخورد، همه بلاک‌ها را بازنشانی می‌کنیم و دوباره سعی می‌کنیم آن‌ها را به‌دست آوریم (چون قطعاً یک بلاک اشتباه از یک همتا دریافت کرده‌ایم).

public event EventHandler<int> PieceVerified;
  
public void Verify(int piece)
{
    byte[] hash = GetHash(piece);

    bool isVerified = (hash != null && hash.SequenceEqual(PieceHashes[piece]));

    if (isVerified)
    {                
        IsPieceVerified[piece] = true;

        for (int j = 0; j < IsBlockAcquired[piece].Length; j++)
            IsBlockAcquired[piece][j] = true;

        var handler = PieceVerified;
        if (handler != null)
            handler(this, piece);

        return;
    }

    IsPieceVerified[piece] = false;

    // کل قطعه را از نو بارگذاری می‌کنیم
    if (IsBlockAcquired[piece].All(x => x))
    {
        for (int j = 0; j < IsBlockAcquired[piece].Length; j++)
            IsBlockAcquired[piece][j] = false;
    }
}

public byte[] GetHash(int piece)
{
    byte[] data = ReadPiece(piece);

    if (data == null)
        return null;            

    return sha1.ComputeHash(data);
}

{

    List<string> trackers = new List<string>();
    if (obj.ContainsKey("announce"))                
        trackers.Add(DecodeUTF8String(obj["announce"]));            

    if (!obj.ContainsKey("info"))
        throw new Exception("Missing info section");

    Dictionary<string,object> info = (Dictionary<string,object>)obj["info"];

    if (info == null)
        throw new Exception("error");

    List<FileItem> files = new List<FileItem>();

    if (info.ContainsKey("name") && info.ContainsKey("length"))
    {
        files.Add(new FileItem() {
            Path = DecodeUTF8String(info["name"]),
            Size = (long)info["length"]
        });
    }
    else if (info.ContainsKey("files"))
    {
        long running = 0;

        foreach (object item in (List<object>)info["files"])
        {
            var dict = item as Dictionary<string,object>;

            if (dict == null || !dict.ContainsKey("path") || !dict.ContainsKey("length") )
                throw new Exception("error: incorrect file specification");

            string path = String.Join(Path.DirectorySeparatorChar.ToString(), ((List<object>)dict["path"]).Select(x => DecodeUTF8String(x)));

            long size = (long)dict["length"];

            files.Add(new FileItem() {
                Path = path,
                Size = size,
                Offset = running
            });

            running += size;
        }
    }
    else
    {
        throw new Exception("error: no files specified in torrent");
    }
        
    if (!info.ContainsKey("piece length"))
        throw new Exception("error");
    int pieceSize = Convert.ToInt32(info["piece length"]);

    if (!info.ContainsKey("pieces"))
        throw new Exception("error");            
    byte[] pieceHashes = (byte[])info["pieces"];

    bool? isPrivate = null;
    if (info.ContainsKey("private"))
        isPrivate = ((long)info["private"]) == 1L;            
    
    Torrent torrent = new Torrent(name, downloadPath, files, trackers, pieceSize, pieceHashes, 16384, isPrivate );

    if (obj.ContainsKey("comment"))
        torrent.Comment = DecodeUTF8String(obj["comment"]);

    if (obj.ContainsKey("created by"))
        torrent.CreatedBy = DecodeUTF8String(obj["created by"]);

    if (obj.ContainsKey("creation date"))
        torrent.CreationDate = UnixTimeStampToDateTime(Convert.ToDouble(obj["creation date"]));

    if (obj.ContainsKey("encoding"))
        torrent.Encoding = Encoding.GetEncoding(DecodeUTF8String(obj["encoding"]));
    
    return torrent;
}

ترکرها (Trackers)

خب، وقتی همه اطلاعات تورنت آماده شد، چطور همتاهایی برای اتصال پیدا کنیم؟ به دو دلیل باید به tracker متصل شویم. اول اینکه فهرستی از همتاها به ما می‌دهد که می‌توانیم فوراً برای اتصال به آن‌ها تلاش کنیم. دوم اینکه ما را به فهرست همتاهایش اضافه می‌کند تا همتاهای جدید آینده بتوانند آدرس IP و شماره پورت ما را به‌دست آورند. همچنین پیشرفت فعلی دریافت فایل را به آن اطلاع می‌دهیم تا بتواند تعداد seederها و leecherها را برای اطلاع‌رسانی پیگیری کند.

اعلام (Announcing)

ابتدایی‌ترین نسخه یک tracker، سرور HTTP با یک endpoint است. tracker opentracker که به‌صورت محلی اجرا می‌کنیم از endpoint ی http://localhost:6969/announce استفاده می‌کند. چند پارامتر وجود دارد که باید به درخواست HTTP GET اضافه کنیم:

  • info_hash: infohash تورنت ما. هر بایت خامی که روی آدرس اثر می‌گذارد باید escape شود؛ ویژگی UrlSafeStringInfohash ما این را فراهم می‌کند.
  • peer_id: رشته ۲۰ بایتی برای شناسایی خودمان. بیشتر کلاینت‌ها از چند کاراکتر اول برای شناسایی برنامه و نسخه‌اش استفاده می‌کنند و بعد چند کاراکتر تصادفی. ما فقط از رشته‌ای از اعداد تصادفی استفاده می‌کنیم.
  • port: پورتی که برای اتصال‌های ورودی به آن گوش می‌دهیم.
  • uploaded: تعداد بایت‌هایی که به همتاهای دیگر فرستاده‌ایم.
  • downloaded: تعداد بایت‌های اعتبارسنجی‌شده‌ای که داریم.
  • left: تعداد بایت‌هایی که برای دانلود باقی مانده است.
  • event: وضعیت فعلی کلاینت: started، paused یا stopped. این‌ها به tracker می‌گویند ما را به فهرست همتاهایش اضافه یا از آن حذف کند.
  • compact: صفر یا یک، که نشان می‌دهد فهرست همتا به‌صورت فشرده (compact) برگردد یا نه. به نظر می‌رسد نرم‌افزار opentracker مورد استفاده ما فقط با حالت فشرده کار می‌کند.

{

                     id, port,

}

متد Request() درخواست واقعی HTTP را می‌سازد. متد HttpWebResponse.BeginGetResponse غیرهمزمان است، پس ترد را معلق نمی‌کند. فقط یک متد callback (به نام HandleResponse) تعیین می‌کنیم که وقتی tracker پاسخ داد صدا زده شود. پس از آن، byte[] برگشتی را می‌خوانیم و با BEncoding.Decode() پردازشش می‌کنیم. در پایان، فاصله درخواست و فهرست همتاها را تجزیه می‌کنیم و رویداد PeerListUpdated را صادر می‌کنیم.

private void Request( string url )
{
    httpWebRequest = (HttpWebRequest)HttpWebRequest.Create(url);
    httpWebRequest.BeginGetResponse(HandleResponse, null);
}

private void HandleResponse(IAsyncResult result)
{
    byte[] data;

    using (HttpWebResponse response = (HttpWebResponse)httpWebRequest.EndGetResponse(result))
    {
        if (response.StatusCode != HttpStatusCode.OK)
        {
            Console.WriteLine("error reaching tracker " + this + ": " + response.StatusCode + " " + response.StatusDescription);
            return;
        }
    
        using (Stream stream = response.GetResponseStream())
        {
            data = new byte[response.ContentLength];
            stream.Read(data, 0, Convert.ToInt32(response.ContentLength));
        }
    }

    Dictionary<string,object> info = BEncoding.Decode(data) as Dictionary<string,object>;

    if (info == null)
    {
        Console.WriteLine("unable to decode tracker announce response");
        return;
    }

    PeerRequestInterval = TimeSpan.FromSeconds((long)info["interval"]);
    byte[] peerInfo = (byte[])info["peers"];
        
    List<IPEndPoint> peers = new List<IPEndPoint>();
    for (int i = 0; i < peerInfo.Length/6; i++)
    {
        int offset = i * 6;
        string address = peerInfo[offset] + "." + peerInfo[offset+1] + "." + peerInfo[offset+2] + "." + peerInfo[offset+3];
        int port = EndianBitConverter.Big.ToChar(peerInfo, offset + 4);

        peers.Add(new IPEndPoint(IPAddress.Parse(address), port));
    }

    var handler = PeerListUpdated;
    if (handler != null)
        handler(this, peers);
}

در ابتدا هر دو طرف باید یک پیام دست‌دادن ارسال کنند. این پیام هرگونه توسعه (extension) پروتکلی که می‌توانند استفاده کنند را مشخص می‌کند و همچنین تأیید می‌کند که درباره همان تورنت صحبت می‌کنند.

پیشرفت (Progress)

بلافاصله بعد از دست‌دادن، هر دو طرف باید پیشرفت دانلود تورنت تا این‌جای کار را به یکدیگر اطلاع دهند. هر تغییر بعدی در پیشرفت نیز باید فوراً اعلام شود.

وضعیت (State)

همه همتاها با وضعیت «علاقه‌مند نبودن» (not interested) و «خفه» (choked) شروع می‌کنند. اگر همتایی بخواهد داده درخواست کند، به همتای دیگر اطلاع می‌دهد که «علاقه‌مند» (interested) است. اگر آن همتا مایل به پاسخ‌گویی به درخواست‌های داده باشد، اطلاع می‌دهد که «خفه نیست» (unchoked). همتاها از این پرچم‌های وضعیت برای محدود کردن تعداد seederها و leecherهایی که به آن‌ها متصل‌اند استفاده می‌کنند تا از ازدحام جلوگیری کنند و پهنای باند را مدیریت کنند.

داده (Data)

پس از unchoked شدن، یک همتا می‌تواند درخواست بلاک‌های داده را شروع کند و همتای دیگر با داده درخواستی پاسخ می‌دهد. برخی همتاها ممکن است همان بلاک را از چند همتا درخواست کنند؛ پس اگر قبلاً آن را دریافت کرده باشند، می‌توانند یک درخواست داده را لغو کنند.

private void HandleRead( IAsyncResult ar )
{            
    int bytes = 0;
    try
    {
        bytes = stream.EndRead(ar);
    }
    catch (Exception e)
    {
        Disconnect();
        return;
    }
       
    data.AddRange(streamBuffer.Take(bytes));

    int messageLength = GetMessageLength(data);
    while (data.Count >= messageLength)
    {
        HandleMessage(data.Take(messageLength).ToArray());
        data = data.Skip(messageLength).ToList();

        messageLength = GetMessageLength(data);
    }

    try
    {
        stream.BeginRead(streamBuffer, 0, Peer.bufferSize, new AsyncCallback(HandleRead), null);
    }
    catch (Exception e)
    {
        Disconnect();
    }
}

private int GetMessageLength(List<byte> data)
{
    if (!IsHandshakeReceived)
        return 68;

    if (data.Count < 4)
        return int.MaxValue;

    return EndianBitConverter.Big.ToInt32(data.ToArray(), 0) + 4;
}

دست‌دادن

اولین پیام دریافت‌شده از یک همتای جدید باید پیام دست‌دادن باشد. این پیام شامل پرچم‌هایی درباره ویژگی‌هایی است که همتا پشتیبانی می‌کند، شناسه کلاینت و تأیید infohash تورنت.

توجه کنید برخلاف همه پیام‌های دیگر، طول دست‌دادن به‌صورت یک بایت واحد تعریف شده است، نه int (۴ بایت)، و همیشه ۱۹ تنظیم می‌شود، حتی اگر پیام دست‌دادن ۶۸ بایت طول داشته باشد.

cs
public static bool DecodeHandshake(byte[] bytes, out byte[] hash, out string id)
{
    hash = new byte[20];
    id = "";

    if (bytes.Length != 68 || bytes[0] != 19)
    {
        Log.WriteLine("invalid handshake, must be of length 68 and first byte must equal 19");
        return false;
    }

    if (Encoding.UTF8.GetString(bytes.Skip(1).Take(19).ToArray()) != "BitTorrent protocol")
    {
        Log.WriteLine("invalid handshake, protocol must equal \"BitTorrent protocol\"");
        return false;
    }

    // پرچم‌ها
    //byte[] flags = bytes.Skip(20).Take(8).ToArray();

    hash = bytes.Skip(28).Take(20).ToArray();

    id = Encoding.UTF8.GetString(bytes.Skip(48).Take(20).ToArray());

    return true;
}

public static byte[] EncodeHandshake(byte[] hash, string id)
{
    byte[] message = new byte[68];
    message[0] = 19;
    Buffer.BlockCopy(Encoding.UTF8.GetBytes("BitTorrent protocol"), 0, message, 1, 19);
    Buffer.BlockCopy(hash,0, message, 28, 20);
    Buffer.BlockCopy(Encoding.UTF8.GetBytes(id), 0, message, 48, 20);

    return message;
}

پیشرفت

پیام have ایندکس قطعه‌ای را مشخص می‌کند که همتا اعلام می‌کند دانلود و اعتبارسنجی‌اش را تکمیل کرده است.

پیام bitfield راه سریعی برای اعلام پیشرفت همتاست و معمولاً درست بعد از دست‌دادن ارسال می‌شود. کمی سخت‌تر است. بعد از بایت نوع، هر بیت مشخص می‌کند که همتا قطعه‌ای را در آن ایندکس دانلود کرده است یا نه.

پس در مثال بالا، مقدار بایت ۲۰۰ است. اگر آن را به باینری تبدیل کنیم، به این می‌رسیم:

text
11001000

در این مثال خاص، همتا اعلام می‌کند اولین، دومین و پنجمین قطعه را دانلود کرده است. اگر تعداد قطعه‌ها بر ۸ بخش‌پذیر نباشد، انتهای bitfield با صفر پر می‌شود.

public static bool DecodeHave(byte[] bytes, out int index)
{
    index = -1;

    if (bytes.Length != 9 || EndianBitConverter.Big.ToInt32(bytes, 0) != 5)
    {
        Log.WriteLine("invalid have, first byte must equal 0x2");
        return false;
    }

    index = EndianBitConverter.Big.ToInt32(bytes, 5);

    return true;
}

public static bool DecodeBitfield(byte[] bytes, int pieces, out bool[] isPieceDownloaded)
{
    isPieceDownloaded = new bool[pieces];

    int expectedLength = Convert.ToInt32(Math.Ceiling(pieces / 8.0)) + 1;

    if (bytes.Length != expectedLength + 4 || EndianBitConverter.Big.ToInt32(bytes,0) != expectedLength)
    {
        Log.WriteLine("invalid bitfield, first byte must equal " + expectedLength);
        return false;
    }

    BitArray bitfield = new BitArray(bytes.Skip(5).ToArray());

    for (int i = 0; i < pieces; i++)
        isPieceDownloaded[i] = bitfield[bitfield.Length - 1 - i];

    return true;
}

public static byte[] EncodeHave(int index) 
{            
    byte[] message = new byte[9];
    Buffer.BlockCopy(EndianBitConverter.Big.GetBytes(5), 0, message, 0, 4);
    message[4] = (byte)MessageType.Have;
    Buffer.BlockCopy(EndianBitConverter.Big.GetBytes(index), 0, message, 5, 4);

    return message;
}

public static byte[] EncodeBitfield(bool[] isPieceDownloaded) 
{
    int numPieces = isPieceDownloaded.Length;
    int numBytes = Convert.ToInt32(Math.Ceiling(numPieces / 8.0));
    int numBits = numBytes * 8;

    int length = numBytes + 1;

    byte[] message = new byte[length + 4];
    Buffer.BlockCopy(EndianBitConverter.Big.GetBytes(length), 0, message, 0, 4);
    message[4] = (byte)MessageType.Bitfield;

    bool[] downloaded = new bool[numBits];
    for (int i = 0; i < numPieces; i++)
        downloaded[i] = isPieceDownloaded[i];

    BitArray bitfield = new BitArray(downloaded);
    BitArray reversed = new BitArray(numBits);
    for (int i = 0; i < numBits; i++)
        reversed[i] = bitfield[numBits - i - 1];

    reversed.CopyTo(message, 5);

    return message;
}

دریافت پیام‌ها

ابتدا می‌توانیم متدی بسازیم که byte[] ورودی ما را می‌گیرد و MessageType آن را برمی‌گرداند. بررسی می‌کنیم که پیام ورودی یکی از دو نوعی باشد که به‌صورت ضمنی اعلام نشده‌اند. پیام دست‌دادن باید اولین پیام دریافت‌شده از یک همتا باشد. دومی پیام keep-alive است که به سادگی یک پیام خالی است (یعنی هدر int طول روی ۰ تنظیم شده). در غیر این صورت، بایت بعد از int طول، یعنی بایت پنجم، نوع پیام را شناسایی می‌کند و می‌توانیم آن را به enum MessageType خودمان cast کنیم. اگر نتوانیم نوع پیام را تشخیص دهیم، آن را Unknown اعلام می‌کنیم.

cs
private MessageType GetMessageType(byte[] bytes)
{
    if (!IsHandshakeReceived)
        return MessageType.Handshake;

    if (bytes.Length == 4 && EndianBitConverter.Big.ToInt32(bytes, 0) == 0)
        return MessageType.KeepAlive;

    if (bytes.Length > 4 && Enum.IsDefined(typeof(MessageType), (int)bytes[4]))
        return (MessageType)bytes[4];

    return MessageType.Unknown;
}

اینجا بخش اصلی است. این متد پیام ورودی ما را می‌گیرد، نوعش را شناسایی، رمزگشایی و سپس به متد مدیریت‌کننده (handler) مناسب منتقل می‌کند. متوجه خواهید شد که اگر پیام از نوع ناشناس باشد، کافی است نادیده‌اش بگیریم — اگر روی آن exception بیندازیم، برنامه ما نمی‌تواند هیچ نوع پیام احتمالی آینده را مدیریت کند، حتی آن‌هایی که با نسخه‌های قبل سازگارند. برای توابع رمزگشایی از پارامترهای out استفاده می‌کنیم، چون بسیاری از پیام‌ها چند مقدار دارند و از این طریق می‌توانیم یک bool برگردانیم که نشان دهد پیام با موفقیت رمزگشایی شده یا نه. اگر هر پیامی با موفقیت رمزگشایی نشود، فوراً از آن همتا قطع می‌شویم.

cs
private void HandleMessage(byte[] bytes)
{
    LastActive = DateTime.UtcNow;

    MessageType type = GetMessageType(bytes);

    if (type == MessageType.Unknown)
    {
        return;   
    }
    else if (type == MessageType.Handshake)
    {
        byte[] hash;
        string id;
        if (DecodeHandshake(bytes, out hash, out id))
        {
            HandleHandshake(hash, id);
            return;
        }
    }
    else if (type == MessageType.KeepAlive && DecodeKeepAlive(bytes))
    {
        HandleKeepAlive();
        return;
    }
    else if (type == MessageType.Choke && DecodeChoke(bytes))
    {
        HandleChoke();
        return;
    }
    else if (type == MessageType.Unchoke && DecodeUnchoke(bytes))
    {
        HandleUnchoke();
        return;
    }
    else if (type == MessageType.Interested && DecodeInterested(bytes))
    {                
        HandleInterested();
        return;
    }
    else if (type == MessageType.NotInterested && DecodeNotInterested(bytes))
    {
        HandleNotInterested();
        return;
    }
    else if (type == MessageType.Have)
    {
        int index;
        if (DecodeHave(bytes, out index))
        {
            HandleHave(index);
            return;
        }                
    }
    else if (type == MessageType.Bitfield)
    {
        bool[] isPieceDownloaded;
        if (DecodeBitfield(bytes, IsPieceDownloaded.Length, out isPieceDownloaded))
        {
            HandleBitfield(isPieceDownloaded);
            return;
        }
    }
    else if (type == MessageType.Request)
    {
        int index;
        int begin;
        int length;
        if (DecodeRequest(bytes, out index, out begin, out length))
        {
            HandleRequest(index, begin, length);
            return;
        }
    }
    else if (type == MessageType.Piece)
    {
        int index;
        int begin;
        byte[] data;
        if (DecodePiece(bytes, out index, out begin, out data))
        {
            HandlePiece(index, begin, data);
            return;
        }
    }
    else if (type == MessageType.Cancel)
    {
        int index;
        int begin;
        int length;
        if (DecodeCancel(bytes, out index, out begin, out length))
        {
            HandleCancel(index, begin, length);
            return;
        }
    }
    else if (type == MessageType.Port)
    {
        Log.WriteLine(this, " <- port: " + String.Join("", bytes.Select(x => x.ToString("x2"))));
        return;
    }

    Log.WriteLine(this, " Unhandled incoming message " + String.Join("", bytes.Select(x => x.ToString("x2"))));
    Disconnect();
}

کلاینت (Client)

کلاینت پنج هدف اصلی دارد:

  • خواندن یک فایل تورنت.
  • درخواست فهرست همتا از trackerها و آگاه نگه‌داشتن آن‌ها از پیشرفت ما.
  • اتصال به همتاها و پذیرش اتصال‌های ورودی از همتاها. آن‌ها را از پیشرفت خود آگاه نگه می‌دارد.
  • انتخاب تعدادی leecher که اجازه می‌دهیم از ما داده درخواست کنند. درخواست‌های داده آن‌ها را پردازش می‌کنیم اما حجم داده آپلودشده را محدود می‌کنیم.
  • انتخاب تعدادی seeder برای درخواست داده (در صورت نیاز). وقتی ما را به‌عنوان leecher پذیرفتند، انتخاب می‌کنیم کدام بلاک‌ها را درخواست کنیم، درخواست‌های این بلاک‌ها را می‌فرستیم و هنگام دریافت، پردازششان می‌کنیم.

private TcpListener listener;
  
private void EnablePeerConnections()
{
    listener = new TcpListener(new IPEndPoint(IPAddress.Any, Port));

{
    if (listener == null)

    TcpClient client = listener.EndAcceptTcpClient(ar);
    listener.BeginAcceptTcpClient(new AsyncCallback(HandleNewConnection), null);

    AddPeer(new Peer(Torrent, Id, client));
}

متد ProcessPeers() وضعیت ما را با هر همتا به‌روز می‌کند و تصمیم می‌گیرد چه کسی برای leech شدن و چه کسی برای seed شدن انتخاب شود.

  • همتاهایی را که در یک بازه زمانی مشخص هیچ پیامی برایمان نفرستاده‌اند از بین می‌برد.
  • پرچم interested/not interested را بسته به اینکه دانلودمان تمام شده یا نه به‌روز می‌کند.
  • اگر هر دو تمام شده باشیم، قطع می‌کند، چون کاری برای انجام دادن نداریم.
  • در صورت نیاز پیام keep alive می‌فرستد.
  • seederها را تا رسیدن به maxSeeders انتخاب می‌کند. همتاها بر اساس تعداد قطعه‌هایی که دارند و ما همچنان به آن‌ها نیاز داریم مرتب می‌شوند. قبلاً اعلام کرده‌ایم که interested هستیم، پس اگر هرکدام ما را unchoke کند، به فهرست seederهایمان اضافه می‌شود.
  • leecherها را تا رسیدن به maxLeechers انتخاب می‌کند. اگر اعلام کرده‌اند که interested هستند، unchokeشان می‌کنیم. مرتب‌سازی همتاها احتمالاً برای انتخاب leecher منصفانه نیست.

این متد از Interlocked.Exchange استفاده می‌کند تا از اجرای هم‌زمان آن روی بیش از یک ترد جلوگیری شود.

cs
private void ProcessPeers()
{
    if (Interlocked.Exchange(ref isProcessPeers, 1) == 1)
        return;

    foreach (var peer in Peers.OrderByDescending(x => x.Value.PiecesRequiredAvailable))
    {
        if (DateTime.UtcNow > peer.Value.LastActive.Add(peerTimeout))
        {                    
            peer.Value.Disconnect();
            continue;
        }

        if (!peer.Value.IsHandshakeSent || !peer.Value.IsHandshakeReceived)
            continue;

        if (Torrent.IsCompleted)
            peer.Value.SendNotInterested();
        else
            peer.Value.SendInterested();

        if (peer.Value.IsCompleted && Torrent.IsCompleted)
        {
            peer.Value.Disconnect();
            continue;
        }

        peer.Value.SendKeepAlive();

        // بگذارید از ما leech کنند (داده بگیرند)
        if (Torrent.IsStarted && Leechers.Count < maxLeechers)
        {
            if (peer.Value.IsInterestedReceived && peer.Value.IsChokeSent)
                peer.Value.SendUnchoke();                
        }

        // درخواست leech کردن (داده گرفتن)
        if (!Torrent.IsCompleted && Seeders.Count <= maxSeeders)
        {
            if(!peer.Value.IsChokeReceived )
                Seeders.TryAdd(peer.Key, peer.Value);
        }
    }

    Interlocked.Exchange(ref isProcessPeers, 0);
}

محدودساز ترافیک (Throttle)

از یک کلاس بسیار ساده به نام Throttle استفاده می‌کنم تا کلاینت از محدودیت‌های پهنای باند تعیین‌شده عبور نکند. حداکثر تعداد بایت در یک بازه زمانی مشخص را تعیین می‌کنید. آیتم‌ها هنگام افزودن به فهرست timestamp می‌شوند و به محض اینکه دیگر در پنجره زمانی نباشند، از فهرست حذف می‌شوند. برای ایمنی ترد از lock استفاده می‌کنم. بررسی اینکه throttle شده‌ایم یا نه، بر عهده کاربر است. همچنین فقط وقتی محدودیت عبور می‌کند پرچم throttle شدن را می‌زند (به‌جای اینکه درست پیش از آنکه آیتمی باعث عبور از محدودیت شود).

cs
using System;
using System.Linq;
using System.Collections.Generic;

namespace BitTorrent
{
    public class Throttle
    {
        public long MaximumSize { get; private set; }
        public TimeSpan MaximumWindow { get; private set; }

        internal struct Item
        {
            public DateTime Time;
            public long Size;
        }

        private object itemLock = new object();
        private List<Item> items = new List<Item>();

        public Throttle(int maxSize, TimeSpan maxWindow)
        {
            MaximumSize = maxSize;
            MaximumWindow = maxWindow;
        }

        public void Add(long size)
        {
            lock (itemLock)
            {
                items.Add(new Item() { Time = DateTime.UtcNow, Size = size });
            }
        }

        public bool IsThrottled
        {
            get
            { 
                lock (itemLock)
                {
                    DateTime cutoff = DateTime.UtcNow.Add(-this.MaximumWindow);
                    items.RemoveAll(x => x.Time < cutoff);
                    return items.Sum(x => x.Size) >= MaximumSize;
                }
            }
        }
    }
}

آپلودها

درخواست‌های داده ورودی را در یک ConcurrentQueue<DataRequest> ذخیره می‌کنیم. چون نمی‌توانیم یک آیتم لغوشده را از هر جای صف حذف کنیم، آن را با پرچم IsCancelled علامت‌گذاری می‌کنیم تا هنگام پردازش نادیده‌اش بگیریم.

cs
private ConcurrentQueue<DataRequest> OutgoingBlocks = new ConcurrentQueue<DataRequest>();
  
private void HandleBlockRequested(object sender, DataRequest block)
{
    OutgoingBlocks.Enqueue(block);

    ProcessUploads();
}

private void HandleBlockCancelled(object sender, DataRequest block)
{
    foreach (var item in OutgoingBlocks)
    {
        if (item.Peer != block.Peer || item.Piece != block.Piece || item.Begin != block.Begin || item.Length != block.Length)
            continue;

        item.IsCancelled = true;
    }

    ProcessUploads();
}

پردازش صف خروجی یک حلقه while ساده است که آیتم‌ها را از بالای صف برمی‌دارد، بررسی می‌کند لغو نشده و ما آن قطعه را داریم، سپس آن را می‌خواند و می‌فرستد.

cs
private Throttle uploadThrottle = new Throttle(maxUploadBytesPerSecond, TimeSpan.FromSeconds(1));

private void ProcessUploads()
{
    if (Interlocked.Exchange(ref isProcessUploads, 1) == 1)
        return;

    DataRequest block;
    while (!uploadThrottle.IsThrottled && OutgoingBlocks.TryDequeue(out block))
    {
        if (block.IsCancelled)
            continue;

        if (!Torrent.IsPieceVerified[block.Piece])
            continue;            

        byte[] data = Torrent.ReadBlock(block.Piece, block.Begin, block.Length);
        if (data == null)
            continue;

        block.Peer.SendPiece(block.Piece, block.Begin, data);
        uploadThrottle.Add(block.Length);
        Torrent.Uploaded += block.Length;
    }

    Interlocked.Exchange(ref isProcessUploads, 0);
}

دانلودها

وقتی بلاک داده‌ای از یک همتا دریافت می‌کنیم، آن را برای پردازش به ConcurrentQueue<DataPackage> می‌فشاریم. همچنین هر درخواست دیگری برای همان بلاک از سایر همتاها را لغو می‌کنیم.

cs
private ConcurrentQueue<DataPackage> IncomingBlocks = new ConcurrentQueue<DataPackage>();
  
private void HandleBlockReceived(object sender, DataPackage args)
{
    IncomingBlocks.Enqueue(args);

    args.Peer.IsBlockRequested[args.Piece][args.Block] = false;

    foreach(var peer in Peers)
    {
        if (!peer.Value.IsBlockRequested[args.Piece][args.Block])
            continue;

        peer.Value.SendCancel(args.Piece, args.Block * Torrent.BlockSize, Torrent.BlockSize);
        peer.Value.IsBlockRequested[args.Piece][args.Block] = false;
    }

    ProcessDownloads();
}

متد ProcessDownloads() کمی طولانی‌تر از متد آپلود است. ابتدا روی صف ورودی حلقه می‌زنیم و هر داده ورودی را روی دیسک می‌نویسیم. اگر دانلود تمام شده باشد، به کار دیگری نیاز نداریم.

اگر تمام نشده باشیم، باید قطعه‌هایی را که می‌خواهیم درخواست کنیم رتبه‌بندی کنیم و بعد seederهایی را که از آن‌ها درخواست می‌کنیم رتبه‌بندی کنیم. در این نسخه، درخواست‌های خود را به یک درخواست در هر زمان برای هر کلاینت محدود می‌کنیم. همچنین هر قطعه را فقط از یک کلاینت درخواست می‌کنیم، نه چند کلاینت. بلاک‌های هر قطعه را به‌صورت ترتیبی درخواست می‌کنیم و درخواست‌هایمان محدود (throttle) می‌شوند.

cs
private Throttle downloadThrottle = new Throttle(maxDownloadBytesPerSecond, TimeSpan.FromSeconds(1));

private void ProcessDownloads()
{
    if (Interlocked.Exchange(ref isProcessDownloads, 1) == 1)
        return;

    DataPackage incomingBlock;
    while (IncomingBlocks.TryDequeue(out incomingBlock))
        Torrent.WriteBlock(incomingBlock.Piece, incomingBlock.Block, incomingBlock.Data);

    if (Torrent.IsCompleted)
    {
        Interlocked.Exchange(ref isProcessDownloads, 0);
        return;
    }

    int[] ranked = GetRankedPieces();

    foreach (var piece in ranked)
    {
        if (Torrent.IsPieceVerified[piece])
            continue;

        foreach (var peer in GetRankedSeeders())
        {
            if (!peer.IsPieceDownloaded[piece])
                continue;

            // فقط بلاک‌ها را به ترتیب درخواست می‌کنیم
            for (int block = 0; block < Torrent.GetBlockCount(piece); block++)
            {                        
                if (downloadThrottle.IsThrottled)
                    continue;

                if(Torrent.IsBlockAcquired[piece][block])
                    continue;

                // از هر همتا فقط یک بلاک در هر بار درخواست می‌کنیم
                if (peer.BlocksRequested > 0)
                    continue;

                // فقط از یک همتا در هر بار درخواست می‌کنیم
                if (Peers.Count(x => x.Value.IsBlockRequested[piece][block]) > 0)
                    continue;

                int size = Torrent.GetBlockSize(piece, block);
                peer.SendRequest(piece, block * Torrent.BlockSize, size);
                downloadThrottle.Add(size);
                peer.IsBlockRequested[piece][block] = true;
            }
        }
    }

    Interlocked.Exchange(ref isProcessDownloads, 0);
}

اول به متد رتبه‌بندی seeder نگاه می‌کنیم چون آسان‌تر است: کافی است seederهای انتخاب‌شده را به‌صورت تصادفی مرتب کنیم.

cs
private Peer[] GetRankedSeeders()
{
    return Seeders.Values.OrderBy(x => random.Next(0, 100)).ToArray();
}

هنگام تصمیم‌گیری درباره قطعه‌هایی که باید دانلود شوند، سه بخش اطلاعات را ترکیب می‌کنیم تا برای هر قطعه امتیازی بگیریم و سپس قطعه‌ها را بر اساس امتیازشان مرتب می‌کنیم. آن سه بخش اطلاعات عبارت‌اند از:

  • پیشرفت ما با آن قطعه، یعنی چند بلاک از قطعه را به‌دست آورده‌ایم. می‌خواهیم تکمیل قطعه‌های کامل را اولویت بدهیم تا بتوانیم آن‌ها را اعتبارسنجی و بعد seed کنیم.
  • نایابی (کمیابی) قطعه، یعنی چند همتا آن قطعه را دارند. می‌خواهیم قطعه‌های نایاب را اولویت بدهیم، چون ممکن است آن seederها قطع شوند.
  • یک مقدار تصادفی تا همه کلاینت‌ها اگر در همان سطح پیشرفت باشند، همان قطعه‌ها را درخواست نکنند.
cs
private int[] GetRankedPieces()
{
    var indexes = Enumerable.Range(0, Torrent.PieceCount).ToArray();
    var scores = indexes.Select(x => GetPieceScore(x)).ToArray();
        
    Array.Sort(scores, indexes);
    Array.Reverse(indexes);

    return indexes;
}

private double GetPieceScore(int piece)
{
    double progress = GetPieceProgress(piece);
    double rarity = GetPieceRarity(piece);

    if( progress == 1.0 )
        progress = 0;

    double rand = random.Next(0,100) / 1000.0;

    return progress + rarity + rand;
}

private double GetPieceProgress(int index)
{
    return Torrent.IsBlockAcquired[index].Average(x => x ? 1.0 : 0.0);
}

private double GetPieceRarity(int index)
{
    if(Peers.Count < 1 )
        return 0.0;

    return Peers.Average(x => x.Value.IsPieceDownloaded[index] ? 0.0 : 1.0);
}

برنامه (Program)

آخر از همه، کد برنامه. یک برنامه خط فرمان است که سه آرگومان می‌گیرد:

  • شماره پورت
  • فایل تورنت
  • مسیر دانلود تورنت

این برنامه فقط آرگومان‌ها را اعتبارسنجی می‌کند، کلاینت را شروع می‌کند و بعد منتظر می‌ماند تا کاربر آن را متوقف کند. چون روی OS X هستم، از کتابخانه Mono برای گرفتن سیگنال‌های یونیکس استفاده می‌کنم.

cs
using System;
using System.IO;
using Mono.Unix;
using Mono.Unix.Native;
using BitTorrent;

namespace Program
{
    public class Program
    {
        public static Client Client;

        public static void Main(string[] args)
        {
            int port = -1;

            if (args.Length != 3 || !Int32.TryParse(args[0], out port) || !File.Exists(args[1]))
            {
                Console.WriteLine("Error: requires port, torrent file and download directory as first, second and third arguments");
                return;
            }

            Client = new Client(port, args[1], args[2]);
            Client.Start();

            new UnixSignal(Signum.SIGINT).WaitOne();
            Client.Stop();
        }
    }
}

تحقیقات بیشتر

چند زمینه وجود دارد که احتمالاً در زمان‌های بعدی روی آن‌ها کار خواهم کرد تا سیستم در یک محیط واقعی کار کند:

  • تست بهتر: هر مؤلفه باید کامل‌تر تست شود. قطعاً باگ‌های متعددی داخلش وجود دارد.
  • بررسی خطای بهتر: همه اطلاعات ورودی (از فایل‌های تورنت، پاسخ‌های tracker یا ارتباطات همتا) باید کامل‌تر بررسی شوند تا در صورت مخرب بودن، مشکلی ایجاد نکنند.
  • ویژگی‌ها و بهبودهای مختلف: توانایی مدیریت چند تورنت، توقف/راه‌اندازی مجدد/اعتبارسنجی دستی تورنت‌ها، الگوریتم‌های بهتر انتخاب قطعه و همتا.
  • رمزگذاری: کلاینت‌ها ارتباطاتشان را رمز می‌کنند. می‌فهمم که این بیشتر یک مبهم‌سازی (obfuscation) است تا رمزگذاری کامل، و عمدتاً برای جلوگیری از مسدود کردن یا محدودسازی ترافیک بیت‌تورنت توسط ISP پیاده‌سازی شده است.
  • پروتکل انتقال uTorrent (uTP): کلاینت‌ها از یک پروتکل UDP سفارشی استفاده می‌کنند که می‌تواند بدون مختل کردن سایر استفاده‌های اینترنتی کاربر، از پهنای باند موجود به‌طور کامل بهره ببرد.
  • تبادل همتا (PEX): همتاها فهرست همتاها را با یکدیگر به اشتراک می‌گذارند.
  • درخت‌های هش توزیع‌شده (DHT): همتاها بدون نیاز به tracker می‌توانند یکدیگر را پیدا کنند.
  • لینک‌های مغناطیسی (Magnet): فقط infohash یک تورنت برای شروع آن لازم است؛ بقیه اطلاعات تورنت از همتاها دانلود می‌شود.
