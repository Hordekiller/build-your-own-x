۱. مقدمه — چرا موتور فیزیک خودمان؟

دلایل بسیاری برای ساخت موتور فیزیک سفارشی هست: اول، یادگیری و تقویت مهارت در ریاضیات، فیزیک و برنامه‌نویسی؛ دوم، موتور سفارشی می‌تواند هر اثر فنی‌ای که خالقش توانش را دارد پیاده کند. در این سری، رندی گال مقدمهٔ محکمی برای ساخت یک موتور فیزیک کاملاً از صفر ارائه می‌دهد: یک موتور دوبعدیِ «موج‌محور» (impulse-based) که در پایان توانایی این را دارد که موتورهای سطح تولید را مدل کند.

چهار مقالهٔ سری این‌ها هستند:

  1. مبانی و حل برخورد با ضربه — تشخیص برخورد ساده، تولید manifold و محاسبهٔ ضربه
  2. موتور هسته — گام زمانی ثابت، طراحی ماژولار و broad phase
  3. اصطکاک، صحنه و جدول پرش — قانون کولن، کلاس Scene و jump table
  4. اجسام صلب جهت‌دار — ریاضی چرخش، SAT، برخورد چندضلعی و حل با درجات چرخشی

موتور نمونهٔ سری، ImpulseEngine است — اندازةٔ کوچک و آموزشی، C++، با پروژهٔ Visual Studio در گیت‌هاب (نسخهٔ اصلی: RandyGaul/ImpulseEngine). در طول مقاله‌ها به برنامهٔ نمونه ارجاع پیوسته می‌شود.

۲. مقالهٔ ۱ — مبانی و حل برخورد با ضربه (Impulse Resolution)

هدف مقالهٔ اول: سه عدد چیز — تشخیص برخورد ساده، تولید manifold ساده و حل ضربه‌ای.

حل برخورد یعنی گرفتن دو جسم متقاطع و اصلاحشان طوری که متقاطع نمانند. ایدهٔ «حل ضربه‌ای»: از یک ضربه (تغییر آنی سرعت) برای جداسازی جسم‌های برخورده استفاده می‌کنیم؛ جرم، موقعیت و سرعت هر دو جسم باید در کار دخالت داشته باشند: جسم بزرگ که با کوچک برخورد می‌کند باید کمی جابه‌جا شود و کوچک را به بیرون پرت کند؛ جسم با جرم بی‌نهایت (کف زمین) اصلاً نباید حرکت کند.

برای اعمال ضربه به دو ناحیهٔ (نرمال برخورد) و بزرگی ضربه (j) نیاز داریم. نرمال، جهتی است که ضربه در آن اعمال می‌شود؛ و عمق نفوذ همراه با چیزهای دیگر بزرگی ضربه را تعیین می‌کند. در محاسبه از ضریب بازگشت (restitution — کشسانی) استفاده می‌شود:

cpp// حل برخورد با ضربه — از مقالهٔ اول سری
void ResolveCollision( Object A, Object B )
{
    // سرعت نسبی
    Vec2 rv = B.velocity - A.velocity;

    // سرعت نسبی در امتداد نرمال برخورد
    float velAlongNormal = DotProduct( rv, normal );

    // اگر جسم‌ها در حال جدا شدن‌اند، کاری نکن!
    if( velAlongNormal > 0 )
        return;

    // ضریب بازگشت: از کوچک‌ترین مقدار دو جسم
    float e = min( A.restitution, B.restitution );

    // بزرگی ضربه
    float j = -(1 + e) * velAlongNormal;
    j /= 1 / A.mass + 1 / B.mass;

    // اعمال ضربه: A هل داده می‌شود، B در خلاف جهت
    Vec2 impulse = j * normal;
    A.velocity -= 1 / A.mass * impulse;
    B.velocity += 1 / B.mass * impulse;
}

سه نکتهٔ کلیدی از مقاله:

  • چکِ velAlongNormal > 0 خیلی مهم است: فقط وقتی برخورد را حل کن که جسم‌ها به سمت هم حرکت می‌کنند.
  • به‌جای محاسبهٔ تکراری 1/mass، جرم معکوس را یک‌بار در هر جسم ذخیره کن.
  • ضربهٔ j هوشمندانه بین دو جسم توزیع می‌شود: جسم کوچک سهم بزرگ از j می‌گیرد و جسم بزرگ سهم خیلی کم — دقیقاً مطابق دنیای واقعی.

جسم‌های فرو رونده (Sinking) و اصلاح موقعیت

با وجود حل ضربه‌ای، جسم‌ها کم‌کم داخل هم فرو می‌روند؛ این خطای موقعیتی را با projection خطی اصلاح می‌کنیم: بعد از اعمال ضربه، هر جسم را به‌اندازهٔ درصدی از عمق نفوذ (معمولاً ۲۰٪ تا ۸۰٪) در امتداد نرمال جابه‌جا می‌کنیم — باز هم متناسب با جرم معکوس:

cppvoid PositionalCorrection( Object A, Object B )
{
    const float percent = 0.2;   // معمولاً ۲۰٪ تا ۸۰٪

    Vec2 correction = penetrationDepth / (A.inv_mass + B.inv_mass)
                      * percent * normal;

    A.position -= A.inv_mass * correction;
    B.position += B.inv_mass * correction;
}

تولید manifold ساده

Manifold (در این کاربرد) آبجکت کوچکی است که اطلاعات برخورد دو جسم را دارد: نرمال و عمق نفوذ (و گاهی نقطهٔ تماس). مقالهٔ اول کارش را با سه شکل ساده تمام می‌کند:

  • دایره در برابر دایره: تقریباً بدیهی — نرمال، بردار از مرکز A به مرکز B است و عمق نفوذ از شعاع‌ها و فاصلهٔ مراکز حساب می‌شود.
  • AABB در برابر AABB: چند یال ممکن است درگیر شوند (مثل برخورد دو گوشه)؛ باید «محور کم‌ترین نفوذ» را پیدا کنیم — مقاله الگوریتم کامل را دارد.
  • دایره در برابر AABB: نزدیک‌ترین نقطهٔ جعبه به دایره را پیدا کن؛ از آن‌جا مسئله به حالت دایره-در-برابر-دایره تبدیل می‌شود!

۳. مقالهٔ ۲ — موتور هسته: گام زمانی ثابت و طراحی ماژولار

یا dt باید در همه‌جای کد مقداری یکسان باشد تا موتور قطعی (deterministic) شود — این هم برای بازی‌های رقابتی و هم برای اشکال‌زدایی حیاتی است: اگر رفتار موتور با هر اجرا یکسان نباشد، اشکال‌زدایی تقریباً غیرممکن می‌شود. روش استاندارد، انباشتگر است: حلقهٔ بازی صبر می‌کند تا زمان کافی بگذرد، بعد تکه‌های dt را از انباشتگر جدا می‌کند و به فیزیک می‌دهد تا وقتی انباشتگر از یک dt کوچک‌تر شود:

cpp// حلقهٔ بازی با گام زمانی ثابت (چکیده)
accumulator += elapsedTime;           // زمان واقعی سپری شده را جمع کن
while( accumulator >= dt ) {          // تا وقتی تکهٔ کافی هست
    physics.Step( dt );               // فیزیک را دقیقاً با dt ثابت جلو ببر
    accumulator -= dt;
}

دو مشکل معروف این روش و راه‌حل‌هایشان در مقاله آمده:

  1. مارپیچ مرگ (Spiral of Death): اگر هر Step کندتر از زمان واقعی اجرا شود، انباشتگر هر فریم بزرگ‌تر می‌شود و موتور قفل می‌کند. راه‌حل: حداکثر چند Step در هر فریم.
  2. باقی‌ماندهٔ زمان: وقتی انباشتگر از dt کوچک‌تر است، فیزیک لَختی دارد؛ با درون‌یابی خطی بین دو حالت فیزیک، حالت رندرِ بین‌دوراهی را محاسبه می‌کنیم.

طراحی ماژولار و ساختار Body

هر جسم فیزیکی به داده‌های مشخصی نیاز دارد؛ ولی جزئیات هر جسم کمی فرق دارد. مقاله یک ساختار Body طراحی می‌کند با یک جا برای نیروها: این عضو force در начале هر به‌روزرسانی صفر می‌شود؛ هر مؤلفهٔ موتور (مثل گرانش) بردارش را به آن اضافه می‌کند؛ درست قبل از یکپارچه‌سازی، همهٔ آن برای محاسبهٔ شتاب استفاده و بعد صفر می‌شود.

Broad Phase

تشخیص برخوردهای مقالهٔ قبل «narrow phase»‌اند. Broad phase فقط می‌گوید کدام جفت‌ها ممکن است برخورد کنند، جفت‌ها را در ساختارهای Pair جمع می‌کند و به narrow phase می‌دهد. دو مهارت مهم این بخش:

  • حذف جفت‌های تکراری: با مرتب‌سازی جفت‌ها (تابع SortPairs()) که (A,B) و (B,A) یکی شوند — بدون کتاب‌خانهٔ مرتب‌سازی می‌توانید خودتان اجراش کنید.
  • لایه‌بندی (Layering): بعضی جسم‌ها هرگز نباید با هم برخورد کنند (راکتِ هم‌تیمی به هم‌تیمی نخورد!)؛ این باید در broad phase اعمال شود.

همین‌جا حدود برخورد (halfspace) هم معرفی می‌شود — مقدمهٔ ریاضی برای مرحله بعد.

۴. مقالهٔ ۳ — اصطکاک، صحنه و جدول پرش

ضربهٔ اصطکاکی

در مقالهٔ اول، j مقدار ضربه در امتداد نرمال بود؛ حالا به بزرگی دوم به نام jT در امتداد مماس برخورد نیاز داریم — اصطکاک به‌عنوان یک ضربه مدل می‌شود که سرعت را در خلاف جهتِ حرکت مماسی تغییر می‌دهد. در دو بعد، یافتن این بردار مماس قابل حل است (در ۳بعد به‌مراتب پیچیده‌تر می‌شود؛ معمولاً دو مماس).

قانون کولن — سخت‌ترین بخش!

قانون کولن در شبیه‌سازی بخشی است که بیشتر برنامه‌نویس‌ها با آن کلنجار می‌روند، چون یک نابرابری است نه معادله:

textنیروی اصطکاک محاسبه‌شده (jT) را بگیر؛
اگر |jT| <  μ * نیروی نرمال  →  از jT استفاده کن
وگرنه                         →  jT را به  μ * نیروی نرمال محدود کن

نیروی نرمال همان j قبلی است. نکتهٔ مهم: در مقایسه باید از |jT| استفاده شود (اگر جرم معکوس صفر باشد می‌تواند منفی شود). ضریب اصطکاک بین دو جسم نمونه: μ = √(μ_A² + μ_B²). مقالهٔ سوم اینجا صریح می‌گوید: بیشتر مقالات سفید یا اصطکاک را رها کرده‌اند یا clamping نادرست انجام داده‌اند — درست فهمیدن همین بخش، فرق موتور خوب و بد است!

برای اصطکاک ایستا و جنبشی، هر ماده دو ضریب دارد. اگر jTِ محاسبه‌شده زیر آستانه باشد، جسم تقریباً «در حال سکون» است و کل jT به‌عنوان ضربه اعمال می‌شود (اصطکاک ایستا)؛ اگر بالای آستانه باشد، جسم «انرژی فعال‌سازی را شکسته» و ضریب جنبشی کوچک‌تر به کار می‌رود.

کلاس Scene و جدول پرش برخورد

Scene ظرف همه‌چیز شبیه‌سازی است: همهٔ اجسام صلب، جریان broad/narrow phase، فراخوانی حل‌کننده و یکپارچه‌سازی. رابط کاربری آن ساده است: BodyDef به‌عنوان ساختار پیکربندی جسم، اضافه/حذف آسان جسم‌ها و Step() که یک دورِ تشخیص+حل+یکپارچه‌سازی انجام می‌دهد (از حلقهٔ timestep مقالهٔ دوم صدا زده می‌شود). کوئری نقطه و AABB هم جزء Scene است تا منطق گیم‌پلی بتواند بپرسد «چه چیزی این‌جا هست؟».

جدول پرش (Jump Table): برای انتخاب تابع برخورد بر اساس نوع دو جسم، به‌جای dispatch مضاعف C++ از یک جدول دوبعدی از تابع‌پوینترها استفاده می‌کنیم — سریع‌تر و قابل‌انتقال به زبان‌های دیگر:

cpp// جدول پرش دوبعدی: نوع دو collider به تابع برخورد نگاشت می‌شود
typedef void (*CollisionCallback)( Manifold*, Body*, Body* );

CollisionCallback dispatch[ShapeType::COUNT][ShapeType::COUNT] = {
    { AABBvsAABB, AABBvsCircle, ... },
    { CirclevsAABB, CirclevsCircle, ... },
    ...
};

// فراخوانی: dispatch[shapeA.type][shapeB.type]( &m, bodyA, bodyB );

نکته: AABBvsCircle و CirclevsAABB تقریباً یکسان‌اند — یک‌شان فقط نرمال را برمی‌گرداند! این کار، رفتار یکسانِ حل‌کننده را برای هر ترکیب تضمین می‌کند.

۵. مقالهٔ ۴ — اجسام صلب جهت‌دار (Oriented Rigid Bodies)

حالا چرخش وارد می‌شود! قبل از هر چیز، کلاس Mat22 (ماتریس ۲×۲) به کتاب‌خانهٔ ریاضی اضافه می‌شود. تبدیل شکل به فضای دنیا: اول چرخش، بعد انتقال — چون چرخش همیشه حول مبدأ انجام می‌شود و اجسام در فضای مدل، مبدأشان مرکز جرم است (در کد نمونه، ماتریس‌های جهت با نام u نشان داده شده‌اند). برای ساده‌شدن تشخیص برخورد، جسم را با تبدیل معکوس به فضای مدلِ جسم دیگر می‌بریم!

چندضلعی در برابر چندضلعی با SAT

  1. نقاط پشتیبان (Support Points): رأس‌های چندضلعی را با ضرب داخلی در جهت داده‌شده تصویر کن؛ رأس با بیشترین فاصلهٔ علامت‌دار، «نقطهٔ پشتیبانِ» آن جهت است.
  2. یافتن محور جداکننده: روی همهٔ یال‌های چندضلعی A بچرخ و برای هر یال، نقطهٔ پشتیبانِ B را در خلافِ نرمال آن یال پیدا کن؛ فاصلهٔ نقطه تا یال، نفوذِ علامت‌دار است. بزرگ‌ترین فاصله، محور کم‌ترین نفوذ را می‌دهد — اگر مثبت باشد یعنی جسم‌ها جدا هستند.
  3. کلیپ کردن (Clipping): با مشخص شدن یال مرجع و یال فرودی، نقاط تماس با کلیپ در برابر صفحات کناری یال مرجع پیدا می‌شوند — کاری که ارین کتو (خالق Box2D) اسلایدهای خوبی برایش دارد.

دایره در برابر چندضلعی

نزدیک‌ترین یال چندضلعی به مرکز دایره پیدا می‌شود (مثل نقاط پشتیبان). سپس باید مشخص کنیم دایره داخل کدام ناحیهٔ Voronoi است: با ضرب داخلی بردارهای رأسِ پاره‌خط در مرکز دایره، زاویهٔ گوشه‌ها بررسی می‌شود؛ اگر هر دو گوشه زیر ۹۰ درجه باشد → دایره در ناحیهٔ یال است و مرکز روی خود پاره‌خط تصویر می‌شود؛ وگرنه دایره با یکی از رأس‌ها برخورد می‌کند.

حل برخورد با درجات چرخشی

حالا ضربه باید انرژی‌ای هم به سرعت زاویه‌ای بدهد. سرعت یک نقطهٔ مشخص از جسم: V' = V + ω × r (با r بردار از مرکز جرم تا نقطهٔ تماس). معادلهٔ ضربه با افزار چرخشی:

text          -(1 + e)((V^A - V^B) · t)
j = ──────────────────────────────────────────────
    1/mass^A + 1/mass^B + (r^A × t)²/I^A + (r^B × t)²/I^B

و اعمال ضربه:

cppvoid Body::ApplyImpulse( const Vec2& impulse, const Vec2& contactVector )
{
    velocity += 1.0f / mass * impulse;
    angularVelocity += 1.0f / inertia * Cross( contactVector, impulse );
}

اشتقاقِ کامل این معادلات در سایت کریس هکر (Chris Hecker) موجود است. همین الگو به اصطکاک هم اضافه می‌شود (jT با مولفه‌های چرخشی) تا موتور کامل شود.

۶. جمع‌بندی سری

با پایان سری، این‌ها را ساخته‌اید: حسginal برخورد با نرمال و عمق نفوذ (manifold)، حل ضربه‌ای با بازگشت‌پذیری و اصلاح موقعیت، گام زمانی ثابت با انباشتگر و درون‌یابی، broad phase با جفت‌ها و لایه‌بندی، اصطکاک با clamping کولن (ایستا/جنبشی)، کلاس Scene با کوئری، جدول پرش دوبعدی، و نهایتاً چرخش کامل با SAT، کلیپ تماس و ضربه‌های چرخشی. این دانستنی‌ها برای ساخت موتور دوبعدی در سطح تولید کافی است؛ ImpulseEngine نمونهٔ مرجع همین سری در گیت‌هاب است.

کپیرایت: مطالب سری «How to Create a Custom Physics Engine» اثر رندی گال (Randy Gaul) است که روی Envato Tuts+ منتشر شده. این صفحه ترجمهٔ فارسی و خلاصهٔ آموزشی آن است؛ تمام حقوق محتوا، کد و موتور نمونه ImpulseEngine متعلق به نویسنده است. صفحات اصلی: سری در Tuts+ و گیت‌هاب ImpulseEngine.
