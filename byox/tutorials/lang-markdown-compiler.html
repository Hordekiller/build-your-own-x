نوشتن یک کامپایلر Markdown در Ruby

منبع اصلی: این صفحه ترجمهٔ فارسی و مرور «Writing a Markdown Compiler» از تیم beezwax است که فرآیند ساخت یک کامپایلر Markdown ساده را در Ruby گام‌به‌گام نشان می‌دهد.

چرا Markdown یک زبان است؟

Markdown اگرچه سینتکسی سبک دارد، اما دقیقاً همان کاری را می‌کند که هر زبان دیگر: یک ساختار متنی را به بازنمایی دیگری تبدیل می‌کند. در این آموزش، متن Markdown بهعنوان ورودی و HTML به‌عنوان خروجی در نظر گرفته می‌شود و مسیر ساخت یک کامپایلر کوچک — از lexer تا generator — بار دیگر تمرین می‌شود.

زیبایی این پروژه آن است که پیچیدگی زبان بسیار کم است، پس می‌توانیم روی معماری کامپایلر تمرکز کنیم: پارس، نگاشت به AST ساده و تولید خروجی یکپارچه.

معماری: parsers و generators

رویکرد beezwax از دو قسمت مستقل استفاده می‌کند. Parser قطعه‌های Markdown را تشخیص می‌دهد و هر خط را به‌صورت یک «حاصل» داخلی (مثل heading، paragraph یا bold) تبدیل می‌کند. Generator این حاصل‌ها را به HTML تبدیل می‌کند. جداسازی این دو مرحله باعث می‌شود که افزودن قواعد جدید صرفاً یک روش کوچک باشد.

نمونهٔ کد: یک rule ساده برای heading

ساده‌ترین قاعده، تشخیص خطی است که با `#` شروع می‌شود. اگر دقت کنیم، هر قاعده فقط باید بگوید «اگر این الگو را دیدم، چه ساختاری بسازم»:

Ruby# قاعدهٔ heading: خطی که با یک تا شش # شروع می‌شود
def parse_heading(line, output)
  if line =~ /^(#{1,6})\s+(.*)$/
    level = $1.length
    text  = $2
    # تبدیل به ساختار داخلی (AST)
    output << { type: :heading, level: level, text: render_inline(text) }
    true
  else
    false
  end
end

# الگوی bold: *متن* به <strong>متن</strong>
def render_inline(text)
  text.gsub(/\*(.*?)\*/) { "<strong>#{$1}</strong>" }
end

این روش، «پارس با پیشوند» نامیده می‌شود: برای هر خط، الگوها به ترتیب تست می‌شوند و اولین مورد موفق، مسئول تولید ساختار می‌شود.

گام‌های پیاده‌سازی کامل

بعد از قواعد heading و پاراگراف، نوبت به مواردی می‌رسد که نیاز به «حالت» دارند: مانند بلاک‌های لیست و code fence که یک خط اول و خط آخر دارند. در این‌جا در نگه‌داشتن وضعیت جاری پیمایش (مثلاً «دارم داخل یک لیست هستم») اهمیت یاد می‌گیرید.

در پایان، یک html_renderer می‌نویسید که AST را به‌صورت تلفیقی به HTML تبدیل می‌کند و خروجی را به‌هم‌راه توابع escapte برای امنیت (جلوگیری از تزریق HTML) تولید می‌کند.

جمع‌بندی

این آموزش مرزهای بین «فرمت مستند» و «زبان برنامه‌نویسی» را کم می‌کند و نمونهٔ عالی برای شروع با پروژه‌های پارسینگ است. بعد از آن می‌توانید به سراغ زبان‌های واقعی‌تر (مثل JSON یا Lisp) بروید که همان معماری را با پیچیدگی بیشتری دنبال می‌کنند.
