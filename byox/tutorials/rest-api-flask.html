پیاده‌سازی یک وب API مبتنی بر REST با پایتون و Flask

⚙ زبان: Python 📁 دسته: وب سرور ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی مقالهٔ «Implementing a RESTful Web API with Python & Flask» از «لویس ری (Luis Rei)» است. نسخه کامل و به‌روز را از سایت اصلی بخوانید.
↗ مشاهده منبع اصلی

مقدمه

برای شروع:

Bashsudo pip install flask

فرض بر این است که مبانی REST را می‌دانید. Flask یک میکروفریم‌ورک پایتون بر پایهٔ Werkzeug است — یک کتابخانهٔ کاربردی WSGI.

Flask انتخاب خوبی برای یک API از نوع REST است چون:

  • به پایتون نوشته شده (که می‌تواند مزیت باشد)؛
  • استفاده از آن ساده است؛
  • انعطاف‌پذیر است؛
  • گزینه‌های استقرار (deployment) خوب متعددی دارد؛
  • توزیع درخواست‌ها (Request Dispatching) RESTful دارد.

نویسنده معمولاً با curl درخواست‌های آزمایشی می‌فرستد و یک مرجع کوچک curl هم در انتهای مقاله هست. REST Console هم ابزار خوبی برای Google Chrome است.

کدهای مثال این مقاله در GitHub است.

منابع (Resources)

با یک برنامهٔ کامل شروع می‌کنیم که به درخواست‌های ریشه، /articles و /articles/:id پاسخ می‌دهد:

pythonfrom flask import Flask, url_for
app = Flask(__name__)

@app.route('/')
def api_root():
    return 'Welcome'

@app.route('/articles')
def api_articles():
    return 'List of ' + url_for('api_articles')

@app.route('/articles/<articleid>')
def api_article(articleid):
    return 'You are reading ' + articleid

if __name__ == '__main__':
    app.run()

با curl می‌توانید این درخواست‌ها را بفرستید:

Bashcurl http://127.0.0.1:5000/

پاسخ‌ها به ترتیب این‌ها هستند:

ConsoleGET /
Welcome

GET /articles
List of /articles

GET /articles/123
You are reading 123

مسیرها می‌توانند از مبدل‌های مختلفی در تعریف‌شان استفاده کنند:

python@app.route('/articles/<articleid>')

می‌تواند با این‌ها جایگزین شود:

python@app.route('/articles/<int:articleid>')
@app.route('/articles/<float:articleid>')
@app.route('/articles/<path:articleid>')

پیش‌فرض string است که هر متنی بدون اسلش را می‌پذیرد.

درخواست‌ها (Requests)

پارامترهای GET

برنامه‌ای می‌سازیم که به درخواست‌های /hello پاسخ دهد و یک پارامتر GET اختیاری مدیریت کند:

pythonfrom flask import request

@app.route('/hello')
def api_hello():
    if 'name' in request.args:
        return 'Hello ' + request.args['name']
    else:
        return 'Hello John Doe'

سرور این‌طور پاسخ می‌دهد:

ConsoleGET /hello
Hello John Doe

GET /hello?name=Luis
Hello Luis

متدهای درخواست (فعل‌های HTTP)

برنامه را طوری تغییر می‌دهیم که فعل‌های HTTP مختلف را مدیریت کند:

python@app.route('/echo', methods = ['GET', 'POST', 'PATCH', 'PUT', 'DELETE'])
def api_echo():
    if request.method == 'GET':
        return "ECHO: GET\n"

    elif request.method == 'POST':
        return "ECHO: POST\n"

    elif request.method == 'PATCH':
        return "ECHO: PACTH\n"

    elif request.method == 'PUT':
        return "ECHO: PUT\n"

    elif request.method == 'DELETE':
        return "ECHO: DELETE"

با curl گزینهٔ -X نوع درخواست را مشخص می‌کند:

Bashcurl -X PATCH http://127.0.0.1:5000/echo

داده و هدرهای درخواست

معمولاً POST و PATCH با داده همراه‌اند؛ گاهی در یکی از چند قالب: متن ساده، JSON، XML، قالب دادهٔ خودتان، فایل باینری و... دسترسی به هدرهای HTTP با دیکشنری request.headers و به دادهٔ درخواست با رشتهٔ request.data انجام می‌شود. اگر mimetype برابر application/json باشد، request.json JSON پارس‌شده را دارد:

pythonfrom flask import json

@app.route('/messages', methods = ['POST'])
def api_message():

    if request.headers['Content-Type'] == 'text/plain':
        return "Text Message: " + request.data

    elif request.headers['Content-Type'] == 'application/json':
        return "JSON Message: " + json.dumps(request.json)

    elif request.headers['Content-Type'] == 'application/octet-stream':
        f = open('./binary', 'wb')
        f.write(request.data)
        f.close()
        return "Binary message written!"

    else:
        return "415 Unsupported Media Type ;)"

مشخص‌کردن نوع محتوا با curl:

Bashcurl -H "Content-type: application/json" \
-X POST http://127.0.0.1:5000/messages -d '{"message":"Hello Data"}'

فرستادن فایل با curl:

Bashcurl -H "Content-type: application/octet-stream" \
-X POST http://127.0.0.1:5000/messages --data-binary @message.bin

پاسخ‌ها برای انواع محتوای مختلف:

ConsolePOST /messages {"message": "Hello Data"}
Content-type: application/json
JSON Message: {"message": "Hello Data"}

POST /message <message.bin>
Content-type: application/octet-stream
Binary message written!

ضمناً Flask می‌تواند فایل‌های POST شده از طریق فرم HTML را با request.files مدیریت کند و curl هم می‌تواند با پرچم -F این رفتار را شبیه‌سازی کند.

پاسخ‌ها (Responses)

پاسخ‌ها توسط کلاس Response فلاسک مدیریت می‌شوند:

pythonfrom flask import Response

@app.route('/hello', methods = ['GET'])
def api_hello():
    data = {
        'hello'  : 'world',
        'number' : 3
    }
    js = json.dumps(data)

    resp = Response(js, status=200, mimetype='application/json')
    resp.headers['Link'] = 'http://luisrei.com'

    return resp

برای دیدن هدرهای پاسخ HTTP با curl گزینهٔ -i را مشخص کنید:

Bashcurl -i http://127.0.0.1:5000/hello
ConsoleGET /hello
HTTP/1.0 200 OK
Content-Type: application/json
Content-Length: 31
Link: http://luisrei.com
Server: Werkzeug/0.8.2 Python/2.7.1
Date: Wed, 25 Apr 2012 16:40:27 GMT
{"hello": "world", "number": 3}

Mimetype فقط همان content-type بدون اطلاعات اضافه است (مثل charset، encoding، language و...). اگر ممکن است، اطلاعات کامل نوع محتوا را برگردانید.

مثال قبلی را می‌توان با یک متد راحتی Flask برای تولید پاسخ‌های JSON ساده‌تر کرد:

python   from flask import jsonify

و جایگزینی:

python resp = Response(js, status=200, mimetype='application/json')

با:

pythonresp = jsonify(data)
resp.status_code = 200

که دقیقاً همان پاسخ قبلی را تولید می‌کند. مشخص‌کردن mime type به‌ویژه برای mime type های سفارشی مثل application/vnd.example.v2+json مفید است.

کدهای وضعیت و خطاها

توجه کنید که 200 کد وضعیت پیش‌فرض برای درخواست‌های GET است و در هر دو مثال، مشخص‌کردن آن فقط برای نشان دادن بود. مواردی هست که باید پیش‌فرض‌ها را override کرد؛ مثلاً مدیریت خطا:

python@app.errorhandler(404)
def not_found(error=None):
    message = {
            'status': 404,
            'message': 'Not Found: ' + request.url,
    }
    resp = jsonify(message)
    resp.status_code = 404

    return resp

@app.route('/users/<userid>', methods = ['GET'])
def api_users(userid):
    users = {'1':'john', '2':'steve', '3':'bill'}
    
    if userid in users:
        return jsonify({userid:users[userid]})
    else:
        return not_found()

این را تولید می‌کند:

ConsoleGET /users/2
HTTP/1.0 200 OK
{
    "2": "steve"
}

GET /users/4
HTTP/1.0 404 NOT FOUND
{
"status": 404, 
"message": "Not Found: http://127.0.0.1:5000/users/4"
}

پیام‌های خطای پیش‌فرض Flask را می‌توان یا با دکوراتور @error_handler یا با app.error_handler_spec[None][404] = not_found بازنویسی کرد. حتی اگر API نیازی به پیام‌های خطای سفارشی ندارد، اگر از mime type های مختلف (JSON, XML و...) پشتیبانی می‌کند این قابلیت مهم است، چون Flask به‌صورت پیش‌فرض خطاهای HTML می‌دهد.

احراز هویت (Authorization)

یک snippet بسیار مفید از Armin Ronacher نحوهٔ مدیریت HTTP Basic Authentication را نشان می‌دهد و به‌راحتی برای طرح‌های دیگر قابل تغییر است. نسخهٔ کمی تغییر یافتهٔ آن:

pythonfrom functools import wraps

def check_auth(username, password):
    return username == 'admin' and password == 'secret'

def authenticate():
    message = {'message': "Authenticate."}
    resp = jsonify(message)

    resp.status_code = 401
    resp.headers['WWW-Authenticate'] = 'Basic realm="Example"'

    return resp

def requires_auth(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        auth = request.authorization
        if not auth: 
            return authenticate()

        elif not check_auth(auth.username, auth.password):
            return authenticate()
        return f(*args, **kwargs)

    return decorated

و استفاده از آن فقط جایگزینی تابع check_auth و استفاده از دکوراتور requires_auth است:

python@app.route('/secrets')
@requires_auth
def api_hello():
    return "Shhh this is top secret spy stuff!"

پس یک درخواست بدون احراز هویت:

ConsoleGET /secrets
HTTP/1.0 401 UNAUTHORIZED
WWW-Authenticate: Basic realm="Example"
{
  "message": "Authenticate."
}

در حالی که درخواست احراز هویت‌شده — که با curl و گزینهٔ -u برای Basic authentication و -v برای دیدن هدرها فرستاده می‌شود — نتیجهٔ مورد انتظار را دارد:

Bashcurl -v -u "admin:secret" http://127.0.0.1:5000/secrets
ConsoleGET /secrets Authorization: Basic YWRtaW46c2VjcmV0
Shhh this is top secret spy stuff!

Flask از یک MultiDict برای ذخیرهٔ هدرها استفاده می‌کند. برای ارائهٔ چند طرح احراز هویت ممکن به کلاینت‌ها، کافی است خطوط WWW-Authenticate بیشتری به هدر اضافه کنید:

pythonresp.headers['WWW-Authenticate'] = 'Basic realm="Example"'
resp.headers.add('WWW-Authenticate', 'Bearer realm="Example"')

یا از یک خط با چند طرح استفاده کنید (استاندارد هر دو را مجاز می‌داند).

اشکال‌زدایی و لاگ ساده

فعال‌کردن پیام‌های اشکال‌زدایی زیبای (HTML) در طول توسعه ساده است — فقط یک آرگومان:

pythonapp.run(debug=True)

Flask از همان logging پایتون استفاده می‌کند — با کمی پیکربندی:

pythonimport logging
file_handler = logging.FileHandler('app.log')
app.logger.addHandler(file_handler)
app.logger.setLevel(logging.INFO)

@app.route('/hello', methods = ['GET'])
def api_hello():
    app.logger.info('informing')
    app.logger.warning('warning')
    app.logger.error('screaming bloody murder!')
    
    return "check your logs\n"

مرجع کوچک: گزینه‌های curl

گزینهکاربرد
-Xمشخص‌کردن متد درخواست HTTP، مثل POST
-Hمشخص‌کردن هدرهای درخواست، مثل "Content-type: application/json"
-dمشخص‌کردن دادهٔ درخواست، مثل '{"message":"Hello Data"}'
--data-binaryمشخص‌کردن دادهٔ باینری درخواست، مثل @file.bin
-iنمایش هدرهای پاسخ
-uمشخص‌کردن نام کاربری و رمز عبور، مثل "admin:secret"
-vفعال‌کردن حالت verbose که اطلاعاتی مثل هدرهای درخواست و پاسخ و خطاها را خروجی می‌دهد
