۱. این پروژه چیست؟

این پروژه یک VPN لایه ۲ شبیه به ZeroTier (یا به‌عبارتی یک سوییچ مجازی) پیاده‌سازی می‌کند. رفتار یک سوییچ شبکه فیزیکی را شبیه‌سازی می‌کند: سرویس تبادل فریم اترنت برای دستگاه‌هایی که به پورت‌های سوییچ وصل‌اند. تفاوت این‌جاست که پورت‌های این سوییچ مجازی می‌توانند از طریق اینترنت به دستگاه‌هایی در سراسر دنیا متصل شوند و برای سیستمعامل، همه آن‌ها مثل یک شبکه محلی واحد دیده می‌شوند.

۲. دانش پس‌زمینه

سوییچ شبکه چیست؟ سخت‌افزاری است که دستگاه‌های شبکه را به هم متصل می‌کند و داده را با سوئیچینگ بسته به مقصد می‌فرستد. یک سوییچ، «پل چندپورته» است که با آدرس‌های MAC در لایه ۲ (نوک OSI) ارسال می‌کند. در هنگام ارسال، سوییچ از «جدول ارسال» برای یافتن پورت متناظر با آدرس مقصد استفاده می‌کند. در سوییچ، این جدول «جدول آدرس MAC» نام دارد: نگه‌دارنده آدرس‌های MAC شناخته‌شده و پورت‌هایشان. وقتی فریم می‌رسد، مقصد را در جدول جست‌وجو می‌کند و فقط به همان پورت می‌فرستد؛ اگر مقصد در جدول نبود، به‌جز پورت مبدا به همه پورت‌ها پخش می‌کند تا دستگاه هدف پاسخ دهد و جدول به‌روز شود.

در این پروژه، برنامه‌ای به نام VSwitch نقش سوییچ مجازی را بازی می‌کند.

۳. دستگاه شبکه مجازی TAP

دستگاه TAP یک رابط شبکه مجازی است که مانند رابط فیزیکی توسط سیستمعامل دیده و استفاده می‌شود؛ پیاده‌سازی‌اش در هسته است. وقتی بسته‌ای از TAP ارسال می‌شود، به‌جای سخت‌افزار، به برنامه کاربر رسانده می‌شود؛ برنامه می‌تواند آن را پردازش و به دستگاه‌های دیگر بفرستد. در این پروژه، TAP رابط بین کامپیوتر کلاینت و سوییچ مجازی است.

۴. معماری سیستم

  • سرور (VSwitch) — رفتار سوییچ فیزیکی را شبیه‌سازی می‌کند:
  • سرویس تبادل فریم اترنت برای کامپیوترهایی که با VPort متصل‌اند؛ جدول MAC (آدرس → پورت) نگه می‌دارد و ارسال را بر این اساس انجام می‌دهد.
  • کلاینت (VPort) — رفتار پورت فیزیکی را شبیه‌سازی می‌کند: یک سر به هسته (کامپیوتر) از طریق TAP وصل است و سر دیگر به VSwitch با سوکت UDP.
text            +----------------------------------------------+
            |                   VSwitch                    |
            |   جدول MAC:  11:11:11:11:11 ↔ VPort-1        |
            |               aa:aa:aa:aa:aa ↔ VPort-a        |
            +--------+---------------------------+---------+
                     |                           |
              UDP (فریم اترنت)            UDP (فریم اترنت)
                     |                           |
            +--------v---------+        +--------v---------+
            | VPort | TAP       |        | VPort | TAP       |
            +--------------------+      +--------------------+
                     |                           |
            کامپیوتر A (هسته لینوکس)     کامپیوتر B (هسته لینوکس)

مسیر بسته: هسته کامپیوتر ← [TAP] ← فریم اترنت ← [UDP] ← VSwitch — و برعکس.

۵. ساختار کد

  • vswitch.py — کد VSwitch (سرور): مدیریت جدول MAC و ارسال فریم‌ها.
  • vport.c — کد VPort (کلاینت): رله فریم بین TAP و UDP.
  • tap_utils.c / tap_utils.h — ابزارهای ساخت و پیکربندی TAP.
  • setup.sh و Makefile — وابستگی‌ها و ساخت.

ساخت پروژه فقط اجرای make است.

۶. راه‌اندازی

پیش‌نیازها: یک سرور با IP عمومی برای VSwitch، و حداقل دو کلاینت. فرض کنید IP سرور SERVER_IP و پورت آن SERVER_PORT است:

bash# مرحله ۱: روی سرور با IP عمومی، VSwitch را اجرا کن
python3 vswitch.py ${SERVER_PORT}

# مرحله ۲: روی کلاینت ۱، VPort را اجرا و TAP را پیکربندی کن
sudo ./vport ${SERVER_IP} ${SERVER_PORT}
sudo ip addr add 10.1.1.101/24 dev tapyuan
sudo ip link set tapyuan up

# مرحله ۳: همین‌طور روی کلاینت ۲ (با آدرس دیگر)
sudo ./vport ${SERVER_IP} ${SERVER_PORT}
sudo ip addr add 10.1.1.102/24 dev tapyuan
sudo ip link set tapyuan up
bash# مرحله ۴: تست با ping — از کلاینت ۱ به کلاینت ۲
ping 10.1.1.102

اگر ping جواب داد، کامپیوترها حین شبکه مجازی، طوری داده رد و بدل می‌کنند که انگار یک LAN فیزیکی هستند.

نکته: مجوز sudo و ماژول TUN/TAP هسته لازم است. برای سرور عمومی می‌توانید یک ماشین مجازی ابری ارزان بگیرید و همان‌جا تست کنید.
