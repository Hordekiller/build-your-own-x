ZeroTier خودت را بساز — سوییچ لایهٔ ۲ در کمتر از ۳۰۰ خط کد

⚙ زبان: C + Python ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: ترجمهٔ فارسی «Build your own ZeroTier» از پی‌یوان (peiyuanix) — پیاده‌سازی مفاهیم VPN مدرن ZeroTier بدون اعداد و رمزنگاری پیچیده: سوییچ لایهٔ ۲ همه‌جا-حاضر (Everywhere Layer-2 Switch) با دو مؤلفهٔ VSwitch و VPort، در کمتر از ۳۰۰ خط کد با یک TAP در C و یک حلقهٔ پخش در Python.
↗ مشاهده منبع اصلی

۱. ZeroTier چیست و چرا باید خودت بسازی؟

ZeroTier یک پروژهٔ متن‌باز است که مانند یک شبکهٔ محلی، کارت شبکهٔ مجازی (Virtual Network Interface) با اتصال‌های همتا-به-همتا (P2P) ایجاد می‌کند؛ در نتیجه ماشین‌های شما می‌توانند مثل اینکه کابل اترنت به‌هم متصل‌اند، به IPهای یکدیگر ping، SSH و REACH بزنند — از هر کجای دنیا.

تولید این قابلیت پیچیده به نظر می‌رسد؛ اما برای ساختن یک نسخهٔ ساده‌شدهٔ عملیاتی، فقط به دو مؤلفهٔ زیر نیاز دارم؛ با هم کاری می‌کنند که «درستی آن با یک پینگ ثابت می‌شود»:

  • VSwitch — منطقهٔ مرکزی تصمیم‌گیری (ثبت MAC، نگاشت به «پرت»، پخش). به زبان Python.
  • VPort — پرتِ دستگاه‌های همسایه (واسط TAP + فرستندهٔ UDP). به زبان C.

معماری: هستهٔ VSwitch روی میزبان مرکزی اجرا می‌شود؛ هر «کاربر نهایی» یک VPort اجرا می‌کند که با TAP، به هستهٔ لینوکس وصل است و فریم‌های اترنت را با UDP به VSwitch می‌رساند. نتیجهٔ کل فقط کمتر از ۳۰۰ خط کد است!

۲. VPort — کارت شبکهٔ مجازی به زبان C (فایل vport.c)

VPort دو کار ایستگاه دارد: (۱) فریم‌های L2 را از طریق یک گروه TAP از لینوکس بگیرد، و (۲) فریم‌ها را از طریق UDP به VSwitch برساند (و برعکس). با ساختار زیر:

c#define TAP_DEV "/dev/net/tun"
#define UDP_PORT 9999

struct vport {
    int tap_fd;      /* fd دستگاه TAP (توسط tun_alloc) */
    int udp_fd;      /* fd سوکت UDP متصل به VSwitch */
    struct sockaddr_in vswitch_addr;
    char mac[6];     /* MAC ساختگی این پرت */
c/* --- tun_alloc: ساخت واسط TAP -- */
int tun_alloc(char *dev) {
    struct ifreq ifr;
    int fd, err;

    if ((fd = open("/dev/net/tun", O_RDWR)) < 0)
        return -1;

    memset(&ifr, 0, sizeof(ifr));
    ifr.ifr_flags = IFF_TAP | IFF_NO_PI;   /* TAP و بدون بسته-اطلاعات */
    if (*dev) strncpy(ifr.ifr_name, dev, IFNAMSIZ);

    err = ioctl(fd, TUNSETIFF, (void *)&ifr);
    if (err < 0) { close(fd); return err; }
    strcpy(dev, ifr.ifr_name);
    return fd;
}

حلقهٔ اصلی VPort: یک read از TAP یا یک recvfrom از UDP؛ چون هر دو side اثر blocking دارند، از select() استفاده می‌کنیم تا همزمان به هر دو گوش دهیم:

cfor (;;) {
    fd_set rfds; FD_ZERO(&rfds);
    FD_SET(vp->tap_fd, &rfds); FD_SET(vp->udp_fd, &rfds);
    select(max_fd + 1, &rfds, NULL, NULL, NULL);

    if (FD_ISSET(vp->tap_fd, &rfds)) {
        /* فریم از لینوکس آمده: برو سمت VSwitch */
        n = read(vp->tap_fd, frame, sizeof frame);
        sendto(vp->udp_fd, frame, n, 0,
               (struct sockaddr *)&vp->vswitch_addr, sizeof vp->vswitch_addr);
    }

    if (FD_ISSET(vp->udp_fd, &rfds)) {
        /* فریم از VSwitch آمده: به TAP تزریق کن */
        n = recvfrom(vp->udp_fd, frame, sizeof frame, 0, NULL, NULL);
        write(vp->tap_fd, frame, n);
    }
}

۳. VSwitch — منطق تصمیم‌گیری به زبان Python (فایل vswitch.py)

سویچ باید خودش یک «پرت» باشد: با هر VPort که به او متصل می‌شود. برای سادگی، نقشهٔ پورت و MAC در حافظه است:

python"""vswitch.py — یک سوییچ L2 بی‌حال."""
import socket

UDP_PORT = 9999
MAC_TABLE = {}          # mac → آدرس (ip, port) پرت
PORT_MAP  = {}          # (ip, port) → macهای دیده‌شده با آن پرت

def main():
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind(("", UDP_PORT))
    print(f"VSwitch listening on UDP {UDP_PORT}")

    while True:
        frame, addr = s.recvfrom(65535)
        print(f"\nGot {len(frame)} bytes from {addr}")

        src_mac = frame[6:12].hex(":")
        dst_mac = frame[0:6].hex(":")

        # ۱. یادگیری: مبدا را به پورت‌ش نقشه کن
        MAC_TABLE[src_mac] = addr
        print(f"  Learn: {src_mac} → {addr}")

        if dst_mac == "ff:ff:ff:ff:ff:ff":
            # ۲. پخش: به همهٔ پرت‌ها جز فرستنده
            for a in set(MAC_TABLE.values()):
                if a != addr:
                    s.sendto(frame, a)
        elif dst_mac in MAC_TABLE:
            # ۳. ارسال تک‌به-تک: فقط پرتِ مقصد
            s.sendto(frame, MAC_TABLE[dst_mac])
        else:
            # ۴. ناشناخته: مثل پخش، بعداً یاد می‌گیریم
            for a in set(MAC_TABLE.values()):
                if a != addr:
                    s.sendto(frame, a)

if __name__ == "__main__":
    main()

۴. استقرار و آزمایش: با یک پینگ اثباتش کن

نکته: vport.c برای ساخت TAP به دسترسی روت نیاز دارد؛ ولی وقتی TAP ساخته شد و آدرس IP به آن دادیم، تابع‌های read/write با مجوز عادی کار می‌کنند.

bash# ۱. VSwitch را روی ماشین مرکزی اجرا کن
python3 vswitch.py

# ۲. VPort را روی هر ماشین بساز و اجرا کن
make
sudo ./vport  # آدرس VSwitch را در کد تنظیم کن

# ۳. برای واسط TAP ساخته‌شده (مثلاً l2vpn0) آدرس IP تنظیم کن
sudo ip addr add 192.168.0.1/24 dev l2vpn0
sudo ip link set l2vpn0 up

# ۴. از طرف دیگر همین‌ها را تکرار کن و پینگ بزن
ping 192.168.0.2

اگر خروجی VSwitch در حین پینگ، «Learn»های pong (پاسخ ARP و ICMP) را نشان دهد، یعنی ساختار کامل کار می‌کند: دو ماشین واقعی مثل اینکه کابل اترنت به هم وصل دارند، بدون هیچ زیرساخت وسط، از طریق UDP با هم حرف می‌زنند.

۵. بعدش چه؟

نسخهٔ اصلی ZeroTier، فریم اترنت را در یک پروتکل تونل خودش بسته‌بندی می‌کند، نه UDP خام؛ و (مهم‌ترینش) رمزنگاری از سر تا سر را با کلیدهای عمومی (curve25519) و رمز AES انجام می‌دهد. در نسخهٔ ما هرکس می‌تواند فریم‌ها را بخواند یا تغییر دهد! ایده‌های تکامل: شمارندهٔ ترتیب و auth token برای جلوگیری از replay، جدول MAC با انقضای زمانی (Timeout) و حذف قدیمی‌ها، هم‌زمانی با thread یا async برای مقیاس‌پذیری، و پشتیبانی IPv4/IPv6/Ethernet باهم.
