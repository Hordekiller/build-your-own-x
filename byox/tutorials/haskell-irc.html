مقدمه

این آموزش به‌عنوان یک راهنمای عملی برای نوشتن کدِ دنیای واقعی در هسکل (Haskell) طراحی شده است و امیدوار است برخی از ویژگی‌های پیشرفتهٔ هسکل را به‌صورت شهودی به برنامه‌نویس تازه‌کار معرفی و ترغیب کند. هدف ما نوشتن یک ربات IRC موجز (concise)، مقاوم و زیبا در هسکل است.

یک نسخهٔ بسته‌بندی‌شده از کد در گیت‌هاب (GitHub) در دسترس است.

شروع کار (Getting started)

به نسخهٔ نسبتاً جدیدی از GHC نیاز دارید. اولین قدم ما این است که وارد شبکه شویم. پس بیایید با وارد کردن (import) ماژول‌ها از کتابخانهٔ استاندارد و بستهٔ network شروع کنیم و سروری را که به آن متصل می‌شویم تعریف نماییم.

hs-- فایل 1.hs

import System.IO                      -- کتابخانهٔ پایه (base)
import qualified Network.Socket as N  -- بستهٔ network

-- گزینه‌های پیکربندی
myServer = "irc.libera.chat" :: String
myPort   = 6667 :: N.PortNumber

-- برنامهٔ سطح‌بالا (Toplevel)
main :: IO ()
main = do
    h <- connectTo myServer myPort
    t <- hGetContents h
    hSetBuffering stdout NoBuffering
    print t

-- اتصال به یک سرور با نام و شمارهٔ پورت آن
connectTo :: N.HostName -> N.PortNumber -> IO Handle
connectTo host port = do
    addr : _ <- N.getAddrInfo Nothing (Just host) (Just (show port))
    sock <- N.socket (N.addrFamily addr) (N.addrSocketType addr) (N.addrProtocol addr)
    N.connect sock (N.addrAddress addr)
    N.socketToHandle sock ReadWriteMode

نکتهٔ کلیدی در این‌جا تابع main است. این نقطهٔ ورود به یک برنامهٔ هسکلی است. ابتدا به سرور متصل می‌شویم و یک سوکت h (به‌صورت یک Handle بسته‌بندی‌شده) دریافت می‌کنیم. سپس می‌توانیم هر داده‌ای را که دریافت می‌کنیم بخوانیم و چاپ کنیم. بافرینگ (buffering) را روی خروجی استاندارد با hSetBuffering غیرفعال می‌کنیم؛ زیرا print رشته‌ها را در یک خط واحد رندر می‌کند و کاراکترهای خط جدید (newline) در آن escape می‌شوند.

این کد را در ماژول 1.hs قرار دهید؛ سپس می‌توانیم آن را اجرا کنیم. از هر سیستمی که دوست دارید استفاده کنید:

مکالمه با IRC (Talking IRC)

حالا که به سرور گوش می‌دهیم، بهتر است شروع به ارسال اطلاعات به عقب کنیم. سه جزئیات مهم‌اند: نام نمایشی (nick)، نام کاربری (user name) و کانالی که باید به آن بپیوندیم. پس بیایید این‌ها را ارسال کنیم.

hs-- فایل 2.hs

import System.IO                      -- کتابخانهٔ پایه (base)
import qualified Network.Socket as N  -- بستهٔ network

-- گزینه‌های پیکربندی
myServer = "irc.libera.chat" :: String
myPort   = 6667 :: N.PortNumber
myChan   = "#tutbot-testing" :: String
myNick   = "tutbot" :: String

-- برنامهٔ سطح‌بالا (Toplevel)
main :: IO ()
main = do
    h <- connectTo myServer myPort
    write h "NICK" myNick
    write h "USER" (myNick ++ " 0 * :tutorial bot")
    write h "JOIN" myChan
    listen h

-- اتصال به یک سرور با نام و شمارهٔ پورت آن
connectTo :: N.HostName -> N.PortNumber -> IO Handle
connectTo host port = do
    addr : _ <- N.getAddrInfo Nothing (Just host) (Just (show port))
    sock <- N.socket (N.addrFamily addr) (N.addrSocketType addr) (N.addrProtocol addr)
    N.connect sock (N.addrAddress addr)
    N.socketToHandle sock ReadWriteMode

-- ارسال یک پیام به یک handle
write :: Handle -> String -> String -> IO ()
write h cmd args = do
    let msg = cmd ++ " " ++ args ++ "\r\n"
    hPutStr h msg          -- ارسال پیام روی سیم (شبکه)
    putStr ("> " ++ msg)   -- نمایش پیام ارسال‌شده در خط فرمان

-- پردازش هر خط دریافتی از سرور
listen :: Handle -> IO ()
listen h = forever $ do
    line <- hGetLine h
    putStrLn line
  where
    forever :: IO () -> IO ()
    forever a = do a; forever a

حالا کارهای زیادی انجام داده‌ایم. اول، یک نام کانال و یک نام نمایشی برای ربات تنظیم کردیم. تابع main گسترش یافته است تا با استفاده از یک تابع write پیام‌هایی را به سرور IRC بازگرداند. بیایید کمی دقیق‌تر به آن نگاه کنیم:

hs-- ارسال یک پیام به یک handle
write :: Handle -> String -> String -> IO ()
write h cmd args = do
    let msg = cmd ++ " " ++ args ++ "\r\n"
    hPutStr h msg          -- ارسال پیام روی سیم (شبکه)
    putStr ("> " ++ msg)   -- نمایش پیام ارسال‌شده در خط فرمان

تابع write سه آرگومان می‌گیرد: یک handle (سوکت ما) و سپس دو رشته که یکی یک کنش (action) پروتکل IRC را نشان می‌دهد و دیگری آرگومان‌های آن کنش. سپس write با به‌هم‌چسباندن (concatenation) رشته‌ها یک پیام IRC می‌سازد و آن را روی سیم به سرور می‌نویسد. برای اهداف اشکال‌زدایی، پیامی را که می‌فرستیم نیز در خروجی استاندارد چاپ می‌کنیم.

دومین تابع ما، listen، به این شکل است:

hs-- پردازش هر خط دریافتی از سرور
listen :: Handle -> IO ()
listen h = forever $ do
    line <- hGetLine h
    putStrLn line
  where
    forever :: IO () -> IO ()
    forever a = do a; forever a

این تابع یک آرگومان Handle می‌گیرد و در یک حلقهٔ بی‌نهایت می‌ماند؛ خطوط متن را از شبکه می‌خواند و آن‌ها را چاپ می‌کند. ما از دو ویژگی قدرتمند بهره می‌بریم: ارزیابی تنبل (lazy evaluation) و توابع مرتبه‌بالا (higher-order functions) تا ساختار کنترلی حلقهٔ خودمان، یعنی forever، را به‌صورت یک تابع معمولی بسازیم! forever یک تکه‌کد را به‌عنوان آرگومان می‌گیرد، آن را ارزیابی می‌کند و بازگشت می‌زند — یک تابع حلقهٔ بی‌نهایت. بسیار رایج است که در هسکل ساختارهای کنترلی را به همین شکل و با استفاده از توابع مرتبه‌بالا خودمان بسازیم. هیچ نیازی به افزودن نحو (syntax) جدید به زبان، ماکروهای شبیه لیسپ (lisp) یا فرابرنامه‌نویسی (meta programming) نیست — شما فقط یک تابع معمولی می‌نویسید تا هر جریان کنترلی که می‌خواهید را پیاده‌سازی کنید. همچنین می‌توانیم از do-notation صرف‌نظر کنیم و مستقیماً بنویسیم: forever a = a >> forever a. توجه کنید که forever را همچنین می‌توان در کتابخانهٔ استاندارد base و در ماژول Control.Monad یافت (با نوعی عمومی‌تر).

یک مفسر ساده (A simple interpreter)

این ایمپورت‌های اضافی را قبل از تغییر تابع listen اضافه کنید.

hsimport Data.List
import System.Exit
hs-- پردازش هر خط دریافتی از سرور
listen :: Handle -> IO ()
listen h = forever $ do
    line <- hGetLine h
    putStrLn line
    let s = init line
    if isPing s then pong s else eval h (clean s)
  where
    forever :: IO () -> IO ()
    forever a = do a; forever a

    clean :: String -> String
    clean = drop 1 . dropWhile (/= ':') . drop 1

    isPing :: String -> Bool
    isPing x = "PING :" `isPrefixOf` x

    pong :: String -> IO ()
    pong x = write h "PONG" (':' : drop 6 x)

با اصلاح listen سه قابلیت به ربات اضافه می‌کنیم. اول، به پیام‌های PING پاسخ می‌دهد: if ping s then pong s .... این برای سرورهایی مفید است که برای متصل نگه‌داشتن کلاینت‌ها پیام ping می‌خواهند. قبل از اینکه بتوانیم یک فرمان را پردازش کنیم، به یاد داشته باشید که پروتکل IRC خطوط ورودی را به این شکل تولید می‌کند:

hs:dons!i=dons@my.net PRIVMSG #tutbot-testing :!id foo

بنابراین به یک تابع clean نیاز داریم که به‌سادگی کاراکتر «:» ابتدایی و سپس هر چیزی را تا «:» بعدی حذف کند و تنها محتوای واقعی فرمان را باقی بگذارد. سپس این رشتهٔ تمیز شده را به eval می‌سپاریم که فرمان‌های ربات را توزیع (dispatch) می‌کند.

hs-- توزیع یک فرمان
eval :: Handle -> String -> IO ()
eval h "!quit"                   = write h "QUIT" ":Exiting" >> exitSuccess
eval h x | "!id " `isPrefixOf` x = privmsg h (drop 4 x)
eval _   _                       = return () -- هر چیز دیگری را نادیده بگیر

پس، اگر رشتهٔ واحد "!quit" دریافت شود، به سرور اطلاع می‌دهیم و از برنامه خارج می‌شویم. اگر رشته‌ای که با "!id " آغاز می‌شود ظاهر شود، هر رشتهٔ آرگومانی را به سرور بازتاب (echo) می‌کنیم (نام فرمان برگرفته از تابع همانی (identity function) یعنی id است که فقط آرگومان خودش را برمی‌گرداند). در نهایت، اگر هیچ تطابق دیگری رخ ندهد، هیچ کاری انجام نمی‌دهیم.

تابع privmsg را اضافه می‌کنیم — یک لفاف (wrapper) مفید بر روی write برای ارسال خطوط PRIVMSG به سرور.

hs-- ارسال privmsg به کانال
privmsg :: Handle -> String -> IO ()
privmsg h s = write h "PRIVMSG" (chan ++ " :" ++ s)

در این‌جا گزارش جلسه (transcript) ربات حداقلی ما در حال اجرا در کانال آمده است:

shell   15:12 -- tutbot [n=tutbot@aa.bb.cc.dd] has joined #tutbot-testing
   15:13  dons> !id hello, world!
   15:13  tutbot> hello, world!
   15:13  dons> !id very pleased to meet you.
   15:13  tutbot> very pleased to meet you.
   15:13  dons> !quit
   15:13 -- tutbot [n=tutbot@aa.bb.cc.dd] has quit [Client Quit]

حالا، قبل از اینکه جلوتر برویم، بیایید کد را کمی بازسازی (refactor) کنیم.

موناد خودت را بساز (Roll your own monad)

یک ناراحتی کوچک تا این‌جا این بود که مجبور بودیم سوکت‌مان را به هر تابعی که نیاز به صحبت با شبکه دارد پاس بدهیم. سوکت اساساً یک وضعیت تغییرناپذیر (immutable state) است که در زبان‌های دیگر می‌توان آن را یک مقدار سراسری فقط‌خواندنی در نظر گرفت. در هسکل می‌توانیم چنین ساختاری را با یک موناد خواندن (reader monad) پیاده‌سازی کنیم. مونادها انتزاع (abstraction) بسیار قدرتمندی هستند و ما در این‌جا فقط به آن‌ها اشاره می‌کنیم. خوانندهٔ علاقه‌مند به All About Monads ارجاع داده می‌شود. ما از یک موناد سفارشی مخصوصاً برای پیاده‌سازی یک وضعیت سراسری فقط‌خواندنی برای رباتمان استفاده خواهیم کرد.

نیاز کلیدی این است که بخواهیم بتوانیم کنش‌های IO را اجرا کنیم و در عین حال یک مقدار وضعیت کوچک را به‌صورت شفاف در کل برنامه دنبال (thread) کنیم. از آنجا که این هسکل است، می‌توانیم قدم اضافه‌ای برداریم و کدِ دارای وضعیت (stateful) خود را با استفاده از یک نوع جدید از همهٔ کدهای دیگر برنامه جدا کنیم.

پس بیایید یک موناد خواندن کوچک تعریف کنیم:

hs-- موناد «Net»، یک لفاف بر روی IO که وضعیت تغییرناپذیر ربات را حمل می‌کند.
data Bot = Bot { botSocket :: Handle }
type Net = ReaderT Bot IO

اول، یک نوع داده (data type) برای وضعیت سراسری تعریف می‌کنیم. در این مورد، نوع Bot است؛ یک struct ساده که سوکت شبکهٔ ما را ذخیره می‌کند. سپس این نوع داده را با یک ترانسفورمر موناد (monad transformer) روی کد IO موجودمان لایه‌بندی می‌کنیم. این به آن اندازه که به نظر می‌رسد ترسناک نیست و نتیجه‌اش این است که می‌توانیم در هر جایی که نیاز داریم، سوکت را به‌عنوان یک مقدار سراسری فقط‌خواندنی در نظر بگیریم. این ساختار جدید «IO + وضعیت» را موناد Net می‌نامیم. ReaderT یک سازندهٔ نوع (type constructor) است؛ در اصل یک تابع نوعی که دو نوع را به‌عنوان آرگومان می‌گیرد و یک نوع حاصل می‌سازد: نوع موناد Net.

حالا می‌توانیم همهٔ آن پاس‌دادن‌های سوکت را کنار بگذاریم و هر وقت لازم شد سوکت را برداریم. گام‌های کلیدی عبارت‌اند از اتصال به سرور، سپس مقداردهی اولیهٔ موناد خواندن جدیدمان، و بعد اجرای حلقهٔ اصلی ربات با آن مقدار سراسری. یک تابع کوچک اضافه می‌کنیم که وضعیت اولیهٔ ربات را می‌گیرد و حلقهٔ run ربات را «درون» موناد Net و با استفاده از تابع runReaderT موناد Reader ارزیابی می‌کند:

hsloop st = runReaderT run st

که در آن run یک تابع کوچک برای ثبت نام نمایشی ربات، پیوستن به یک کانال و شروع گوش‌دادن به فرمان‌هاست.

در همین حین می‌توانیم تابع main را کمی مرتب کنیم: با استفاده از Control.Exception.bracket فازهای اتصال، قطع اتصال و حلقهٔ اصلی برنامه را به‌صورت صریح از هم جدا کنیم — تکنیکی مفید.

hs-- برنامهٔ سطح‌بالا (Toplevel)
main :: IO ()
main = bracket connect disconnect loop
  where
    disconnect = hClose . socket
    loop st    = runReaderT run st

یعنی تابع مرتبه‌بالای bracket سه آرگومان می‌گیرد: تابعی برای اتصال به سرور، تابعی برای قطع اتصال و یک حلقهٔ اصلی که در بین آن‌ها اجرا می‌شود. هر وقت بخواهیم کدی را قبل و بعد از یک کنش خاص اجرا کنیم می‌توانیم از bracket استفاده کنیم — مانند forever، این نیز ساختار کنترلی دیگری است که به‌صورت یک تابع معمولی هسکل پیاده‌سازی شده است.

به‌جای پاس‌دادن سوکت به همه‌جا، حالا می‌توانیم به‌سادگی هر وقت لازم شد آن را بخواهیم. توجه کنید که نوع write تغییر می‌کند — اکنون در موناد Net است، که به ما می‌گوید ربات باید از قبل به یک سرور متصل باشد (و بنابراین استفاده از سوکت مجاز است، چون مقداردهی شده است).

hs-- ارسال پیام به سروری که در حال حاضر به آن متصل هستیم
write :: String -> String -> Net ()
write cmd args = do
    h <- asks botSocket
    let msg = cmd ++ " " ++ args ++ "\r\n"
    liftIO $ hPutStr h msg          -- ارسال پیام روی سیم (شبکه)
    liftIO $ putStr ("> " ++ msg)   -- نمایش پیام ارسال‌شده در خط فرمان

برای اینکه هم وضعیت و هم IO را استفاده کنیم، از تابع liftIO برای بالابردن (lift) یک عبارت IO به درون موناد Net استفاده می‌کنیم؛ این کار آن تابع IO را در دسترس کدِ درون موناد Net قرار می‌دهد.

hs-- واردشده از Control.Monad.IO.Class
liftIO :: IO a -> Net a

ربات مونادیک، دارای وضعیت و مجهز به مدیریت استثنا (exception)، در تمام شکوهش:

hs-- فایل 4.hs

import Control.Exception              -- کتابخانهٔ پایه (base)
import Control.Monad.IO.Class         --
import Data.List                      --
import System.Exit                    --
import System.IO                      --
import qualified Network.Socket as N  -- بستهٔ network
import Control.Monad.Trans.Reader     -- بستهٔ transformers

-- گزینه‌های پیکربندی
myServer = "irc.libera.chat" :: String
myPort   = 6667 :: N.PortNumber
myChan   = "#tutbot-testing" :: String
myNick   = "tutbot" :: String

-- برپایی کنش‌های آغاز و پایان، و اجرای حلقهٔ اصلی
main :: IO ()
main = bracket connect disconnect loop
  where
    disconnect = hClose . botSocket
    loop st = runReaderT run st

-- موناد «Net»، یک لفاف بر روی IO که وضعیت تغییرناپذیر ربات را حمل می‌کند.
data Bot = Bot { botSocket :: Handle }
type Net = ReaderT Bot IO

-- اتصال به سرور و بازگرداندن وضعیت اولیهٔ ربات
connect :: IO Bot
connect = notify $ do
    h <- connectTo myServer myPort
    return (Bot h)
  where
    notify a = bracket_
      (putStrLn ("Connecting to " ++ myServer ++ " ...") >> hFlush stdout)
      (putStrLn "done.")
      a

-- اتصال به سرور و بازگرداندن یک Handle (کمکی برای connect)
connectTo :: N.HostName -> N.PortNumber -> IO Handle
connectTo host port = do
    addr : _ <- N.getAddrInfo Nothing (Just host) (Just (show port))
    sock <- N.socket (N.addrFamily addr) (N.addrSocketType addr) (N.addrProtocol addr)
    N.connect sock (N.addrAddress addr)
    N.socketToHandle sock ReadWriteMode

-- حالا در موناد Net هستیم؛ یعنی با موفقیت متصل شده‌ایم
-- پیوستن به یک کانال و شروع پردازش فرمان‌ها
run :: Net ()
run = do
    write "NICK" myNick
    write "USER" (myNick ++ " 0 * :tutorial bot")
    write "JOIN" myChan
    listen

-- ارسال پیام به سروری که در حال حاضر به آن متصل هستیم
write :: String -> String -> Net ()
write cmd args = do
    h <- asks botSocket
    let msg = cmd ++ " " ++ args ++ "\r\n"
    liftIO $ hPutStr h msg          -- ارسال پیام روی سیم (شبکه)
    liftIO $ putStr ("> " ++ msg)   -- نمایش پیام ارسال‌شده در خط فرمان

-- پردازش هر خط دریافتی از سرور
listen :: Net ()
listen = forever $ do
    h <- asks botSocket
    line <- liftIO $ hGetLine h
    liftIO (putStrLn line)
    let s = init line
    if isPing s then pong s else eval (clean s)
  where
    forever :: Net () -> Net ()
    forever a = do a; forever a

    clean :: String -> String
    clean = drop 1 . dropWhile (/= ':') . drop 1

    isPing :: String -> Bool
    isPing x = "PING :" `isPrefixOf` x

    pong :: String -> Net ()
    pong x = write "PONG" (':' : drop 6 x)

-- توزیع یک فرمان
eval :: String -> Net ()
eval "!quit" = write "QUIT" ":Exiting" >> liftIO exitSuccess
eval x | "!id " `isPrefixOf` x = privmsg (drop 4 x)
eval _ = return ()  -- هر چیز دیگری را نادیده بگیر

-- ارسال یک privmsg به کانال و سرور فعلی
privmsg :: String -> Net ()
privmsg msg = write "PRIVMSG" (myChan ++ " :" ++ msg)

توجه کنید که برای تفریح یک ساختار کنترلی جدید به نام notify هم اضافه کردیم. حالا تقریباً تمام شده‌ایم! بیایید این ربات را اجرا کنیم. با استفاده از runhaskell:

shell   $ runhaskell 4.hs

یا با استفاده از GHC:

shell   $ ghc --make 4.hs -o tutbot

   Compiling Main             ( 4.hs, 4.o )
   Linking ...
   $ ./tutbot

   15:28  dons> !id all good?

پس حالا رباتی داریم با وضعیت مونادیک فقط‌خواندنیِ صریح، مدیریت خطا و برخی عملیات پایهٔ IRC. اگر بخواهیم وضعیت خواندن-نوشتن (read-write) اضافه کنیم، فقط کافی است ترانسفورمر ReaderT را به StateT تغییر دهیم.

گسترش ربات (Extending the bot)

بیایید یک فرمان پایهٔ جدید پیاده‌سازی کنیم: پیگیری زمان کار (uptime). از نظر مفهومی، باید زمانی را که ربات شروع به کار می‌کند به خاطر بسپاریم. سپس، اگر کاربری درخواست داد، مجموع زمان اجرا را حساب می‌کنیم و آن را به‌صورت یک رشته چاپ می‌کنیم. راه زیبایی برای این کار این است که وضعیت ربات را با یک فیلد زمان شروع گسترش دهیم:

hsimport Data.Time
hs-- نوع به‌روزشدهٔ Bot
data Bot = Bot { botSocket :: Handle, startTime :: UTCTime }

سپس می‌توانیم تابع connect اولیه را نیز اصلاح کنیم تا زمان شروع را هم تنظیم کند.

hs-- اتصال به سرور و بازگرداندن وضعیت اولیهٔ ربات
connect :: IO Bot
connect = notify $ do
    t <- getCurrentTime
    h <- connectTo myServer myPort
    return (Bot h t)

سپس یک مورد جدید به تابع eval اضافه می‌کنیم تا درخواست‌های uptime را مدیریت کند:

hseval "!uptime" = uptime >>= privmsg
eval ...

این کار تابع uptime را اجرا می‌کند و نتیجه را به سرور بازمی‌گرداند. خود uptime به این شکل است:

hs-- دریافت زمان کار (uptime) فعلی
uptime :: Net String
uptime = do
  now <- liftIO getCurrentTime
  zero <- asks startTime
  return (pretty (diffUTCTime now zero))

یعنی، در موناد Net، زمان فعلی و زمان شروع را پیدا می‌کنیم و سپس تفاضل را محاسبه می‌کنیم و آن عدد را به‌صورت یک رشته برمی‌گردانیم. به‌جای استفاده از نمایش معمول تاریخ‌ها، قالب‌بند سفارشی خودمان را برای تاریخ‌ها می‌نویسیم:

hs-- نمایش زیبای تاریخ در قالب '1d 9h 9m 17s'
pretty :: NominalDiffTime -> String
pretty diff =
    unwords
      . map (\(t, unit) -> show t ++ unit)
      $ if null diffs then [(0, "s")] else diffs
  where
    diffs :: [(Integer, String)]
    diffs = filter ((/= 0) . fst)
      $ decompose [(86400, "d"), (3600, "h"), (60, "m"), (1, "s")] (floor diff)
    decompose [] _ = []
    decompose ((secs, unit) : metrics) t =
      let (n, t') = t `divMod` secs
      in (n, unit) : decompose metrics t'

و تمام. اجرای ربات با این فرمان جدید:

shell   16:03 -- tutbot [n=tutbot@aa.bb.cc.dd] has joined #tutbot-testing
   16:03  dons> !uptime
   16:03  tutbot> 51s
   16:03  dons> !uptime
   16:03  tutbot> 1m 1s
   16:12  dons> !uptime
   16:12  tutbot> 9m 46s

از اینجا به کجا؟ (Where to now?)

این فقط یک نمونهٔ کوچک از برنامه‌نویسی کاربردی (application programming) در هسکل است و تنها به گوشه‌ای از قدرت ارزیابی تنبل، تایپ ایستا (static typing)، افکت‌های مونادیک و توابع مرتبه‌بالای هسکل اشاره می‌کند. دربارهٔ این موضوعات بسیار بسیار بیشتر برای گفتن وجود دارد. چند نقطهٔ شروع:

  • کدهای هسکل بیشتر
  • یادگیری هسکل
  • گالری‌ای از برنامه‌های شبکه‌ای در هسکل

  • برخی فرمان‌ها را از لامبدابات (Lambdabot) منتقل (port) کنید.
