باندل‌کننده ماژول خودت را بساز — Minipack

⚙ زبان: JavaScript ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور «Minipack» از رون آمی است که باندل‌رهای شبیه به webpack را در چند صد خط JavaScript می‌سازد.
↗ مشاهده منبع اصلی

باندلر چه کار می‌کند؟

وقتی پروژهٔ جاوااسکریپت شما از ماژول‌های ES Modules استفاده می‌کند، مرورگر نم‌تواند همهٔ آن‌ها را در یک فایل HTML بخواند (مگر با import map). باندلر (webpack، Rollup) همهٔ ماژول‌ها را به یک فایل اجرایی واحد تبدیل می‌کند. Minipack این فرآیند را با سه مرحلهٔ اصلی پیاده می‌کند: استخراج وابستگی‌ها، ساخت گراف و تولید باندل.

مرحلهٔ ۱: خواندن و تجزیه

هر فایل ماژول باید به AST تجزیه شود تا عبارت‌های import پیدا شوند. با `babel-core` و `babel-traverse` این کار ساده است:

JavaScript// خواندن فایل، تجزیه به AST و یافتن وابستگی‌های import
function createAsset(filename) {
  const source = fs.readFileSync(filename, 'utf-8');

  // تجزیه به درخت نحو (AST)
  const ast = babel.parse(source, { sourceType: 'module' });

  const dependencies = [];
  // پیمایش درخت و پیدا کردن import ها
  traverse(ast, {
    ImportDeclaration: ({ node }) => {
      dependencies.push(node.source.value);
    }
  });

  // تبدیل ES Modules به CommonJS برای استفاده در باندل
  const { code } = babel.transformFromAst(ast, null, {
    presets: ['env']
  });

  return { filename, dependencies, code };
}

هر «asset» یعنی یک فایل با وابستگی‌هایش — بلوک ساخت گراف.

مرحلهٔ ۲: ساخت گراف وابستگی

با پیمایش BFS از فایل ورودی، همهٔ ماژول‌ها را جمع می‌کنیم و به هرکدام یک شناسه (id) می‌دهیم. گراف نهایی نقشهٔ id → asset است:

JavaScript// ساخت graph با پیمایش breadth-first
function createGraph(entry) {
  const mainAsset = createAsset(entry);
  const queue = [mainAsset];

  for (const asset of queue) {
    asset.mapping = {};
    const dirname = path.dirname(asset.filename);

    asset.dependencies.forEach(relativePath => {
      const absolutePath = path.join(dirname, relativePath);
      const child = createAsset(absolutePath);
      asset.mapping[relativePath] = child.id;
      queue.push(child);
    });
  }
  return queue;
}

`mapping` همان جدولی است که نام‌مسیرِ نسبی را به id تبدیل می‌کند؛ در اجرای باندل استفاده می‌شود.

مرحلهٔ ۳: توليد باندل

حالا همهٔ assets به همراه یک loader کوچک (که `require` را شبیه‌سازی می‌کند) در یک IIFE کنار هم قرار می‌گیرند:

JavaScript// ساخت خروجی: هر ماژول داخل function با require-local
function bundle(graph) {
  let modules = '';

  graph.forEach(mod => {
    modules += `${mod.id}: [
      function (require, module, exports) {
        ${mod.code}
      },
      ${JSON.stringify(mod.mapping)},
    ],`;
  });

  return `(function(modules) {
    function require(id) {
      const [fn, mapping] = modules[id];
      function localRequire(name) { return require(mapping[name]); }
      const module = { exports: {} };
      fn(localRequire, module, module.exports);
      return module.exports;
    }
    require(0);
  })({${modules}})`;
}

این `require` داخلی دقیقاً کاری را می‌کند که runtime وب‌پک انجام می‌دهد: حل وابستگی‌ها از روی mapping و اجرای ماژول‌ها.

جمع‌بندی

Minipack در کمتر از ۲۰۰ خط نشان می‌دهد که باندلرها جادو نیستند: تجزیه، گراف و runtime. بعد از این، درک شما از رفتار واقعی webpack (tree shaking، chunking) بسیار عمیق‌تر می‌شود.
