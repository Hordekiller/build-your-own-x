Redux بنویسیم! — ساخت Redux از صفر (وبلاگ جما سافتور)

⚙ زبان: JavaScript ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور مقالهٔ «Let's Write Redux!» از مارک سنت اونگ (Marc St. Onge) در وبلاگ جما سافتور (Jama Software) است. در این مقاله Redux با رویکرد «تست‌محور» (TDD) قدم‌به‌قدم ساخته می‌شود.
↗ مشاهده منبع اصلی

۱. رویکرد مقاله: تست‌محور (TDD)

ویژگی متمایز این آموزش این است که Redux را با روش تست‌محور می‌سازد: برای هر تابع API اول تست می‌نویسیم (که شکست می‌خورد)، بعد آن را پیاده می‌کنیم تا تست سبز شود. این روش هم منطق Redux را روشن می‌کند و هم عادت درست نوشتن کد را تقویت می‌کند. ابزارها: Jest برای تست و Babel برای ماژول‌ها.

نکته: اگر با TDD آشنا نیستید، این مقاله یک نمونهٔ آموزشی عالی است؛ چرخهٔ «قرمز ← سبز ← بازسازی» را با یک پروژهٔ واقعی تمرین می‌کنید.

۲. طراحی API از نگاه مصرف‌کننده

قبل از نوشتن کد، مشخص می‌کنیم مصرف‌کنندهٔ Redux چه API ای می‌بیند — همان API واقعی Redux:

jsconst store = createStore(reducer, initialState);

store.getState();              // خواندن state فعلی
store.dispatch(action);        // ارسال اکشن (الزاماً یک شیء با type)
store.subscribe(listener);     // شنیدن تغییرات؛ خروجی: تابع لغو اشتراک

سپس تست‌ها دقیقاً همین قرارداد را قفل می‌کنند. مثلاً اولین تست‌ها:

jsdescribe('createStore', () => {
  it('حالت اولیه را برمی‌گرداند', () => {
    const reducer = (state = {}, action) => state;
    const store = createStore(reducer, { count: 0 });
    expect(store.getState()).toEqual({ count: 0 });
  });

  it('با dispatch اکشن state را به‌روز می‌کند', () => {
    const reducer = (state = { count: 0 }, action) => {
      if (action.type === 'ADD') return { count: state.count + action.payload };
      return state;
    };
    const store = createStore(reducer);
    store.dispatch({ type: 'ADD', payload: 5 });
    expect(store.getState()).toEqual({ count: 5 });
  });
});

۳. پیاده‌سازی createStore

برای سبز شدن تست‌ها، createStore را پیاده می‌کنیم — همان اجرای کلاسیک با closure:

jsexport function createStore(reducer, initialState) {
  let state = initialState;
  const listeners = [];

  function getState() {
    return state;
  }

  function dispatch(action) {
    // reducer باید تابعی خالص باشد: state جدید برمی‌گرداند، نه دستکاری
    state = reducer(state, action);
    listeners.forEach((listener) => listener());
    return action;
  }

  function subscribe(listener) {
    listeners.push(listener);
    return function unsubscribe() {
      const index = listeners.indexOf(listener);
      if (index > -1) listeners.splice(index, 1);
    };
  }

  return { getState, dispatch, subscribe };
}

دقت کنید: dispatch مقداری برنمی‌گرداند که کسی به آن وابسته باشد؛ همهٔ مصرف‌کننده‌ها باید state را از getState بخوانند و از طریق subscribe از تغییرات باخبر شوند.

۴. تست subscribe و لغو اشتراک

jsit('شنونده‌ها هنگام dispatch صدا زده می‌شوند', () => {
  const store = createStore((s = 0, a) => (a.type === 'INC' ? s + 1 : s));
  const spy = jest.fn();
  store.subscribe(spy);
  store.dispatch({ type: 'INC' });
  expect(spy).toHaveBeenCalledTimes(1);
});

it('unsubscribe شنونده را حذف می‌کند', () => {
  const store = createStore((s = 0, a) => (a.type === 'INC' ? s + 1 : s));
  const spy = jest.fn();
  const unsubscribe = store.subscribe(spy);
  unsubscribe();
  store.dispatch({ type: 'INC' });
  expect(spy).not.toHaveBeenCalled();
});

۵. ترکیب reducerها

بخش بعدی مقاله combineReducers است — این‌بار هم با تست شروع می‌شود: هر کلید state توسط یک reducer مستقل مدیریت می‌شود و در کنار هم یک درخت state می‌سازند. نکتهٔ پیاده‌سازی: هنگام اجرا، به هر reducer فقط بخش خودش از state داده می‌شود (نه کل state) تا هیچ reducer ای از بخش‌های دیگر خبردار نشود:

jsexport function combineReducers(reducers) {
  return function combinedReducer(state = {}, action) {
    const nextState = {};
    for (const key of Object.keys(reducers)) {
      nextState[key] = reducers[key](state[key], action);
    }
    return nextState;
  };
}

۶. جمع‌بندی و درس‌ها

  • کل Redux در یک تابع createStore و یک تابع combineReducers خلاصه می‌شود — بقیه ابزارها راحتی‌اند، نه ضرورت.
  • روش TDD به این پروژه خیلی می‌آید چون قراردادها (contract) از اول مشخص‌اند: state، action و reducer.
  • پس از این آموزش، کد واقعی Redux را در گیت‌هاب باز کنید؛ می‌بینید createStore.js آن فقط کمی از نسخهٔ ما کامل‌تر است (مثلاً validators برای جلوگیری از استفادهٔ اشتباه).
