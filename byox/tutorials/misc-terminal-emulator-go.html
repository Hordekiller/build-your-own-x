ترمینال و pseudo-terminal

یک ترمینال رندری می‌کند که برنامه‌ها در آن اجرا می‌شوند. برای اینکه یک برنامهٔ واقعی (مثل sh) داخل ترمینال شما اجرا شود، به یک pty (پایانهٔ شبه) نیاز دارید: جفت master/slave که ورودی و خروجی را به‌هم می‌پیوندد. در Go، کتابخانهٔ `creack/pty` این کار را ساده می‌کند.

معماری: دو حلقه

شبیه‌ساز دو جریان داده دارد: خروجیِ برنامه → نمایش، و ورودی کاربر → برنامه. این دو به‌صورت همزمان اجرا می‌شوند. نمایش با `termbox-go` (یک کتابخانهٔ TUI) انجام می‌شود:

Gofunc runTerminal(ptmx *os.File) {
    go func() {
        // حلقهٔ خواندن خروجی برنامه و نمایش آن
        buf := make([]byte, 4096)
        for {
            n, err := ptmx.Read(buf)
            if err != nil { return }
            termbox.SetCell(x, y, rune(buf[i]), fg, bg)
            ...
        }
    }()

    // حلقهٔ رویدادهای کیبورد: ارسال به ptmx
    for {
        ev := termbox.PollEvent()
        if ev.Type == termbox.EventKey {
            _, err := ptmx.Write([]byte{byte(ev.Ch)})
            if err != nil { ... }
        }
    }
}

در این‌جا `ptmx` هم «بخوان» و هم «بنویس» می‌شود: خروجی برنامه را می‌خوانیم و روی grid نمایش می‌دهیم، و کلیدهای کاربر را به برنامه می‌فرستیم.

مدیریت escape sequences

تمام ترمینال‌ها باید دنباله‌های ANSI را تفسیر کنند. ساده‌ترین طراحی، یک حالت‌ماشین کوچک است: وقتی کاراکتر `\x1b` دیده شد، بقیه را تا پایان کد (مثل `[m`) جمع کن:

Go// تفسیر سادهٔ کدهای رنگی ANSI
func interpretANSI(data []byte) {
    if len(data) > 2 && data[0] == 0x1b && data[1] == '[' {
        // پارس پارامترها تا حرف پایانی
        parts := strings.Split(string(data[2:len(data)-1]), ";")
        if len(parts) > 0 {
            switch parts[0] {
            case "31": fg = termbox.ColorRed
            case "32": fg = termbox.ColorGreen
            case "0":  fg = termbox.ColorDefault
            }
        }
    }
}

با این تابع ساده، خروجی‌های رنگی `ls --color` به‌درستی نمایش داده می‌شوند.
