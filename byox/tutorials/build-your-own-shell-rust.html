شل خودت را با رست بساز (Build Your Own Shell using Rust)

⚙ زبان: Rust ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی آموزش «Build Your Own Shell using Rust» از جاش مک‌گیگان (Josh Mcguigan، نوامبر ۲۰۱۸) است — ساختن شل گام‌به‌گام با رست، از چند خط ابتدایی تا پایپ‌ها، در کمتر از ۱۰۰ خط کد. کد نهایی (bubble-shell) روی گیت‌هاب موجود است.
↗ مشاهده منبع اصلی

شل چیست؟

شل برنامه‌ای است که به شما اجازه می‌دهد کامپیوترتان را کنترل کنید؛ بیشترِ این کار را با آسان‌کردنِ اجرای برنامه‌های دیگر انجام می‌دهد. اما شل به‌تنهایی برنامه‌ای تعاملی نیست! بیشتر کاربران از طریق یک «شبیه‌ساز ترمینال» با شل تعامل می‌کنند:

شبیه‌ساز ترمینال (که معمولاً فقط به آن «ترمینال» می‌گویند) «فقط همان پنجره است». یک برنامهٔ متنی اجرا می‌کند که به‌صورت پیش‌فرض شلِ ورود شماست. وقتی در پنجره تایپ می‌کنید، ترمینال کاراکترها را در پنجره رسم می‌کند و به‌همان صورت به stdin شل می‌فرستد؛ و خروجی stdout و stderr شل به ترمینال می‌رود و ترمینال آن را در پنجره رسم می‌کند. — کاربر geirha

در این آموزش شل خودمان را می‌نویسیم و داخل ترمینال معمولی‌مان اجرا می‌کنیم. (مثال‌ها در Rust Playground اجرا نمی‌شوند چون از stdin یا فرایندهای طولانی پشتیبانی نمی‌کند.)

نقطهٔ شروع — ساده‌ترین شل ممکن

فقط چند خط رست کافی است: stdin().read_line بلاک می‌شود تا کاربر Enter را بزند و سپس کل ورودی (با خط جدید) را در رشتهٔ ما می‌نویسد؛ با input.trim() خط جدید را می‌کنیم و دستور را اجرا می‌کنیم:

rustfn main() {
    let mut input = String::new();
    stdin().read_line(&mut input).unwrap();

    let command = input.trim();   // read_line یک خط جدید انتهایی می‌گذارد

    Command::new(command)
        .spawn()
        .unwrap();
}

بعد از cargo run یک مکان‌نما می‌بینید که منتظر ورودی است؛ ls را بزنید، محتوای پوشه چاپ می‌شود و بعد شل خارج می‌شود.

پذیرش چند دستور و آرگومان‌ها

برای اینکه شل بعد از یک دستور خارج نشود، کد را داخل loop می‌بریم و روی هر فرزند wait صدا می‌زنیم تا قبل از تمام‌شدن فرایند فعلی، اعلانِ جدید چاپ نشود (و برای تشخیص ورودی کاربر از خروجی فرایندها، > چاپ می‌کنیم که باید صریحاً stdout().flush() شود):

rustfn main() {
    loop {
        print!("> ");
        stdout().flush();

        let mut input = String::new();
        stdin().read_line(&mut input).unwrap();

        let command = input.trim();

        let mut child = Command::new(command).spawn().unwrap();
        child.wait();   // تا پایان این دستور، دستور بعدی نگیر
    }
}

حالا ls -a کرش می‌کند چون شلِ ما از آرگومان بی‌خبر است و دارد برنامهِ به‌نام ls -a را اجرا می‌کند. راه‌حل: ورودی را روی کاراکترهای فاصله می‌شکنیم؛ هرچه قبل از اولین فاصله است نام دستور است و بقیه آرگومان‌ها:

rustlet mut parts = input.trim().split_whitespace();
let command = parts.next().unwrap();
let args = parts;

let mut child = Command::new(command)
    .args(args)
    .spawn()
    .unwrap();
child.wait();

Builtin ها — چرا cd باید در شل پیاده شود؟

دستورهایی هستند که شل نمی‌تواند به فرایند دیگری بسپاردشان: چیزهایی که به وضعیتِ درونیِ خودِ شل مربوط‌اند و باید توسط خود شل پیاده شوند. معروف‌ترین مثال cd است (برای دلیلش این دو لینک مرجع‌اند: چرا cd باید builtin باشد و چرا با این حال یک برنامهٔ cd هم وجود دارد). پیاده‌سازی:

rustmatch command {
    "cd" => {
        // اگر مسیری داده نشد، پیش‌فرض '/'
        let new_dir = args.peekable().peek().map_or("/", |x| *x);
        let root = Path::new(new_dir);
        if let Err(e) = env::set_current_dir(&root) {
            eprintln!("{}", e);
        }
    },
    command => {
        let mut child = Command::new(command).args(args).spawn().unwrap();
        child.wait();
    }
}

مدیریت خطا و دستور exit

اگر دستوری که وجود ندارد وارد کنید، شل‌های قبلی کرش می‌کردند. اینجا خطا به‌شکلی شایسته چاپ و به کاربر اجازه داده می‌شود دستور دیگری وارد کند. چون «دستور بد» تا قبل از این، راهی آسان برای بستن شل بود، builtin دیگری به‌نام exit هم اضافه می‌کنیم:

rust"exit" => return,
command => {
    let child = Command::new(command).args(args).spawn();
    match child {
        Ok(mut child) => { child.wait(); },
        Err(e) => eprintln!("{}", e),  // مدیریت شایستهٔ ورودی ناقص
    };
}

پایپ‌ها

کارکردن در شلی بدون پایپ دشوار است. | به شل می‌گوید خروجی دستور اول را به ورودی دستور دوم بریزد؛ مثلاً ls | grep Cargo: (۱) ls فهرست فایل‌ها را می‌دهد (۲) شل این فهرست را به grep پایپ می‌کند (۳) grep فیلتر می‌کند و فقط فایل‌های دارای «Cargo» را چاپ می‌کند. پیاده‌سازی پایه: ورودی را روی " | " می‌شکنیم (peekable تا بدانیم روی آخرین دستور هستیم) و خروجیِ هر فرایند، stdinِ بعدی می‌شود:

rustlet mut commands = input.trim().split(" | ").peekable();
let mut previous_command = None;

while let Some(command) = commands.next() {
    let mut parts = command.trim().split_whitespace();
    let command = parts.next().unwrap();
    let args = parts;

    match command {
        "cd" => { /* ... */ previous_command = None; },
        "exit" => return,
        command => {
            let stdin = previous_command
                .map_or(Stdio::inherit(),
                        |output: Child| Stdio::from(output.stdout.unwrap()));

            let stdout = if commands.peek().is_some() {
                Stdio::piped()       // دستور دیگری پشت این است
            } else {
                Stdio::inherit()     // دستور آخر؛ به stdout شل
            };

            let output = Command::new(command)
                .args(args).stdin(stdin).stdout(stdout).spawn();

            match output {
                Ok(output) => { previous_command = Some(output); },
                Err(e) => { previous_command = None; eprintln!("{}", e); },
            };
        }
    }
}

if let Some(mut final_command) = previous_command {
    final_command.wait();  // تا پایان دستور آخر صبر کن
}

جمع‌بندی

در کمتر از ۱۰۰ خط رست شلی ساخته‌ایم که برای بسیاری از کارهای روزمره کاربردی است، اما شل واقعی امکانات خیلی بیشتری دارد. کتابچهٔ آنلاین bash در گنو با فهرست امکانات شل نقطهٔ عالی برای شروع است. نویسنده تصریح می‌کند که این یک پروژهٔ یادگیری است و هر جا بین سادگی و استحکام تعارض بود، بیشتر سادگی را برگزیده. کد این شل (bubble-shell) در github.com/JoshMcguigan/bubble-shell موجود است.
