مقدمه

اگر این پست را می‌خوانید، احتمالاً از گیت استفاده می‌کنید یا می‌خواهید استفاده کنید. من طرفدار پر و پا قرص گیت هستم و عاشق پست‌هایی هستم که در آن‌ها کسی برای فهمیدنِ طرز کار یک فناوری، تکه‌ای از همان فناوری را پیاده می‌کند. منطقش روشن است: اگر چیزی را پیاده کرده باشید، مسلماً می‌دانید چگونه کار می‌کند. این هم یکی از آن پست‌هاست که برای گسترش عشق‌ام به گیت نوشته‌ام. بله، گیت را پیاده می‌کنیم!... در جاوااسکریپت.

این قسمت مفاهیم پایه زیر را پیاده می‌کند:

  1. مخزن (Repository)
  2. کامیت (Commit)
  3. زنجیره‌سازی کامیت‌ها
  4. شاخه (Branch)

گیت چیست؟

تعریف بسیار ساده‌ای از گیت در kernel.org هست:

«گیت را بهتر است ابزاری برای ذخیره تاریخچه مجموعه‌ای از فایل‌ها بدانیم.» — kernel.org

بله، اساساً به همین دلیل از گیت استفاده می‌شود: حفظ تاریخچه تغییرات یک پروژه.

مخزن (Repository)

وقتی می‌خواهید در پروژه‌تان از گیت استفاده کنید، چیزی به نام مخزن می‌سازید. تعریف رسمی خیلی پیچیده است؛ ساده‌اش کنیم: یک مخزن گیت را مجموعه‌ای از همه چیزهای مرتبط با گیت در نظر بگیرید. وقتی پوشه پروژه را به مخزن گیت تبدیل می‌کنید، گیت تعدادی چیز داخلی در آن می‌سازد و در آن محصور می‌کند.

یک کلاس ساده به نام Git می‌سازیم که معرف مخزن است:

javascriptfunction Git(name) {
  this.name = name; // نام مخزن
}

ساخت مخزن فقط به‌سادگی ساختن نمونه‌ای از کلاس Git با نام مخزن است:

javascriptvar repo = new Git("my-repo");
// دستور واقعی:
// > git init

کامیت (Commit)

مفهوم بعدی کامیت است. به زبان خیلی ساده، یک کامیت «عکس فوری» از محتوای پروژه شماست. همین کامیت‌ها وقتی به هم زنجیر می‌شوند، تاریخچه پروژه شما را می‌سازند.

کلاس ساده Commit یک شناسه برای ارجاع به آن و یک تغییر شامل عکس فوری تغییرات دارد. (درک نحوه واقعی ذخیره تغییرات خارج از حوصله این پیاده‌سازی است؛ فرض می‌کنیم هر کامیت تغییراتش را همراه دارد.) گیت اجازه می‌دهد به هر کامیت یک پیام توصیفی بدهید که «پیام کامیت» نام دارد:

javascriptfunction Commit(id, message) {
  this.id = id;
  this.message = message;
}

توانایی ساخت کامیت را به کلاس Git اضافه می‌کنیم. کلاس گیت شناسه کامیت‌ها را با یک شمارنده به نام lastCommitId پیگیری می‌کند:

javascriptfunction Git() {
  this.lastCommitId = -1;
}

Git.prototype.commit = function(message) {
  var commit = new Commit(++this.lastCommitId, message);
  return commit;
};

repo.commit("Make commit work");
// دستور واقعی:
// > git commit -m "Make commit work"

نکته: در گیت واقعی شناسه کامیت یک عدد ۴۰ رقم هگزایSHA-1 است؛ برای سادگی از اعداد صحیح استفاده می‌کنیم.

تاریخچه کامیت‌ها — زنجیره‌سازی

گیت فرمان log دارد که تاریخچه کامیت‌ها را به ترتیب زمانی معکوس نشان می‌دهد (اول جدیدترین). این فرمان را به‌صورت متد روی کلاس Git پیاده می‌کنیم که آرایه‌ای از کامیت‌ها به ترتیب معکوس برمی‌گرداند.

برای پیاده‌سازی منطق آن دو نیاز داریم: (۱) دانستن آخرین کامیت و (۲) هر کامیت باید بداند کدام کامیت قبل از آن ساخته شده.

نیاز اول: HEAD

گیت چیزی به نام HEAD دارد. در گیت واقعی HEAD صرفاً اشاره‌گری به شاخه فعلی شماست. (چون شاخه‌ها را هنوز پوشش نداده‌ایم، فعلاً تعریف را شل می‌گیریم.) به کلاس گیت یک خاصیت HEAD اضافه می‌کنیم که به آبجکت کامیت آخرین کامیت اشاره می‌کند و در هر commit به‌روز می‌شود:

javascriptfunction Git(name) {
  this.name = name; // نام مخزن
  this.lastCommitId = -1; // ردیابی شناسه آخرین کامیت
  this.HEAD = null; // ارجاع به آخرین کامیت
}

Git.prototype.commit = function(message) {
  var commit = new Commit(++this.lastCommitId, message);
  this.HEAD = commit;
  return commit;
};

نیاز دوم: والد (parent)

کامیت‌ها در گیت با یک ساختار داده به نام لیست پیوندی کنار هم نگه داشته می‌شوند. هر آیتم اشاره‌گری به آیتم والدش ذخیره می‌کند تا از هر آیتم به والدش برسیم و با دنبال‌کردن اشاره‌گرها فهرست مرتب بگیریم:

javascriptfunction Commit(id, parent, message) {
  this.id = id;
  this.parent = parent;
  this.message = message;
}

Git.prototype.commit = function (message) {
  // شناسه آخرین کامیت را زیاد کن و به کامیت جدید بده.
  var commit = new Commit(++this.lastCommitId, this.HEAD, message);
  this.HEAD = commit;
  return commit;
};

حالا تابع log():

javascriptGit.prototype.log = function () {
  // از HEAD شروع کن
  var commit = this.HEAD,
    history = [];
  while (commit) {
    history.push(commit);
    // والد را دنبال کن
    commit = commit.parent;
  }
  return history;
};
// قابل استفاده به‌صورت repo.log();
// دستور واقعی:
// > git log

شاخه‌ها (Branches)

به جذاب‌ترین و قدرتمندترین ویژگی گیت رسیدیم. شاخه چیست و چه کاربردی دارد؟ فرض کنید روی پروژه‌ای کار می‌کنید و مدام کامیت می‌زنید. در مقطعی، شما یا یکی از هم‌تیمی‌ها می‌خواهد روی کار فعلی آزمایشی انجام دهد، مثلاً الگوریتمی متفاوت. می‌توانید آن کامیت‌های آزمایشی را بسازید، اما یادتان باشد این آزمایش شماست و قرار نیست حتماً در پروژه اصلی بماند. این‌طوری پروژه اصلی‌تان را آلوده کرده‌اید.

شاخه‌ها به کمک می‌آیند. شاخه چیزی جز یک اشاره‌گر به یک کامیت نیست. جدی، همین است. این همان چیزی است که شاخه‌ها را در گیت این‌قدر سبک و مصرفی می‌کند. می‌گویید HEAD دقیقاً همین بود؟ درست است؛ تنها تفاوت این است که HEAD یکی است (چون در هر لحظه فقط روی یک کامیت هستید)، اما شاخه‌ها می‌توانند زیاد باشند و هرکدام به یک کامیت اشاره کنند.

هر مخزن گیت هنگام مقداردهی با یک شاخه پیش‌فرض به نام master می‌آید. با نمودارهای git-scm.com بفهمیم:

  • مخزن جدید می‌سازید و چند کامیت می‌زنید → فقط master
  • شاخه جدید testing می‌سازید → فقط یک اشاره‌گر جدید به آخرین کامیت
  • HEAD به شاخه فعلی اشاره می‌کند
  • روی شاخه testing کامیت می‌زنید → حالا فقط اشاره‌گر testing حرکت می‌کند، نه master

با همین منطق، تاریخچه هر شاخه با دنبال‌کردن اشاره‌گرها از HEAD شاخه قابل بازسازی است — همان الگوریتم log() ما.

کدنویسی

کلاس Branch: نام و ارجاع به یک کامیت دارد. و کلاس گیت فهرست شاخه‌ها و HEAD را به شاخه فعلی نگه می‌دارد (master هنگام ساخت):

javascriptfunction Branch(name, commit) {
  this.name = name;
  this.commit = commit;
}

function Git(name) {
  this.name = name; // نام مخزن
  this.lastCommitId = -1; // ردیابی شناسه آخرین کامیت
  this.branches = []; // فهرست همه شاخه‌ها
  var master = new Branch("master", null); // هنوز کامیتی نیست، پس null
  this.branches.push(master); // شاخه master را ذخیره کن
  this.HEAD = master; // HEAD به شاخه فعلی اشاره می‌کند
}

تغییرات لازم در commit و log چون HEAD دیگر به کامیت اشاره نمی‌کند بلکه به شاخه:

javascriptGit.prototype.commit = function(message) {
  // شناسه آخرین کامیت را زیاد کن و به کامیت جدید بده.
  var commit = new Commit(++this.lastCommitId, this.HEAD.commit, message);
  // اشاره‌گر شاخه فعلی را به کامیت جدید به‌روز کن
  this.HEAD.commit = commit;
  return commit;
};

Git.prototype.log = function () {
  // از کامیت HEAD شروع کن
  var commit = this.HEAD.commit, history = [];
  while (commit) {
    history.push(commit);
    commit = commit.parent;
  }
  return history;
};

checkout

برای سوییچ‌کردن بین شاخه‌ها، checkout را پیاده می‌کنیم: اگر شاخه با نام داده‌شده موجود باشد، HEAD را به آن اشاره می‌دهیم; اگر نباشد، شاخه جدیدی می‌سازیم (رفتار شبیه git checkout -b):

javascriptGit.prototype.checkout = function(branchName) {
  // از بین همه شاخه‌ها بگرد آیا شاخه‌ای با نام branchName هست
  for (var i = this.branches.length; i--; ) {
    if (this.branches[i].name === branchName) {
      // شاخه موجود پیدا شد
      console.log("Switched to existing branch: " + branchName);
      this.HEAD = this.branches[i];
      return this;
    }
  }
  // شاخه پیدا نشد؛ یکی جدید بساز
  var newBranch = new Branch(branchName, this.HEAD.commit);
  this.branches.push(newBranch);
  this.HEAD = newBranch;
  console.log("Switched to new branch: " + branchName);
  return this;
};
// دستور واقعی:
// > git checkout existing-branch
// > git checkout -b new-branch

آزمون نهایی — همان نمودارهایی که دیدیم (پاک‌ماندن تاریخچه master از کامیت‌های آزمایشی):

javascriptvar repo = new Git("test");
repo.commit("Initial commit");
repo.commit("Change 1");
console.assert(historyToIdMapper(repo.log()) === "1-0"); // باید ۲ کامیت نشان دهد
repo.checkout("testing");
repo.commit("Change 3");
console.assert(historyToIdMapper(repo.log()) === "2-1-0"); // باید ۳ کامیت نشان دهد
repo.checkout("master");
console.assert(historyToIdMapper(repo.log()) === "1-0"); // master پاک مانده
repo.commit("Change 3");
console.assert(historyToIdMapper(repo.log()) === "3-1-0"); // ادامه روی master با کامیت چهارم

پیاده‌سازی ما با تئوری هم‌سو است.

بعدش چه؟

در قدم‌های بعدی قصد دارم مفاهیمی مثل merge (fast-forward و 3-way) و rebase شاخه‌ها را پیاده کنم. نوشتنش برایم خیلی لذت‌بخش بود؛ امیدوارم شما هم لذت برده باشید.
