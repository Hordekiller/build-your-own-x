مقدمه

سریع‌ترین راه یادگیری نحوهٔ کار بلاک‌چین‌ها، ساختن یکی از آن‌هاست.

شما اینجا هستید چون مثل من از ظهور ارزهای رمزنگاری‌شده (Cryptocurrencies) هیجان‌زده‌اید و می‌خواهید بدانید بلاک‌چین‌ها (Blockchains) — فناوری بنیادین پشت آن‌ها — چگونه کار می‌کنند.

اما درک بلاک‌چین‌ها آسان نیست — یا دست‌کم برای من آسان نبود. من ویدیوهای فشرده و متراکم را به سختی دنبال کردم، از آموزش‌های ناقصی که به‌جا می‌گذاشتند گذشتم و با ناامیدیِ فزایندهٔ ناشی از کم بودنِ بیش از حدِ مثال‌ها دست‌وپنجه نرم کردم.

من یادگیری با عمل (learning by doing) را دوست دارم. این روش مرا وادار می‌کند در سطح کد با موضوع درگیر شوم و همین باعث می‌شود مطالب در ذهنم بماند. اگر شما هم همین رویکرد را دارید، در پایان این راهنما یک بلاک‌چین کارا خواهید داشت و درک درستی از نحوهٔ کار آن‌ها به دست خواهید آورد.

قبل از اینکه شروع کنید…

به یاد داشته باشید که بلاک‌چین یک زنجیرهٔ تغییرناپذیر (immutable) و ترتیبی از رکوردهایی است که «بلاک» (Block) نامیده می‌شوند. آن‌ها می‌توانند تراکنش‌ها، فایل‌ها یا هر دادهٔ دلخواه دیگری را در خود داشته باشند. اما نکتهٔ مهم این است که آن‌ها با استفاده از هش‌ها (hashes) به هم زنجیر شده‌اند.

اگر مطمئن نیستید هش چیست، این‌جا توضیحی برای آن آمده است.

این راهنما برای چه کسانی است؟ باید در خواندن و نوشتن پایتون پایه راحت باشید و همچنین درکی از نحوهٔ کار درخواست‌های HTTP داشته باشید؛ زیرا قرار است از طریق HTTP با بلاک‌چین خود صحبت کنیم.

به چه چیزهایی نیاز دارم؟ مطمئن شوید که پایتون 3.6 یا بالاتر (به‌همراه pip) نصب است. همچنین باید Flask و کتابخانهٔ فوق‌العادهٔ Requests را نصب کنید:

shellpip install Flask==0.12.2 requests==2.18.4

آه، همچنین به یک کلاینت HTTP مانند پست‌من (Postman) یا cURL نیاز دارید. اما هر ابزاری جواب می‌دهد.

کد نهایی کجاست؟ کد منبع اینجا در دسترس است.

گام ۱: ساختن یک بلاک‌چین

ویرایشگر متن یا IDE موردعلاقهٔ خود را باز کنید؛ من شخصاً PyCharm را دوست دارم. یک فایل جدید به نام blockchain.py بسازید. ما فقط از یک فایل استفاده خواهیم کرد؛ اما اگر گم شدید، همیشه می‌توانید به کد منبع مراجعه کنید.

نمایش یک بلاک‌چین (Representing a Blockchain)

یک کلاس Blockchain می‌سازیم که سازندهٔ (constructor) آن یک لیست خالی اولیه (برای ذخیرهٔ بلاک‌چین ما) و لیستی دیگر برای ذخیرهٔ تراکنش‌ها ایجاد می‌کند. در این‌جا طرح کلی کلاس ما آمده است:

        # یک تراکنش جدید به فهرست تراکنش‌ها اضافه می‌کند
        pass
    
    @staticmethod

        pass

    @property
    def last_block(self):
        # آخرین بلاک زنجیره را برمی‌گرداند
        pass

کلاس Blockchain ما مسئول مدیریت زنجیره است. تراکنش‌ها را ذخیره می‌کند و چند متد کمکی برای افزودن بلاک‌های جدید به زنجیره دارد. بیایید شروع به کامل‌کردن برخی از متدها کنیم.

یک بلاک چه شکلی است؟ (What does a Block look like?)

هر بلاک یک ایندکس (index)، یک مهر زمانی (timestamp) (به زمان یونیکس)، یک فهرست از تراکنش‌ها، یک اثبات (proof) (بعداً بیشتر دربارهٔ آن صحبت می‌کنیم) و هش بلاک قبلی دارد.

در این‌جا نمونه‌ای از شکل یک بلاک منفرد آمده است:

jsonblock = {
    'index': 1,
    'timestamp': 1506057125.900785,
    'transactions': [
        {
            'sender': "8527147fe1f5426f9dd545de4b27ee00",
            'recipient': "a77f5cdfa2934df3954a5c7c7da5df1f",
            'amount': 5,
        }
    ],
    'proof': 324984774000,
    'previous_hash': "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"
}

(نمونه‌ای از یک بلاک در بلاک‌چین ما)

در این مرحله، ایدهٔ «زنجیره» باید روشن شده باشد — هر بلاک جدید، هش بلاک قبلی را در درون خود دارد. این نکته حیاتی است، زیرا همین ویژگی است که به بلاک‌چین‌ها تغییرناپذیری (immutability) می‌بخشد: اگر مهاجمی بلاک اولیهٔ زنجیره را دستکاری کند، آنگاه همهٔ بلاک‌های بعدی هش‌های نادرستی خواهند داشت.

آیا این موضوع منطقی است؟ اگر نه، کمی وقت بگذارید تا کاملاً جا بیفتد — این ایدهٔ مرکزی پشت بلاک‌چین‌هاست.

افزودن تراکنش‌ها به یک بلاک (Adding Transactions to a Block)

به راهی برای افزودن تراکنش‌ها به یک بلاک نیاز داریم. متد new_transaction() ما مسئول این کار است و کاملاً سرراست است:

pyclass Blockchain(object):
    ...
    
    def new_transaction(self, sender, recipient, amount):
        """
        یک تراکنش جدید برای قرار گرفتن در بلاک بعدی که استخراج می‌شود ایجاد می‌کند
        :param sender: <str> آدرس فرستنده
        :param recipient: <str> آدرس گیرنده
        :param amount: <int> مقدار
        :return: <int> ایندکس بلاکی که این تراکنش را در خود نگه می‌دارد
        """

        self.current_transactions.append({
            'sender': sender,
            'recipient': recipient,
            'amount': amount,
        })

        return self.last_block['index'] + 1

بعد از اینکه new_transaction() تراکنش را به فهرست اضافه کرد، ایندکس بلاکی را برمی‌گرداند که تراکنش به آن اضافه خواهد شد — بلاک بعدی که قرار است استخراج شود. این موضوع بعداً برای کاربری که تراکنش را ارسال می‌کند مفید خواهد بود.

ایجاد بلاک‌های جدید (Creating new Blocks)

وقتی Blockchain ما نمونه‌سازی (instantiate) می‌شود، باید آن را با یک بلاک پیدایش (genesis) آغاز کنیم — بلاکی بدون پیشینیان. همچنین باید یک «اثبات» (proof) به بلاک پیدایش خود اضافه کنیم که نتیجهٔ استخراج (mining) یا اثبات کار است. بعداً دربارهٔ استخراج بیشتر صحبت خواهیم کرد.

علاوه بر ایجاد بلاک پیدایش در سازندهٔ خود، متدهای new_block()، new_transaction() و hash() را نیز کامل می‌کنیم:

pyimport hashlib
import json
from time import time


class Blockchain(object):
    def __init__(self):
        self.current_transactions = []
        self.chain = []

        # ایجاد بلاک پیدایش
        self.new_block(previous_hash=1, proof=100)

    def new_block(self, proof, previous_hash=None):
        """
        یک بلاک جدید در بلاک‌چین ایجاد می‌کند
        :param proof: <int> اثباتی که توسط الگوریتم اثبات کار ارائه شده است
        :param previous_hash: (اختیاری) <str> هش بلاک قبلی
        :return: <dict> بلاک جدید
        """

        block = {
            'index': len(self.chain) + 1,
            'timestamp': time(),
            'transactions': self.current_transactions,
            'proof': proof,
            'previous_hash': previous_hash or self.hash(self.chain[-1]),
        }

        # بازنشانی فهرست فعلی تراکنش‌ها
        self.current_transactions = []

        self.chain.append(block)
        return block

    def new_transaction(self, sender, recipient, amount):
        """
        یک تراکنش جدید برای قرار گرفتن در بلاک بعدی که استخراج می‌شود ایجاد می‌کند
        :param sender: <str> آدرس فرستنده
        :param recipient: <str> آدرس گیرنده
        :param amount: <int> مقدار
        :return: <int> ایندکس بلاکی که این تراکنش را در خود نگه می‌دارد
        """
        self.current_transactions.append({
            'sender': sender,
            'recipient': recipient,
            'amount': amount,
        })

        return self.last_block['index'] + 1

    @property
    def last_block(self):
        return self.chain[-1]

    @staticmethod
    def hash(block):
        """
        هش SHA-256 از یک بلاک ایجاد می‌کند
        :param block: <dict> بلاک
        :return: <str>
        """

        # باید مطمئن شویم دیکشنری مرتب (Ordered) است، وگرنه هش‌های ناسازگاری خواهیم داشت
        block_string = json.dumps(block, sort_keys=True).encode()
        return hashlib.sha256(block_string).hexdigest()

کد بالا باید سرراست باشد — برای شفافیت، چند کامنت و مستندسازی (docstring) اضافه کرده‌ام. ما تقریباً با نمایش بلاک‌چین خود کارمان تمام شده است. اما در این مرحله حتماً از خود می‌پرسید بلاک‌های جدید چگونه ایجاد، جعل یا استخراج می‌شوند.

آشنایی با اثبات کار (Understanding Proof of Work)

الگوریتم اثبات کار (Proof of Work) همان چیزی است که به‌واسطهٔ آن بلاک‌های جدید در بلاک‌چین ایجاد یا استخراج (mined) می‌شوند. هدف PoW کشف عددی است که مسئله‌ای را حل کند. این عدد باید — از نظر محاسباتی — یافتنش دشوار اما بررسیش آسان باشد، برای هر کسی در شبکه. این ایدهٔ اصلی پشت اثبات کار است.

برای اینکه این مفهوم کاملاً جا بیفتد، به یک مثال بسیار ساده نگاه می‌کنیم.

تصمیم می‌گیریم که هشِ حاصل‌ضربِ عدد صحیح x در عدد صحیح دیگر y باید به صفر ختم شود. یعنی hash(x * y) = ac23dc...0. و برای این مثال ساده‌شده، فرض می‌کنیم x = 5. پیاده‌سازی این مثال در پایتون:

pyfrom hashlib import sha256
x = 5
y = 0  # هنوز نمی‌دانیم y باید چه باشد...
while sha256(f'{x*y}'.encode()).hexdigest()[-1] != "0":
    y += 1
print(f'The solution is y = {y}')

جواب این‌جا y = 21 است؛ زیرا هش تولیدشده به صفر ختم می‌شود:

texthash(5 * 21) = 1253e9373e...5e3600155e860

در بیت‌کوین، الگوریتم اثبات کار هش‌کش (Hashcash) نام دارد و تفاوت چندانی با مثال پایهٔ بالا ندارد. این الگوریتمی است که ماینرها (miners) برای ایجاد یک بلاک جدید در حل کردنش مسابقه می‌دهند. به‌طور کلی، سختی کار با تعداد کاراکترهایی که در یک رشته جست‌وجو می‌شود تعیین می‌گردد. سپس به ماینرها برای راه‌حلشان پاداش داده می‌شود — دریافت یک سکه در قالب یک تراکنش.

شبکه قادر است راه‌حل آن‌ها را به‌آسانی بررسی کند.

پیاده‌سازی اثبات کار پایه (Implementing basic Proof of Work)

بیایید الگوریتم مشابهی برای بلاک‌چین خود پیاده‌سازی کنیم. قانون ما شبیه مثال بالا خواهد بود:

قانون: عددی مانند p بیابید که وقتی با راه‌حل بلاک قبلی هش می‌شود، هشی با ۴ صفر پیشرو (leading zeros) تولید کند. 
pyimport hashlib
import json

from time import time
from uuid import uuid4


class Blockchain(object):
    ...
        
    def proof_of_work(self, last_proof):
        """
        الگوریتم سادهٔ اثبات کار:
         - عددی مانند p' بیابید که hash(pp') شامل 4 صفر پیشرو باشد؛ که در آن p اثبات قبلی و p' اثبات جدید است
         - p اثبات قبلی است و p' اثبات جدید
        :param last_proof: <int>
        :return: <int>
        """

        proof = 0
        while self.valid_proof(last_proof, proof) is False:
            proof += 1

        return proof

    @staticmethod
    def valid_proof(last_proof, proof):
        """
        اثبات را اعتبارسنجی می‌کند: آیا hash(last_proof, proof) شامل 4 صفر پیشرو است؟
        :param last_proof: <int> اثبات قبلی
        :param proof: <int> اثبات فعلی
        :return: <bool> اگر درست باشد True و اگر نادرست باشد False
        """

        guess = f'{last_proof}{proof}'.encode()
        guess_hash = hashlib.sha256(guess).hexdigest()
        return guess_hash[:4] == "0000"

برای تنظیم سختی الگوریتم، می‌توانیم تعداد صفرهای پیشرو را تغییر دهیم. اما ۴ کافی است. خواهید دید که افزودن تنها یک صفر پیشرویِ اضافه، تفاوتی عظیم در زمان لازم برای یافتن راه‌حل ایجاد می‌کند.

کلاس ما تقریباً کامل است و ما آماده‌ایم تعامل با آن را از طریق درخواست‌های HTTP آغاز کنیم.

گام ۲: بلاک‌چین ما به‌عنوان یک API

ما از چارچوب (framework) فلاسک (Flask) پایتون استفاده خواهیم کرد. فلاسک یک میکروچارچوب است و نگاشت اندپوینت‌ها (endpoints) به توابع پایتون را آسان می‌کند. این قابلیت به ما امکان می‌دهد از طریق وب و با استفاده از درخواست‌های HTTP با بلاک‌چین خود صحبت کنیم.

سه متد ایجاد می‌کنیم:

  • /transactions/new برای ایجاد یک تراکنش جدید در یک بلاک
  • /mine برای گفتن این‌که سرور یک بلاک جدید استخراج کند
  • /chain برای برگرداندن کامل بلاک‌چین

راه‌اندازی فلاسک (Setting up Flask)

«سرور» ما یک نود (node) منفرد در شبکهٔ بلاک‌چین ما را تشکیل می‌دهد. بیایید کمی کد قالبی (boilerplate) بسازیم:

pyimport hashlib
import json
from textwrap import dedent

from uuid import uuid4

from flask import Flask


class Blockchain(object):
    ...


# نمونه‌سازی نود ما
app = Flask(__name__)

# تولید یک آدرس یکتا و سراسری برای این نود
node_identifier = str(uuid4()).replace('-', '')

# نمونه‌سازی بلاک‌چین
blockchain = Blockchain()


@app.route('/mine', methods=['GET'])

    return "We'll mine a new Block"
  
@app.route('/transactions/new', methods=['POST'])
def new_transaction():
    return "We'll add a new transaction"

@app.route('/chain', methods=['GET'])
def full_chain():
    response = {
        'chain': blockchain.chain,
        'length': len(blockchain.chain),
    }
    return jsonify(response), 200

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)

توضیح کوتاهی از آنچه در بالا اضافه کردیم:

  • خط ۱۵: نود ما را نمونه‌سازی می‌کند. دربارهٔ فلاسک در این‌جا بیشتر بخوانید.
  • خط ۱۸: یک نام تصادفی برای نود ما ایجاد می‌کند.
  • خط ۲۱: کلاس Blockchain ما را نمونه‌سازی می‌کند.
  • خط ۲۴–۲۶: اندپوینت /mine را می‌سازد؛ که یک درخواست GET است.
  • خط ۲۸–۳۰: اندپوینت /transactions/new را می‌سازد؛ که یک درخواست POST است، زیرا قرار است داده به آن ارسال کنیم.
  • خط ۳۲–۳۸: اندپوینت /chain را می‌سازد؛ که کل بلاک‌چین را برمی‌گرداند.
  • خط ۴۰–۴۱: سرور را روی پورت ۵۰۰۰ اجرا می‌کند.

اندپوینت تراکنش‌ها (The Transactions Endpoint)

درخواست یک تراکنش این‌گونه خواهد بود. این همان چیزی است که کاربر به سرور می‌فرستد:

json{
 "sender": "my address",
 "recipient": "someone else's address",
 "amount": 5
}

چون از قبل متد کلاسی خود را برای افزودن تراکنش‌ها به یک بلاک داریم، بقیهٔ کار آسان است. بیایید تابع افزودن تراکنش‌ها را بنویسیم:

pyimport hashlib
import json
from textwrap import dedent
from time import time
from uuid import uuid4

from flask import Flask, jsonify, request

...

@app.route('/transactions/new', methods=['POST'])
def new_transaction():
    values = request.get_json()

    # بررسی اینکه فیلدهای لازم در داده‌های POST شده وجود دارند
    required = ['sender', 'recipient', 'amount']
    if not all(k in values for k in required):
        return 'Missing values', 400

    # ایجاد یک تراکنش جدید
    index = blockchain.new_transaction(values['sender'], values['recipient'], values['amount'])

    response = {'message': f'Transaction will be added to Block {index}'}
    return jsonify(response), 201

گام ۴: اجماع (Consensus)

این خیلی جالب است. ما یک بلاک‌چین پایه داریم که تراکنش‌ها را می‌پذیرد و به ما اجازهٔ استخراج بلاک‌های جدید را می‌دهد. اما نکتهٔ اصلی بلاک‌چین‌ها این است که باید غیرمتمرکز (decentralized) باشند. و اگر غیرمتمرکز باشند، اصلاً چطور تضمین می‌کنیم همهٔ آن‌ها همان زنجیره را بازتاب دهند؟ به این مسئله «مسئلهٔ اجماع (Consensus)» گفته می‌شود؛ و اگر بخواهیم بیش از یک نود در شبکهٔ خود داشته باشیم، باید یک «الگوریتم اجماع» (Consensus Algorithm) پیاده‌سازی کنیم.

ثبت نودهای جدید (Registering new Nodes)

پیش از پیاده‌سازی الگوریتم اجماع، به راهی نیاز داریم که به یک نود اجازه دهد از نودهای همسایه در شبکه باخبر شود. هر نود در شبکهٔ ما باید فهرستی از نودهای دیگر شبکه نگهداری کند. بنابراین به چند اندپوینت بیشتر نیاز داریم:

  • /nodes/register برای پذیرش فهرستی از نودهای جدید در قالب URLها.
  • /nodes/resolve برای پیاده‌سازی الگوریتم اجماع ما که هر تعارضی را حل می‌کند — تا اطمینان یابد نود زنجیرهٔ درست را دارد.

باید سازندهٔ بلاک‌چین خود را اصلاح کنیم و متدی برای ثبت نودها فراهم کنیم:

پیاده‌سازی الگوریتم اجماع (Implementing the Consensus Algorithm)

همان‌طور که اشاره شد، تعارض (conflict) زمانی است که یک نود زنجیره‌ای متفاوت از نود دیگر داشته باشد. برای حل این مسئله، این قانون را می‌گذاریم که طولانی‌ترین زنجیرهٔ معتبر، مرجع (authoritative) است. به عبارت دیگر، بلندترین زنجیره در شبکه، زنجیرهٔ بالفعل (de-facto) محسوب می‌شود. با استفاده از این الگوریتم، به اجماع میان نودهای شبکهٔ خود می‌رسیم.

py...
import requests


class Blockchain(object)
    ...
    
    def valid_chain(self, chain):
        """
        تعیین می‌کند که آیا یک بلاک‌چین مشخص معتبر است یا نه
        :param chain: <list> یک بلاک‌چین
        :return: <bool> اگر معتبر باشد True و اگر نه False
        """

        last_block = chain[0]
        current_index = 1

        while current_index < len(chain):
            block = chain[current_index]
            print(f'{last_block}')
            print(f'{block}')
            print("\n-----------\n")
            # بررسی اینکه هش بلاک درست است
            if block['previous_hash'] != self.hash(last_block):
                return False

            # بررسی اینکه اثبات کار درست است
            if not self.valid_proof(last_block['proof'], block['proof']):
                return False

            last_block = block
            current_index += 1

        return True

    def resolve_conflicts(self):
        """
        این الگوریتم اجماع ماست؛ تعارض‌ها را با جایگزینی
        زنجیرهٔ ما با طولانی‌ترین زنجیره در شبکه حل می‌کند.
        :return: <bool> اگر زنجیرهٔ ما جایگزین شده باشد True و اگر نه False
        """

        neighbours = self.nodes
        new_chain = None

        # ما فقط به دنبال زنجیره‌هایی بلندتر از زنجیرهٔ خود هستیم
        max_length = len(self.chain)

        # دریافت و بررسی زنجیره‌های همهٔ نودهای شبکهٔ ما
        for node in neighbours:
            response = requests.get(f'http://{node}/chain')

            if response.status_code == 200:
                length = response.json()['length']
                chain = response.json()['chain']

                # بررسی اینکه طول بلندتر و زنجیره معتبر باشد
                if length > max_length and self.valid_chain(chain):
                    max_length = length
                    new_chain = chain

        # جایگزینی زنجیرهٔ خود در صورت کشف زنجیرهٔ معتبر جدیدی بلندتر از زنجیرهٔ ما
        if new_chain:
            self.chain = new_chain
            return True

        return False

متد نخست، یعنی valid_chain()، مسئول بررسی معتبر بودن یک زنجیره است؛ با حلقه زدن روی هر بلاک و بررسی هم هش و هم اثبات.

resolve_conflicts() متدی است که در تمام نودهای همسایهٔ ما حلقه می‌زند، زنجیره‌هایشان را «دانلود» می‌کند و با استفاده از متد بالا آن‌ها را بررسی می‌کند. اگر زنجیرهٔ معتبری یافت شود که طولش از زنجیرهٔ ما بیشتر است، زنجیرهٔ خود را با آن جایگزین می‌کنیم.

بیایید دو اندپوینت را به API خود ثبت کنیم؛ یکی برای افزودن نودهای همسایه و دیگری برای حل تعارض‌ها:
