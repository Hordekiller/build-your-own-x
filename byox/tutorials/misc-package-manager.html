مدیر بسته کوچک: یاد بگیر npm یا Yarn چگونه کار می‌کند

⚙ زبان: TypeScript ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور «tiny package manager» از g-plane است که گام‌به‌گام npm را با TypeScript پیاده می‌کند.
↗ مشاهده منبع اصلی

npm چه کار می‌کند؟ (و چه کار نمی‌کند؟)

مدیر بسته سه کار اصلی دارد: خواندن `package.json`، حل وابستگی‌ها (رزولوشن) و نصب فایل‌ها در `node_modules`. ساده به نظر می‌رسد، اما بخش «حل وابستگی» — فهمیدن اینکه هر پکیج کدام نسخه را می‌خواهد — جایی است که پیچیدگی واقعی است. این پروژه با نوشتن تدریجی گام‌به‌گام، آن را روشن می‌کند.

رزولوشن: کدام نسخه؟

یک پکیج می‌گوید `"lodash": "^4.17.0"` — یعنی 4.17.0 یا بالاتر ولی زیر 5. برای هر وابستگی، باید اطلاعات نسخه‌های موجود را از رجیستری بگیریم و بهترین را انتخاب کنیم. نسخه‌های semver با مقایسهٔ اجزا (major.minor.patch) معنا می‌یابند:

TypeScript// مقایسهٔ دو نسخهٔ semver مثل "2.1.4" و "2.2.0"
function compareVersions(a: string, b: string): number {
  const pa = a.split('.').map(Number);
  const pb = b.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    if (pa[i] !== pb[i]) return pa[i] - pb[i];
  }
  return 0;
}

// "^4.17.0": نسخه‌ای که major=4 داشته باشد و بیشترین نسخه
function resolveRange(range: string, versions: string[]): string {
  const [major] = range.slice(1).split('.').map(Number);
  return versions
    .filter(v => Number(v.split('.')[0]) === major)
    .sort(compareVersions)
    .pop()!;
}

در واقعیت semver پیچیده‌تر است (پرام ها، tilde، prerelease) — پکیج‌هایی مثل `semver` هست که باید آن را هم ببینید یا خودتان بنویسید.

گراف وابستگی و بحران تو در تویی

پکیج A به B وابسته است، B به C و... ساختار درخت (گراف) ساخته می‌شود و با BFS حل می‌شود و یک «قفل» (lockfile) می‌سازد که همهٔ نسخه‌ها را دقیق ثبت کرده تا نصب‌های بعدی یکسان باشد:

TypeScript// فلت کردن گراف وابستگی و ثبت در lockfile
const lock: Record<string, string> = {};

function resolve(pkg, versions, depth = 0) {
  for (const [name, range] of Object.entries(pkg.dependencies ?? {})) {
    const version = resolveRange(range, versions[name]);
    if (lock[name] === undefined) lock[name] = version;
    // ... برای زیروابستگی‌ها بازگشت
  }
}

چالشی که yarn/pnpm حل می‌کنند: دو پکیج می‌توانند دو نسخهٔ متفاوت از یک وابستگی مشترک بخواهند؛ «همگام‌سازی» (dedupe) یا «پوشه‌های جدا» (pnpm) — هر دو راه‌حل همین مسئله‌اند.

نصب و جمع‌بندی

مرحلهٔ آخر: دانلود tarball از رجیستری (`registry.npmjs.org`)، آنزیپ کردن در `node_modules/`. با همین ۲۰۰ خط TypeScript، `tiny-package-manager` npm را شبیه‌سازی می‌کند. بعد از آن، هر ابزار مثل Yarn، pnpm یا Bun را ببینید، می‌دانید چه تصمیم‌هایی گرفته‌اند و چرا.

کپیرایت: g-plane. این صفحه فقط ترجمهٔ فارسی و مرور آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. برای مشاهدهٔ اصل مطلب به سایت اصلی مراجعه کنید.
