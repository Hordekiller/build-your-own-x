pygit — دقیقاً به اندازه کافی کلاینت گیت

⚙ زبان: Python ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی مقاله «pygit: Just enough of a Git client to create a repo, commit, and push itself to GitHub» از بن هویت (آوریل ۲۰۱۷) است — حدود ۵۰۰ خط پایتون که init، add، commit، push و چند دستور دیگر گیت را با کتابخانه استاندارد پیاده می‌کند. کد کامل در مخزن benhoyt/pygit.
↗ مشاهده منبع اصلی

خلاصه

چند وقت پیش حدود ۵۰۰ خط کد پایتون نوشتم که به اندازه کافی از یک کلاینت گیت را پیاده می‌کند تا بتواند یک مخزن بسازد، فایل‌ها را به index اضافه کند، commit بزند و خودش را به GitHub بفرستد. این مقاله کمی از پیش‌زمینه این کار می‌گوید و کد را قدم‌به‌قدم بررسی می‌کند.

گیت (در میان چیزهای دیگر) به خاطر مدل اشیای بسیار ساده‌اش معروف است. هنگام یادگیری گیت کشف کردم که پایگاه داده اشیای محلی در واقع فقط مجموعه‌ای از فایل‌های ساده در پوشه .git است. به استثنای indexو pack files (که تا حدی اختیاری‌اند)، چیدمان و قالب این فایل‌ها فوق‌العاده سرراست است.

کمی الهام‌گرفته از تلاش مشابه ماری رز کوک (gitlet)، می‌خواستم ببینم آیا می‌توانم به اندازه کافی از گیت را پیاده کنم که یک مخزن بسازد، commit انجام دهد و به یک سرور واقعی (اینجا GitHub) push کند. برنامه gitlet او تمرکز آموزشی بیشتری دارد؛ برنامه من خودش را به GitHub فرستاد و بنابراین (به زعم فروتنانه خودم) ارزش هک بیشتری دارد. نسخه pygit فقط از یک شاخه خطی ساده پشتیبانی می‌کند، از قالب باینری index واقعی گیت استفاده می‌کند (تا بتوانم کارم را با دستورهای گیت در هر قدم چک کنم) و فقط کتابخانه استاندارد پایتون ۳.۵+ را به کار می‌برد. pygit این دستورها را دارد: init، status، add، diff، commit، cat-file، ls-files، hash-object و push.

مقداردهی یک مخزن

مقداردهی مخزن محلی گیت فقط شامل ساخت پوشه .git و چند فایل و پوشه زیر آن است:

pythondef init(repo):
    """Create directory for repo and initialize .git directory."""
    os.mkdir(repo)
    os.mkdir(os.path.join(repo, '.git'))
    for name in ['objects', 'refs', 'refs/heads']:
        os.mkdir(os.path.join(repo, '.git', name))
    write_file(os.path.join(repo, '.git', 'HEAD'),
               b'ref: refs/heads/master')
    print('initialized empty repository: {}'.format(repo))

مدیریت خطا چندان ظریف نیست — این یک زیرمجموعه ۵۰۰ خطی است؛ اگر پوشه مخزن از قبل وجود داشته باشد، با traceback سخت خطا می‌دهد.

هش‌کردن اشیاء

تابع hash_object یک شیء را هش می‌کند و در پایگاه داده .git/objects می‌نویسد. سه نوع شیء در مدل گیت هست: blob (فایل‌های معمولی)، commit و tree (وضعیت یک پوشه). هر شیء هدر کوچکی با نوع و اندازه (بایت) دارد، بعد یک بایت NUL و بعد داده فایل. همه این‌ها با zlib فشرده شده و در .git/objects/ab/cd... نوشته می‌شود که ab دو کاراکتر اول هش ۴۰ کاراکتری SHA-1 است:

pythondef hash_object(data, obj_type, write=True):
    """Compute hash of object data of given type and write to object store
    if "write" is True. Return SHA-1 object hash as hex string.
    """
    header = '{} {}'.format(obj_type, len(data)).encode()
    full_data = header + b'\x00' + data
    sha1 = hashlib.sha1(full_data).hexdigest()
    if write:
        path = os.path.join('.git', 'objects', sha1[:2], sha1[2:])
        if not os.path.exists(path):
            os.makedirs(os.path.dirname(path), exist_ok=True)
            write_file(path, zlib.compress(full_data))
    return sha1

سپس find_object() (پیداکردن شیء با هش یا پیشوند هش) و read_object() (خواندن شیء و نوعش — برعکس hash_object) و در نهایت cat_file که معادل pygit از git cat-file است (نمایش زیبای محتوای یک شیء).

index گیت

قدم بعدی افزودن فایل‌ها به index (ناحیه stage) است. index فهرستی از ورودی‌های فایل است، مرتب‌شده بر اساس مسیر؛ هر ورودی شامل نام مسیر، زمان تغییر، هش SHA-1 و چیزهای دیگر است. توجه کنید index همه فایل‌های درخت فعلی را فهرست می‌کند، نه فقط فایل‌هایی که همین حالا برای commit در حال stage شدن‌اند.

index — تک‌فایل .git/index — در قالب باینری سفارشی ذخیره می‌شود. ۱۲ بایت اول هدر است، ۲۰ بایت آخر هش SHA-1 index و بایت‌های بین آن‌ها ورودی‌های index هستند: هر ورودی ۶۲ بایت به اضافه طول مسیر با طول متغیر و کمی padding:

python# Data for one entry in the git index (.git/index)
IndexEntry = collections.namedtuple('IndexEntry', [
    'ctime_s', 'ctime_n', 'mtime_s', 'mtime_n', 'dev', 'ino', 'mode',
    'uid', 'gid', 'size', 'sha1', 'flags', 'path',
])

def read_index():
    """Read git index file and return list of IndexEntry objects."""
    try:
        data = read_file(os.path.join('.git', 'index'))
    except FileNotFoundError:
        return []
    digest = hashlib.sha1(data[:-20]).digest()
    assert digest == data[-20:], 'invalid index checksum'
    signature, version, num_entries = struct.unpack('!4sLL', data[:12])
    assert signature == b'DIRC', \
            'invalid index signature {}'.format(signature)
    assert version == 2, 'unknown index version {}'.format(version)
    entry_data = data[12:-20]
    entries = []
    i = 0
    while i + 62 < len(entry_data):
        fields_end = i + 62
        fields = struct.unpack('!LLLLLLLLLL20sH',
                               entry_data[i:fields_end])
        path_end = entry_data.index(b'\x00', fields_end)
        path = entry_data[fields_end:path_end]
        entry = IndexEntry(*(fields + (path.decode(),)))
        entries.append(entry)
        entry_len = ((62 + len(path) + 8) // 8) * 8
        i += entry_len
    assert len(entries) == num_entries
    return entries

بعد از آن ls_files، status و diff می‌آیند که ر�وش‌های مختلف چاپ وضعیت index هستند: ls_files همه فایل‌های index را چاپ می‌کند، status با get_status() فایل‌های index را با فایل‌های پوشه فعلی مقایسه می‌کند و فایل‌های تغییرکرده/جدید/حذف‌شده را نشان می‌دهد و diff تفاوت هر فایل تغییرکرده را با ماژول difflib پایتون نشان می‌دهد. مثال — مجموعه‌سازی برای محاسبه فایل‌های تغییرکرده:

pythonchanged = {p for p in (paths & entry_paths)
           if hash_object(read_file(p), 'blob', write=False) !=
              entries_by_path[p].sha1.hex()}

در نهایت write_index برای نوشتن index و add() که یک یا چند مسیر را اضافه می‌کند: کل index را می‌خواند، مسیرها را اضافه و مرتب می‌کند و دوباره می‌نویسد. حالا می‌توانیم فایل‌ها را به index اضافه کنیم و آماده commit شویم.

کامیت گرفتن

انجام commit شامل نوشتن دو شیء است. اول یک شیء tree: عکس فوری از پوشه فعلی (در واقع index) در زمان commit. یک tree فقط هش فایل‌ها (blobها) و زیردرخت‌های یک پوشه را فهرست می‌کند — بازگشتی است. پس هر commit عکس فوری از کل درخت پوشه است. اما نکته قشنگ ذخیره‌سازی با هش: اگر هر فایلی در درخت تغییر کند، هش کل درخت هم تغییر می‌کند. برعکس، اگر فایل/زیردرختی تغییر نکرده باشد، با همان هش ارجاع داده می‌شود — پس تغییرات در درخت‌های پوشه کارآمد ذخیره می‌شوند:

pythondef write_tree():
    """Write a tree object from the current index entries."""
    tree_entries = []
    for entry in read_index():
        assert '/' not in entry.path, \
                'currently only supports a single, top-level directory'
        mode_path = '{:o} {}'.format(entry.mode, entry.path).encode()
        tree_entry = mode_path + b'\x00' + entry.sha1
        tree_entries.append(tree_entry)
    return hash_object(b''.join(tree_entries), 'tree')

دوم، یک شیء commit که هش tree، commit والد، نویسنده و زمان‌سنج و پیام commit را ثبت می‌کند. pygit فقط یک شاخه خطی ساده را پشتیبانی می‌کند، پس همیشه فقط یک والد هست (یا در commit اول هیچ):

pythondef commit(message, author):
    """Commit the current state of the index to master with given message.
    Return hash of commit object.
    """
    tree = write_tree()
    parent = get_local_master_hash()
    timestamp = int(time.mktime(time.localtime()))
    utc_offset = -time.timezone
    author_time = '{} {}{:02}{:02}'.format(
            timestamp,
            '+' if utc_offset > 0 else '-',
            abs(utc_offset) // 3600,
            (abs(utc_offset) // 60) % 60)
    lines = ['tree ' + tree]
    if parent:
        lines.append('parent ' + parent)
    lines.append('author {} {}'.format(author, author_time))
    lines.append('committer {} {}'.format(author, author_time))
    lines.append('')
    lines.append(message)
    lines.append('')
    data = '\n'.join(lines).encode()
    sha1 = hash_object(data, 'commit')
    master_path = os.path.join('.git', 'refs', 'heads', 'master')
    write_file(master_path, (sha1 + '\n').encode())
    print('committed to master: {:7}'.format(sha1))
    return sha1

صحبت با یک سرور

بخش کمی سخت‌تر: pygit را با یک سرور گیت واقعی و زنده صحبت می‌کنیم (با GitHub کار می‌کند و با Bitbucket و دیگر سرورها هم). ایده پایه: از سرور بپرسیم master‌اش روی چه commitی است، بعد تعیین کنیم سرور به کدام مجموعه اشیا برای رسیدن به commit محلی فعلی نیاز دارد، و در نهایت هش commit راه‌دور را به‌روز کنیم و یک «pack file» از همه اشیای غایب بفرستیم.

این «پروتکل هوشمند» نامیده می‌شود؛ از ۲۰۱۱ گیت‌هاب پشتیبانی از «پروتکل گنگ» (انتقال مستقیم فایل‌های .git) را متوقف کرده است. پس باید از پروتکل هوشمند استفاده کنیم و اشیا را در pack file بسته‌بندی کنیم.

قالب pkt-line

یکی از بخش‌های کلیدی پروتکل انتقال، قالب «pkt-line» است: قالب بسته‌ای با طول‌پیشوند برای فرستادن فراداده‌هایی مثل هش‌های commit. هر «خط» طول ۴ رقمی هگز دارد (به اضافه ۴ برای خود طول) و بعد طول منهای ۴ بایت داده. هر خط معمولاً بایت LF پایانی هم دارد. طول خاص 0000 نشانگر بخش و پایان داده است:

pythondef extract_lines(data):
    """Extract list of lines from given server data."""
    lines = []
    i = 0
    for _ in range(1000):
        line_length = int(data[i:i + 4], 16)
        line = data[i + 4:i + line_length]
        lines.append(line)
        if line_length == 0:
            i += 4
        else:
            i += line_length
        if i >= len(data):
            break
    return lines

def build_lines_data(lines):
    """Build byte string from given lines to send to server."""
    result = []
    for line in lines:
        result.append('{:04x}'.format(len(line) + 5).encode())
        result.append(line)
        result.append(b'\n')
    result.append(b'0000')
    return b''.join(result)

(نکته: در build_lines_data طول +۵ است چون یک بایت LF اضافه می‌شود.)

درخواست HTTPS

قلب بعدی پروتکل هوشمند: درخواست HTTPS معتبر بدون کتابخانه requests، فقط با urllib:

pythondef http_request(url, username, password, data=None):
    """Make an authenticated HTTP request to given URL (GET by default,
    POST if "data" is not None).
    """
    password_manager = urllib.request.HTTPPasswordMgrWithDefaultRealm()
    password_manager.add_password(None, url, username, password)
    auth_handler = urllib.request.HTTPBasicAuthHandler(password_manager)
    opener = urllib.request.build_opener(auth_handler)
    f = opener.open(url, data=data)
    return f.read()

نمونه بالا دقیقاً دلیل وجود requests است! نسخه معادل با requests حتی نیازی به تابع کمکی نداشت.

پرسیدن از سرور که شاخه master‌اش به کجا رسیده (تابعی نسبتاً شکننده اما به‌راحتی قابل عمومی‌سازی):

pythondef get_remote_master_hash(git_url, username, password):
    """Get commit hash of remote master branch, return SHA-1 hex string or
    None if no remote commits.
    """
    url = git_url + '/info/refs?service=git-receive-pack'
    response = http_request(url, username, password)
    lines = extract_lines(response)
    assert lines[0] == b'# service=git-receive-pack\n'
    assert lines[1] == b''
    if lines[2][:40] == b'0' * 40:
        return None
    master_sha1, master_ref = lines[2].split(b'\x00')[0].split()
    assert master_ref == b'refs/heads/master'
    assert len(master_sha1) == 40
    return master_sha1.decode()

تعیین اشیای غایب

حالا باید تعیین کنیم سرور به چه اشیایی نیاز دارد که ندارد. pygit فرض می‌کند همه چیز محلی است (پشتیبانی از pull ندارد). تابع read_tree (برعکس write_tree) و دو تابع بازگشتی برای پیدا کردن مجموعه هش اشیای یک درخت و یک commit:

pythondef find_tree_objects(tree_sha1):
    """Return set of SHA-1 hashes of all objects in this tree
    (recursively), including the hash of the tree itself.
    """
    objects = {tree_sha1}
    for mode, path, sha1 in read_tree(sha1=tree_sha1):
        if stat.S_ISDIR(mode):
            objects.update(find_tree_objects(sha1))
        else:
            objects.add(sha1)
    return objects

def find_commit_objects(commit_sha1):
    """Return set of SHA-1 hashes of all objects in this commit
    (recursively), its tree, its parents, and the hash of the commit itself.
    """
    objects = {commit_sha1}
    obj_type, commit = read_object(commit_sha1)
    assert obj_type == 'commit'
    lines = commit.decode().splitlines()
    tree = next(l[5:45] for l in lines if l.startswith('tree '))
    objects.update(find_tree_objects(tree))
    parents = (l[7:47] for l in lines if l.startswith('parent '))
    for parent in parents:
        objects.update(find_commit_objects(parent))
    return objects

def find_missing_objects(local_sha1, remote_sha1):
    """Return set of SHA-1 hashes of objects in local commit that are
    missing at the remote (based on the given remote commit hash).
    """
    local_objects = find_commit_objects(local_sha1)
    if remote_sha1 is None:
        return local_objects
    remote_objects = find_commit_objects(remote_sha1)
    return local_objects - remote_objects

خود push

برای push باید یک درخواست pkt-line بفرستیم («شاخه master را به این هش commit به‌روز کن») و بعد یک pack file شامل محتوای به‌هم‌پیوسته همه اشیای غایب. pack file هدر ۱۲ بایتی دارد (شروع با PACK)، بعد هر شیء با اندازه طول متغیر فشرده zlib و در آخر هش ۲۰ بایتی کل pack file. ما از نمایش «بدون دلتا» برای سادگی استفاده می‌کنیم:

pythondef encode_pack_object(obj):
    """Encode a single object for a pack file and return bytes
    (variable-length header followed by compressed data bytes).
    """
    obj_type, data = read_object(obj)
    type_num = ObjectType[obj_type].value
    size = len(data)
    byte = (type_num << 4) | (size & 0x0f)
    size >>= 4
    header = []
    while size:
        header.append(byte | 0x80)
        byte = size & 0x7f
        size >>= 7
    header.append(byte)
    return bytes(header) + zlib.compress(data)

def create_pack(objects):
    """Create pack file containing all objects in given given set of
    SHA-1 hashes, return data bytes of full pack file.
    """
    header = struct.pack('!4sLL', b'PACK', 2, len(objects))
    body = b''.join(encode_pack_object(o) for o in sorted(objects))
    contents = header + body
    sha1 = hashlib.sha1(contents).digest()
    data = contents + sha1
    return data

و گام آخر — خود push() با کمی حذف کد حاشیه‌ای برای اختصار:

pythondef push(git_url, username, password):
    """Push master branch to given git repo URL."""
    remote_sha1 = get_remote_master_hash(git_url, username, password)
    local_sha1 = get_local_master_hash()
    missing = find_missing_objects(local_sha1, remote_sha1)
    lines = ['{} {} refs/heads/master\x00 report-status'.format(
            remote_sha1 or ('0' * 40), local_sha1).encode()]
    data = build_lines_data(lines) + create_pack(missing)
    url = git_url + '/git-receive-pack'
    response = http_request(url, username, password, data=data)
    lines = extract_lines(response)
    assert lines[0] == b'unpack ok\n', \
        "expected line 1 b'unpack ok', got: {}".format(lines[0])
