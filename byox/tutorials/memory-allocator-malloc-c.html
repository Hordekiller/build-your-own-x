Malloc جادو نیست — پیاده‌سازی تخصیص‌دهندهٔ حافظهٔ خودت (Malloc is not magic)

۱. چرا malloc را خودمان بسازیم؟

هر روز میلیاردها بار malloc/free صدا زده می‌شود، اما چه کسی می‌داند پشت پرده چه می‌گذرد؟ این مقاله تخصیص‌دهندهٔ حافظهٔ خودمان (an_malloc / an_free) را از صفر می‌سازد تا «جادو» حذف شود. تخصیص‌دهندهٔ پیاده‌شده در مقاله:

  • لیستی از مکان‌های آزاد داخل heap را نگه می‌دارد.
  • همهٔ تخصیص‌ها را ردیابی می‌کند.
  • در صورت تقاضا، ناحیهٔ آزادی به اندازهٔ دلخواه برمی‌گرداند؛ اگر هیچ بلوک آزادی به‌اندازهٔ کافی نبود، از سیستمعامل رشد heap را درخواست می‌کند.
  • در صورت تقاضا، بلوکِ انتخاب‌شده را آزاد می‌کند — و آزادسازی بلوک‌ها می‌تواند باعث کوچک‌کردن heap (بازگرداندن صفحه‌ها به OS) شود.
  • نخ‌امن (thread-safe) است: از چند نخ هم‌زمان قابل استفاده است.

۲. ساختار داده: header و بلوک‌ها

اول، یک header در ابتدای heap داریم که بخشی از لیست پیوندی نیست. نشانگرِ ابتدای آن یک عدد ثابت («جملهٔ جادویی» — MAGICAL_BYTES) است که می‌گوید «ساختار مقداردهی اولیه شده» (در پیاده‌سازی محکم، طولانی‌کردن این مقدار احتمال برخورد با زبالهٔ تصادفی RAM را خیلی کم می‌کند). این header همچنین قفل را نگه می‌دارد — یک بولی که قبل از هر malloc/free قفل و بعد آزاد می‌شود؛ هر نخِ دیگری منتظر می‌ماند تا قفل باز شود. بعد، آمار: تعداد بلوک‌ها و تعداد صفحه‌ها.

هر بلوک یک header مخصوص خودش دارد: نشانگرِ بلوک بعدی و قبلی (next/ prev)، طولش و این‌که آزاد است یا استفاده‌شده. بعد از header، محتوای واقعی می‌آید:

cint *an_malloc(ssize_t size) {
    if (heap_start == NULL) {
        heap_start = sbrk(0);
        sbrk(4096);                       // برداشتن یک صفحهٔ اولیه از OS
    }
    char *heap_end = sbrk(0);
    long int length = heap_end - heap_start;

    // بررسیِ «جملهٔ جادویی» — اولین اجرای malloc:
    if ((*heap_start) != MAGICAL_BYTES) {
        *(heap_start) = MAGICAL_BYTES;
        my_stats *malloc_header = (my_stats *)heap_start;
        malloc_header->amount_of_blocks = 1;
        malloc_header->amount_of_pages = 1;

        area *first_block = (area *)((char *)heap_start + sizeof(my_stats));
        first_block->marker = BLOCK_MARKER;
        first_block->in_use = false;
        first_block->length = length - sizeof(my_stats) - sizeof(area);
        first_block->next = NULL;
        first_block->prev = NULL;
    }
    return add_used_block(size);
}

۳. تخصیص: بهترین تطبیق و شکستن بلوک‌ها

بعد از قفل کردن، liلیست پیوندی را برای بلوکی که «به‌اندازهٔ کافی بزرگ» باشد جست‌وجو می‌کنیم. اگر هیچ‌کدام نبود، با sbrk(4096) صفحه‌های بیشتری از OS می‌گیریم و آخرین بلوک را بزرگ می‌کنیم. برای کاهش تکه‌تکه‌شدن (fragmentation) از استراتژی بهترین تطبیق (best fit) استفاده می‌شود: به‌جای اولین بلوکِ به‌اندازهٔ کافی، کوچک‌ترین بلوکی را می‌گیریم که داده در آن جا شود. و چون بلوکِ انتخاب‌شده معمولاً بزرگ‌تر از نیاز است، آن را می‌شکنیم: بلوک استفاده‌شده به اندازهٔ دقیقِ درخواست + یک بلوک آزادِ باقی‌مانده — قانونِ مهم این است که «لیست همیشه باید به یک بلوک آزاد ختم شود»:

c// پیدا نشد؟ به اندازهٔ لازم از OS صفحه بگیر
if (smallest_block == NULL) {
    area *last_block = find_last_block();
    while (last_block->length < size) {
        sbrk(4096);
        last_block->length += 4096;
        malloc_header->amount_of_pages += 1;
    }
    smallest_block = last_block;
}

// شکستن بلوک: به اندازهٔ کافی جای باقی‌مانده هست؟
int must_have_size = smallest_block->length - size - sizeof(area) - 1;
if (must_have_size <= 0) {
    sbrk(4096);                          // نه؛ یک صفحه دیگر بگیر
    must_have_size = smallest_block->length - size - sizeof(area) - 1;
}
smallest_block->in_use = true;

// بلوک آزادِ جدید را درست بعد از بخشِ استفاده‌شده می‌سازیم
area *new_block = (area *)((char *)smallest_block + sizeof(area) + size);
new_block->marker = BLOCK_MARKER;
new_block->in_use = false;
new_block->prev = smallest_block;
new_block->next = smallest_block->next;
if (new_block->next != NULL) { (new_block->next)->prev = new_block; }
smallest_block->next = new_block;

۴. آزادسازی: تأیید، ادغام و کوچک‌کردن heap

free (یعنی an_free) نکته‌ای کلیدی دارد: کاربر «شروعِ بلوک» را نمی‌گیرد بلکه نشانی‌ای را می‌گیرد که بعد از header بلوک است. پس با کم‌کردنِ اندازهٔ header از pointer، به ابتدای بلوک می‌رسیم. اول بررسی می‌کنیم marker درست است یا نه (اگر نه، pointer به malloc تعلق ندارد و false برمی‌گردد). بعد بلوک را آزاد علامت می‌زنیم و — مهم‌ترین بخش — اگر همسایهٔ بعدی یا قبلی هم آزاد باشد، آن‌ها را ادغام (merge) می‌کنیم تا یک بلوک بزرگِ هم‌پیوسته بسازیم:

carea *block = ptr - sizeof(area);       // شروعِ واقعیِ بلوک
if (block->marker != BLOCK_MARKER) { return false; }   // پوینتر نامعتبر
block->in_use = false;
memset(ptr, 0, block->length);

if (block->next != NULL && (block->next)->in_use == false) {
    // بلوک بعدی آزاد است → ادغام
    area *next_free = block->next;
    block->next = next_free->next;
    if (next_free->next != NULL) { next_free->next->prev = block; }
    block->length += sizeof(area) + next_free->length;  // طول‌ها با هم جمع شوند
    memset(next_free, 0, sizeof(area) + next_free->length);
    malloc_header->amount_of_blocks -= 1;
}
// (و همان‌طور برای بلوک قبلیِ آزاد)

reduce_heap_size_if_possible();   // آخرین بلوکِ بزرگِ آزاد → پس‌دادن صفحه‌ها به OS

در پایان، reduce_heap_size_if_possible() به انتهای لیست می‌رود و اگر آن‌قدر فضای آزاد پشت آخرین بلوکِ استفاده‌شده باشد (sbrk مقدار منفی می‌پذیرد)، صفحه‌ها را به سیستمعامل برمی‌گرداند و آمار را اصلاح می‌کند؛ و اگر شکافِ کوچکی ماند، یک بلوک آزادِ کوچک در همان جا «تزریق» می‌شود تا بعداً قابل استفاده باشد.

۵. چه چیزهایی یاد می‌گیرید

  • جدا کردن «واقعیتِ تخصیص» از «محصولِ تخصیص»: کاربر فقط pointer استفاده می‌کند؛ متادیتا (header) برای کاربر کاملاً نامرئی است.
  • رشد و کوچک‌کردن heap با sbrk — مثبت برای بزرگ‌کردن، منفی برای برگرداندن.
  • شکستن و ادغام بلوک‌ها: دو ابزار اصلی مقابله با تکه‌تکه‌شدن حافظه.
  • بهترین تطبیق به‌جای «اولین تطبیق» برای استفادهٔ بهینه از فضا.
  • همزمانی با یک قفل ساده و ایدهٔ markerها برای تشخیص بلوک‌های معتبر از زبالهٔ حافظه — پایهٔ درک سیستم‌های امنیتیِ allocatorهای واقعی.
جهان واقعی: allocatorهای تولیدی (glibc ptmalloc، jemalloc) همین مفاهیم را با دهه‌ها بهینه‌سازی دارند: buckets بر اساس اندازه، thread caches، cookies و… — اما با درک این پیاده‌سازی ساده، خواندن کد آن‌ها دیگر معمایی نیست.

۶. جمع‌بندی

«Malloc جادو نیست» — فقط یک ساختار دادهٔ هوشمند روی sbrk است: لیست پیوندیِ بلوک‌ها، markerها، شکستن/ادغام، بهترین تطبیق و یک قفل. ساختنش بهترین راه برای باورکردنِ این جمله است.

کپیرایت: مقالهٔ «Malloc is not magic — Implementing your own memory allocator» اثر آلخاندرو نادال (Alejandro Nadal) است و در Medium (Level Up Coding) منتشر شده. این صفحه فقط ترجمهٔ فارسی و مرور آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. برای مشاهده اصل مطلب به سایت اصلی مراجعه کنید.
