با ساختن React DOM سبک خودت، یاد بگیر بستهٔ Reconciler ری‌اکت چطور کار می‌کند

⚙ زبان: JavaScript ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور مقالهٔ «Learn you some custom React renderers» از آتول آر (Atul R) در HackerNoon است. او با ساخت یک React DOM مینیاتوری با استفاده از بستهٔ رسمی react-reconciler توضیح می‌دهد رندرکننده‌های React (React DOM، React Native و…) دقیقاً چطور کار می‌کنند.
↗ مشاهده منبع اصلی

۱. معماری رندرکننده‌های React

React از دو لایهٔ کاملاً جدا تشکیل شده: reconciler (مغز: مقایسهٔ درخت مجازی و تشخیص تغییرات — همان الگوریتم diff و ساخت Fiberها) و renderer (دست‌ها: اعمال آن تغییرات در محیط هدف؛ DOM، native، canvas و…). در واقع

js// بستهٔ react-reconciler یک کارخانه است:
// با دادن host config مخصوص پلتفرم، یک رندرکننده می‌سازد
const Reconciler = require('react-reconciler');
const reconciler = Reconciler(HostConfig);

HostConfig پل ارتباطی است: مجموع‌ای از توابع که قرارداد «چطور با محیط هدف حرف بزنم» را مشخص می‌کنند — مثل createInstance، appendChild و commitUpdate. همین یک رابط است که React DOM را برای مرورگر، React Native را برای موبایل و React ART را برای SVG فعال می‌کند.

۲. ساختار اولیهٔ رندرکننده

مقاله پروژه‌ای با create-react-app راه می‌اندازد، سپس در src/renderer/index.js رندرکنندهٔ سفارشی می‌سازد و در index.js به‌جای react-dom از آن استفاده می‌کند. ابتدا فقط یک بدنهٔ خالی:

jsconst CustomRenderer = {
  render(element, renderDom, callback) {
    // element: عنصر ریشه (کامپوننت App)
    // renderDom: عنصر DOM میزبان
    // callback: پس از پایان رندر صدا زده می‌شود
    console.log('render called', element, renderDom, callback);
  },
};

export default CustomRenderer;

حالا react-reconciler را نصب و یک نمونهٔ reconciler با HostConfig می‌سازیم. ابتدا createContainer برای ساخت فایبر ریشه، سپس updateContainer برای آغاز مقایسه و رندر:

jsconst Reconciler = require('react-reconciler');
const HostConfig = {
  /* توابع پلتفرم اینجا تعریف می‌شوند */
};

const reconcilerInstance = Reconciler(HostConfig);

const CustomRenderer = {
  render(element, renderDom, callback) {
    const isAsync = false; // حالت رندر همگام
    const container = reconcilerInstance.createContainer(renderDom, isAsync);
    const parentComponent = null; // فایبر ریشه پدر ندارد
    reconcilerInstance.updateContainer(element, container, parentComponent, callback);
  },
};

export default CustomRenderer;

۳. پیاده‌سازی HostConfig

قلب آموزش، پیاده‌سازی توابع HostConfig برای DOM است. نسخهٔ کامل این مقاله در سه بخش همین کار را انجام می‌دهد؛ خلاصهٔ توابع اصلی:

jsconst HostConfig = {
  createInstance(type, props, rootContainerInstance, hostContext, internalInstanceHandle) {
    // ساخت عنصر DOM بر اساس نوع
    const el = document.createElement(type);
    return el;
  },

  createTextInstance(text, rootContainerInstance, hostContext, internalInstanceHandle) {
    return document.createTextNode(text);
  },

  appendChildToContainer(container, child) {
    container.appendChild(child);
  },

  appendChild(parent, child) {
    parent.appendChild(child);
  },

  appendInitialChild(parent, child) {
    parent.appendChild(child);
  },

  removeChildFromContainer(container, child) {
    container.removeChild(child);
  },

  removeChild(parent, child) {
    parent.removeChild(child);
  },

  insertInContainerBefore(container, child, before) {
    container.insertBefore(child, before);
  },

  insertBefore(parent, child, before) {
    parent.insertBefore(child, before);
  },

  prepareUpdate(instance, type, oldProps, newProps, rootContainerInstance, currentHostContext) {
    // تفاوت props را محاسبه و برمی‌گرداند
    const changedProps = {};
    for (const key in Object.assign({}, oldProps, newProps)) {
      if (oldProps[key] !== newProps[key]) changedProps[key] = newProps[key];
    }
    return Object.keys(changedProps).length > 0 ? changedProps : null;
  },

  commitUpdate(instance, updatePayload, type, oldProps, newProps, finishedWork) {
    // اعمال تغییرات روی نود واقعی
    for (const key in updatePayload) {
      if (key === 'children') continue;
      instance[key] = updatePayload[key];
    }
  },

  commitTextUpdate(textInstance, oldText, newText) {
    textInstance.nodeValue = newText;
  },

  shouldSetTextContent(type, props) {
    return false;
  },

  getChildHostContext() { return {}; },
  getPublicInstance(instance) { return instance; },
  getRootHostContext() { return {}; },
  prepareForCommit() {},
  resetAfterCommit() {},
  finalizeInitialChildren() {},
};

روند ساخت در این مقاله گام‌به‌گام است: اول رندر اولیه کار می‌کند، بعد به‌روزرسانی props (که نیازمند prepareUpdate + commitUpdate است) و در انتها مدیریت حذف و جابه‌جایی نودها اضافه می‌شود. در هر مرحله یک ارور مشخص از reconciler دریافت می‌کنید و همان راهنمای شماست.

۴. نتیجه: همین است!

بعد از تکمیل HostConfig، برنامهٔ React ما با رندرکنندهٔ سفارشی خودمان اجرا می‌شود: کامپوننت‌ها state خودشان را مدیریت می‌کنند، reconciler تغییرات را محاسبه می‌کند و توابع ما آن‌ها را روی DOM اعمال می‌کنند.

نکتهٔ تکمیلی: حالا می‌فهمید چرا React Native بدون تغییر مغز React کار می‌کند: همان reconciler با یک HostConfig دیگر (پل native). و چرا رندرکننده‌هایی مثل React Three Fiber برای WebGL وجود دارند: فقط یک HostConfig جدید لازم است.
