نوشتن یک سیستم Build

منبع اصلی: این صفحه ترجمهٔ فارسی و مرور «Day 11: Build System» از سری NimDays است که یک سیستم build ساده، با پشتیبانی از وابستگی‌های task، می‌سازد.
↗ مشاهده منبع اصلی

سیستم Build چه کار می‌کند؟

ابزارهایی مثل make یا ninja می‌دانند که «برای رسیدن به خروجی X، اول باید این کارها با این ترتیب انجام شوند». شما فقط خروجی را می‌خواهید؛ build system گراف وابستگی‌ها را می‌سازد، فقط کارهایی که لازم‌اند را اجرا می‌کند و کارهای تکراری (وقتی ورودی‌ها تغییر نکرده‌اند) را رد می‌کند.

در این آموزش، یک build system ساده در Nim می‌سازیم که taskها و وابستگی‌هایشان را تعریف می‌کند و با ترتیب درست اجرا می‌شود.

تعریف Task و وابستگی

ایدهٔ اصلی: یک task اسم، بدنهٔ اجرایی و لیست وظایف پیش‌نیاز دارد. بعد از اجرای taskها، سیستم باید هر task را فقط یک بار اجرا کند (حتی اگر چند جا به آن اشاره شده باشد):

Nimtype
  Task = ref object
    name: string
    deps: seq[string]
    action: proc()

var tasks = initTable[string, Task]()

# ثبت یک task جدید
proc task(name: string, deps: seq[string] = @[], action: proc()) =
  tasks[name] = Task(name: name, deps: deps, action: action)

# اجرای یک task + همهٔ وابستگی‌هایش (یک بار)
proc build(name: string) =
  if name in built: return        # بار دوم را رد کن
  built.incl(name)
  let t = tasks[name]
  for d in t.deps: build(d)      # اول وابستگی‌ها
  t.action()                     # بعد خود task

مجموعهٔ `built` همان نقش «علامت‌گذاری انجام‌شده» را دارد و باعث می‌شود گراف حلقه‌ نمی‌زند و کار تکراری اجرا نشود.

مثال استفاده

چند task با وابستگی به هم تعریف می‌کنیم تا ترتیب اجرا دیده شود:

Nimtask("compile") do:
  echo "کامپایل فایل‌ها..."

task("test", @["compile"]) do:
  echo "اجرای تست‌ها..."

task("package", @["test"]) do:
  echo "ساخت بستهٔ نهایی..."

build("package")
# خروجی:
# کامپایل فایل‌ها...
# اجرای تست‌ها...
# ساخت بستهٔ نهایی...

این دقیقاً همان الگوریتمی است که make برای «هدف»ها انجام می‌دهد؛ فقط بدون تجزیهٔ سینتکس Makefile.

به سمت سیستم واقعی

در گام بعد می‌توانید مقایسهٔ «زمان فایل‌ها» (timestamps) را اضافه کنید تا مثل make فقط فایل‌های تغییرکرده ساخته شوند، خطاهای زنجیره‌ای را گزارش دهید، و taskها را موازی اجرا کنید. همین چهارچوب ساده، پایهٔ همهٔ build systemهای دنیاست.

کپیرایت: احمد منصور (xmonader). این صفحه فقط ترجمهٔ فارسی و مرور آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. برای مشاهدهٔ اصل مطلب به سایت اصلی مراجعه کنید.
