مقدمه

موتورهای رندر سه‌بعدی که امروزه در بازی‌ها و تولید مالتی‌مدیا استفاده می‌شوند، در پیچیدگی ریاضیات و برنامه‌نویسی به‌کاررفته در آن‌ها نفس‌گیر هستند. نتایجی که تولید می‌کنند نیز به‌همان‌اندازه خیره‌کننده است.

بسیاری از توسعه‌دهندگان ممکن است فکر کنند که ساختن حتی ساده‌ترین اپلیکیشن سه‌بعدی از صفر نیازمند دانش و تلاشی فرابشری است، اما خوشبختانه همیشه هم این‌طور نیست. در این‌جا می‌خواهم با شما در میان بگذارم که چطور می‌توانید موتور رندر سه‌بعدی مخصوص خودتان را بسازید؛ موتوری که کاملاً قادر به تولید تصاویر سه‌بعدی خوش‌منظر است.

چرا اصلاً بخواهید یک موتور سه‌بعدی بسازید؟ دست‌کم اینکه واقعاً به درک این کمک می‌کند که موتورهای مدرنِ واقعی چگونه جادوی سیاه خود را انجام می‌دهند. همچنین گاهی مفید است که بدون وابستگی به کتابخانه‌های خارجی حجیم، قابلیت رندر سه‌بعدی را به اپلیکیشن‌تان اضافه کنید. در مورد جاوا، این یعنی می‌توانید یک اپلیکیشن نمایش‌گر سه‌بعدی با صفر وابستگی (جز APIهای جاوا) بسازید که تقریباً همه‌جا اجرا شود — و در ۵۰ کیلوبایت جا بگیرد!

البته اگر می‌خواهید اپلیکیشن‌های سه‌بعدی بزرگ با گرافیک روان بسازید، خیلی بهتر است از OpenGL/WebGL استفاده کنید. با این حال، وقتی درک پایه‌ای از ساختار داخلی موتورهای سه‌بعدی داشته باشید، موتورهای پیچیده‌تر بسیار قابل‌درک‌تر به نظر می‌رسند.

در این پست، رندر سه‌بعدی پایه با پروجکشن ارتواگرافیک (تصویر عمود)، رسترایز سادهٔ مثلث، z-buffering (بافر عمق) و سایه‌زنی تخت (flat shading) را پوشش خواهم داد. روی بهینه‌سازی‌های سنگین عملکرد و موضوعات پیچیده‌تر مانند تکسچرها یا چیدمان‌های متفاوت نور تمرکز نخواهم کرد — اگر به آن‌ها نیاز دارید، بهتر است از ابزارهای مناسب‌تر مانند OpenGL استفاده کنید (کتابخانه‌های زیادی وجود دارند که حتی از داخل جاوا هم امکان کار با OpenGL را می‌دهند).

مثال‌های کد به زبان جاوا خواهند بود، اما ایده‌های توضیح‌داده‌شده را می‌توانید در هر زبانی که انتخاب می‌کنید به‌کار ببندید. برای راحتی شما، در همین پست همراه با دموهای کوچک تعاملی جاوااسکریپت پیش خواهم رفت.

بس است دیگر صحبت — بزن بریم!

۱. رابط گرافیکی اولیه (GUI wrapper)

اول از همه، می‌خواهیم دست‌کم چیزی روی صفحه داشته باشیم. برای این کار از یک اپلیکیشن بسیار ساده با تصویر رندرشده و دو اسلایدر برای تنظیم چرخش استفاده خواهم کرد.

۲. کلاس‌های مدل — رأس و مثلث

حالا چند کلاس مدل ضروری اضافه می‌کنیم — رأس‌ها (vertices) و مثلث‌ها. رأس صرفاً ساختاری است برای ذخیره سه مختصات ما (X، Y و Z)، و مثلث سه رأس را به هم پیوند می‌دهد و رنگش را ذخیره می‌کند. 

javaclass Vertex {
    double x;
    double y;
    double z;
    Vertex(double x, double y, double z) {
        this.x = x;
        this.y = y;
        this.z = z;
    }
}

class Triangle {
    Vertex v1;
    Vertex v2;
    Vertex v3;
    Color color;
    Triangle(Vertex v1, Vertex v2, Vertex v3, Color color) {
        this.v1 = v1;
        this.v2 = v2;
        this.v3 = v3;
        this.color = color;
    }
}

در این پست فرض می‌کنم مختصات X یعنی حرکت در جهت چپ-راست، Y یعنی حرکت بالا-پایین روی صفحه، و Z عمق است (یعنی محور Z عمود بر صفحه نمایش شماست). Z مثبت یعنی «به سمت ناظر».

به‌عنوان شیء نمونه، چهاروجهی (tetrahedron) را انتخاب کردم، چون ساده‌ترین شکل سه‌بعدی‌ای بود که به ذهنم رسید — فقط ۴ مثلث برای توصیفش لازم است. این هم تصویر آن:

۴. تبدیل‌ها با ماتریس‌های چرخش

حالا باید چرخش را اضافه کنیم. برای این کار کمی حاشیه می‌روم و درباره استفاده از ماتریس‌ها برای انجام تبدیل روی نقاط سه‌بعدی صحبت می‌کنم.

راه‌های زیادی برای دستکاری نقاط سه‌بعدی وجود دارد، اما انعطاف‌پذیرترین آن‌ها ضرب ماتریسی است. ایده این است که نقاط را به‌صورت بردارهای ۳×۱ نمایش دهید و سپس تبدیل، صرفاً ضرب در یک ماتریس ۳×۳ است.

بردار ورودی A را می‌گیرید:

A = [ ax , ay , az ]

و آن را در ماتریس تبدیل T ضرب می‌کنید تا بردار خروجی B به دست آید:

AT = [ ax ay az ] × [ txx txy txz ; tyx tyy tyz ; tzx tzy tzz ] = [ axtxx+aytyx+aztzx , axtxy+aytyy+aztzy , axtxz+aytyz+aztzz ] = [ bx by bz ]

مثلاً این‌طور یک نقطه را در مقیاس ۲ بزرگ می‌کنید:

[ 1 2 3 ] × [ 2 0 0 ; 0 2 0 ; 0 0 2 ] = [ 1×2 , 2×2 , 3×2 ] = [ 2 4 6 ]

نمی‌توانید همه تبدیل‌های ممکن را با ماتریس‌های ۳×۳ توصیف کنید — برای مثال، ترجمه (انتقال) خارج از محدوده است. می‌توانید آن را با ماتریس‌های ۴×۴ به دست آورید (با شیب‌دهی مؤثر در فضای چهاربعدی)، اما این از حیطه این آموزش خارج است.

مفیدترین تبدیل‌هایی که در این آموزش به آن‌ها نیاز خواهیم داشت، مقیاس‌بندی و چرخش هستند.

هر چرخشی در فضای سه‌بعدی را می‌توان به‌صورت ترکیبی از ۳ چرخش ابتدایی بیان کرد: چرخش در صفحه XY، چرخش در صفحه YZ و چرخش در صفحه XZ. ماتریس‌های تبدیل هر یک از این چرخش‌ها را می‌توانیم این‌گونه بنویسیم:

ماتریس چرخش XY:

[ cosθ , −sinθ , 0 ; sinθ , cosθ , 0 ; 0 , 0 , 1 ]

ماتریس چرخش YZ:

[ 1 , 0 , 0 ; 0 , cosθ , sinθ ; 0 , −sinθ , cosθ ]

ماتریس چرخش XZ:

[ cosθ , 0 , −sinθ ; 0 , 1 , 0 ; sinθ , 0 , cosθ ]

جادوی ماجرا این‌جاست: اگر ابتدا نیاز دارید نقطه را با ماتریس تبدیل T₁ در صفحه XY بچرخانید و سپس با ماتریس تبدیل T₂ در صفحه YZ، کافی است T₁ را در T₂ ضرب کنید و یک ماتریس واحد برای توصیف کل چرخش به دست آورید:

(AT₁)T₂ = A(T₁T₂)

این یک بهینه‌سازی بسیار مفید است — به‌جای محاسبه مجدد چند چرخش برای هر نقطه، ماتریس را یک بار از پیش محاسبه می‌کنید و بعد در خط لوله (pipeline) خود از آن استفاده می‌کنید.

بس است دیگر از این ریاضیات ترسناک، برویم سراغ کد. کلاس کمکی Matrix3 را می‌سازیم که ضرب ماتریس-در-ماتریس و بردار-در-ماتریس را مدیریت می‌کند:

javaclass Matrix3 {
    double[] values;
    Matrix3(double[] values) {
        this.values = values;
    }
    Matrix3 multiply(Matrix3 other) {
        double[] result = new double[9];
        for (int row = 0; row < 3; row++) {
            for (int col = 0; col < 3; col++) {
                for (int i = 0; i < 3; i++) {
                    result[row * 3 + col] +=
                        this.values[row * 3 + i] * other.values[i * 3 + col];
                }
            }
        }
        return new Matrix3(result);
    }
    Vertex transform(Vertex in) {
        return new Vertex(
            in.x * values[0] + in.y * values[3] + in.z * values[6],
            in.x * values[1] + in.y * values[4] + in.z * values[7],
            in.x * values[2] + in.y * values[5] + in.z * values[8]
        );
    }
}

حالا می‌توانیم اسلایدرهای چرخش را به زندگی برگردانیم. اسلایدر افقی «heading» را کنترل می‌کند — در مورد ما چرخش در جهت XZ (چپ-راست) — و اسلایدر عمودی «pitch» را کنترل می‌کند — چرخش در جهت YZ (بالا-پایین).

بیایید ماتریس چرخش‌مان را بسازیم و به خط لوله اضافه کنیم:

javadouble heading = Math.toRadians(headingSlider.getValue());
Matrix3 transform = new Matrix3(new double[] {
        Math.cos(heading), 0, -Math.sin(heading),
        0, 1, 0,
        Math.sin(heading), 0, Math.cos(heading)
    });

g2.translate(getWidth() / 2, getHeight() / 2);
g2.setColor(Color.WHITE);
for (Triangle t : tris) {
    Vertex v1 = transform.transform(t.v1);
    Vertex v2 = transform.transform(t.v2);
    Vertex v3 = transform.transform(t.v3);
    Path2D path = new Path2D.Double();
    path.moveTo(v1.x, v1.y);
    path.lineTo(v2.x, v2.y);
    path.lineTo(v3.x, v3.y);
    path.closePath();
    g2.draw(path);
}

این است چیزی که باید کار کند (این مثال تعاملی است — سعی کنید دستگیره‌ها را بکشید!): دموی تعاملی در نسخه اصلی مقاله موجود است.

همان‌طور که متوجه شده‌اید، چرخش بالا-پایین هنوز کار نمی‌کند. بیایید تبدیل بعدی را اضافه کنیم:

javaMatrix3 headingTransform = new Matrix3(new double[] {
        Math.cos(heading), 0, Math.sin(heading),
        0, 1, 0,
        -Math.sin(heading), 0, Math.cos(heading)
    });
double pitch = Math.toRadians(pitchSlider.getValue());
Matrix3 pitchTransform = new Matrix3(new double[] {
        1, 0, 0,
        0, Math.cos(pitch), Math.sin(pitch),
        0, -Math.sin(pitch), Math.cos(pitch)
    });
Matrix3 transform = headingTransform.multiply(pitchTransform);

ببینید که هر دو چرخش حالا کار می‌کنند و به‌خوبی با هم ترکیب می‌شوند: دموی تعاملی در نسخه اصلی مقاله موجود است.

۵. رسترایز کردن مثلث‌ها

تا این‌جا فقط فریم‌ورک (سیم‌خط) شکل را رسم می‌کردیم. حالا باید مثلث‌ها را با محتوا پر کنیم. برای این کار اول باید مثلث را «رسترایز» کنیم — یعنی آن را به فهرست پیکسل‌های روی صفحه‌ای که اشغال می‌کند تبدیل کنیم.

من از روش نسبتاً ساده‌ای استفاده می‌کنم که چندان کارآمد نیست — رسترایز با مختصات باری‌سنتریک. موتورهای سه‌بعدی واقعی از رسترایز سخت‌افزاری استفاده می‌کنند که بسیار سریع و کارآمد است، اما ما نمی‌توانیم از کارت گرافیک استفاده کنیم و برای همین آن را دستی در کد خود انجام می‌دهیم.

ایده این است که برای هر پیکسلی که احتمالاً داخل مثلث قرار می‌گیرد، مختصات باری‌سنتریک را محاسبه کنیم و آن‌هایی را که خارج هستند دور بیندازیم. قطعه زیر الگوریتم را پیاده‌سازی می‌کند. توجه کنید که از این‌جا به بعد شروع به استفاده مستقیم از پیکسل‌های تصویر کرده‌ایم. 

javaBufferedImage img = 
    new BufferedImage(getWidth(), getHeight(), BufferedImage.TYPE_INT_ARGB);

for (Triangle t : tris) {
    Vertex v1 = transform.transform(t.v1);
    Vertex v2 = transform.transform(t.v2);
    Vertex v3 = transform.transform(t.v3);

    // چون دیگر از Graphics2D استفاده نمی‌کنیم،
    // باید ترجمه (translate) را دستی انجام دهیم
    v1.x += getWidth() / 2;
    v1.y += getHeight() / 2;
    v2.x += getWidth() / 2;
    v2.y += getHeight() / 2;
    v3.x += getWidth() / 2;
    v3.y += getHeight() / 2;

    // محاسبه محدوده مستطیلی دور مثلث
    int minX = (int) Math.max(0, Math.ceil(Math.min(v1.x, Math.min(v2.x, v3.x))));
    int maxX = (int) Math.min(img.getWidth() - 1, 
                              Math.floor(Math.max(v1.x, Math.max(v2.x, v3.x))));
    int minY = (int) Math.max(0, Math.ceil(Math.min(v1.y, Math.min(v2.y, v3.y))));
    int maxY = (int) Math.min(img.getHeight() - 1,
                              Math.floor(Math.max(v1.y, Math.max(v2.y, v3.y))));

    double triangleArea =
       (v1.y - v3.y) * (v2.x - v3.x) + (v2.y - v3.y) * (v3.x - v1.x);

    for (int y = minY; y <= maxY; y++) {
        for (int x = minX; x <= maxX; x++) {
            double b1 = 
              ((y - v3.y) * (v2.x - v3.x) + (v2.y - v3.y) * (v3.x - x)) / triangleArea;
            double b2 =
              ((y - v1.y) * (v3.x - v1.x) + (v3.y - v1.y) * (v1.x - x)) / triangleArea;
            double b3 =
              ((y - v2.y) * (v1.x - v2.x) + (v1.y - v2.y) * (v2.x - x)) / triangleArea;
            if (b1 >= 0 && b1 <= 1 && b2 >= 0 && b2 <= 1 && b3 >= 0 && b3 <= 1) {
                img.setRGB(x, y, t.color.getRGB());
            }
        }
    }

}

g2.drawImage(img, 0, 0, null);

کلی کد است، اما حالا یک چهاروجهی رنگی روی نمایشگر داریم: دموی تعاملی در نسخه اصلی مقاله موجود است.

اگر با دمو بازی کنید، متوجه می‌شوید که همه‌چیز آن‌طور که باید نیست — برای مثال، مثلث آبی همیشه بالای بقیه است. این اتفاق می‌افتد چون فعلاً مثلث‌ها را یکی پس از دیگری رنگ می‌کنیم و مثلث آبی آخرین است — برای همین روی همه دیگران نقاشی می‌شود.

۶. بافر عمق (Z-Buffer)

برای رفع این مشکل مفهوم z-buffer (یا بافر عمق) را معرفی می‌کنم. ایده این است که در طول رسترایز یک آرایه میانی بسازیم که عمق آخرین عنصر دیده‌شده در هر پیکسل را ذخیره کند. هنگام رسترایز مثلث‌ها، بررسی می‌کنیم که عمق پیکسل کمتر از مقدار قبلی باشد و فقط اگر بالاتر از بقیه است، رنگش کنیم. 

javadouble[] zBuffer = new double[img.getWidth() * img.getHeight()];
// مقداردهی اولیه آرایه با عمق‌های بسیار دور
for (int q = 0; q < zBuffer.length; q++) {
    zBuffer[q] = Double.NEGATIVE_INFINITY;
}

for (Triangle t : tris) {
    // ادامه رسترایز...
    // برای هر پیکسل رسترایز شده:
    double depth = b1 * v1.z + b2 * v2.z + b3 * v3.z;
    int zIndex = y * img.getWidth() + x;
    if (zBuffer[zIndex] < depth) {
        img.setRGB(x, y, t.color.getRGB());
        zBuffer[zIndex] = depth;
    }
}

۷. سایه‌زنی تخت با نور (Flat Shading)

اما هنوز کارمان تمام نشده. در زندگی واقعی، رنگ درک‌شده سطح با موقعیت منبع نور تغییر می‌کند — اگر مقدار کمی نور به سطح بتابد، آن سطح را تیره‌تر درک می‌کنیم.

در گرافیک کامپیوتری، می‌توانیم با استفاده از به‌اصطلاح «shading» (سایه‌زنی) اثر مشابهی ایجاد کنیم — تغییر رنگ سطح بر اساس زاویه و فاصله آن تا منابع نور.

ساده‌ترین شکل سایه‌زنی، سایه‌زنی تخت (flat shading) است. فقط زاویه بین نرمال سطح و جهت منبع نور را در نظر می‌گیرد. فقط کافی است کسینوس زاویه بین این دو بردار را پیدا کنید و رنگ را در مقدار حاصل ضرب کنید. این روش بسیار ساده و ارزان است، برای همین اغلب برای رندر پرسرعت وقتی فناوری‌های پیشرفته‌تر سایه‌زنی از نظر محاسباتی بسیار گران هستند استفاده می‌شود.

۷.۱. محاسبه نرمال سطح (ضرب خارجی)

اول باید بردار نرمال مثلث‌مان را محاسبه کنیم. اگر مثلث ABC داشته باشیم، می‌توانیم بردار نرمال آن را با محاسبه ضرب خارجی (cross product) بردارهای AB و AC و سپس تقسیم بردار حاصل بر طولش به دست آوریم.

ضرب خارجی یک عمل دوتایی روی دو بردار است که در فضای سه‌بعدی این‌طور تعریف می‌شود:

u × v = [ ux , uy , uz ] × [ vx , vy , vz ] = [ uy×vz − uz×vy , uz×vx − ux×vz , ux×vy − uy×vx ]

این هم توضیح تصویری این‌که ضرب خارجی چه می‌کند:

javafor (Triangle t : tris) {
    // ابتدا رأس‌ها را قبل از محاسبه نرمال تبدیل کنید...

    Vertex norm = new Vertex(
         ab.y * ac.z - ab.z * ac.y,
         ab.z * ac.x - ab.x * ac.z,
         ab.x * ac.y - ab.y * ac.x
    );
    double normalLength =
        Math.sqrt(norm.x * norm.x + norm.y * norm.y + norm.z * norm.z);
    norm.x /= normalLength;
    norm.y /= normalLength;
    norm.z /= normalLength;
}

۷.۲. محاسبه کسینوس زاویه با جهت نور

حالا باید کسینوس بین نرمال مثلث و جهت نور را محاسبه کنیم. برای سادگی فرض می‌کنیم که نور مستقیماً پشت دوربین در فاصله‌ای بی‌نهایت قرار دارد (به چنین پیکربندی «نور جهتی» یا directional light گفته می‌شود) — برای همین جهت منبع نور ما [ 0 0 1 ] خواهد بود.

کسینوس زاویه بین بردارها را می‌توان با این فرمول محاسبه کرد:

cosθ = (A·B) / (||A|| × ||B||)

که ||A|| طول بردار است و A·B ضرب داخلی (نقطه‌ای) بردارها:

A·B = [ ax , ay , az ] · [ bx , by , bz ] = ax×bx + ay×by + az×bz

توجه کنید که طول بردار جهت نور ([ 0 0 1 ]) برابر ۱ است، و طول نرمال مثلث هم همین‌طور (چون از قبل نرمالایز کرده‌ایم). برای همین فرمول صرفاً به این صورت درمی‌آید:

cosθ = A·B = [ ax , ay , az ] · [ bx , by , bz ]

همچنین ببینید که فقط مؤلفه Z بردار جهت نور غیرصفر است، پس می‌توانیم بیشتر ساده کنیم:

cosθ = A·B = [ ax , ay , az ] · [ 0 0 1 ] = az

کد حالا بی‌اهمیت است:

javadouble angleCos = Math.abs(norm.z);

علامت را از نتیجه حذف می‌کنیم چون برای مقاصد ساده ما فرقی نمی‌کند کدام طرف مثلث رو به دوربین است. در اپلیکیشن واقعی باید این را پیگیری کنید و سایه‌زنی را مطابق آن اعمال کنید.

۷.۳. اعمال سایه روی رنگ

حالا که ضریب سایه را داریم، می‌توانیم آن را روی رنگ مثلث اعمال کنیم. نسخه ساده‌لوحانه ممکن است این‌طور باشد:

javapublic static Color getShade(Color color, double shade) {
    int red = (int) (color.getRed() * shade);
    int green = (int) (color.getGreen() * shade);
    int blue = (int) (color.getBlue() * shade);
    return new Color(red, green, blue);
}

اگرچه این به ما کمی اثر سایه می‌دهد، افت آن بسیار سریع‌تر از آن چیزی خواهد بود که نیاز داریم. این اتفاق می‌افتد چون جاوا از فضای رنگی sRGB استفاده می‌کند که از قبل برای مطابقت با درک لگاریتمی ما از رنگ تنظیم شده است.

برای همین باید هر رنگ را از فرمت تنظیم‌شده (scaled) به فرمت خطی تبدیل کنیم، سایه را اعمال کنیم و بعد دوباره به فرمت تنظیم‌شده برگردانیم. تبدیل واقعی از sRGB به RGB خطی کاملاً پیچیده است، برای همین مشخصات کامل را این‌جا پیاده‌سازی نمی‌کنم — فقط تقریب پایه را می‌زنم. 

javapublic static Color getShade(Color color, double shade) {
    double redLinear = Math.pow(color.getRed(), 2.4) * shade;
    double greenLinear = Math.pow(color.getGreen(), 2.4) * shade;
    double blueLinear = Math.pow(color.getBlue(), 2.4) * shade;

    int red = (int) Math.pow(redLinear, 1/2.4);
    int green = (int) Math.pow(greenLinear, 1/2.4);
    int blue = (int) Math.pow(blueLinear, 1/2.4);

    return new Color(red, green, blue);
}

۸. جایزه: ساخت کره از چهاروجهی

این هم یک جایزه برای شما — می‌توانیم به‌سرعت از این چهاروجهی یک تقریب کره بسازیم. این کار با تقسیم مکرر هر مثلث به چهار مثلث کوچک‌تر و «باد کردن» (inflate) آن‌ها انجام می‌شود: 

javapublic static List<triangle> inflate(List<triangle> tris) {
    List<triangle> result = new ArrayList<>();
    for (Triangle t : tris) {
        Vertex m1 =
            new Vertex((t.v1.x + t.v2.x)/2, (t.v1.y + t.v2.y)/2, (t.v1.z + t.v2.z)/2);
        Vertex m2 =
            new Vertex((t.v2.x + t.v3.x)/2, (t.v2.y + t.v3.y)/2, (t.v2.z + t.v3.z)/2);
        Vertex m3 =
            new Vertex((t.v1.x + t.v3.x)/2, (t.v1.y + t.v3.y)/2, (t.v1.z + t.v3.z)/2);
        result.add(new Triangle(t.v1, m1, m3, t.color));
        result.add(new Triangle(t.v2, m1, m2, t.color));
        result.add(new Triangle(t.v3, m2, m3, t.color));
        result.add(new Triangle(m1, m2, m3, t.color));
    }
    for (Triangle t : result) {
        for (Vertex v : new Vertex[] { t.v1, t.v2, t.v3 }) {
            double l = Math.sqrt(v.x * v.x + v.y * v.y + v.z * v.z) / Math.sqrt(30000);
            v.x /= l;
            v.y /= l;
            v.z /= l;
        }
    }
    return result;
}
