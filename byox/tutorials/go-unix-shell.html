نوشتن یک شل ساده با گو (Writing a simple shell in Go)

شل چیست؟

«شل رابط پایهٔ کاربر با سیستمعامل است: به آن دستور می‌دهید و خروجیِ متناظرش را می‌گیرید.» گنوم و ویندوز هم شل‌هایی گرافیکی‌اند، اما وقتی اغلب اهل فناوری از شل حرف می‌زنند، منظورش شل متنی است (مثل Bash و Zsh). عملکرد ساده است: ls را بدهید و فهرست پوشه را بگیرید.

یونیکس خیلی ساده است؛ فقط یک نابغه لازم دارد تا سادگی‌اش را بفهمد. — دنیس ریچی

شل فقط بخش کوچکی از سیستمعامل است (و نسبت به هسته واقعاً بخش آسانش!)؛ امید نویسنده این است که در پایان، شما هم مثل او شگفت‌زده شوید که نوشتن شل وقتی مفاهیم پشتش را فهمیدید چقدر ساده است.

حلقهٔ ورودی

صفحه‌کلیدِ ما دستگاه ورودی استاندارد (os.Stdin) است. با هر بار فشردن Enter یک خط نو (\n) ساخته می‌شود و ما آن خط را می‌خوانیم:

gofunc main() {
    reader := bufio.NewReader(os.Stdin)
    for {
        fmt.Print("> ")
        input, err := reader.ReadString('\n')
        if err != nil {
            fmt.Println(err)
        }
        err = execInput(input)
        if err != nil {
            fmt.Println(err)
        }
    }
}

نکتهٔ جانبی: بهتر است خطاها به os.Stderr نوشته شوند (مثلاً با log.Println)، اما آن تایم‌استمپ اضافه می‌کند و پرگویی به نظر می‌رسد؛ بعداً می‌توانید اصلاحش کنید.

اجرای دستورها

اول کاراکتر خط جدید را از انتهای ورودی می‌کنیم، بعد دستور را با exec.Command آماده و با cmd.CombinedOutput() اجرا می‌کنیم (خروجی موفق به stdout و خطا به stderr می‌رود، ولی هر دو در متغیر stdoutStderr جمع می‌شوند):

gofunc execInput(input string) error {
    // حذف کاراکتر خط جدید
    input = strings.TrimSuffix(input, "\n")

    // تهیهٔ دستور برای اجرا
    cmd := exec.Command(input)

    // اجرا و گرفتن خروجی
    stdoutStderr, err := cmd.CombinedOutput()
    if err != nil {
        return err
    }
    fmt.Printf("%s", stdoutStderr)
    return nil
}

اولین تست: go run main.go، اعلان >، و ls کار می‌کند! خروجی از برنامه گرفته می‌شود و CTRL-C مثل هر برنامهٔ دیگری شل را می‌بندد.

آرگومان‌ها — داستان ls -l

ترمینال> ls -l
exec: "ls -l": executable file not found in $PATH

شکست خورد! چون شلِ ما دارد برنامه‌ای به‌نام ls -l را اجرا می‌کند؛ در حالی که برنامه فقط ls است و -l آرگومانی است که خودِ برنامه تجزیه‌اش می‌کند. پس ورودی را روی هر فاصله می‌شکنیم:

go// جدا کردن دستور از آرگومان‌ها
args := strings.Split(input, " ")

// عبور جداگانهٔ برنامه و آرگومان‌ها
cmd := exec.Command(args[0], args[1:]...)

حالا نام برنامه در args[0] و آرگومان‌ها در اندیس‌های بعدی‌اند و ls -l آن‌طور که انتظار می‌رود کار می‌کند.

Builtin — چرا cd کار نمی‌کند؟

تماشای cd / و بعد ls که فهرستِ پوشهٔ فعلی را می‌دهد! پاسخ ساده است: برنامهٔ «واقعی» cd وجود ندارد — این قابلیت یک دستور داخلیِ شل است (برای اینکه بتواند حالتِ خودِ شل را تغییر دهد). پس یک switch روی اولین آرگومان اضافه می‌کنیم:

go// بررسی دستورهای داخلی
switch args[0] {
case "cd":
    // با مسیر خالی، cd به خانهٔ کاربر هنوز پشتیبانی نمی‌شود
    if len(args) < 2 {
        return errors.New("path required")
    }
    if err := os.Chdir(args[1]); err != nil {
        return err
    }
    return nil
case "exit":
    os.Exit(0)
}

بهبودهای پیشنهادی و جمع‌بندی

  • اصلاح اعلان: اضافه کردن دایرکتوری کاری، نام میزبان یا کاربر فعلی
  • نوشتن خطاها به stderr
  • مرور تاریخچهٔ ورودی با کلیدهای بالا/پایین

در مجموع حرف اصلی این است: برخلاف آنچه به نظر می‌رسد، گو هم به سادگی‌اش کمک کرد — بدون هیچ کار سطح‌پایینی مثل مدیریت حافظه. «راب پایک و کن تامسون که به‌همراه رابرت گریزمِر گو را ساختند، در ساخت یونیکس هم دست داشتند؛ پس نوشتن شل با گو ترکیب خوبی است.»
