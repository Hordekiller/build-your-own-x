ترکیب‌گر Parser چیست؟

بجای اینکه برای هر زبان یک parser بنویسیم، «ترکیب‌گرها» (Combinators) تابع‌های کوچکی هستند که در هم ترکیب می‌شوند و parser می‌سازند. یک parser یک «تابع» است: ورودی (رشته) می‌گیرد و یا موفق برمی‌گردد (نتیجه + ماندهٔ ورودی) یا شکست.

اسکات ولاشین این ایده را با F# — زبانی تابعی و خوانا — توضیح می‌دهد؛ مفاهیم آن به هر زبان قابل انتقال است (و نسخه‌های Rust، Go، JavaScript هم دارند).

مفهوم اصلی: توابع پایه و ترکیب

سه ترکیب‌گر پایه: preturn (همیشه موفق با مقدار ثابت)، pzero (همیشه شکست)، satisfy (یک حرفی که با پیش‌شرط منطبق باشد). سپس ترکیب‌گرهای ساختاری: andThen (p1 سپس p2)، orElse (یا p1 یا p2)، many (صفر یا چند بار). با همین‌ها، parserهای پیچیده ساخته می‌شوند:

F#type Parser<'a> = string -> Result<'a * string, string>

// و سپس: p1 و بعد p2
let andThen p1 p2 = fun input ->
    match p1 input with
    | Error e -> Error e
    | Ok (r1, rest) ->
      match p2 rest with
      | Error e -> Error e
      | Ok (r2, rest2) -> Ok ((r1, r2), rest2)

// p1 یا p2
let orElse p1 p2 = fun input ->
    match p1 input with
    | Ok r -> Ok r
    | Error _ -> p2 input

توجه کنید که با بازگشت و همین دو تابع ساده، می‌توان grammarهای کامل تعریف کرد — بدون هیچ ابزار parser generator تا وقتی که بخواهید.

استفادهٔ عملی: ساخت یک ماشین‌حساب

در ادامهٔ مقاله، با این ترکیب‌گرها یک ماشین‌حساب کوچک (اعداد، جمع، ضرب با اولویت) ساخته می‌شود. همچنین بحث می‌شود که چطور با «monad» (در F# با forwardPipe و record) می‌توان خطاها و وضعیت را تمیزتر مدیریت کرد؛ و چرا ترکیب‌گرها به‌طور طبیعی به‌صورت «بازگشتی به چپ» (left recursion) مشکل دارند — مشکلی که parserهای LALR حل می‌کنند.

نمونهٔ کد: اعداد و عملگرها

F#let digitChar = satisfy (fun ch -> System.Char.IsDigit ch)
let digits = many1 digitChar   // یک یا چند رقم

// تبدیل رشتهٔ رقم‌ها به int
let toInt (str:string) : int = System.Int32.Parse(str)

let number = digits |>> toInt   // parser عدد

// expr := number (("+"|"-") number)*
let expr =
    let op = char '-' |>> (fun _ -> (-)) <|> char '+' |>> (fun _ -> (+))
    number .>>. many (op .>>. number)
