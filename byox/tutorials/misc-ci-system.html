سیستم یکپارچه‌سازی پیوسته (CI)

منبع اصلی: این صفحه ترجمهٔ فارسی و مرور فصل «A Continuous Integration System» از کتاب 500 Lines or Less است که CI را از صفر می‌سازد.
↗ مشاهده منبع اصلی

CI چیست و چه می‌کند؟

یکپارچه‌سازی پیوسته (Continuous Integration) یعنی: با هر کامیت، به‌طور خودکار تست‌ها روی یک سرور مستقل اجرا شوند و نتیجه در وب‌روی نمایش داده شود. GitHub Actions و GitLab CI همین کار را می‌کنند؛ این فصل (از کتاب معروف 500 Lines) آن را با یک سرور شیءگرا و یک runner ساده می‌سازد.

معماری: دو بخش اصلی

سیستم از دو مؤلفهٔ مستقل ساخته می‌شود: برنامهٔ سرور که وضعیت تست‌ها را ثبت و گزارش می‌کند، و runner که در هر ماشین تست را اجرا می‌کند. Publisherها هم وقایع را به کانال‌ها (ایمیل، IRC) می‌فرستند. این جدایی یعنی تست‌ها روی هر سروری قابل اجرا هستند و سرور فقط هماهنگ‌کننده است.

مدل داده

هر تست یک `Build` است که وضعیت‌های مختلف دارد. تغییر وضعیت، مشترکین (subscribe/unsubscribe) را خبر می‌کند — الگوی Observer:

Pythonclass BuildStatus:
    """وضعیت یک build که مشترکان را خبر می‌کند."""
    def __init__(self, name):
        self.name = name
        self.status = 'pending'
        self.subscribers = []

    def subscribe(self, sub):
        self.subscribers.append(sub)

    def set_status(self, status):
        self.status = status
        for sub in self.subscribers:
            sub(self)   # خبر بده: buildت به این وضعیت رسید

خبر کردن مشترکین (مثل ایمیل) در همان لحظهٔ تغییر وضعیت — و نه در حلقهٔ پولینگ — ساده و مستقیم است.

Runner: اجرای تست

runner درخواست‌ها را دریافت می‌کند، با تست مواجه شود یا نرود. نکتهٔ جالب فصل: تست‌ها در thread جدا با timeout اجرا می‌شوند تا تست آویزان (hang) CI را قفل نکند— «بن‌بست» بین مرگ یک thread و timeout:

Pythondef run_tests(repo, test_cmd, timeout=60):
    """اجرای تست‌ها در thread جداگانه با محدودیت زمان."""
    result = {'status': 'running'}

    def _run():
        # clone/repo update، اجرا و ثبت نتیجه
        rc = subprocess.run(test_cmd, shell=True, timeout=timeout)
        result['status'] = 'success' if rc.returncode == 0 else 'failed'

    t = threading.Thread(target=_run)
    t.start(); t.join(timeout)
    if t.is_alive():
        result['status'] = 'timeout'   # تست گیر کرده
    return result

می‌بینید که CI در قلبش فقط ۴ حالت می‌شناسد: pending، running، success، failed — همین چهارتا برای کل اکوسیستم Actions کافی است.

جمع‌بندی

کل کتاب در ۵۰۰ خط؛ مفاهیم بزرگ (Observer، Publisher/Subscriber، threading با timeout، رست API) در یک پروژهٔ واقعی گره می‌خورد. بعد از این، هر پلتفرم CI را نگاه کنید، معماریش برایتان شفاف است.
