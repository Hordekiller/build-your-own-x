۱. مقدمه و طراحی زبان

این آموزش یک موتور قالب سادهٔ پایتونی می‌سازد و زیرِ کاپوتش — چطور یک قالب «کامپایل» و بعد «رندر» می‌شود — را نشان می‌دهد. زبان قالب دوتا تگ دارد: متغیرها با {{ }} و بلوک‌ها با {% %}:

html<!-- متغیرها بین دو آکولاد -->
<div>{{my_var}}</div>

<!-- بلوک‌ها با {% %} و بستن با «end» -->
{% each items %}
    <div>{{it}}</div>
{% end %}

امکانات زبان: حلقه‌های each، شرط‌های if/else (با عملگرهای ==، <=، >=، !=، is، >، <) و همچنین فراخوانی توابع (callables) با آرگومان موقعیتی یا کلیدواژه‌ای:

html<!-- حلقه روی افراد؛ «it» آیتم فعلی است -->
{% each people %}
    <div>{{it.name}}</div>
{% end %}

<!-- «..» یعنی دسترسی به متغیرِ کانتکستِ والد -->
{% each records %}
    <div>{{..name}}</div>
{% end %}

<!-- شرط -->
{% if num > 5 %}
    <div>more than 5</div>
{% else %}
    <div>less than or equal to 5</div>
{% end %}

<!-- فراخوانی تابع با آرگومان و کلیدواژه -->
<div class='date'>{% call prettify date_created %}</div>
<div>{% call log 'here' verbosity='debug' %}</div>

۲. نظریه: چرا درخت نحو (AST)؟

مترجم‌ها محتوای برنامه را با درخت نحو انتزاعی (AST) نشان می‌دهند — حاصلِ تحلیلِ واژگانیِ متن. درخت نسبت به متنِ خام مزیت دارد: جداکننده‌های بی‌مصرف (مثل آکولادهای قالب) در آن نیست و می‌توان بدون دست‌زدن به کد، به گره‌ها ویژگی اضافه کرد. مسیر کارِ موتور ما: توکن‌سازی → ساختن AST → رندر (پیمایش درخت با کانتکست).

۳. توکن‌سازی با رگکس

اولین قدم، شکستن قالب به تکه‌هاست؛ هر تکه یا HTML خام است یا یک تگ. با re.split و یک رگکسِ lazy (غیرحریص) که به هر دو نوع تگ می‌خورد:

pythonimport re

VAR_TOKEN_START = '{{'
VAR_TOKEN_END = '}}'
BLOCK_TOKEN_START = '{%'
BLOCK_TOKEN_END = '%}'

TOK_REGEX = re.compile(r"(%s.*?%s|%s.*?%s)" % (
    VAR_TOKEN_START, VAR_TOKEN_END,
    BLOCK_TOKEN_START, BLOCK_TOKEN_END
))

# مثال:
>>> TOK_REGEX.split('{% each vars %}<i>{{it}}</i>{% endeach %}')
['{% each vars %}', '<i>', '{{it}}', '</i>', '{% endeach %}']

? داخل گزینه‌ها یعنی تکرارِ lazy؛ رگکس باید در اولین تطبیق بایستد تا مثلاً تگ‌های متغیرِ داخلِ داخلِ بلوک‌ها درست جدا شوند. هر تکه داخل یک آبجکت _Fragment می‌شود که نوعش را تعیین می‌کند؛ چهار نوع: VAR، OPEN_BLOCK، CLOSE_BLOCK و TEXT.

۴. ساختن AST

حالا تکه‌ها گره می‌شوند. کلاس پایهٔ _Node متدهای process_fragment() و render() را تعریف می‌کند و هوک‌های enter_scope()/exit_scope() را دارد که مترجم موقع باز/بسته شدنِ scope گره‌ها صدا می‌زند. بچه‌های هر گره در children نگه‌داری می‌شوند:

pythonclass _Node(object):
    def __init__(self, fragment=None):
        self.children = []
        self.creates_scope = False
        self.process_fragment(fragment)
    def process_fragment(self, fragment): pass
    def enter_scope(self): pass
    def render(self, context): pass
    def exit_scope(self): pass
    def render_children(self, context, children=None):
        if children is None:
            children = self.children
        def render_child(child):
            child_html = child.render(context)
            return '' if not child_html else str(child_html)
        return ''.join(map(render_child, children))

# مثال: گرهٔ متغیر
class _Variable(_Node):
    def process_fragment(self, fragment):
        self.name = fragment
    def render(self, context):
        return resolve_in_context(self.name, context)

نوع گره از روی «فرمانِ بلوک» (اولین کلمهٔ داخل {% %}) تعیین می‌شود؛ مثلاً {% each items %} یک گرهٔ each است. گره‌هایی که scope می‌سازند (حلقه‌ها/شرط‌ها) در زمان کامپایل به پشتهٔ scope اضافه و بچه‌هایشان به آن‌ها چسبانده می‌شوند؛ رسیدن به تگِ بستن، scope را می‌بندد:

pythondef compile(self):
    root = _Root()
    scope_stack = [root]
    for fragment in self.each_fragment():
        if not scope_stack:
            raise TemplateError('nesting issues')
        parent_scope = scope_stack[-1]
        if fragment.type == CLOSE_BLOCK_FRAGMENT:
            parent_scope.exit_scope()
            scope_stack.pop()
            continue
        new_node = self.create_node(fragment)
        if new_node:
            parent_scope.children.append(new_node)
            if new_node.creates_scope:
                scope_stack.append(new_node)
                new_node.enter_scope()
    return root

۵. رندر: تفکیک literal از نام متغیر

در مرحلهٔ رندر باید بفهمیم یک عبارت، «مقدار ثابت» است یا «نام متغیر در کانتکست» — این کار با ast.literal_eval انجام می‌شود که رشتهٔ پایتونی را امن ارزیابی می‌کند:

pythonimport ast

def eval_expression(expr):
    try:
        return 'literal', ast.literal_eval(expr)
    except (ValueError, SyntaxError):
        return 'name', expr

۶. حل‌کردن نام‌ها: مسیر نقطه‌دار و «..»

قطعهٔ پایانی پازل: تابعِ حل‌کردن نام که هم نام‌های نقطه‌دار (it.name) را در دیکشنری‌های تودرتو دنبال می‌کند و هم با پیشوند .. به کانتکستِ والد برمی‌گردد:

pythondef resolve(name, context):
    if name.startswith('..'):
        context = context.get('..', {})
        name = name[2:]
    try:
        for tok in name.split('.'):
            context = context[tok]
        return context
    except KeyError:
        raise TemplateContextError(name)

۷. جمع‌بندی

این تمرین «آکادمیک» چشیدنِ طعمِ داخلِ یک موتور قالب واقعی است: توکن‌سازی با رگکس، ساختن درخت نحوی با مدیریت scope، و رندرِ پیمایشی با کانتکست. بدیهی است که این پیاده‌سازی آمادهٔ تولید نیست — اما راهنمای عالی برای فهمِ پایه‌های موتورهایی مثل Jinja2 است. کد کامل: github.com/alexmic/microtemplates.
