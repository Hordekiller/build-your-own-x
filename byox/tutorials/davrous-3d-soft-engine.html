بخش ۱: مقدمه و منطق هسته (دوربین، مش و شیء Device)

می‌خواهم با شما در میان بگذارم که چگونه ساخت چیزی به نام «موتور سه‌بعدی نرم (3D soft engine)» را از طریق یک سری آموزش یاد گرفتم. منظور از «موتور نرم‌افزاری» این است که برای ساخت موتور سه‌بعدی فقط از CPU استفاده می‌کنیم، آن‌هم به سبک قدیمی‌ها (یادتان هست Doom روی 80386 شما؟). کد این آموزش را به هر سه زبان C#، TypeScript و JavaScript با شما به اشتراک می‌گذارم؛ در این فهرست باید زبان محبوب خودتان یا حداقل زبانی نزدیک به آن را پیدا کنید. هدف این است که کمک کنم نمونه‌ها و مفاهیم زیر را روی پلتفرم محبوب خودتان پیاده کنید. در انتها نیز راه‌حل‌های Visual Studio 2012 (مخصوص C#/TypeScript/JavaScript) را برای دانلود پیدا می‌کنید.

اما چرا یک موتور سه‌بعدی نرم بسازیم؟ ساده است: چون واقعاً کمک می‌کند بفهمیم سه‌بعدی مدرن در GPUهای امروزی چگونه کار می‌کند. من در حال حاضر مقدمات سه‌بعدی را از طریق کارگاه‌های داخلی مایکروسافت که دیوید کاتو (David Catuhe) فوق‌العاده برگزار می‌کند، یاد می‌گیرم. او سال‌هاست استاد سه‌بعدی است و عملیات ماتریسی در مغزش حک شده است. وقتی جوان بودم، آرزو داشتم بتوانم چنین موتورهایی بنویسم اما حس می‌کردم این کار برایم بیش از حد پیچیده است. در پایان خواهید دید که آن‌قدرها هم پیچیده نیست؛ فقط لازم است کسی باشد که اصول زیربنایی را ساده برایتان توضیح دهد.

در طول این سری یاد می‌گیرید چگونه مختصات سه‌بعدی (X، Y، Z) مرتبط با یک نقطه (رأس) را روی صفحه دوبعدی پروژه کنید، چگونه بین هر دو نقطه خط بکشید، چگونه مثلث‌ها را پر کنید و نور و متریال را مدیریت کنید. این آموزش اول فقط نشان می‌دهد چگونه ۸ نقطه مربوط به یک مکعب را نمایش دهید و آن‌ها را در یک دنیای سه‌بعدی مجازی حرکت دهید.

بافر پشتی و حلقه رندر

در یک موتور سه‌بعدی، در هر فریم کل صحنه را رندر می‌کنیم به این امید که نرخ ۶۰ فریم در ثانیه (FPS) بهینه حفظ شود تا انیمیشن‌ها روان بمانند. برای انجام کار رندر به چیزی نیاز داریم که به آن «بافر پشتی (back buffer)» می‌گوییم. می‌شود آن را آرایه‌ای دوبعدی در نظر گرفت که با اندازه پنجره/صفحه نمایش نقشه می‌شود؛ هر خانه آرایه به یک پیکسل روی صفحه نگاشت می‌شود.

در اپلیکیشن‌های XAML ویندوز استور ما، از یک آرایه byte[] استفاده می‌کنیم که نقش بافر پشتی پویا را بازی می‌کند. در هر فریمی که در حلقه انیمیشن (tick) رندر می‌شود، این بافر به یک WriteableBitmap نسبت داده می‌شود که نقش منبع کنترل تصویر XAML را دارد و «بافر جلویی (front buffer)» نامیده می‌شود. برای حلقه رندر، از موتور رندرینگ XAML می‌خواهیم برای هر فریمی که تولید می‌کند ما را صدا بزند. ثبت این کار با این خط کد انجام می‌شود:

c#CompositionTarget.Rendering += CompositionTarget_Rendering;

در HTML5 البته از عنصر <canvas /> استفاده می‌کنیم. عنصر canvas از قبل یک آرایه داده بافر پشتی دارد که از طریق توابع getImageData() و setImageData() به آن دسترسی دارید. حلقه انیمیشن توسط تابع requestAnimationFrame() مدیریت می‌شود. این تابع بسیار کارآمدتر از معادلِ setTimeout(function() {}, 1000/60) است چون به‌صورت بومی توسط مرورگر مدیریت می‌شود؛ مرورگر فقط وقتی آماده رسم باشد کد ما را صدا می‌زند.

نکته: در هر دو حالت می‌توانید فریم‌ها را با رزولوشنی متفاوت از عرض و ارتفاع واقعی پنجره نهایی رندر کنید. مثلاً می‌توانید بافر پشتی ۶۴۰×۴۸۰ داشته باشید در حالی که صفحه نمایش نهایی (بافر جلویی) ۱۹۲۰×۱۰۸۰ است. در XAML و در HTML5 به‌لطف CSS از «مقیاس‌بندی سخت‌افزاری (hardware scaling)» بهره می‌برید: موتورهای رندر XAML و مرورگر داده بافر پشتی را با یک الگوریتم ضدپلگی (anti-aliasing) تا اندازه پنجره بافر جلویی بزرگ می‌کنند. در هر دو حالت این کار توسط GPU انجام می‌شود و به همین دلیل به آن «مقیاس‌بندی سخت‌افزاری» می‌گوییم (سخت‌افزار یعنی همان GPU). بیشتر بخوانید (در HTML5): Unleash the power of HTML 5 Canvas for gaming. این روش اغلب در بازی‌ها برای افزایش کارایی به‌کار می‌رود چون پیکسل‌های کمتری را آدرس‌دهی می‌کنید.

اشیای دوربین و مش (Camera & Mesh)

بریم سراغ کدنویسی. اول باید شیءهایی تعریف کنیم که جزئیات لازم برای دوربین و مش را در خود جای می‌دهند. «مش (Mesh)» نام باحالی برای توصیف یک شیء سه‌بعدی است.

دوربین ما (Camera) دو ویژگی خواهد داشت: موقعیتش در دنیای سه‌بعدی و جایی که به آن نگاه می‌کند یعنی هدف (Target). هر دو از مختصات سه‌بعدی به‌نام Vector3 ساخته می‌شوند. C# از SharpDX.Vector3 و TypeScript و JavaScript از BABYLON.Vector3 استفاده می‌کنند.

مش (Mesh) ما مجموعه‌ای از رأس‌ها (vertices — چند رأس یا نقطه سه‌بعدی) خواهد داشت که برای ساخت شیء سه‌بعدی به کار می‌روند، به‌علاوه موقعیتش در دنیای سه‌بعدی و حالت چرخشش. برای شناسایی، یک نام هم خواهد داشت.

به‌طور خلاصه به کد زیر نیاز داریم:

c#// Camera.cs و Mesh.cs
using SharpDX;

namespace SoftEngine
{
    public class Camera
    {
        public Vector3 Position { get; set; }
        public Vector3 Target { get; set; }
    }
    public class Mesh
    {
        public string Name { get; set; }
        public Vector3[] Vertices { get; private set; }
        public Vector3 Position { get; set; }
        public Vector3 Rotation { get; set; }

        public Mesh(string name, int verticesCount)
        {
            Vertices = new Vector3[verticesCount];
            Name = name;
        }
    }
}
typescript//
module SoftEngine {
    export class Camera {
        Position: BABYLON.Vector3;
        Target: BABYLON.Vector3;

        constructor() {
            this.Position = BABYLON.Vector3.Zero();
            this.Target = BABYLON.Vector3.Zero();
        }
    }
    export class Mesh {
        Position: BABYLON.Vector3;
        Rotation: BABYLON.Vector3;
        Vertices: BABYLON.Vector3[];

        constructor(public name: string, verticesCount: number) {
            this.Vertices = new Array(verticesCount);
            this.Rotation = BABYLON.Vector3.Zero();
            this.Position = BABYLON.Vector3.Zero();
        }
    }
}

حالا که شیءهای پایه را داریم و می‌دانیم مش‌های سه‌بعدی را چگونه بسازیم، به مهم‌ترین بخش می‌رسیم: شیء Device. این قلب موتور سه‌بعدی ماست.

در تابع رندر آن، بر اساس دوربینی که قبلاً تعریف کرده‌ایم، ماتریس دید (view) و ماتریس پروجکشن (projection) را می‌سازیم. سپس از میان هر مش موجود می‌گذریم تا ماتریس دنیای (world) مربوط به هر کدام را بر اساس مقادیر فعلی چرخش و انتقال‌شان بسازیم. در پایان، ماتریس تبدیل نهایی که باید اعمال شود این است:

c# / typescript / javascriptvar transformMatrix = worldMatrix * viewMatrix * projectionMatrix;

این همان مفهومی است که حتماً باید با خواندن منابع پیش‌نیاز بفهمید. وگرنه احتمالاً کد را کپی‌پیست می‌کنید بدون اینکه چیزی از جادوی زیر آن بفهمید. این مسئله چندان بزرگی برای آموزش‌های بعدی نیست، اما باز هم بهتر است بدانید چه چیزی می‌نویسید.

با استفاده از این ماتریس تبدیل، هر رأس از هر مش را در دنیای دوبعدی پروژه می‌کنیم تا از مختصات X،Y،Z آن‌ها مختصات X،Y بگیریم. برای رسم نهایی روی صفحه، یک منطق برش (clip) کوچک اضافه می‌کنیم تا فقط پیکسل‌های قابل مشاهده از طریق تابع PutPixel نمایش داده شوند.

در این‌جا نسخه‌های گوناگون شیء Device را می‌بینید. سعی کرده‌ام کد را تا حد امکان کامنت‌گذاری کنم تا درکش برای شما آسان‌تر شود.

نکته: مایکروسافت ویندوز با فضای رنگی BGRA (آبی، سبز، قرمز، آلفا) رسم می‌کند در حالی که canvas در HTML5 با RGBA (قرمز، سبز، آبی، آلفا) رسم می‌کند. به همین دلیل تفاوت‌های جزئی در کد بین C# و HTML5 می‌بینید.

namespace SoftEngine
{
    public class Device
    {
        private byte[] backBuffer;
        private WriteableBitmap bmp;

        public Device(WriteableBitmap bmp)
        {
            this.bmp = bmp;
            // اندازه بافر پشتی برابر است با تعداد پیکسل‌هایی که باید رسم شوند
            // روی صفحه (عرض*ارتفاع) ضربدر ۴ (مقادیر R,G,B و Alpha)
            backBuffer = new byte[bmp.PixelWidth * bmp.PixelHeight * 4];
        }

        // این متد برای پاک کردن بافر پشتی با یک رنگ مشخص صدا زده می‌شود
        public void Clear(byte r, byte g, byte b, byte a) {
            for (var index = 0; index < backBuffer.Length; index += 4)
            {
                // ویندوز از BGRA استفاده می‌کند نه RGBA مثل HTML5
                backBuffer[index] = b;
                backBuffer[index + 1] = g;
                backBuffer[index + 2] = r;
                backBuffer[index + 3] = a;
            }
        }

        // وقتی همه‌چیز آماده شد می‌توانیم بافر پشتی را
        // داخل بافر جلویی تخلیه کنیم
        public void Present()
        {
            using (var stream = bmp.PixelBuffer.AsStream())
            {
                // نوشتن بافر پشتی byte[] داخل استریم WriteableBitmap
                stream.Write(backBuffer, 0, backBuffer.Length);
            }
            // درخواست رسم مجدد کل بیت‌مپ
            bmp.Invalidate();
        }

        // برای گذاشتن یک پیکسل روی صفحه در مختصات X,Y مشخص صدا زده می‌شود
        public void PutPixel(int x, int y, Color4 color)
        {
            // چون بافر پشتی ما آرایه‌ای یک‌بعدی است
            // باید خانه معادل آن را در یک‌بعد بر اساس
            // مختصات دوبعدی روی صفحه بدانیم
            var index = (x + y * bmp.PixelWidth) * 4;

            backBuffer[index] = (byte)(color.Blue * 255);
            backBuffer[index + 1] = (byte)(color.Green * 255);
            backBuffer[index + 2] = (byte)(color.Red * 255);
            backBuffer[index + 3] = (byte)(color.Alpha * 255);
        }

        // Project مختصات سه‌بعدی می‌گیرد و آن‌ها را با ماتریس تبدیل
        // به مختصات دوبعدی تبدیل می‌کند
        public Vector2 Project(Vector3 coord, Matrix transMat)
        {
            // تبدیل مختصات
            var point = Vector3.TransformCoordinate(coord, transMat);
            // مختصات تبدیل‌شده بر اساس دستگاه مختصاتی است که
            // از مرکز صفحه شروع می‌شود اما رسم روی صفحه معمولاً از
            // گوشه بالا-چپ شروع می‌شود؛ پس باید دوباره تبدیلشان کنیم
            // تا x:0, y:0 در بالا-چپ باشد
            var x = point.X * bmp.PixelWidth + bmp.PixelWidth / 2.0f;
            var y = -point.Y * bmp.PixelHeight + bmp.PixelHeight / 2.0f;
            return (new Vector2(x, y));
        }

        // DrawPoint تابع PutPixel را صدا می‌زند اما قبلش عملیات برش را انجام می‌دهد
        public void DrawPoint(Vector2 point)
        {
            // برش آنچه روی صفحه دیده می‌شود
            if (point.X >= 0 && point.Y >= 0 && point.X < bmp.PixelWidth && point.Y < bmp.PixelHeight)
            {
                // رسم یک نقطه زرد
                PutPixel((int)point.X, (int)point.Y, new Color4(1.0f, 1.0f, 0.0f, 1.0f));
            }
        }

        // متد اصلی موتور که در هر فریم پروجکشن هر رأس را دوباره محاسبه می‌کند
        public void Render(Camera camera, params Mesh[] meshes)
        {
            // برای فهم این بخش لطفاً منابع پیش‌نیاز را بخوانید
            var viewMatrix = Matrix.LookAtLH(camera.Position, camera.Target, Vector3.UnitY);
            var projectionMatrix = Matrix.PerspectiveFovRH(0.78f,
                                                           (float)bmp.PixelWidth / bmp.PixelHeight,
                                                           0.01f, 1.0f);

            foreach (Mesh mesh in meshes)
            {
                // مواظب باشید: چرخش باید قبل از انتقال اعمال شود
                var worldMatrix = Matrix.RotationYawPitchRoll(mesh.Rotation.Y,
                                                              mesh.Rotation.X, mesh.Rotation.Z) *
                                  Matrix.Translation(mesh.Position);

                var transformMatrix = worldMatrix * viewMatrix * projectionMatrix;

                foreach (var vertex in mesh.Vertices)
                {
                    // اول مختصات سه‌بعدی را به فضای دوبعدی پروژه می‌کنیم
                    var point = Project(vertex, transformMatrix);
                    // بعد می‌توانیم روی صفحه رسم کنیم
                    DrawPoint(point);
                }
            }
        }
    }
}

                    // بعد می‌توانیم روی صفحه رسم کنیم
                    this.drawPoint(projectedPoint);

بعد حلقه انیمیشن/رندر را شروع می‌کنیم. در حالت بهینه، این حلقه هر ۱۶ میلی‌ثانیه (۶۰ FPS) صدا زده می‌شود. در هر tick (هر بار فراخوانی handler ثبت‌شده در حلقه رندر) این منطق را هر بار اجرا می‌کنیم:

  1. پاک کردن صفحه و همه پیکسل‌های مرتبط با رنگ سیاه (تابع Clear())
  2. به‌روزرسانی مقادیر موقعیت و چرخش مش‌هایمان
  3. رندر آن‌ها در بافر پشتی با انجام عملیات ماتریسی لازم (تابع Render())
  4. نمایش آن‌ها روی صفحه با تخلیه داده بافر پشتی داخل بافر جلویی (تابع Present())

اولین الگوریتم پایه برای رسم خط بین دو نقطه

با کدنویسی یک الگوریتم ساده شروع می‌کنیم. برای رسم خط بین ۲ رأس از این منطق استفاده می‌کنیم:

  • اگر فاصله بین ۲ نقطه (point0 و point1) کمتر از ۲ پیکسل باشد، کاری نداریم
  • در غیر این صورت، نقطه میانی بین دو نقطه را پیدا می‌کنیم (مختصات point0 + (مختصات point1 – مختصات point0) / 2)
  • آن نقطه را روی صفحه رسم می‌کنیم
  • این الگوریتم را به‌صورت بازگشتی بین point0 و نقطه میانی و بین نقطه میانی و point1 اجرا می‌کنیم

کد این کار در ادامه آمده:

نمایش وجه‌ها با مثلث

حالا که می‌دانیم چگونه خط بکشیم، راه بهتری برای رندر مش با آن‌ها لازم داریم. ساده‌ترین شکل هندسی دوبعدی مثلث است. ایده در سه‌بعدی این است که همه مش‌هایمان را با این مثلث‌ها رسم کنیم. پس باید هر وجه مکعب‌مان را به ۲ مثلث تقسیم کنیم. این کار را «دستی» انجام می‌دهیم، اما در آموزش بعدی خواهیم دید که مدل‌سازهای سه‌بعدی این مرحله را به‌صورت خودکار برایمان انجام می‌دهند.

برای رسم مثلث باید ۳ نقطه/رأس داشته باشید. «وجه» در واقع ساختاری ساده شامل ۳ مقدار است که ایندکس‌هایی به آرایه رأس‌های مشِ موردنظر برای رندر هستند.

همان‌طور که در ابتدای مقاله گفتم، همه منطق لازم برای نمایش مش‌های پیچیده‌تر مثل Suzanne را از قبل ساخته‌ایم. منطق Face، Mesh و Vertex را داریم؛ همین برای حالا کافی است.

در قالب JSON، صادرکننده Babylon جزئیات بیشتری از آنچه الان لازم داریم اضافه می‌کند؛ مثلاً جزئیات احتمالی تکسچرها، نورها و… به همین دلیل فایل را پارس می‌کنیم و مستقیم سراغ بخش‌هایی می‌رویم که فقط به آن‌ها علاقه داریم: رأس‌ها و ایندکس‌های وجه‌ها تا رندر وایرفریم‌مان را بسازیم.

c#// بارگذاری فایل JSON به‌صورت غیرهمزمان
public async Task LoadJSONFileAsync(string fileName)
{
    var meshes = new List();
    var file = await Windows.ApplicationModel.Package.Current.InstalledLocation.GetFileAsync(fileName);
    var data = await Windows.Storage.FileIO.ReadTextAsync(file);
    dynamic jsonObject = Newtonsoft.Json.JsonConvert.DeserializeObject(data);

    for (var meshIndex = 0; meshIndex < jsonObject.meshes.Count; meshIndex++)
    {
        var verticesArray = jsonObject.meshes[meshIndex].vertices;
        // وجه‌ها
        var indicesArray = jsonObject.meshes[meshIndex].indices;

        var uvCount = jsonObject.meshes[meshIndex].uvCount.Value;
        var verticesStep = 1;

        // بسته به تعداد مختصات تکسچر برای هر رأس
        // در آرایه رأس‌ها با پنجره‌های 6، 8 و 10 پرش می‌کنیم
        switch ((int)uvCount)
        {
            case 0:
                verticesStep = 6;
                break;
            case 1:
                verticesStep = 8;
                break;
            case 2:
                verticesStep = 10;
                break;
        }

        // تعداد اطلاعات رأس‌هایِ برای ما جالب
        var verticesCount = verticesArray.Count / verticesStep;
        // تعداد وجه‌ها منطقاً اندازه آرایه تقسیم بر ۳ است (A, B, C)
        var facesCount = indicesArray.Count / 3;
        var mesh = new Mesh(jsonObject.meshes[meshIndex].name.Value, verticesCount, facesCount);

        // اول آرایه رأس‌های مش را پر می‌کنیم
        for (var index = 0; index < verticesCount; index++)
        {
            var x = (float)verticesArray[index * verticesStep].Value;
            var y = (float)verticesArray[index * verticesStep + 1].Value;
            var z = (float)verticesArray[index * verticesStep + 2].Value;
            mesh.Vertices[index] = new Vector3(x, y, z);
        }

        // بعد آرایه وجه‌ها را پر می‌کنیم
        for (var index = 0; index < facesCount; index++)
        {
            var a = (int)indicesArray[index * 3].Value;
            var b = (int)indicesArray[index * 3 + 1].Value;
            var c = (int)indicesArray[index * 3 + 2].Value;
            mesh.Faces[index] = new Face { A = a, B = b, C = c };
        }

        // گرفتن موقعیتی که در Blender تنظیم کرده‌اید
        var position = jsonObject.meshes[meshIndex].position;
        mesh.Position = new Vector3((float)position[0].Value, (float)position[1].Value, (float)position[2].Value);
        meshes.Add(mesh);
    }
    return meshes.ToArray();
}

رسترایزیشن

الگوریتم‌های رسترایزیشن انواع بسیار مختلفی دارند. من حتی کسی را در تیم‌ام می‌شناسم که الگوریتم رسترایزیشن ثبت‌اختراع‌شده خودش را برای یک سازنده معروف GPU ساخته است. به لطف اوست که حالا می‌دانم «بوستروفدون (Boustrophedon)» چیست؛ و این واقعاً از آن موقع زندگی‌ام را تغییر داده است. 🙂

جدیت را کنار می‌گذاریم؛ در این آموزش یک الگوریتم رسترایزیشن ساده اما کارآمد پیاده می‌کنیم. چون با موتور سه‌بعدی نرم روی CPU اجرا می‌شویم، باید خیلی به این بخش توجه کنیم؛ واقعاً هزینه CPU زیادی دارد. امروزه البته این بخش سنگین مستقیماً توسط GPUها انجام می‌شود.

بیایید با یک تمرین شروع کنیم. یک کاغذ بردارید و همه نوع مثلثی که به ذهنتان می‌رسد را بکشید. ایده این است که راهی عمومی برای رسم هر نوع مثلثی پیدا کنیم.

اگر سه رأس هر مثلث را بر اساس مختصات Y مرتب کنیم تا همیشه P1 و بعدش P2 و بعدش P3 باشد، در نهایت فقط ۲ حالت ممکن خواهیم داشت:

می‌بینید که ۲ حالت داریم: P2 سمت راست خط P1P3 است یا سمت چپ آن. در مورد ما، چون می‌خواهیم همیشه خطوط را از چپ به راست (از sx تا ex) رسم کنیم، یک IF شرطی اول برای مدیریت این ۲ حالت خواهیم داشت.

علاوه بر آن، از چپ به راست رسم می‌کنیم و از P1.Y به سمت پایین تا P3.Y حرکت می‌کنیم و خط قرمزِ رسم‌شده روی حالت چپ شکل را دنبال می‌کنیم. اما باید منطق‌مان را با رسیدن به P2.Y عوض کنیم، چون شیب در هر دو حالت عوض می‌شود. برای همین در فرآیند خط اسکن (scan line) ۲ گام داریم: حرکت رو به پایین از P1.Y تا P2.Y و بعد از P2.Y تا P3.Y، مقصد نهایی‌مان.

تمام منطق لازم برای فهم ساخت الگوریتم‌مان در ویکی‌پدیا توضیح داده شده: http://en.wikipedia.org/wiki/Slope. این واقعاً ریاضیات پایه است.

برای مرتب‌سازی حالت‌ها بین حالت ۱ و حالت ۲، فقط کافی است شیب‌های وارون (inverse slopes) را این‌گونه محاسبه کنید:

dP1P2 = P2.X – P1.X / P2.Y – P1.Y و dP1P3 = P3.X – P1.X / P3.Y – P1.Y

اگر dP1P2 > dP1P3، در حالت اول هستیم با P2 در سمت راست؛ وگرنه در حالت دوم با P2 در سمت چپ.

حالا که منطق پایه الگوریتم‌مان را داریم، باید بدانیم X را روی هر خط بین SX (شروع X) و EX (پایان X) در شکل چگونه محاسبه کنیم. پس اول باید SX و EX را محاسبه کنیم. چون مقدار Y و شیب P1P3 و P1P2 را می‌دانیم، به راحتی می‌توانیم SX و EX موردنظرمان را پیدا کنیم.

مثلاً گام ۱ از حالت ۱ را در نظر بگیرید. اولین گام محاسبه گرادیان با مقدار فعلی Y در حلقه‌مان است؛ به ما می‌گوید در پردازش خط اسکن بین P1.Y و P2.Y در گام ۱ در چه مرحله‌ای هستیم.

gradient = currentY – P1.Y / P2.Y – P1.Y

چون X و Y به‌طور خطی به هم مرتبط‌اند، می‌توانیم SX را بر اساس این گرادیان با P1.X و P3.X درون‌یابی کنیم و EX را با P1.X و P2.X.

اگر موفق شوید این مفهوم درون‌یابی (interpolation) را بفهمید، می‌توانید همه آموزش‌های باقی‌مانده (نور و تکسچر) را بفهمید. پس حتماً باید وقت صرف خواندن کد مرتبط کنید و مطمئن شوید می‌توانید خودتان بدون کپی‌پیست کد زیر، از صفر دوباره‌اش بسازید.

{

Z-Buffering یا چگونه از یک بافر عمق استفاده کنیم

پس باید مقدار Z پیکسل فعلی را آزمایش کنیم و قبل از رسم، آن را با یک بافر مقایسه کنیم. اگر Z پیکسلِ در حال رسم کمتر از پیکسل قبلی‌ای بود که اینجا رسم شده، می‌توانیم بازنویسی‌اش کنیم. این یعنی وجهی که داریم رسم می‌کنیم جلوی وجهِ قبلاً رسم‌شده است. اما اگر Z پیکسلِ در حال رسم بزرگ‌تر از پیکسل قبلیِ رسم‌شده اینجا باشد، می‌توانیم عملیات رسم را کنار بگذاریم.

پس باید تاریخچه‌ای از این ایندکس‌های Z به‌ازای هر پیکسل روی صفحه نگه داریم. برای این کار، آرایه جدیدی از float با نام depthBuffer اعلام کنید که اندازه‌اش برابر با تعداد پیکسل‌های روی صفحه (عرض * ارتفاع) است. این بافر عمق باید در هر عملیات clear() با یک مقدار Z پیش‌فرض خیلی زیاد مقداردهی شود.

در تابع/متد putPixel فقط باید ایندکس Z پیکسل را با آنچه در بافر عمق ذخیره شده مقایسه کنیم. علاوه بر آن، بخشی از منطق قبلی‌مان Vector2 برمی‌گرداند تا به‌صورت منطقی روی صفحه رسم کند. این را به Vector3 تغییر می‌دهیم تا مقادیر Z رأس‌ها را منتقل کند، چون برای رسم درست وجه‌ها به این اطلاعات نیاز داریم.

در نهایت، همان‌طور که مقدار X را بین هر ضلع مثلث‌ها درون‌یابی می‌کردیم، باید مقادیر Z را هم با دقیقاً همان الگوریتم برای هر پیکسل درون‌یابی کنیم.

    // چون بافر پشتی ما آرایه‌ای یک‌بعدی است
    // باید ایندکس خانه معادل آن را در یک‌بعد بر اساس

    var index = ((x >> 0) + (y >> 0) * this.workingWidth);
    var index4 = index * 4;

    if(this.depthbuffer[index] < z) {
        return; // کنار گذاشتن
    }

    this.depthbuffer[index] = z;

    // فضای رنگی RGBA توسط canvas در HTML5 استفاده می‌شود

    this.backbufferdata[index4 + 1] = color.g * 255;
    this.backbufferdata[index4 + 2] = color.b * 255;
    this.backbufferdata[index4 + 3] = color.a * 255;

    // تا x:0, y:0 در بالا-چپ باشد

        this.putPixel(point.x, point.y, point.z, color);
    }

Device.prototype.processScanLine = function (y, pa, pb, pc, pd, color) {
    // به لطف Y فعلی می‌توانیم گرادیان را محاسبه کنیم تا مقادیر دیگری مثل
    // X شروع (sx) و X پایان (ex) که بینشان رسم می‌کنیم محاسبه شود
    // اگر pa.Y == pb.Y یا pc.Y == pd.Y باشد، گرادیان برابر 1 می‌شود
    var gradient1 = pa.y != pb.y ? (y - pa.y) / (pb.y - pa.y) : 1;
    var gradient2 = pc.y != pd.y ? (y - pc.y) / (pd.y - pc.y) : 1;

    var sx = this.interpolate(pa.x, pb.x, gradient1) >> 0;
    var ex = this.interpolate(pc.x, pd.x, gradient2) >> 0;

    // Z شروع و Z پایان
    var z1 = this.interpolate(pa.z, pb.z, gradient1);
    var z2 = this.interpolate(pc.z, pd.z, gradient2);

    // رسم خط از چپ (sx) به راست (ex)
    for(var x = sx; x < ex; x++) {
        var gradient = (x - sx) / (ex - sx);
        var z = this.interpolate(z1, z2, gradient);
        this.drawPoint(new BABYLON.Vector3(x, y, z), color);
    }
};

محاسبه FPS

قدم اول محاسبه FPS است تا بتوانیم بررسی کنیم با اصلاح الگوریتم‌مان کارایی‌ای به دست می‌آوریم یا نه. البته می‌توانید این کار را در C# یا TypeScript/JavaScript انجام دهید.

باید زمان دلتا (delta time) بین دو فریم رندر شده را بدانیم. پس فقط کافی است زمان فعلی را بگیریم، یک فریم جدید رسم کنیم (requestAnimationFrame در HTML5 یا CompositionTarget.Rendering در XAML)، دوباره زمان فعلی را بگیریم و با زمان قبلی ذخیره‌شده مقایسه کنیم. نتیجه را بر حسب میلی‌ثانیه دارید. برای به‌دست آوردن FPS کافی است ۱۰۰۰ را بر این نتیجه تقسیم کنید. مثلاً اگر ۱۶.۶۶ میلی‌ثانیه باشد (زمان دلتای بهینه) ۶۰ FPS خواهید داشت.

می‌توانید این کار را بعد از هر فریم رندر انجام دهید تا FPS بسیار دقیقی داشته باشید، یا میانگین FPS را مثلاً روی ۶۰ نمونه محاسبه کنید. دیوید (کاتو) و من قبلاً روی این موضوع در این سری کار کرده‌ایم: Benchmarking a HTML5 game: HTML5 Potatoes Gaming Bench

از دست زدن به کنترل‌های UI اجتناب کنید

اولین قانون برای چندنخی/چندوظیفگی این است که در نخ‌های ایجادشده، ۰ کدِ در حال دست‌زدن به UI داشته باشیم؛ فقط نخ UI می‌تواند به کنترل‌های گرافیکی دست بزند/دستکاری‌شان کند. در مورد ما، تکه‌کدی داشتیم که به bmp.PixelWidth یا bmp.PixelHeight دسترسی داشت که bmp از نوع WriteableBitmap است.         {

        backBuffer[index4] = (byte)(color.Blue * 255);

        backBuffer[index4 + 2] = (byte)(color.Red * 255);
        backBuffer[index4 + 3] = (byte)(color.Alpha * 255);
    }

Flat Shading

مفهوم

برای اعمال الگوریتم flat shading اول باید بردار نرمال وجه را محاسبه کنیم. وقتی آن را داشتیم، باید زاویه بین این بردار نرمال و بردار نور را بدانیم. دقیق‌تر بگوییم، از ضرب نقطه‌ای (dot product) استفاده می‌کنیم که کسینوس زاویه بین آن ۲ بردار را به ما می‌دهد. چون این مقدار می‌تواند بین 1- و 1 باشد، آن را بین ۰ و ۱ قطع می‌کنیم. این مقدار نهایی برای اعمال میزان نوری که بر اساس رنگ فعلی‌اش به وجه‌مان می‌رسد به کار می‌رود. خلاصه، رنگ نهایی وجه ما = color * Math.Max(0, cos(angle)).

از بردار نرمال شروع کنیم. تعریف ویکی‌پدیا (Normal (geometry)) می‌گوید: «برای یک چندضلعی محدب (مثل مثلث)، نرمال سطح را می‌توان ضرب عرضی (vector cross product) دو لبه (غیرموازی) چندضلعی محاسبه کرد».

// papb -> pcpd
// pa, pb, pc, pd باید قبلش مرتب شده باشند
void ProcessScanLine(ScanLineData data, Vertex va, Vertex vb, Vertex vc, Vertex vd, Color4 color)
{
    Vector3 pa = va.Coordinates;
    Vector3 pb = vb.Coordinates;
    Vector3 pc = vc.Coordinates;
    Vector3 pd = vd.Coordinates;

    // به لطف Y فعلی می‌توانیم گرادیان را محاسبه کنیم تا مقادیر دیگری مثل
    // X شروع (sx) و X پایان (ex) که بینشان رسم می‌کنیم محاسبه شود
    // اگر pa.Y == pb.Y یا pc.Y == pd.Y باشد، گرادیان برابر 1 می‌شود
    var gradient1 = pa.Y != pb.Y ? (data.currentY - pa.Y) / (pb.Y - pa.Y) : 1;
    var gradient2 = pc.Y != pd.Y ? (data.currentY - pc.Y) / (pd.Y - pc.Y) : 1;

    int sx = (int)Interpolate(pa.X, pb.X, gradient1);
    int ex = (int)Interpolate(pc.X, pd.X, gradient2);

    // Z شروع و Z پایان
    float z1 = Interpolate(pa.Z, pb.Z, gradient1);
    float z2 = Interpolate(pc.Z, pd.Z, gradient2);

    // رسم خط از چپ (sx) به راست (ex)
    for (var x = sx; x < ex; x++)
    {
        float gradient = (x - sx) / (float)(ex - sx);

        var z = Interpolate(z1, z2, gradient);
        var ndotl = data.ndotla;
        // تغییر مقدار رنگ با کسینوس زاویه
        // بین بردار نور و بردار نرمال
        DrawPoint(new Vector3(x, data.currentY, z), color * ndotl);
    }
}

// محاسبه کسینوس زاویه بین بردار نور و بردار نرمال
// مقداری بین 0 و 1 برمی‌گرداند
float ComputeNDotL(Vector3 vertex, Vector3 normal, Vector3 lightPosition)
{
    var lightDirection = lightPosition - vertex;

    normal.Normalize();
    lightDirection.Normalize();

    return Math.Max(0, Vector3.Dot(normal, lightDirection));
}

public void DrawTriangle(Vertex v1, Vertex v2, Vertex v3, Color4 color)
{
    // مرتب‌سازی نقطه‌ها تا همیشه این ترتیب را روی صفحه داشته باشیم p1, p2 و p3
    // با p1 همیشه بالا (پس کمترین Y ممکن نزدیک بالای صفحه)
    // و بعد p2 بین p1 و p3
    if (v1.Coordinates.Y > v2.Coordinates.Y)
    {
        var temp = v2;
        v2 = v1;
        v1 = temp;
    }

    if (v2.Coordinates.Y > v3.Coordinates.Y)
    {
        var temp = v2;
        v2 = v3;
        v3 = temp;
    }

    if (v1.Coordinates.Y > v2.Coordinates.Y)
    {
        var temp = v2;
        v2 = v1;
        v1 = temp;
    }

    Vector3 p1 = v1.Coordinates;
    Vector3 p2 = v2.Coordinates;
    Vector3 p3 = v3.Coordinates;

    // بردار نرمال وجه، میانگین نرمال بین نرمال هر رأس است
    // مرکز نقطه وجه را هم محاسبه می‌کنیم
    Vector3 vnFace = (v1.Normal + v2.Normal + v3.Normal) / 3;
    Vector3 centerPoint = (v1.WorldCoordinates + v2.WorldCoordinates + v3.WorldCoordinates) / 3;
    // موقعیت نور
    Vector3 lightPos = new Vector3(0, 10, 10);
    // محاسبه کسینوس زاویه بین بردار نور و بردار نرمال
    // مقداری بین 0 و 1 برمی‌گرداند که به‌عنوان شدت رنگ استفاده می‌شود
    float ndotl = ComputeNDotL(centerPoint, vnFace, lightPos);

    var data = new ScanLineData { ndotla = ndotl };

    // محاسبه جهت خطوط
    float dP1P2, dP1P3;

    // http://en.wikipedia.org/wiki/Slope
    // محاسبه شیب‌ها
    if (p2.Y - p1.Y > 0)
        dP1P2 = (p2.X - p1.X) / (p2.Y - p1.Y);
    else
        dP1P2 = 0;

    if (p3.Y - p1.Y > 0)
        dP1P3 = (p3.X - p1.X) / (p3.Y - p1.Y);
    else
        dP1P3 = 0;

    // حالت اول: مثلث‌هایی شبیه این
    // P1
    // -
    // --
    // - -
    // -  -
    // -   - P2
    // -  -
    // - -
    // -
    // P3
    if (dP1P2 > dP1P3)
    {
        for (var y = (int)p1.Y; y <= (int)p3.Y; y++)
        {
            data.currentY = y;

            if (y < p2.Y)
            {
                ProcessScanLine(data, v1, v3, v1, v2, color);
            }
            else
            {
                ProcessScanLine(data, v1, v3, v2, v3, color);
            }
        }
    }
    // حالت دوم: مثلث‌هایی شبیه این
    //       P1
    //        -
    //       --
    //      - -
    //     -  -
    // P2 -   -
    //     -  -
    //      - -
    //        -
    //       P3
    else
    {
        for (var y = (int)p1.Y; y <= (int)p3.Y; y++)

مفهوم

اگر توانسته‌اید Flat Shading را بفهمید، می‌بینید که Gouraud Shading اصلاً پیچیده نیست. این بار به‌جای ۱ نرمال یکتا برای هر وجه (و در نتیجه یک رنگ یکتا برای هر وجه)، از ۳ نرمال استفاده می‌کنیم: برای هر رأس مثلث‌مان یکی. پس ۳ سطح رنگ خواهیم داشت و رنگ هر پیکسل را بین هر رأس با همان الگوریتمی که در آموزش‌های قبلی استفاده کردیم درون‌یابی می‌کنیم. با این درون‌یابی، نورپردازی پیوسته‌ای روی مثلث‌هایمان خواهیم داشت.

منبع: Tutorial 5. Terrain – Light & Vertex Normal Vector

در این شکل تفاوت‌های flat shading و gouraud shading را می‌بینید: flat از یک نرمال مرکزی و gouraud از ۳ نرمال استفاده می‌کند. روی یک مش سه‌بعدی (هرم) هم می‌بینید که نرمال به‌ازای هر رأسِ هر وجه است؛ یعنی همان رأس بر اساس وجهی که فعلاً رسم می‌کنیم نرمال‌های متفاوتی خواهد داشت.

برگردیم به منطق draw triangle. راه خوب دیگر برای فهم کاری که با shading انجام می‌دهیم این‌جا نشان داده شده است (منبع: TUTORIALS – CREATING NORMAL MAPS by Ben Cloward): در این شکل فرض کنید نرمال رأس بالایی با جهت نور زاویه‌ای بزرگ‌تر از ۹۰ درجه دارد؛ پس رنگش باید سیاه باشد (حداقل سطح نور = 0). حالا فرض کنید ۲ نرمال رأس دیگر با جهت نور زاویه ۰ درجه دارند؛ یعنی باید حداکثر سطح نور (1) را دریافت کنند.

منطق Texture

در HTML5 با TypeScript/JavaScript، طبیعتاً تکسچر را با ساختن پویای یک عنصر canvas بارگذاری می‌کنیم و داده تصویر مرتبطش را می‌گیریم تا آرایه بایت‌های رنگ را به‌دست آوریم. با C#/XAML یک WriteableBitmap می‌سازیم، منبعش را با تصویری که بارگذاری می‌کنیم تنظیم می‌کنیم و خصوصیت PixelBuffer آن را می‌گیریم تا آرایه بایت‌های رنگ به‌دست آید.

c#public class Texture
{
    private byte[] internalBuffer;
    private int width;
    private int height;

    // با تکسچری با اندازه ثابت کار می‌کنیم (512x512، 1024x1024 و...)
    public Texture(string filename, int width, int height)
    {
        this.width = width;
        this.height = height;
        Load(filename);
    }

    async void Load(string filename)
    {
        var file = await Windows.ApplicationModel.Package.Current.InstalledLocation.GetFileAsync(filename);

        using (var stream = await file.OpenReadAsync())
        {
            var bmp = new WriteableBitmap(width, height);
            bmp.SetSource(stream);

            internalBuffer = bmp.PixelBuffer.ToArray();
        }
    }

    // مختصات U و V صادرشده از Blender را می‌گیرد
    // و رنگ پیکسل متناظر را در تکسچر برمی‌گرداند
    public Color4 Map(float tu, float tv)
    {
        // تصویر هنوز بارگذاری نشده است
        if (internalBuffer == null)
        {
            return Color4.White;
        }
        // با عملگر % در صورت نیاز تکسچر را چرخش/تکرار می‌کنیم
        int u = Math.Abs((int) (tu*width) % width);
        int v = Math.Abs((int) (tv*height) % height);

        int pos = (u + v * width) * 4;
        byte b = internalBuffer[pos];
        byte g = internalBuffer[pos + 1];
        byte r = internalBuffer[pos + 2];
        byte a = internalBuffer[pos + 3];

        return new Color4(r / 255.0f, g / 255.0f, b / 255.0f, a / 255.0f);
    }
}

عبور دادن اطلاعات تکسچر در جریان کار

وارد همه جزئیات نمی‌شوم چون کد منبع کامل را کمی پایین‌تر برای دانلود دارید. بگذارید در عوض کلیات کاری که باید انجام دهید را مرور کنیم:

  • یک خصوصیت Texture به کلاس Mesh و یک خصوصیت Vector2 به نام TextureCoordinates به ساختار Vertex اضافه کنید
  • ScanLineData را به‌روزرسانی کنید تا ۸ عدد/شناور دیگر را جاسازی کند: مختصات UV به‌ازای هر رأس (ua, ub, uc, ud و va, vb, vc, vd)
  • متد/تابع Project را به‌روزرسانی کنید تا Vertex جدیدی با TextureCoordinates عبور داده‌شده (pass through) برگرداند
  • یک شیء Texture را به‌عنوان آخرین پارامتر به متدها/توابع ProcessScanLine و DrawTriangle بفرستید
  • ساختار جدید ScanLineData را در drawTriangle با مختصات UV مناسب پر کنید
  • UV را در ProcessScanLine روی Y درون‌یابی کنید تا SU/SV و EU/EV (شروع U/شروع V/پایان U/پایان V) داشته باشید؛ بعد U و V را روی X درون‌یابی کنید، رنگ متناظر را در تکسچر با آن پیدا کنید. این رنگ تکسچر با رنگ بومی شیء (در آموزش‌های ما همیشه سفید) و مقدار نورِ اندازه‌گیری‌شده با عملیات NDotL با نرمال ترکیب می‌شود
نکته: می‌توان متد Project ما را چیزی که در یک موتور سه‌بعدی سخت‌افزاری «ورتکس شیدر (Vertex Shader)» می‌نامیم در نظر گرفت و ProcessScanLine را «پیکسل شیدر (Pixel Shader)».

در این مقاله فقط متد جدید ProcessScanLine را به اشتراک می‌گذارم که واقعاً بخش اصلی به‌روزرسانی‌شده است:

c#void ProcessScanLine(ScanLineData data, Vertex va, Vertex vb, Vertex vc, Vertex vd, Color4 color, Texture texture)
{
    Vector3 pa = va.Coordinates;
    Vector3 pb = vb.Coordinates;
    Vector3 pc = vc.Coordinates;
    Vector3 pd = vd.Coordinates;

    // به لطف Y فعلی می‌توانیم گرادیان را محاسبه کنیم تا مقادیر دیگری مثل
    // X شروع (sx) و X پایان (ex) که بینشان رسم می‌کنیم محاسبه شود
    // اگر pa.Y == pb.Y یا pc.Y == pd.Y باشد، گرادیان برابر 1 می‌شود
    var gradient1 = pa.Y != pb.Y ? (data.currentY - pa.Y) / (pb.Y - pa.Y) : 1;
    var gradient2 = pc.Y != pd.Y ? (data.currentY - pc.Y) / (pd.Y - pc.Y) : 1;

    int sx = (int)Interpolate(pa.X, pb.X, gradient1);
    int ex = (int)Interpolate(pc.X, pd.X, gradient2);

    // Z شروع و Z پایان
    float z1 = Interpolate(pa.Z, pb.Z, gradient1);
    float z2 = Interpolate(pc.Z, pd.Z, gradient2);

    // درون‌یابی نرمال‌ها روی Y
    var snl = Interpolate(data.ndotla, data.ndotlb, gradient1);
    var enl = Interpolate(data.ndotlc, data.ndotld, gradient2);

    // درون‌یابی مختصات تکسچر روی Y
    var su = Interpolate(data.ua, data.ub, gradient1);
    var eu = Interpolate(data.uc, data.ud, gradient2);
    var sv = Interpolate(data.va, data.vb, gradient1);
    var ev = Interpolate(data.vc, data.vd, gradient2);

    // رسم خط از چپ (sx) به راست (ex)
    for (var x = sx; x < ex; x++)
    {
        float gradient = (x - sx) / (float)(ex - sx);

        // درون‌یابی Z، نرمال و مختصات تکسچر روی X
        var z = Interpolate(z1, z2, gradient);
        var ndotl = Interpolate(snl, enl, gradient);
        var u = Interpolate(su, eu, gradient);
        var v = Interpolate(sv, ev, gradient);

        Color4 textureColor;

        if (texture != null)
            textureColor = texture.Map(u, v);
        else
            textureColor = new Color4(1, 1, 1, 1);

        // تغییر رنگ بومی با کسینوس زاویه
        // بین بردار نور و بردار نرمال
        // و رنگ تکسچر
        DrawPoint(new Vector3(x, data.currentY, z), color * ndotl * textureColor);
    }
}

public async Task LoadJSONFileAsync(string fileName)
{
    var meshes = new List();
    var materials = new Dictionary();
    var file = await Windows.ApplicationModel.Package.Current.InstalledLocation.GetFileAsync(fileName);
    var data = await Windows.Storage.FileIO.ReadTextAsync(file);
    dynamic jsonObject = Newtonsoft.Json.JsonConvert.DeserializeObject(data);

    for (var materialIndex = 0; materialIndex < jsonObject.materials.Count; materialIndex++)
    {
        var material = new Material();
        material.Name = jsonObject.materials[materialIndex].name.Value;
        material.ID = jsonObject.materials[materialIndex].id.Value;
        if (jsonObject.materials[materialIndex].diffuseTexture != null)
            material.DiffuseTextureName = jsonObject.materials[materialIndex].diffuseTexture.name.Value;

        materials.Add(material.ID, material);
    }

    for (var meshIndex = 0; meshIndex < jsonObject.meshes.Count; meshIndex++)
    {
        var verticesArray = jsonObject.meshes[meshIndex].vertices;
        // وجه‌ها
        var indicesArray = jsonObject.meshes[meshIndex].indices;

        var uvCount = jsonObject.meshes[meshIndex].uvCount.Value;
        var verticesStep = 1;

        // بسته به تعداد مختصات تکسچر برای هر رأس
        // در آرایه رأس‌ها با پنجره‌های 6، 8 و 10 پرش می‌کنیم
        switch ((int)uvCount)
        {
            case 0:
                verticesStep = 6;
                break;
            case 1:
                verticesStep = 8;
                break;
            case 2:
                verticesStep = 10;
                break;
        }

        // تعداد اطلاعات رأس‌هایِ برای ما جالب
        var verticesCount = verticesArray.Count / verticesStep;
        // تعداد وجه‌ها منطقاً اندازه آرایه تقسیم بر ۳ است (A, B, C)
        var facesCount = indicesArray.Count / 3;
        var mesh = new Mesh(jsonObject.meshes[meshIndex].name.Value, verticesCount, facesCount);

        // اول آرایه رأس‌های مش را پر می‌کنیم
        for (var index = 0; index < verticesCount; index++)
        {
            var x = (float)verticesArray[index * verticesStep].Value;
            var y = (float)verticesArray[index * verticesStep + 1].Value;
            var z = (float)verticesArray[index * verticesStep + 2].Value;
            // بارگذاری نرمال رأس صادرشده از Blender
            var nx = (float)verticesArray[index * verticesStep + 3].Value;
            var ny = (float)verticesArray[index * verticesStep + 4].Value;
            var nz = (float)verticesArray[index * verticesStep + 5].Value;

            mesh.Vertices[index] = new Vertex
            {
                Coordinates = new Vector3(x, y, z),
                Normal = new Vector3(nx, ny, nz)
            };

            if (uvCount > 0)
            {
                // بارگذاری مختصات تکسچر
                float u = (float)verticesArray[index * verticesStep + 6].Value;
                float v = (float)verticesArray[index * verticesStep + 7].Value;
                mesh.Vertices[index].TextureCoordinates = new Vector2(u, v);
            }
        }

        // بعد آرایه وجه‌ها را پر می‌کنیم
        for (var index = 0; index < facesCount; index++)
        {
            var a = (int)indicesArray[index * 3].Value;
            var b = (int)indicesArray[index * 3 + 1].Value;
            var c = (int)indicesArray[index * 3 + 2].Value;
            mesh.Faces[index] = new Face { A = a, B = b, C = c };
        }

        // گرفتن موقعیتی که در Blender تنظیم کرده‌اید
        var position = jsonObject.meshes[meshIndex].position;
        mesh.Position = new Vector3((float)position[0].Value, (float)position[1].Value, (float)position[2].Value);

        if (uvCount > 0)
        {
            // تکسچر
            var meshTextureID = jsonObject.meshes[meshIndex].materialId.Value;
            var meshTextureName = materials[meshTextureID].DiffuseTextureName;
            mesh.Texture = new Texture(meshTextureName, 512, 512);
        }

        meshes.Add(mesh);
    }
    return meshes.ToArray();
}

رندر با WebGL به لطف Babylon.JS
