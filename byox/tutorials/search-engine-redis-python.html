ساخت موتور جست‌وجو با Redis و redis-py

۱. چرا Redis؟ چرا از صفر؟

بیشتر موتورهای جست‌وجو به «نمایهٔ معکوس» (inverted index) وابسته‌اند: جدولی که برای هر واژه، فهرستِ اسنادِ حاوی آن واژه را نگه می‌دارد. پرس‌وجو، تلاقیِ (intersection) این فهرست‌هاست. اما ساخت چنین نمایه‌ای به‌صورت درست نیازمند حجم قابل‌توجهی مهندسی است: ذخیره‌سازی، همزمانی، مقیاس‌پذیری… مقالهٔ جوزایا کارلسون یک میان‌بُر هوشمندانه دارد: Redis یک «سرور ساختار دادهٔ از راه دور» (remote data structure server) است — نه فقط یک کش. پس می‌توانیم ساختارهای دادهٔ نمایهٔ معکوس (ون حتی امتیازهای TF-IDF) را مستقیماً داخل Redis تعریف کنیم و برنامهٔ پایتون‌مان را فقط «ترجمهٔ پرس‌وجو به دستورهای Redis» بسازیم؛ همزمانی و ماندگاری هم با سرور حل می‌شود.

نکتهٔ کلیدی: انتخاب ابزار درست، نیمی از طراحی است. به‌جای اینکه الگوریتم‌های جست‌وجو را با پایگاه دادهٔ ارتباطی شبیه‌سازی کنیم، از ساختارهایی استفاده می‌کنیم که «توسط طراحی» برای این کار ساخته شده‌اند: هش‌ها (Hashes) و مجموعه‌های مرتب (Sorted Sets) در Redis.

۲. طراحی نمایهٔ معکوس با هش‌ها و مجموعه‌های مرتب

طرحِ مقاله سه بخش دارد که هرکدام به یک ساختار Redis نگاشت می‌شود:

  1. خودِ اسناد: هر سند در یک هش Redis ذخیره می‌شود؛ فیلدهایی مثل عنوان، متن، آدرس و شناسهٔ (id) سند. حالا «خواندن سند» فقط یک HGETALL است.
  2. نمایهٔ معکوس — فراوانی واژه در سند (tf): برای هر واژه یک هش نگه می‌داریم که در آن، کلید = شناسهٔ سند و مقدار = تعداد دفعاتی که واژه در آن سند آمده است. «افزایش» با یک HINCRBY اتمی‌شده انجام می‌شود.
  3. نقش آماری سند در واژه (idf) و امتیازها: برای محاسبهٔ «چقدر این واژه برای این سند خاص است» به سندفرکانس نیاز داریم: تعداد اسنادی که واژه در آن‌ها آمده. این عدد را با یک شمارندهٔ ساده به‌روز نگه می‌داریم و «وزن» هر واژه برای هر سند به‌صورت نسبت tf در آن سند به idfِ واژه (به‌صورت لگاریتمی) محاسبه می‌شود: w(t,d) = tf(t,d) / idf(t).
pythonimport redis

r = redis.Redis(host='localhost', port=6379, db=0)

def index_document(doc_id, text):
    """نمایه‌کردن یک سند: ذخیرهٔ متن و به‌روزرسانی نمایهٔ معکوس"""
    # ۱) خود سند را ذخیره کن
    r.hset('doc:%s' % doc_id, 'text', text)

    # ۲) هر واژه را شمارش کن و در نمایهٔ معکوس اضافه کن
    for word in text.split():
        r.hincrby('index:%s' % word, doc_id, 1)

def search(query):
    """جست‌وجوی ساده: همهٔ اسنادی که همهٔ واژه‌ها را دارند"""
    words = query.split()
    if not words:
        return []
    # اشتراکِ مجموعهٔ اسنادِ هر واژه — در Redis با SINTER
    keys = ['index:%s' % w for w in words]
    return r.sinter(keys)

نسخهٔ ساده‌شدهٔ بالا ایدهٔ اصلی را نشان می‌دهد؛ مقاله همین پوسته را با جزئیات کامل (توکن‌سازی، نرمال‌سازی، امتیازدهی بر اساس w(t,d) و مرتب‌سازی نتایج) پر می‌کند تا بازیابی واقعاً «بهترتیب ربط» برگردد و نه فقط اشتراک خالی.

۳. امتیازدهی TF-IDF روی Redis

پس از نمونهٔ ساده، مقاله به سراغ رتبه‌بندی واقعی می‌رود. برای هر واژه و هر سند، امتیاز tf/idf را محاسبه می‌کنیم؛ برای «سندِ پرس‌وجو» مجموع امتیازهای همهٔ واژه‌هایش را می‌گیریم. جا می‌دهیم این‌جا هم Redis یک قدم جلوتر بیاید: امتیازهای سند-به‌سند را داخل یک مجموعهٔ مرتب (Sorted Set) نگه می‌داریم، بعد با دستورهای ZUNIONSTORE/ZINTERSTORE امتیازهای چند واژه را با هم ادغام می‌کنیم و با ZREVRANGE نتایج را «بهترتیب ربط» برمی‌گردانیم.

python# محاسبهٔ idf ساده: تعداد اسنادِ دارای واژه
doc_count = int(r.get('total_docs'))
for word in words_of_query:
    df = r.scard('docswith:%s' % word)   # تعداد اسنادِ دارای واژه
    idf = math.log(doc_count / (1.0 + df))
    # برای هر سندِ آن واژه، وزن w = tf * idf را در zset امتیازها بریز
    for doc_id, tf in r.hgetall('index:%s' % word).items():
        r.zadd('score:%s' % word, float(tf) * idf, doc_id)

# جمع امتیازها برای همهٔ واژه‌های پرس‌وجو
r.zunionstore('result', ['score:%s' % w for w in words_of_query])
# ده نتیجهٔ برتر
top = r.zrevrange('result', 0, 9, withscores=True)
یادآوری ریاضی: TF (فراوانی واژه در سند) می‌گوید واژه چقدر در این سند پررنگ است؛ IDF (عکسِ فراوانی سند) می‌گوید واژه چقدر «اختصاصی» است. حاصل‌ضربشان امتیازی است که واژه‌های متداولِ بی‌ارزش (مثل «و»، «در») را بی‌اثر و واژه‌های نشانه‌دار را مؤثر می‌کند.

۴. آنچه از این آموزش یاد می‌گیرید

  • نمایهٔ معکوس یعنی «از واژه به اسناد»، نه «از سند به واژه» — کلید موفقیت هر موتور جست‌وجو، و این‌جا با سه نوع ساختار Redis پیاده می‌شود.
  • انتخاب ساختار دادهٔ درست: هش برای دادهٔ کلید-مقدارِ سند، zset برای امتیازهای قابل مرتب‌سازی، set برای اشتراک سریع — Redis دقیقاً دیکشنری‌ای است که «از راه دور» حرف می‌زند.
  • امتیازدهی: جست‌وجوی خوب فقط «پیداکردن» نیست؛ «رتبه‌بندی» است. TF-IDF ساده و قابل‌فهم، و به‌صورت توزیع‌شده با دستورهای Redis بدون حلقهٔ پایتونی پیاده می‌شود.
  • مقیاس‌پذیری عملی: با Redis، نمایه و امتیازها در حافظه اند؛ میلی‌ها سند و میلی‌ها پرس‌وجو بدون بازطراحی فانتزی پاسخ می‌دهند.

۵. جمع‌بندی

این مقاله نشان می‌دهد ساخت یک موتور جست‌وجوی «واقعاً کاربردی» بدون نوشتن حتی یک میلی‌ثانیه کدِ مدیریت حافظه، ممکن است — فقط کافی است ساختار دادهٔ مناسب را در جای مناسب استفاده کنید. مسیر پیشنهادی آموزشی: اول مفاهیم جست‌وجو و TF-IDF را (مثلاً با آموزش «یافتن کلمات مهم در متن با TF-IDF» همین مجموعه) بفهمید، بعد این پیاده‌سازیِ Redis را بخوانید تا ببینید چطور مفاهیم تبدیل به معماری سیستم می‌شوند.
