پروژه R: موتورهای عبارت باقاعده

عبارت‌های باقاعده جادو نیستند. می‌توانید با ساختن یک یا دو موتور regex خودتان آن‌ها را بفهمید.

آن‌قدرها هم سخت نیست: می‌توانیم regex را با حدود ۱۰۰ خط پایتون تحلیل کنیم و آن را با حدود ۵۰ خط backtracking اجرا کنیم. و برای خوانندگان میانی، یک NFA با حدود ۱۰۰ خط پایتون کدنویسی می‌شود.

  • R3. پیمایش گراف و Regex (متوسط)
  • R4. اتوماتای متناهی قطعی (پیشرفته)

R1. تحلیل عبارت‌های باقاعده (مبتدی)

مقدمه

چه چیزی یاد می‌گیرید:

  • Regex جادو نیست.
  • درخت‌ها و داده ساختاریافته.
  • بازگشت و تکنیک‌های تحلیل.

ویژگی‌های regex که پیاده می‌کنید:

  • ab — الحاق: ابتدا زیرعبارت a را مطابقت بده، بعد b را.
  • a|b — جایگزینی: یا a یا b را مطابقت بده.
  • a*، a+، a{n}، a{x,y} — تکرار: صفر یا چند بار، حداقل یک بار، n بار، و x تا y بار.
  • (a) — زیرعبارت: یک زیرعبارت را نقل‌قول کن. عبارت‌ها می‌توانند تودرتو باشند.
  • x، . — مطابقت یک کاراکتر: یک کاراکتر تحت‌اللفظی یا یک کاراکتر دلخواه.

تحلیل مسئله

یک regex یک تکه رشته است. این رشته معرف ساختاری است. اغلب ما روی رشته کار نمی‌کنیم بلکه روی ساختاری که نشان می‌دهد. فرآیند تبدیل رشته به ساختار «تحلیل» (parsing) نامیده می‌شود.

ساختار یک regex بازگشتی است. بازگشت به معنای سلسله‌مراتب و زیرساختارهایی است که شبیه خود ساختارند. شاید برایتان آشکار نباشد regex چگونه بازگشتی است؛ با چیزی شروع کنیم که با آن آشنا هستید.

فرمول (1+2)+3 بازگشتی است؛ + دوم دارای دو زیرفرمول است: 1+2 و 3. 1+2+3 معادل (1+2)+3 است، فقط پرانتزها ضمنی‌اند. 1+2×3 به‌صورت ضمنی 1+(2×3) است؛ × اولویت بالاتر از + دارد.

حالا برگردیم به regex. abc به‌صورت ضمنی ((a)b)c است؛ فقط عملگر الحاق نامرئی را مثل × در نظر بگیرید: ((a)×b)×c. به همین ترتیب، a|bc برابر a|(bc) است، مثل a+(b×c).

الحاق و جایگزینی عملگرهای «میانوندی» (infix) هستند؛ زیرعبارت‌هایشان چپ و راست عملگرند. عملگر تکرار، عملگر «پسوندی» (postfix) است، مثل فاکتوریل (n!).

سه عملگر، سه اولویت. عملگر پسوندی بالاترین است، بعد الحاق، بعد جایگزینی.

برای تحلیل regex با بازگشت، عملگر با بالاترین اولویت باید در پایین‌ترین سلسله‌مراتب (عمیق‌ترین) تحلیل شود. پایین‌ترین سطح یک regex یا یک کاراکتر منفرد است یا یک زیرعبارت نقل‌قول‌شده. در یک سطح بالاتر، عملگر تکرار افزوده می‌شود (ممکن است هیچ‌کدام نباشد). سپس الحاق، سپس جایگزینی.

شروع کدنویسی

اول، شکل ساختارهای تحلیل‌شده‌مان را تعیین می‌کنیم. آن‌ها درخت‌اند، بدیهی است.

pythonassert re_parse('') is None
assert re_parse('.') == 'dot'
assert re_parse('a') == 'a'
assert re_parse('ab') == ('cat', 'a', 'b')
assert re_parse('a|b') == ('split', 'a', 'b')
assert re_parse('a+') == ('repeat', 'a', 1, float('inf'))
assert re_parse('a{3,6}') == ('repeat', 'a', 3, 6)
assert re_parse('a|bc') == ('split', 'a', ('cat', 'b', 'c'))

بالاترین سطح تحلیل، عملگر جایگزینی است.

آرگومان‌ها:

  • r: رشته regex.
  • idx: موقعیت تحلیل فعلی.
python# a|b|c...
def parse_split(r, idx):
    idx, prev = parse_concat(r, idx)
    while idx < len(r):
        if r[idx] == ')':
            # به parse_node بیرونی برگرد
            break
        assert r[idx] == '|', 'BUG'
        idx, node = parse_concat(r, idx + 1)
        prev = ('split', prev, node)
    return idx, prev

در یک نگاه، parse_split زیرعبارت‌ها را از parse_concat می‌گیرد و گره «split» می‌سازد.

parse_concat یک سطح پایین‌تر است. بسیار شبیه parse_split است.

python# abc...
def parse_concat(r, idx):
    prev = None
    while idx < len(r):
        if r[idx] in '|)':
            # به parse_split یا parse_node بیرونی برگرد
            break
        idx, node = parse_node(r, idx)
        if prev is None:
            prev = node
        else:
            prev = ('cat', prev, node)
    # وقتی prev هنوز None است، رشته خالی را نشان می‌دهد
    return idx, prev

هر دو parse_split و parse_concat در «)» می‌ایستند. «)» معمولاً به این معناست که تحلیل داخل یک زیرعبارت نقل‌قول‌شده بیرونی است و به پایان زیرعبارت رسیده و باید به تحلیل‌گر بیرونی برگردد. به همین ترتیب، parse_concat در «|» می‌ایستد تا به parse_split بیرونی برگردد.

پایین‌رفتن به parse_node. یا یک کاراکتر منفرد یا یک زیرعبارت نقل‌قول‌شده را تحلیل می‌کند و سپس ممکن است عملگر تکرار اضافه کند.

python# یک عنصر منفرد را تحلیل کن
def parse_node(r, idx):
    ch = r[idx]
    idx += 1
    assert ch not in '|)'
    if ch == '(':
        idx, node = parse_split(r, idx)
        if idx < len(r) and r[idx] == ')':
            idx += 1
        else:
            raise Exception('unbalanced parenthesis')
    elif ch == '.':
        node = 'dot'
    elif ch in '*+{':
        raise Exception('nothing to repeat')
    else:
        node = ch

    idx, node = parse_postfix(r, idx, node)
    return idx, node

توجه کنید فراخوانی parse_split به بالاترین سلسله‌مراتب بازگشت می‌کند.

parse_postfix خیلی طولانی‌تر است، اما فقط کد ترتیبی خسته‌کننده است.

python# a*, a+, a{x}, a{x,}, a{x,y}
def parse_postfix(r, idx, node):
    if idx == len(r) or r[idx] not in '*+{':
        return idx, node

    ch = r[idx]
    idx += 1
    if ch == '*':
        rmin, rmax = 0, float('inf')
    elif ch == '+':
        rmin, rmax = 1, float('inf')
    else:
        # اولین عدد داخل {}
        idx, i = parse_int(r, idx)
        if i is None:
            raise Exception('expect int')
        rmin = rmax = i
        # عدد دوم اختیاری
        if idx < len(r) and r[idx] == ',':
            idx, j = parse_int(r, idx + 1)
            rmax = j if (j is not None) else float('inf')
        # آکولاد را ببند
        if idx < len(r) and r[idx] == '}':
            idx += 1
        else:
            raise Exception('unbalanced brace')

    # بررسی‌های سلامت
    if rmax < rmin:
        raise Exception('min repeat greater than max repeat')
    if rmin > RE_REPEAT_LIMIT:
        raise Exception('the repetition number is too large')

    node = ('repeat', node, rmin, rmax)
    return idx, node
pythondef parse_int(r, idx):
    save = idx
    while idx < len(r) and r[idx].isdigit():
        idx += 1
    return idx, int(r[save:idx]) if save != idx else None

رابط واقعی:

pythondef re_parse(r):

نتیجه‌گیری

یاد گرفتیم چگونه regex را با بازگشت تحلیل کنیم. این دانش برای تحلیل چیزهای دیگر هم مفید است. هرچند تحلیل اغلب صفحات قابل‌توجهی را در کتاب‌های ساخت کامپایلر اشغال می‌کند، بسیاری از زبان‌های دنیای واقعی را فقط با بازگشت می‌توان تحلیل کرد، و اغلب ساده‌ترین راه برای تحلیل چیزی، کد بازگشتی دست‌ساز است. فصل بعد به شما می‌آموزد چگونه regex تحلیل‌شده را با «backtracking» اجرا کنید، که آن هم از بازگشت استفاده می‌کند.

R2. موتور Regex با Backtracking (مبتدی)

مقدمه

چه چیزی یاد می‌گیرید:

  • تجزیه یک مسئله به زیرمسئله‌ها.
  • جست‌وجو و backtracking.

در فصل قبل یاد گرفتیم regexها را به ساختارهای درختی تحلیل کنیم. از ساختار درختی می‌توانیم ساخت یک موتور regex را شروع کنیم. روش استفاده‌شده در این فصل «backtracking» نامیده می‌شود. Backtracking کارآمدترین روش پیاده‌سازی regex نیست؛ روش‌های دیگر در فصل‌های بعد معرفی می‌شوند.

تحلیل مسئله

اغلب اولین گام حل مسئله، تجزیه آن به تکه‌های کوچک‌تر یا زیرمسئله‌هاست. ماهیت ساختار درختی این را حتی آشکارتر می‌کند.

  • الحاق، ab: زیرعبارت a را اجرا کن، بعد b را از موقعیت نتیجه a.
  • جایگزینی، a|b: نتایج a و b را ترکیب کن.

برای الحاق‌ها، اولی می‌تواند هر تعداد نامزد مطابقت تولید کند. و دومی به نتایج اولی وابسته است: اگر دومی از موقعیت خاصی از نتایج اولی نتواند مطابقتی بیابد، جست‌وجو اگر موقعیت دیگری باشد، از آنجا دوباره شروع می‌شود. این همان معنای «backtracking» است. برای تکرارها هم اوضاع مثل الحاق است.

به طور خلاصه:

  1. یک زیرعبارت از موقعیت معین رشته، فهرستی از نامزدها تولید می‌کند.
  2. عملگر الحاق: برای هر نتیجه از زیرعبارت اول، اجرا کن و نتایج را به زیرعبارت دوم بده.
  3. عملگر تکرار مثل عملگر الحاق است.
  4. نتایج زیرعبارت‌های جایگزینی را اجتماع بگیر.

شروع کدنویسی

کد کوتاه است:

python# روش backtracking تقریباً نیروی کور است.
# می‌توان برای حذف idxهای تکراری هم کش اضافه کرد.
def match_backtrack(node, text, idx):
    if node is None:
        yield idx   # رشته خالی
    elif node == 'dot':
        if idx < len(text):
            yield idx + 1
    elif isinstance(node, str):
        assert len(node) == 1   # تک‌کاراکتری
        if idx < len(text) and text[idx] == node:
            yield idx + 1
    elif node[0] == 'cat':
        # yield from معادل است با:
        # for idx1 in match_backtrack_concat(node, text, idx):
        #     yield idx1
        yield from match_backtrack_concat(node, text, idx)
    elif node[0] == 'split':
        yield from match_backtrack(node[1], text, idx)
        yield from match_backtrack(node[2], text, idx)
    elif node[0] == 'repeat':
        yield from match_backtrack_repeat(node, text, idx)
    else:
        assert not 'reachable'

برای کسانی که با پایتون آشنا نیستند: دستور yield اجرای خودش را به حالت تعلیق درمی‌آورد و مقداری به فراخواننده برمی‌گرداند و فراخواننده معمولاً روی نتایج حلقه می‌زند. yield from میان‌بر حلقه و عبور همه‌چیز است.

هر بار که مطابقت یافت می‌شود، نتیجه از طریق yield به فراخواننده منتقل می‌شود. فراخواننده می‌تواند با آن کاری کند و نتیجه بعدی را (با ادامه پیمایش) بخواهد.

انتقال رفت‌وبرگشتی کنترل، نوشتن کد backtracking را در پایتون بی‌دردسر می‌کند. اما اگر اولین بارتان است که سعی می‌کنید backtracking را بفهمید، توصیه می‌شود این کار را بدون دستور yield انجام دهید و حالت‌های backtracking را صریح مدیریت کنید — تمرینی برای کسانی که از پایتون استفاده نمی‌کنند.

کد الحاق:

pythondef match_backtrack_concat(node, text, idx):
    met = set()
    for idx1 in match_backtrack(node[1], text, idx):
        if idx1 in met:
            continue    # تکراری
        met.add(idx1)
        yield from match_backtrack(node[2], text, idx1)

توجه کنید یک hash set اضافه کردم تا نتایج تکراری زیرعبارت اول را رد کنم.

کد تکرار طولانی‌تر است:

pythondef match_backtrack_repeat(node, text, idx):
    _, node, rmin, rmax = node
    rmax = min(rmax, RE_REPEAT_LIMIT)
    # خروجی بافر شده و بعداً معکوس می‌شود
    output = []
    if rmin == 0:
        # لازم نیست چیزی مطابقت کند
        output.append(idx)
    # موقعیت‌های گام قبلی
    start = {idx}
    # همه تعداد تکرارهای ممکن را امتحان کن
    for i in range(1, rmax + 1):
        found = set()
        for idx1 in start:
            for idx2 in match_backtrack(node, text, idx1):
                found.add(idx2)
                if i >= rmin:
                    output.append(idx2)
        # TODO: اگر تنها مطابقت طول صفر بود، خارج شو
        if not found:
            break
        start = found
    # تکرار حریص است؛ اول مطابقت با بیشترین تکرار را خروجی بده.
    yield from reversed(output)

تکرار با اجرای دوباره‌و‌دوباره زیرعبارت تا وقتی دیگر نتواند مطابقت بیابد مدیریت می‌شود. هر گام با نتایج گام قبلی شروع می‌شود و موقعیت شروع‌ها هم حذف تکراری می‌شوند.

نکته دیگر: تکرار regex «حریص» است؛ باید مطابقت با حداکثر تکرار را پیدا کنیم و اول خروجی بدهیم.

تابع آزمایش اینکه آیا رشته با regex کاملاً مطابقت دارد:

pythondef re_full_match_bt(node, text):
    for idx in match_backtrack(node, text, 0):
        # idx اندازه پیشوند مطابقت‌شده است
        if idx == len(text):
            # توجه: جنبه حریص بودن regexها به نظر
            # بی‌ربط می‌رسد اگر فقط متن کامل مطابقت‌شده را بپذیریم.
            return True
    return False

پیداکردن موارد آزمون به‌عنوان تمرین برای خواننده است.
