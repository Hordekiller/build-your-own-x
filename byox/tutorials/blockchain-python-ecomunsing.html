بلاک‌چین خودت را بساز — اصول پایه

این آموزش شما را با اصول ساخت یک بلاک‌چین از صفر آشنا می‌کند. تمرکز بر جزئیات یک مثال عینی، درک عمیق‌تری از نقاط قوت و محدودیت‌های بلاک‌چین‌ها به شما می‌دهد. برای یک مرور سطح‌بالاتر، این مقالهٔ عالی از BitsOnBlocks را پیشنهاد می‌کنم.

نسخهٔ کامل نوت‌بوک: نسخه کامل نوت‌بوک Jupyter/iPython این آموزش را می‌توانید از اینجا در GitHub دانلود کنید.

تراکنش‌ها، اعتبارسنجی و به‌روزرسانی وضعیت سیستم

بلاک‌چین در هستهٔ خود یک پایگاه‌دادهٔ توزیع‌شده (distributed database) است که مجموعه‌ای از قوانین برای تأیید افزوده‌های جدید به پایگاه‌داده دارد. ما کار را با پیگیری حساب‌های دو شخص خیالی شروع می‌کنیم: آلیس (Alice) و باب (Bob)، که قرار است با یکدیگر پول مجازی مبادله کنند.

ما باید یک استخر تراکنش (transaction pool) از تراکنش‌های ورودی بسازیم، آن تراکنش‌ها را اعتبارسنجی کنیم و آن‌ها را به یک بلاک تبدیل کنیم.

ما از یک تابع هش (hash function) برای ایجاد یک «اثر انگشت» برای هر یک از تراکنش‌هایمان استفاده خواهیم کرد — این تابع هش هر یک از بلاک‌های ما را به یکدیگر پیوند می‌دهد. برای آسان‌تر کردن استفاده از آن، یک تابع کمکی تعریف می‌کنیم تا تابع هش پایتونی که استفاده می‌کنیم را بپوشاند.

pyimport hashlib, json, sys

def hashMe(msg=""):
    # برای راحتی، این یک تابع کمکی است که الگوریتم هش ما را در بر می‌گیرد
    if type(msg)!=str:
        msg = json.dumps(msg,sort_keys=True)  # اگر کلیدها را مرتب نکنیم، تکرارپذیری تضمین نمی‌شود!

    if sys.version_info.major == 2:
        return unicode(hashlib.sha256(msg).hexdigest(),'utf-8')
    else:
        return hashlib.sha256(str(msg).encode('utf-8')).hexdigest()

در قدم بعد، می‌خواهیم تابعی برای تولید مبادلات بین آلیس و باب بسازیم. برداشت‌ها را با اعداد منفی و واریزها را با اعداد مثبت نشان می‌دهیم. تراکنش‌هایمان را طوری می‌سازیم که همیشه بین دو کاربر سیستم باشند و مطمئن می‌شویم واریز همان قدر با برداشت برابر است — یعنی نه پول می‌سازیم و نه پول را از بین می‌بریم.

pyimport random
random.seed(0)

def makeTransaction(maxValue=3):
    # این تابع تراکنش‌های معتبری در بازهٔ (1,maxValue) می‌سازد
    sign      = int(random.getrandbits(1))*2 - 1   # این به‌طور تصادفی 1- یا 1 را انتخاب می‌کند
    amount    = random.randint(1,maxValue)
    alicePays = sign * amount
    bobPays   = -1 * alicePays
    # با این ساختار، این تابع همیشه تراکنش‌هایی برمی‌گرداند که به اصل پایستگی توکن‌ها احترام می‌گذارند.
    # با این حال توجه کنید که ما هیچ‌کاری برای بررسی برداشتِ بیش از موجودی حساب انجام نداده‌ایم
    return {u'Alice':alicePays,u'Bob':bobPays}

قدم بعدی: ساخت بلاک‌های مخصوص خودمان! اولین k تراکنش را از بافر تراکنش برمی‌داریم و آن‌ها را به یک بلاک تبدیل می‌کنیم. قبل از انجام این کار، باید روشی برای بررسی اعتبار تراکنش‌هایی که به داخل بلاک آورده‌ایم تعریف کنیم.

برای بیت‌کوین، تابع اعتبارسنجی بررسی می‌کند که مقادیر ورودی، خروجی‌های تراکنشِ خرج‌نشدهٔ معتبر (UTXO) باشند، خروجی‌های تراکنش از ورودی بزرگ‌تر نباشند و کلیدهای استفاده‌شده برای امضاها معتبر باشند. در اتریوم (Ethereum)، تابع اعتبارسنجی بررسی می‌کند که قراردادهای هوشمند به‌درستی اجرا شده‌اند و به محدودیت‌های گاز (gas) احترام می‌گذارند.

با این حال نگران نباشید — لازم نیست سیستمی به این پیچیدگی بسازیم. ما مجموعه‌قوانین بسیار سادهٔ خودمان را تعریف می‌کنیم که برای یک سیستم توکن پایه منطقی است:

  • مجموع واریزها و برداشت‌ها باید صفر باشد (توکن‌ها نه ساخته می‌شوند و نه از بین می‌روند)
  • حساب یک کاربر باید وجوه کافی برای پوشش هر برداشتی داشته باشد

اگر هر یک از این شرایط نقض شود، تراکنش را رد می‌کنیم.

pydef updateState(txn, state):
    # ورودی‌ها: txn, state: دیکشنری‌هایی که با نام حساب‌ها کلید خورده‌اند و مقادیر عددی
    # مبلغ انتقال (txn) یا موجودی حساب (state) را نگه می‌دارند
    # خروجی: وضعیت به‌روزشده، با افزوده‌شدن کاربران جدید به state در صورت نیاز
    # توجه: این تابع تراکنش را اعتبارسنجی نمی‌کند — فقط وضعیت را به‌روز می‌کند!

    # اگر تراکنش معتبر باشد، وضعیت به‌روز می‌شود
    state = state.copy() # چون دیکشنری‌ها تغییرپذیرند، برای جلوگیری از هر ابهامی یک نسخهٔ کاری از داده‌ها می‌سازیم
    for key in txn:
        if key in state.keys():
            state[key] += txn[key]
        else:
            state[key] = txn[key]
    return state
pydef isValidTxn(txn,state):
    # فرض کنید که تراکنش یک دیکشنری است که با نام حساب‌ها کلید خورده است

    # بررسی اینکه مجموع واریزها و برداشت‌ها صفر باشد
    if sum(txn.values()) is not 0:
        return False

    # بررسی اینکه تراکنش باعث برداشتِ بیش از موجودی (overdraft) نشود
    for key in txn.keys():
        if key in state.keys():
            acctBalance = state[key]
        else:
            acctBalance = 0
        if (acctBalance + txn[key]) < 0:
            return False

    return True

ساخت بلاک‌چین: از تراکنش‌ها تا بلاک‌ها

ما آماده‌ایم ساخت بلاک‌چین‌مان را شروع کنیم! در حال حاضر، هیچ‌چیز روی بلاک‌چین نیست، اما می‌توانیم با تعریف «بلاک مبدأ» (genesis block) — نخستین بلاک در سیستم — کار را راه بیندازیم. چون بلاک مبدأ به هیچ بلاک قبلی پیوند نخورده است، کمی متفاوت با آن برخورد می‌شود و می‌توانیم وضعیت سیستم را به دلخواه تعیین کنیم. در مورد ما، برای دو کاربرمان (آلیس و باب) حساب ایجاد می‌کنیم و به هر یک ۵۰ سکه می‌دهیم.

برای هر بلاک، می‌خواهیم مجموعه‌ای از تراکنش‌ها را جمع کنیم، یک سربرگ بسازیم، آن را هش کنیم و به زنجیره اضافه کنیم.

pydef makeBlock(txns,chain):
    parentBlock = chain[-1]
    parentHash  = parentBlock[u'hash']
    blockNumber = parentBlock[u'contents'][u'blockNumber'] + 1
    txnCount    = len(txns)
    blockContents = {u'blockNumber':blockNumber,u'parentHash':parentHash,
                     u'txnCount':len(txns),'txns':txns}
    blockHash = hashMe( blockContents )
    block = {u'hash':blockHash,u'contents':blockContents}

    return block

بررسی اعتبار زنجیره

حالا که می‌دانیم چگونه بلاک‌های جدید بسازیم و آن‌ها را به‌صورت یک زنجیره به یکدیگر پیوند دهیم، بیایید توابعی تعریف کنیم تا بررسی کنند بلاک‌های جدید معتبرند — و کل زنجیره معتبر است.

در یک شبکهٔ بلاک‌چین، این موضوع به دو شکل اهمیت پیدا می‌کند:

  • هنگامی که در ابتدا گره (node) خود را راه‌اندازی می‌کنیم، تاریخچهٔ کامل بلاک‌چین را دانلود خواهیم کرد. پس از دانلود زنجیره، باید از میان بلاک‌چین عبور کنیم تا وضعیت سیستم را محاسبه کنیم. برای محافظت در برابر کسی که تراکنش‌های نامعتبری در زنجیرهٔ اولیه جاسازی می‌کند، باید در همین دانلود اولیه اعتبار کل زنجیره را بررسی کنیم.
  • هنگامی که گرهٔ ما با شبکه همگام شد (نسخهٔ به‌روزی از بلاک‌چین و نمایشی از وضعیت سیستم دارد)، باید اعتبار بلاک‌های جدیدی را که به شبکه پخش می‌شوند بررسی کند.

برای انجام این کار به سه تابع نیاز خواهیم داشت:

  • checkBlockHash: یک تابع کمکی ساده که مطمئن می‌شود محتوای بلاک با هش آن مطابقت دارد
  • checkBlockValidity: اعتبار یک بلاک را با در نظر گرفتن بلاک والد و وضعیت فعلی سیستم بررسی می‌کند. می‌خواهیم این تابع در صورت معتبر بودن بلاک، وضعیت به‌روزشده را برگرداند و در غیر این صورت یک خطا پرتاب کند.
  • checkChain: اعتبار کل زنجیره را بررسی می‌کند و وضعیت سیستم را از بلاک مبدأ محاسبه می‌کند. اگر زنجیره معتبر باشد وضعیت سیستم را برمی‌گرداند و در غیر این صورت یک خطا پرتاب می‌کند.
pydef checkBlockHash(block):
    # اگر هش با محتوای بلاک مطابقت نداشت یک استثنا پرتاب می‌کنیم
    expectedHash = hashMe( block['contents'] )
    if block['hash']!=expectedHash:
        raise Exception('Hash does not match contents of block %s'%
                        block['contents']['blockNumber'])
    return
pydef checkBlockValidity(block,parent,state):
    # می‌خواهیم شرایط زیر را بررسی کنیم:
    # - هر یک از تراکنش‌ها به‌روزرسانی‌های معتبری برای وضعیت سیستم باشند
    # - هش بلاک برای محتوای بلاک معتبر باشد
    # - شمارهٔ بلاک، شمارهٔ بلاک والد را یک واحد افزایش دهد
    # - به‌طور دقیق به هش بلاک والد ارجاع دهد
    parentNumber = parent['contents']['blockNumber']
    parentHash   = parent['hash']
    blockNumber  = block['contents']['blockNumber']

    # بررسی اعتبار تراکنش؛ اگر تراکنش نامعتبری پیدا شود یک خطا پرتاب می‌کنیم
    for txn in block['contents']['txns']:
        if isValidTxn(txn,state):
            state = updateState(txn,state)
        else:
            raise Exception('Invalid transaction in block %s: %s'%(blockNumber,txn))

    checkBlockHash(block) # بررسی یکپارچگی هش؛ در صورت عدم دقت خطا پرتاب می‌کند

    if blockNumber!=(parentNumber+1):
        raise Exception('Hash does not match contents of block %s'%blockNumber)

    if block['contents']['parentHash'] != parentHash:
        raise Exception('Parent hash not accurate at block %s'%blockNumber)

    return state

    #    - اعتبار شمارهٔ بلاک
    for block in chain[1:]:
        state = checkBlockValidity(block,parent,state)
        parent = block

    return state

کنار هم گذاشتن قطعات: معماری نهایی بلاک‌چین

در یک شبکهٔ واقعی بلاک‌چین، گره‌های جدید یک نسخه از بلاک‌چین را دانلود و آن را تأیید می‌کنند (همان‌طور که بالا انجام دادیم)، سپس حضور خود را در شبکهٔ همتا‌به‌همتا (peer-to-peer) اعلام می‌کنند و گوش دادن به تراکنش‌ها را آغاز می‌کنند. آن‌ها تراکنش‌ها را در یک بلاک بسته‌بندی می‌کنند و سپس بلاک پیشنهادی خود را به گره‌های دیگر منتقل می‌کنند.

ما دیده‌ایم که چگونه یک نسخه از بلاک‌چین را تأیید کنیم و چگونه تراکنش‌ها را در یک بلاک بسته‌بندی کنیم. اگر بلاکی را از جایی دیگر دریافت کنیم، تأیید آن و افزودنش به بلاک‌چین خودمان آسان است.

فرض کنید کد زیر روی گرهٔ A اجرا می‌شود که بلاک را استخراج می‌کند:

pyimport copy
nodeBchain = copy.copy(chain)
nodeBtxns  = [makeTransaction() for i in range(5)]
newBlock   = makeBlock(nodeBtxns,nodeBchain)

حالا فرض کنید که newBlock به گرهٔ ما منتقل شده است و می‌خواهیم آن را بررسی کنیم و اگر بلاک معتبری بود وضعیت خود را به‌روز کنیم:

pyprint("Blockchain on Node A is currently %s blocks long"%len(chain))

try:
    print("New Block Received; checking validity...")
    state = checkBlockValidity(newBlock,chain[-1],state) # وضعیت را به‌روز می‌کند — اگر بلاک نامعتبر باشد خطا پرتاب می‌کند!
    chain.append(newBlock)
except:
    print("Invalid block; ignoring and waiting for the next block...")

print("Blockchain on Node A is now %s blocks long"%len(chain))

نتیجه‌گیری و بسط‌ها

ما تمام معماری پایهٔ یک بلاک‌چین را ایجاد کرده‌ایم؛ از مجموعه‌ای از قوانین انتقال حالت (state transition) تا روشی برای ایجاد بلاک‌ها و مکانیزم‌هایی برای بررسی اعتبار تراکنش‌ها، بلاک‌ها و کل زنجیره. می‌توانیم وضعیت سیستم را از یک نسخهٔ دانلودشدهٔ بلاک‌چین استخراج کنیم، بلاک‌های جدیدی را که از شبکه دریافت می‌کنیم اعتبارسنجی کنیم و بلاک‌های خودمان را بسازیم.

وضعیت سیستمی که ایجاد کرده‌ایم در واقع یک دفتر کل توزیع‌شده (distributed ledger) یا پایگاه‌داده است — هستهٔ بسیاری از بلاک‌چین‌ها. می‌توانیم این را بسط دهیم تا انواع خاصی از تراکنش‌ها یا قراردادهای هوشمند (smart contracts) کامل را در بر بگیرد.

ما معماری شبکه، گام اعتبارسنجی اثبات کار (proof-of-work) یا اثبات سهام (proof-of-stake) و مکانیزم اجماع (consensus) را که امنیت بلاک‌چین‌ها را در برابر حمله فراهم می‌کند، بررسی نکرده‌ایم. همچنین دربارهٔ رمزنگاری کلید عمومی (public key cryptography)، حریم خصوصی و مراحل تأیید صحبت نکرده‌ایم. در آینده بیشتر دربارهٔ این‌ها خواهیم گفت!
