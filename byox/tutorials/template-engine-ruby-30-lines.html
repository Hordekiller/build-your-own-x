۱. مقدمه: قالب‌سازی سخت نیست

موتورهای قالب ابزارهایی‌اند که از قالب‌ها متن (رشته) تولید می‌کنند و «ارائه» را از «منطق برنامه» جدا می‌کنند. تقریباً همهٔ ما با آن‌ها کار کرده‌ایم — اما چطور کار می‌کنند؟ نگاهی سریع به کتابخانه‌های بزرگ نشان می‌دهد ERB چندصد خط، Erubis چند هزار خط و حتی Slim هم «لاغر» نیست. این مقاله این تصور را می‌شکند: یک موتور قالب کاربردی را فقط با دو قانون و کمتر از ۳۰ خط روبی می‌سازیم.

منبع الهام: این مقاله بر پایهٔ کتابخانهٔ بسیار کوچک و پرسرعت mote نوشته شده که در برنامه‌های بزرگ وب در محیط تولید استفاده می‌شود.

۲. دو قانون زبان قالب

  1. خط‌هایی که با % شروع می‌شوند، کد روبی‌اند و همان‌طور اجرا می‌شوند.
  2. بین {{ ... }} در هر خط، کد روبی درون‌یابی می‌شود (مثل {{article.title}}).

فقط همین! واقعاً همین. قانون اول به ما «تمام روبی» را می‌دهد: حلقه‌ها، شرط‌ها، فراخوانی توابع مرتبه‌بالاتر و حتی قراردادنِ قالبِ دیگر در قالب — بدون اینکه لازم باشد یک «زبان قالب» جدید یاد بگیرید:

ruby<html>
<body>
% if access == 0
   <div> no access :( </div>
% else
   <ul>
  % data.each do |i|
      <li>{{i}}</li>
  % end
  </ul>
% end
% # کامنت هم کامنت معمولی روبی است
</body>
</html>

۳. نقطهٔ شروع: رندر با روبی خالص

قبل از هر چیز فکر کنیم «دست‌نویسِ» همین قالب در روبیِ خالص چه شکلی است — تابعی که رشتهٔ خروجی را خط به خط می‌سازد:

rubydef render_index(access, data)
  output = ""                     # رشتهٔ خروجی
  output << "<html>"
  output << "<body>"

  if access == 0
     output << "<div> no access :( </div>"
  else
     output << "<ul>"
     data.each do |i|
        output << "<li>\#{ i }</li>"
     end
     output << "</ul>"
  end

  output << "</body>"
  output << "</html>"
  return output
end

معنی‌اش: اگر بتوانیم index.template را به‌صورت عمومی به چنین تابعی ترجمه کنیم، موتور قالب ساخته‌ایم — بدون اینکه برای هر قالب، «تولیدکنندهٔ کدِ دستی» بنویسیم؛ می‌خواهیم تابعی بسازیم که در هر لحظه که لازم بود، مترجمِ معادل آن قالب را به‌صورت پویا تولید کند.

۴. گام میانی: ساخت تابع با eval

یک گام میانی: «برنامه‌ای که برنامه می‌نویسد». رشتهٔ منبعِ render_index را خط‌به‌خط می‌سازیم و با eval اجرا می‌کنیم — نتیجه، یک متد واقعی روبی:

rubydef define_render_index()
  func = ""
  func << "def render_index(access, data) \n"
  func << "output = \"\" \n"
  func << "output << \"<html>\" \n"
  func << "output << \"<body>\" \n"
  func << "if access == 0\n"
  func << "  output << \"<div> no access :( </div>\" \n"
  func << "else\n"
  func << "  output << \"<ul>\" \n"
  func << "  data.each do |i|\n"
  func << "    output << \"<li> \#{ i } </li>\" \n"
  func << "  end \n"
  func << "  output << \"</ul>\" \n"
  func << "end\n"
  func << "  output << \"</body>\" \n"
  func << "  output << \"</html>\" \n"
  func << "  return output \n"
  func << "end\n"
  eval(func)
end

define_render_index
render_index(1, ["foo", "bar"])
# => "<html><body><ul><li>foo</li><li>bar</li></ul></body></html>"

۵. تابع parse: ترجمهٔ خط‌به‌خط قالب

حالا منطقِ define_render_index را عمومی می‌کنیم. به‌جای متدِ نام‌دار، یک Proc می‌سازیم؛ نام متغیرها را به‌صورت رشته به parse می‌دهیم (parse(template, "access, data")) و قالب را خط‌به‌خط ترجمه می‌کنیم. قوانین ترجمه:

  • داخل همهٔ خطوط، کوتیشنِ دوتایی escape می‌شود؛ محتوای خط بین دو کوتیشنِ دوتایی می‌رود و \n به انتها اضافه می‌شود.
  • اگر اولین نویسهٔ خط (بدون فاصلهٔ سفید) % بود، فقط % حذف می‌شود — خط همان کدِ روبی می‌شود: % if data.empty? → "if data.empty?\n".
  • هر خطِ دیگر با output << شروع می‌شود: خطِ HTML به «افزودن به خروجی» بدل می‌شود.
  • {{ ... }} با رگکس به #{ ... } تبدیل می‌شود (درون‌یابیِ روبی).
rubydef parse(template, vars = "")
  lines = File.read(template).split("\n")

  func = "Proc.new do |#{vars}| \n output = \"\" \n "

  lines.each do |line|
      if line =~ /^\s*(%)(.*?)$/
         func << " #{line.gsub(/^\s*%(.*?)$/, '\1') } \n"
      else
         func << " output << \" #{line.gsub(/\{\{([^\r\n\{]*)\}\}/, '#{\1}') }\" \n "
      end
  end

  func << " output; end \n "

  eval(func)
end

آزمایش در IRB:

ruby>> index = parse("index.template", "access, data")
=> nil
>> index.call(1, ["Foo"])
=> " <html>\n <body>\n<ul>\n<li>foo</li> \n</ul>\n </body>\n </html>\n"

۶. آیا مقیاس‌پذیر است؟

کدِ این مقاله آموزشی است، اما کتابخانهٔ mote — همان‌که الهام‌بخش مقاله بود — با همین ایده، همراه با راهنماها (helpers) و کش، در برنامه‌های وب بزرگ در محیط تولید استفاده می‌شود و در بنچمارک‌ها بسیار سریع است. پیام پایانی مقاله مهم است: کوچک‌بودن به معنی ناقص‌بودن نیست؛ mote راه‌حلی متمرکز و کامل برای مسئله‌ای است که برایش طراحی شده. پیچیدگیِ کمتر یعنی برنامه‌ای که راحت‌تر درک، اشکال‌زدایی و توسعه پیدا می‌کند.

۷. جمع‌بندی

با ۲ قانون زبان و کمتر از ۳۰ خط کد، یک موتور قالب کاربردی ساختیم: قالب خط‌به‌خط به یک Proc ترجمه، با eval ساخته و با .call اجرا می‌شود. حالا هر موتور قالبِ روبی (ERB، Erubis، Slim و…) برایتان «رمزگشایی‌شده» است: همه در اصل دارند «قالب → کد → اجرا» می‌کنند.

کپیرایت: مقالهٔ «How to Write a Template Engine in Less Than 30 Lines of Code» اثر ویل جساپ (Will Jessup) است و در وبلاگ مهندسی citrusbyte/TheoremOne منتشر شده (بر پایهٔ کتابخانهٔ mote اثر overan). این صفحه فقط ترجمهٔ فارسی آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسنده اصلی است. برای مشاهده اصل مطلب به سایت اصلی و مخزن mote مراجعه کنید.
