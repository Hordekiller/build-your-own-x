مقدمه

تصویر: برانکو استانچویچ (Branko Stancevic) در Unsplash

ذهن معامله‌گر، حلقهٔ ضعیف هر استراتژی یا برنامهٔ معاملاتی است. اجرای مؤثر معاملات به ورودی‌های انسانی نیاز دارد که در جهت مخالف غرایز ما حرکت می‌کنند. باید زمانی بخریم که مغز خزنده‌مان می‌خواهد بفروشد؛ باید زمانی بفروشیم که وجدانمان به ما می‌گوید بیشتر بخریم. معاملهٔ ارزهای دیجیتال با چنان ذهنیتی حتی دشوارتر است. بازارهای جوان و نوظهور مملو از «گروه‌های پامپ» (pump groups) هستند که ترس شدید از جا ماندن (FOMO — fear of missing out) را دامن می‌زنند و قیمت‌ها را تا آسمان بالا می‌برند و سپس آن‌ها را با ضربه به زمین می‌کوبند. بسیاری از سرمایه‌گذاران تازه‌کار نیز در این بازارها معامله می‌کنند؛ سرمایه‌گذارانی که شاید حتی هرگز معامله‌ای را در بورس نیویورک (NYSE) انجام نداده باشند. در هر معامله یک سازنده (maker) و یک گیرنده (taker) وجود دارد و سرمایه‌گذاران باهوش کریپتو به‌راحتی می‌توانند از تازه‌کارانی که به این فضا هجوم آورده‌اند سوءاستفاده کنند.

برای اینکه احساساتم را از معامله‌گری کریپتو جدا کنم و از بازارهایی که ۲۴ ساعته و ۷ روز هفته باز هستند بهره ببرم، تصمیم گرفتم یک ربات معامله‌گر ساده بسازم که از یک استراتژی ساده پیروی کند و در حالی که من خواب هستم معامله اجرا کند. بسیاری از «معامله‌گران رباتی» (bot traders) همان‌طور که نامیده می‌شوند، از زبان برنامه‌نویسی پایتون برای اجرای این معاملات استفاده می‌کنند. اگر «crypto trading bot» را جست‌وجو کنید، به کدهای پایتون در مخزن‌های مختلف گیت‌هاب (GitHub) برخواهید خورد. من دانشمند داده هستم و R ابزار اصلی من است. برای یافتن یک آموزش خوب در مورد استفاده از زبان R برای ساخت ربات معامله‌گر جست‌وجو کردم، اما چیزی پیدا نکردم. مصمم بودم پکیج شخصی خودم را برای ارتباط با API گدَکس (GDAX) بسازم که پکیج rgdax را پیدا کردم؛ بسته‌ای که یک واسط R (wrapper) برای API گدکس است. در ادامه راهنمایی برای کنار هم چیدن یک ربات معامله‌گر خواهید دید که می‌توانید از آن برای ساخت استراتژی‌های خودتان استفاده کنید.

استراتژی

به زبان ساده، ما جفت ارز اتریوم — دلار آمریکا (Ethereum — USD) را در صرافی گدکس از طریق API آن و با کمک واسط rgdax معامله خواهیم کرد. من معاملهٔ این جفت را دوست دارم، زیرا اتریوم (ETH) معمولاً در وضعیت صعودی (bullish) قرار دارد و این استراتژی در چنین وضعیتی می‌درخشد.

توجه: این یک استراتژی فوق‌العاده ساده‌شده است که در بازار صعودی فقط چند دلار سود به دست می‌آورد. در هر صورت، آن را به‌عنوان پایه‌ای برای ساختن استراتژی خودتان به کار بگیرید.

ما زمانی خرید خواهیم کرد که ترکیبی از اندیکاتورهای شاخص قدرت نسبی (RSI — Relative Strength Index) به یک بازار موقتاً اشباع‌فروش (oversold) اشاره کنند؛ با این فرض که گاوها (bulls) بار دیگر قیمت‌ها را بالا خواهند راند و ما می‌توانیم سود جمع کنیم. پس از خرید، ربات سه سفارش فروش محدود (limit sell order) ثبت می‌کند: یکی با ۱٪ سود، دیگری با ۴٪ سود و آخرین مورد با ۷٪ سود. این کار به ما امکان می‌دهد با دو سفارش اول به‌سرعت سرمایه را برای ورود به معاملهٔ بعدی آزاد کنیم و سفارش ۷٪ سودآوری کلی ما را تقویت می‌کند.

نرم‌افزار

ما از آر استودیو (Rstudio) و زمان‌بند وظایف ویندوز (Windows Task Scheduler) برای اجرای منظم کد R خود (هر ۱۰ دقیقه) استفاده خواهیم کرد. برای ارسال سفارش‌ها به یک حساب گدکس (GDAX) و برای دریافت اعلان‌های معاملات به یک حساب جیمیل (Gmail) نیاز دارید.

تابع curr_bal_usd و curr_bal_eth

شما از api key، secret و passphrase که از بخش API گدکس تولید می‌شوند استفاده خواهید کرد. این توابع، آخرین موجودی حساب گدکس شما را پرس‌وجو می‌کنند که بارها در معامله‌گری‌مان استفاده خواهیم کرد:

r# ساخت توابع
curr_bal_usd <- function(x){
  m <-  accounts(api.key = "your_api_key", secret = "your_secret", passphrase = "your_passphrase")#[3,3]
  m <-  subset(m$available, m$currency == 'USD')
  m
}
curr_bal_eth <- function(x){
  n <- accounts(api.key = "your_api_key", secret = "your_secret", passphrase = "your_passphrase")
  n <- subset(n$available, n$currency == 'ETH')
  n
}

توابع bid و ask

در ادامه، برای استراتژی‌مان به قیمت‌های پیشنهادی خرید (bid) و فروش (ask) فعلی نیاز خواهیم داشت:

r# نسخهٔ ۲
bid <- function(x){
  bid <- public_orderbook(product_id = "ETH-USD", level = 1)
  bid <- bid$bids[1]
  bid
}
ask <- function(x){
  ask <- public_orderbook(product_id = "ETH-USD", level = 1)
  ask <- ask$asks[1]
  ask
}

توابع usd_hold، eth_hold و cancel_orders

برای اینکه بتوانیم سفارش‌های محدود را به‌صورت تکراری (iterative) ثبت کنیم، باید بتوانیم وضعیت فعلی سفارش‌هایی را که قبلاً ثبت کرده‌ایم دریافت کنیم و سفارش‌هایی را که در دفتر سفارش (order book) بیش از حد پایین رفته‌اند تا پر شوند، لغو کنیم. برای مورد نخست از تابع holds پکیج rgdax و برای مورد دوم از cancel_order استفاده خواهیم کرد:

rusd_hold <- function(x){

تابع buy_exe

این تابع اصلی‌ترین تابع (big-daddy) است که سفارش‌های محدود ما را واقعاً اجرا می‌کند. این تابع چند گام را طی می‌کند:

  1. تابع order_size محاسبه می‌کند چقدر اتریوم می‌توانیم بخریم؛ زیرا می‌خواهیم هر بار حداکثر مقدار ممکن را بخریم، منهای ۰.۰۰۵ اتریوم برای در نظر گرفتن خطاهای گرد کردن (rounding errors).
  2. تابع حلقهٔ WHILE ما در حالی که هنوز صفر اتریوم داریم، سفارش‌های محدود ثبت می‌کند.
  3. یک سفارش با قیمت bid() اضافه می‌شود؛ سیستم ۱۷ ثانیه می‌خوابد تا سفارش پر شود و سپس بررسی می‌کند که آیا سفارش پر شده است یا نه. اگر پر نشده باشد، فرایند تکرار می‌شود.
rbuy_exe <- function(x){
  # دریافت اندازهٔ سفارش به‌صورت تکراری
  order_size <- round(curr_bal_usd()/ask(),3)[1]-0.005
  # ثبت سفارش اولیه
  while(curr_bal_eth() == 0){
    #order_size <- curr_bal_usd() / ask() - 0.009
    add_order(product_id = "ETH-USD", api.key = "your_api_key", secret = "your_secret", passphrase = "your_passphrase",
              type="limit", price = bid(), side = "b",  size = order_size )
    # خوابیدن برای اینکه ببینیم سفارش پر می‌شود یا نه
    Sys.sleep(17)
    # بررسی اینکه آیا موجودی اتریوم از مقدار سفارش بیشتر شده است
    if(curr_bal_eth() > 0){"buysuccess"}else{
      
      cancel_orders()    # اگر موجودی اتریوم از صفر بیشتر نشد، سفارش را لغو کن و از نو شروع کن 
    }
  }
}

بخش ۳: اجرای حلقهٔ معاملاتی

تا این‌جا، ما فقط توابع و متغیرهای خود را برای اجرای حلقهٔ معاملاتی آماده کرده‌ایم. در ادامه، شرح گفتاری (verbal walk through) حلقهٔ معاملاتی واقعی آمده است:

  • اگر موجودی فعلی حساب ما به دلار (USD) بیشتر از ۲۰ دلار باشد، حلقه را شروع می‌کنیم.
  • در گام بعدی، اگر RSI فعلی بزرگ‌تر یا مساوی ۳۰ باشد و RSI دورهٔ قبلی کوچک‌تر یا مساوی ۳۰ باشد و در ۳ دورهٔ قبلی، حداقل یک بار RSI کمتر از ۳۰ بوده باشد، آن‌گاه با موجودی دلاری فعلی، بیشترین مقدار اتریومی که می‌توانیم می‌خریم.
  • سپس این قیمت خرید را در یک فایل CSV ذخیره می‌کنیم.
  • بعد، برای اطلاع از عمل خرید، به خودمان ایمیل می‌فرستیم.
  • حلقه سپس «buy» را چاپ می‌کند تا بتوانیم آن را در فایل لاگ خود ردیابی کنیم.
  • سیستم سپس ۳ ثانیه می‌خوابد.
  • حالا برای برداشت سود، ۳ سفارش فروش محدود پلکانی ثبت می‌کنیم. سفارش فروش محدود اول با سود ۱٪، سفارش بعدی با سود ۴٪ و آخرین سفارش با سود ۷٪:

کل هدف این ربات، حذف خطای انسانی از معامله است و این امکان را به ما می‌دهد که بدون نیاز به حضور جلوی صفحه‌نمایش، وارد معامله شویم. برای رسیدن به این هدف از زمان‌بند وظایف ویندوز (Windows Task Scheduler) استفاده خواهیم کرد.

آن را مال خودتان کنید

می‌توانید این اسکریپت را هر چقدر که می‌خواهید ساده یا پیچیده کنید. من در حال بهبود این اسکریپت با افزودن شبکه‌های عصبی (neural networks) از ماژول Keras متعلق به TensorFlow برای آر استودیو هستم. این شبکه‌های عصبی عنصری به‌طور نمایی پیچیده‌تر به اسکریپت اضافه می‌کنند، اما برای یافتن الگوهای پنهان در داده‌ها فوق‌العاده قدرتمند هستند. علاوه بر این، پکیج TTR تعداد زیادی توابع مالی و اندیکاتورهای تکنیکال در اختیار ما قرار می‌دهد که می‌توان از آن‌ها برای بهبود مدل‌تان استفاده کرد.
