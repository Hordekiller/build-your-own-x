OS Blog — ساخت سیستم‌عامل برای RISC-V با راست (استیون مارز)

⚙ زبان: Rust 🎛 معماری RISC-V ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور مجموعه مقالات «OS Blog» از استیون مارز (Stephen Marz) است که یک سیستم‌عامل را برای معماری RISC-V با زبان راست و شبیه‌ساز QEMU می‌سازد — تا مبنایی برای توسعهٔ هسته‌های آینده (مثل سیستم‌های لینوکس‌گونه RISC-V) باشد.

۱. دربارهٔ مجموعه

استیون مارز (استاد دانشگاه تنسی) در این سری مقالات، یک سیستم‌عامل چندوظیفه‌ای را برای معماری RISC-V (مهم‌ترین معماری متن‌باز سخت‌افزاری امروز) با زبان Rust می‌سازد. انتخاب RISC-V مزیت بزرگی دارد: این معماری ساده، تمیز و مدرن است و مستنداتش در دسترس همه قرار گرفته — برخلاف x86 که پر از پیچیدگی‌های تاریخی است. همهٔ کارها در شبیه‌ساز QEMU انجام می‌شود.

۲. فصل‌های مجموعه

  • فصل ۰ — چرا RISC-V و چرا راست: معرفی معماری، اهداف و تنظیم محیط (کامپایلر متقاطع، QEMU).
  • فصل ۱ — اولین کد: بوت، تعریف stack pointer و اولین چرخهٔ بوت؛ روشن کردن UART برای خروجی.
  • فصل ۲ — حالت ممتاز: سطح‌های اجرا (Machine/Supervisor/User) و مدیریت SBI.
  • فصل ۳ — وقفه‌ها و تایمر: کنترل‌کنندهٔ وقفه، CLINT و t0/t1 تایمرها؛ پایهٔ زمان‌بندی.
  • فصل ۴ — جدول صفحات: MMU و ترجمهٔ آدرس با satp.
  • فصل ۵ — حافظهٔ هسته: فریم‌آلکیتور و مدیریت حافظهٔ فیزیکی.
  • فصل ۶ — حافظهٔ فرایند: جداول صفحهٔ هر فرایند و آدرس‌دهی مجازی مستقل.
  • فصل ۷ — زمان‌بند: جابه‌جایی context بین فرایندها با ذخیره‌سازی در saved_context.
  • فصل ۸ — ورودی/خروجی: درایور UART کامل و زیرسیستم I/O.
  • فصل ۹ — فراخوان‌های سیستم: syscall و رابط هسته/کاربر.
  • فصل ۱۰ — ران‌تایم کاربر: اجرای برنامه‌های کاربری در فضای کاربری.

۳. نمونهٔ کد: ذخیره و بازیابی context

هنگام تعویض فرایند، همهٔ رجیسترها باید ذخیره و بازیابی شوند. در RISC-V، با یک بلوک saved_context و بارگذاری در mepc (رجیستر شمارندهٔ برنامهٔ حالت ماشین) ادامهٔ اجرا از همان نقطهٔ قبلی انجام می‌شود:

rust// ذخیره‌ی کامل context یک فرایند روی پشته
core::arch::global_asm!(
    "save_context:",
    "addi sp, sp, -264",      // جا برای همه‌ی رجیسترها
    "sd ra,   0(sp)",
    "sd gp,   8(sp)",
    // ... همه‌ی رجیسترهای عمومی
    "sd sp, 256(sp)",         // ذخیره‌ی خود پشته
    "csrr t0, mepc",          // آدرس بازگشت
    "sd t0, 264-8(sp)",
    "ret");

// بازیابی و بازگشت به فرایند بعدی
"restore_context:",
"ld ra,   0(sp)",
// ...
"csrw mepc, t0",             // ادامه از همان‌جا
"addi sp, sp, 264",
"mret"                        // بازگشت به حالت قبل

این الگو — ذخیرهٔ «همه‌چیز روی پشته» — در معماری‌های دیگر هم مشابه است و تفاوت‌های ریز (مثل mepc به‌جای lr در ARM) دقیقاً در مقالات توضیح داده شده‌اند.

۴. نقاط قوت

  • معماری آینده‌دار: RISC-V به‌سرعت در حال رشد است و این مسیر، آموزشِ متناسب با آینده است.
  • کامل بودن: از بوت تا syscall و اجرای برنامهٔ کاربر — تقریباً همهٔ سیستم‌عامل.
  • راست + سیستم‌عامل: ترکیب ایمنی Rust با جزئیات bare-metal.
  • مستندات معماری: هر فصل به بخش‌های مربوط مستندات RISC-V ارجاع می‌دهد.
نکتهٔ تکمیلی: اگر دنبال مسیری «متفاوت و مدرن» هستید — نه x86 کهنه و نه حتی ARM — این مجموعه بهترین گزینه است؛ و برای دیدن همان مفاهیم روی x86 با Rust، سری phil-opp در همین مجموعه را ببینید.
