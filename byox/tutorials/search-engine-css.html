یک موتور جست‌وجو در CSS

۱. جست‌وجوهایی که فراموش کردیم

موتورهای جست‌وجو معمولاً به‌عنوان سیستم‌هایی پیچیده تصور می‌شوند: خزش وب، ایندکس‌کردن، تحلیل زبانی، رتبه‌بندی… اما اگر کمی به گذشته برگردیم، «جست‌وجو» یعنی جایی که یک موتور (مکانیزم) رشته‌ای را می‌گیرد و چیزهای منطبق را پیدا می‌کند. مرورگر شما پیش از آن‌که یک کلمه در کادر جست‌وجوی گوگل تایپ کنید، همین‌کار را می‌کند: وقتی داخل فیلدی از یک فرم تایپ می‌کنید، مجموعهٔ پیشنهادهای autocomplete از جست‌وجوی داخل HTML خودِ صفحه نیستند — این‌ها «جست‌وجوهای» کوچکی هستند که هر مرورگر برای تاریخی که خودش نگه می‌دارد انجام می‌دهد. این مقاله همان ایده را یک قدم جلوتر می‌برد: یک موتور جست‌وجو که فقط با CSS کار می‌کند و هیچ جاوااسکریپتی در آن نیست.

ایدهٔ محوری: موتور جست‌وجوی CSS از «انجین خود مرورگر» به‌عنوان موتور جست‌وجو استفاده می‌کند — متنی که تایپ می‌کنید انتخاب‌گر می‌شود و انتخاب‌گر، صفحات/محتوا را فیلتر می‌کند.

۲. انتخاب‌گرها، همان موتور هستند

وقتی چیزی را در یک موتور جست‌وجو تایپ می‌کنید، موتور یک «نمایهٔ معکوس» را جست‌وجو می‌کند و نتیجه را بر اساس ربط برمی‌گرداند. در CSS، معادل این کار انتخاب‌گر است: موتور رندر مرورگر برای اینکه بفهمد کدام عناصر زیر یک انتخاب‌گر قرار می‌گیرند، درخت DOM را پیمایش می‌کند — این یک جست‌وجوی واقعی روی ساختار سند است. نکتهٔ کلیدی مقاله انتخاب‌گری است که به مقداری که در حال تایپ‌شدن است نگاه می‌کند:

css/* اگر مقدارِ فعلیِ input دقیقاً «tim» باشد، این قانون فعال می‌شود */
input[value="tim" i] ~ p.tim {
  /* عنصر مرتبط را نشان بده */
  display: block;
}

علامت i بعد از مقدار، مقایسه را غیرحساس به بزرگی/کوچکی حروف می‌کند (case-insensitive). به این ترتیب جست‌وجوی «TIM»، «Tim» یا «tim» همگی همان نتیجه را می‌دهند. از آن‌جا که مقدار attribute داخل CSS قابل «چسباندن» با ~= و شبه‌کلاس‌ها (مثل :valid) هم هست، می‌توان رفتار موتور جست‌وجو را گسترش داد: مثلاً فقط وقتی جست‌وجو «معتبر» است نتایج نمایش داده شوند.

چرا i؟ افزونهٔ سطح ۴ انتخاب‌گرها (Selectors Level 4) به CSS اجازه می‌دهد تا منطبق‌سازی attribute را به‌صورت موردی غیرحساس کند؛ این «پرچم» دقیقاً همان چیزی است که تجربهٔ جست‌وجوی طبیعی کاربر را می‌سازد.

۳. معماری: ورودی، مطالب، و قانون‌های نمایش

ساختار دمو در سه بخش ساده خلاصه می‌شود:

  1. یک <input> سراسری: کادر جست‌وجو؛ هر چیزی که تایپ شود، به‌صورت زنده attribute-value یعنی value عمل می‌کند (برخی مرورگرها attribute را به‌روز می‌کنند و CSS می‌تواند همان لحظه به آن واکنش نشان دهد).
  2. مجموعه‌ای از «نتایج»: هر نتیجه یک پاراگراف/کارت با کلمه‌های کلیدی که در attribute اختصاصی (مثل data-kw) ذخیره شده‌اند.
  3. قانون‌های نمایش: برای هر نتیجه یک قانون می‌نویسیم که آن را فقط وقتی نشان دهد که کلمهٔ تایپ‌شده در attribute نتیجه موجود باشد — یعنی یک «پرس‌وجو» در درخت CSS.

این یعنی موتور جست‌وجویی که اتفاقاً «هوشمندانه» رفتار می‌کند ولی یک خط جاوااسکریپت ندارد: جست‌وجوگرِ واقعی، موتور انتخاب‌گرِ خودِ مرورگر است که با سرعت بومی اجرا می‌شود.

۴. محدودیت‌ها و چیزهایی که یاد می‌گیرید

  • CSS یک زبان اعلامی است: ما «نحوهٔ فیلترشدن» را توصیف می‌کنیم، نه گام‌های الگوریتم را. حرکت از «الگوریتم» به «دستورالعمل‌های انتخاب»، طرز فکر را عوض می‌کند.
  • رفتار value در همهٔ مرورگرها یکسان نیست؛ بخشی از سرگرمی آزمایش مرورگرهاست (دمو عمدتاً برای مرورگرهای مدرن طراحی شده).
  • این دمو مهندسی معکوسِ خلاقانه است: به‌جای ساختن موتور، از موف‌قیت موجود (موتور CSS مرورگر) بهره می‌برد — همان «هاک» خلاقانه‌ای که در کارهای قدیمی وب‌سازها می‌بینیم.

این مقاله نمونهٔ عالی «فکر کردن خارج از چارچوب» است: قبل از این‌که سراغ Elasticsearch بروید، دقایقی با CSS بازی کنید — گاهی موتور جست‌وجوی موردنیازتان از قبل در مرورگر کاربر هست.

۵. نتیجه‌گیری

«یک موتور جست‌وجو در CSS» یک اثبات مفهوم (proof of concept) سرگرم‌کننده است که نشان می‌دهد حتی «زبان توصیف ظاهر» وقتی انتخاب‌گرها در دسترس باشند از پس جست‌وجوی ساده برمی‌آید. برای بود معتبر، ایدهٔ مقاله به‌طور خاص جذاب است: input به‌عنوان پایگاه دادهٔ زنده، selector به‌عنوان پرس‌وجو، و نمایش/پنهان‌سازی به‌عنوان رتبه‌بندی. اگر می‌خواهید بفهمید موتورهای جست‌وجو واقعاً چه «حداقلی» دارند، این دمو یک نقطهٔ شروع خنده‌دار اما روشنگرانه است.

برای عمیق‌تر شدن: بعد از این دمو، نسخهٔ واقعی‌تر را با «ساخت موتور جست‌وجو با Redis و redis-py» در همین مجموعه دنبال کنید تا ببینید یک نمایهٔ معکوس واقعی چطور کار می‌کند.
