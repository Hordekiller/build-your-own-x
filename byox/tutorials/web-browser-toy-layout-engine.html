موتور مرورگر اسباب‌بازی (Toy Layout Engine) — سری «Let's build a browser engine!»

⚙ زبان: Rust ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور سری ۷ قسمتی «Let's build a browser engine!"» از مت بروبک (Matt Brubeck) — توسعه‌دهندهٔ سابق Mozilla و Servo — است. او در این سری یک موتور مرورگر «اسباب‌بازی» در زبان Rust می‌سازد: نه جاوااسکریپت، نه تصویر، نه خیلی چیزهای دیگر — فقط HTML + CSS و رندر آن روی صفحه.

۱. موتور مرورگر چیست؟

مقالهٔ اول این سری با یک تعریف مهم شروع می‌کند: موتور مرورگر (browser engine) آن بخشی از مرورگر است که صفحات وب را می‌گیرد (fetch می‌کند)، ترجمه می‌کند و روی صفحه نمایش می‌دهد. موتور با «chrome» مرورگر فرق دارد: chrome همان «قاب» مرورگر است — تب‌ها، نوار آدرس، دکمه‌ها و آن‌چه دورِ صفحهٔ وب است. فایرفاکس و سیمانکی هر دو موتور Gecko را با دو chrome متفاوت دارند.

سری بروبک یک موتور کوچک می‌سازد که فقط HTML و CSS را پشتیبانی می‌کند — «اسباب‌بازی»ی برای یادگیری، نه رقیب Blink/Gecko/WebKit/Servo که میلیون‌ها خط کد دارند (حتی نسخهٔ سادهٔ Servo هم آن‌موقع ده‌ها هزار خط داشت). اما ساختار همان است و فهمیدنش ساده:

text   HTML ──> Parse ──> DOM
   CSS  ──> Parse ──> Style Rules        ──> Style ──> Layout ──> Paint ──> پیکسل‌ها
                    DOM + Style Rules ──/

۲. نقشهٔ ۷ قسمتی

این سری با یک پیمایش کاملاً واقعی از مراحل رندر جلو می‌رود، هر قسمت یک مرحلهٔ تازه — از سازوکار لولهٔ رندر (rendering pipeline):

  • HTML و CSS: دو گرامر کوچک نوشته می‌شوند که ورودی متنی را به ساختارهای درختی تبدیل می‌کنند. پارسر HTML در ساختار DOM؛ پارسر CSS در مجموعه‌ای از قواعدِ selectors + declarations.
  • Style و تطبیق selector: قواعد CSS با DOM ترکیب می‌شوند تا هر گره «سبک» خودش را بگیرد — cascade اولیه و منطق matching selector.
  • Boxes و مدل جعبه‌ای: گره‌های DOM به «جعبه»های مستطیلی تبدیل می‌شوند؛ مدل جعبه‌ای (margin/border/padding/content) همان‌طور که در CSS تعریف می‌شود.
  • Layout: الگوریتم چیدمان بلوکی (block layout) شبیه به آنچه موتورهای واقعی دارند — محاسبهٔ موقعیت و اندازهٔ هر جعبه در فضای دو بعدی.
  • Paint: در پایان، جعبه‌های محاسبه‌شده «رنگ‌آمیزی» می‌شوند روی یک سطح نقاشی ساده (بدون پشتیبانی از تصویر، فقط رنگ‌های پس‌زمینهٔ solid).

قسمت هفتم هم «کارهای بعدی» را فهرست می‌کند: متن، تصویر، فرم‌ها و تعامل — یعنی جایی که اسباب‌بازی تمام می‌شود و کار واقعی شروع.

۳. نکته‌های طراحی

بروبک چند انتخاب هوشمندانه دارد که نگاه «انسانِ موتورِ مرورگر» می‌دهد:

  • جلاسازی (splitting): وقتی یک selector روی یک گره اعمال می‌شود اما بخشی از گره‌های فرزند تحت تأثیر استایل‌های دیگرند، پایپ‌لاین به‌جای پیچیدگی، گره را به چند «جعبهٔ مجازی» می‌شکند (مثلاً برای display: block با فرزند اولِ inline).
  • معیار CSS 2.1: مدل چیدمان مبتنی بر مشخصات CSS 2.1 است، نه خیال‌پردازی — حتی فرمول‌های margin collapse هم استفاده می‌شود.
  • منطق اتصال pipe‌ها: دادهٔ خروجی هر مرحله، ورودی مرحلهٔ بعد است؛ با ساختارهای دادهٔ ساده (struct های Rust) که تا انتها قابل debug کردن‌اند.
rust// چیدمان: هر جعبه یک موقعیت مستطیلی مطلق می‌گیرد
pub fn layout(&self, containing_block: Dimensions) -> LayoutBox {
    let mut layout_box = self.build_layout_tree();
    layout_box.layout(containing_block);
    layout_box
}

fn layout(&mut self, containing_block: Dimensions) {
    match self.box_type {
        BlockNode(_) => self.layout_block(containing_block),
        InlineNode(_) => self.layout_inline(containing_block),
        AnonymousBlock => self.layout_block(containing_block),
    }
}

۴. سناریوی عملی

برای نشان دادن کارکرد، هر قسمت با یک مثال کوچک همراه است. بدین ترتیب متوجه می‌شوید که کل «رندر» دو صفحه وب یعنی چه چیزهایی لازم دارد — صفحه‌ای بدون CSS تقریباً «سیل» است و با یک style ساده، همه‌چیز شکل می‌گیرد. موتور ساخته‌شده یک خروجی مبتنی بر متن/ساده دارد، اما برای یک ابزار بررسی الگوریتم‌های رندر واقعاً کافی است.

دربارهٔ «مرورگر» و «موتور»: این سری بهترین نقطه‌ٔ ورود به نحوهٔ کار مرورگرهای امروزی است — از فهمیدن لولهٔ رندر گرفته تا نقش Bridge بین HTML و CSS. ادامه‌دهنده‌های این مسیر: کتاب Web Browser Engineering و پروژه‌های مثل Servo، یا آموزش‌های مختصرتر برای ساختن مرورگر با پایتون.

۵. چه چیزهایی یاد می‌گیرید

  • تفاوت موتور مرورگر با chrome، و جایگاه لولهٔ رندر در مرورگرهای واقعی.
  • پیاده‌سازی یک parser سادهٔ HTML و CSS بدون وابستگی.
  • مدل جعبه‌ای و چیدمان بلوکی بر اساس مشخصات CSS 2.1.
  • پایپ‌لاین رندر کامل: parse → style → layout → paint.

۶. جمع‌بندی

این که با حدود هزار خط کد بتوان موتوری نوشت که HTML و CSS را رندر کند، شگفت‌انگیز و در عین حال آموزنده است. این سری به‌خوبی نشان می‌دهد که چندان‌ها «جادو» در مرورگر وجود ندارد — فقط چند لایهٔ کوچک و منظم است که هرکدام را می‌شود ساخت.

کپیرایت: سری «Let's build a browser engine!» اثر مت بروبک (Matt Brubeck) است و در وبلاگ شخصی او (limpet.net) منتشر شده. این صفحه فقط ترجمهٔ فارسی و مرور آن است و تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. برای مشاهدهٔ اصل مطلب به سایت اصلی مراجعه کنید.
