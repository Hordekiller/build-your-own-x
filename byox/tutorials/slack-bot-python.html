ساخت اولین ربات اسلک خود با پایتون

⚙ زبان: Python 📁 دسته: ربات ✅ ترجمه شده 🔗 منبع اصلی

مقدمه

ربات‌ها (bots) راهی کاربردی برای تعامل با سرویس‌های پیام‌رسانی مانند اسلک (Slack) هستند. اگر قبلاً هرگز ربات نساخته‌اید، این نوشته یک آموزش شروع ساده برای ترکیب Slack API با پایتون و ساخت اولین ربات شما فراهم می‌کند.

ما گام‌به‌گام راه‌اندازی محیط توسعه (development environment)، به‌دست آوردن توکن ربات Slack API (bot token) و کدنویسی ربات سادهٔ خودمان با پایتون را مرور خواهیم کرد.

ابزارهای مورد نیاز

ربات ما که نامش را «StarterBot» می‌گذاریم، به پایتون و Slack API نیاز دارد. برای اجرای کد پایتون‌مان به این موارد نیاز داریم:

  • یا پایتون ۲ یا پایتون ۳
  • pip و virtualenv برای مدیریت وابستگی‌های برنامه (application dependencies)
  • حساب رایگان Slack — باید حداقل در یک فضای کاری (workspace) که در آن به ساخت برنامه‌ها (apps) دسترسی دارید، وارد شده باشید.

همچنین مفید است که مستندات Slack API را هنگام ساخت این آموزش در دسترس داشته باشید.

تمام کد این آموزش به‌صورت متن‌باز (open source) و تحت مجوز MIT در مخزن عمومی slack-starterbot در دسترس است.

راه‌اندازی محیط

حالا می‌دانیم به چه ابزارهایی برای پروژهٔ خود نیاز داریم؛ پس بیایید محیط توسعه‌مان را آماده کنیم. به ترمینال (یا Command Prompt در ویندوز) بروید و به دایرکتوری‌ای که می‌خواهید پروژه در آن ذخیره شود تغییر مسیر دهید. داخل آن دایرکتوری، یک virtualenv جدید بسازید تا وابستگی‌های اپلیکیشن خود را از سایر پروژه‌های پایتون جدا نگه دارید.

shellvirtualenv starterbot

virtualenv را فعال کنید:

shellsource starterbot/bin/activate

حالا اعلان (prompt) شما باید شبیه اعلان موجود در این تصویر به نظر برسد.

کتابخانهٔ کمکی رسمی slackclient که توسط خود Slack ساخته شده است، می‌تواند پیام‌ها را از یک کانال اسلک ارسال و دریافت کند. کتابخانهٔ slackclient را با دستور pip نصب کنید:

shellpip install slackclient==1.3.2

وقتی pip کارش تمام شد، باید خروجی‌ای مانند این ببینید و دوباره به اعلان برگردید.

ما همچنین باید یک Slack App بسازیم تا برای ربات‌مان یک توکن API (API token) دریافت کنیم. از «Starter Bot» به‌عنوان نام App استفاده کنید. اگر در بیش از یک فضای کاری وارد شده‌اید، از منوی کشویی یک «Development Workspace» انتخاب کنید.

پس از ارسال فرم، صفحهٔ پیکربندی برنامه را باز نگه دارید.

Slack APIs و پیکربندی برنامه

ما می‌خواهیم Starter Bot مانند هر کاربر دیگری در تیم شما به نظر برسد — در گفتگوهای داخل کانال‌ها (channels)، گروه‌ها (groups) و پیام‌های مستقیم (DMs) شرکت کند. در یک Slack App، این «کاربر ربات» (bot user) نامیده می‌شود که با انتخاب «Bot Users» در بخش «Features» آن را تنظیم می‌کنیم. پس از کلیک روی «Add a Bot User»، باید یک نام نمایشی انتخاب کنید، یک نام کاربری پیش‌فرض برگزینید و انتخاب‌های خود را با کلیک روی «Add Bot User» ذخیره کنید. در پایان صفحه‌ای خواهید داشت شبیه به صفحهٔ زیر:

کتابخانهٔ slackclient استفاده از RTM API و Web API اسلک را ساده می‌کند. ما از هر دو برای پیاده‌سازی Starter Bot استفاده خواهیم کرد و هر کدام احراز هویت (authentication) جداگانه‌ای نیاز دارند. خوشبختانه، کاربر رباتی که قبلاً ساختیم می‌تواند برای احراز هویت هر دو API استفاده شود.

روی «Install App» در بخش «Settings» کلیک کنید. دکمهٔ این صفحه، App را در Development Workspace ما نصب می‌کند. وقتی App نصب شد، یک توکن دسترسی OAuth کاربر ربات (bot user oauth access token) برای احراز هویت به‌عنوان کاربر ربات نمایش می‌دهد.

روش رایج توسعه‌دهندگان پایتون، صادر کردن توکن‌های محرمانه به‌عنوان متغیرهای محیطی (environment variables) است. دوباره در ترمینال، توکن اسلک را با نام SLACK_BOT_TOKEN صادر کنید:

shellexport SLACK_BOT_TOKEN='your bot user access token here'

عالی، حالا مجازیم به‌عنوان کاربر ربات از Slack RTM و Web APIs استفاده کنیم.

کدنویسی Starter Bot

همه‌چیزهایی را که برای نوشتن کد Starter Bot نیاز داریم در اختیار داریم. فایل جدیدی به نام starterbot.py بسازید و کد زیر را داخل آن قرار دهید.

pyimport os
import time
import re
from slackclient import SlackClient

با وابستگی‌های واردشده می‌توانیم مقادیر متغیرهای محیطی را به‌دست آوریم و سپس کلاینت Slack را نمونه‌سازی (instantiate) کنیم.

py# نمونه‌سازی کلاینت Slack
slack_client = SlackClient(os.environ.get('SLACK_BOT_TOKEN'))
# شناسهٔ کاربری starterbot در اسلک: مقدار پس از راه‌اندازی ربات نسبت داده می‌شود
starterbot_id = None

# ثابت‌ها
RTM_READ_DELAY = 1  # تاخیر ۱ ثانیه‌ای بین خواندن از RTM
EXAMPLE_COMMAND = "do"
MENTION_REGEX = "^<@(|[WU].+?)>(.*)"

این کد کلاینت SlackClient را با SLACK_BOT_TOKEN که به‌عنوان متغیر محیطی صادر شده است، نمونه‌سازی می‌کند. همچنین متغیری را اعلان می‌کند که می‌توانیم برای ذخیرهٔ شناسهٔ کاربری Slack استارتربات از آن استفاده کنیم. چند ثابت (constant) نیز اعلان شده‌اند که هرکدام هنگام استفاده در کدِ در ادامه، توضیح داده می‌شوند.

pyif __name__ == "__main__":
    if slack_client.rtm_connect(with_team_state=False):
        print("Starter Bot connected and running!")
        # خواندن شناسهٔ کاربری ربات با فراخوانی متد Web API به نام `auth.test`
        starterbot_id = slack_client.api_call("auth.test")["user_id"]
        while True:
            command, channel = parse_bot_commands(slack_client.rtm_read())
            if command:
                handle_command(command, channel)
            time.sleep(RTM_READ_DELAY)
    else:
        print("Connection failed. Exception traceback printed above.")

کلاینت Slack به RTM API اسلک متصل می‌شود. پس از اتصال، یک متد Web API (auth.test) را برای یافتن شناسهٔ کاربری Starter Bot فراخوانی می‌کند.

هر کاربر ربات برای هر فضای کاری‌ای که Slack App در آن نصب شده است، یک شناسهٔ کاربری دارد. ذخیرهٔ این شناسهٔ کاربری به برنامه کمک می‌کند بفهمد آیا کسی در یک پیام، ربات را اشاره (mention) کرده است یا نه.

سپس برنامه وارد یک حلقهٔ بی‌نهایت (infinite loop) می‌شود؛ در هر بار اجرای حلقه، کلاینت هر رویدادی (event) را که از RTM API اسلک رسیده است دریافت می‌کند. توجه کنید که قبل از پایان حلقه، برنامه یک ثانیه مکث می‌کند تا خیلی سریع لوپ نزند و زمان پردازندهٔ شما را هدر ندهد.

برای هر رویدادی که خوانده می‌شود، تابع parse_bot_commands() تعیین می‌کند که آیا رویداد شامل یک دستور برای Starter Bot است یا نه. اگر باشد، command مقداری خواهد داشت و تابع handle_command() تعیین می‌کند با دستور چه کاری انجام دهد.

ما زمینهٔ پردازش رویدادهای اسلک و فراخوانی متدهای اسلک را در برنامه فراهم کرده‌ایم. حالا سه تابع جدید بالای قطعهٔ کد قبلی اضافه کنید تا مدیریت دستورها کامل شود:

pydef parse_bot_commands(slack_events):
    """
        فهرستی از رویدادهای دریافتی از RTM API اسلک را تجزیه می‌کند تا دستورهای ربات را پیدا کند.
        اگر یک دستور ربات پیدا شود، این تابع یک تاپل (tuple) از دستور و کانال برمی‌گرداند.
        اگر پیدا نشود، این تابع None, None برمی‌گرداند.
    """
    for event in slack_events:
        if event["type"] == "message" and not "subtype" in event:
            user_id, message = parse_direct_mention(event["text"])
            if user_id == starterbot_id:
                return message, event["channel"]
    return None, None

def parse_direct_mention(message_text):
    """
        یک اشارهٔ مستقیم (اشاره‌ای که در ابتدای پیام است) را در متن پیام پیدا می‌کند
        و شناسهٔ کاربری را که اشاره شده است برمی‌گرداند. اگر اشارهٔ مستقیمی وجود نداشته باشد، None برمی‌گرداند
    """
    matches = re.search(MENTION_REGEX, message_text)
    # گروه اول شامل نام کاربری و گروه دوم شامل بقیهٔ پیام است
    return (matches.group(1), matches.group(2).strip()) if matches else (None, None)

def handle_command(command, channel):
    """
        اگر دستور شناخته شده باشد، آن را اجرا می‌کند
    """
    # پاسخ پیش‌فرض، متن راهنما برای کاربر است
    default_response = "Not sure what you mean. Try *{}*.".format(EXAMPLE_COMMAND)

    # دستور داده‌شده را پیدا و اجرا می‌کند و پاسخ را پر می‌کند
    response = None
    # اینجاست که شروع به پیاده‌سازی دستورهای بیشتر می‌کنید!
    if command.startswith(EXAMPLE_COMMAND):
        response = "Sure...write some more code then I can do that!"

    # ارسال پاسخ به کانال
    slack_client.api_call(
        "chat.postMessage",
        channel=channel,
        text=response or default_response
    )

تابع parse_bot_commands() رویدادها را از اسلک می‌گیرد و تعیین می‌کند که آیا دستورهایی هستند که به Starter Bot هدف گرفته شده‌اند. انواع رویدادهای بسیاری وجود دارد که ربات ما با آن‌ها مواجه خواهد شد، اما برای یافتن دستورها فقط می‌خواهیم رویدادهای پیام (message events) را در نظر بگیریم. رویدادهای پیام همچنین زیرنوع‌هایی (subtypes) دارند، اما دستورهایی که می‌خواهیم پیدا کنیم هیچ زیرنوع تعریف‌شده‌ای ندارند. این تابع رویدادهای بی‌اهمیت را با بررسی این ویژگی‌ها فیلتر می‌کند. حالا می‌دانیم رویداد نمایانگر یک پیام با مقداری متن است، اما می‌خواهیم بفهمیم آیا Starter Bot در متن اشاره شده است یا نه. تابع parse_direct_mention() تشخیص می‌دهد که آیا متن پیام با یک اشاره شروع می‌شود و سپس آن را با شناسهٔ کاربری‌ای که قبلاً برای Starter Bot ذخیره کرده‌ایم مقایسه می‌کنیم. اگر یکسان بودند، می‌دانیم که این یک دستور ربات است و متن دستور را به‌همراه شناسهٔ کانال برمی‌گردانیم.

تابع parse_direct_mention() از یک عبارت منظم (regular expression) استفاده می‌کند تا تشخیص دهد آیا کاربری در ابتدای پیام اشاره شده است یا نه. شناسهٔ کاربری و بقیهٔ پیام را برمی‌گرداند (و اگر اشاره‌ای پیدا نشود، None, None برمی‌گرداند).

آخرین تابع، handle_command()، جایی است که در آینده همهٔ دستورهای جالب، شوخی‌ها و شخصیت Starter Bot را اضافه خواهید کرد. فعلاً فقط یک دستور نمونه دارد: do. اگر دستور با یک دستور شناخته‌شده شروع شود، پاسخ مناسبی خواهد داشت. اگر نه، از یک پاسخ پیش‌فرض استفاده می‌شود. پاسخ با فراخوانی متد Web API chat.postMessage با کانال، به اسلک بازگردانده می‌شود.

یادداشت تکمیلی: در حال حاضر یک مشکل شناخته‌شده بین بستهٔ websocket و گواهی CA که استفاده می‌کند وجود دارد؛ بنابراین اگر با خطایی مانند این مواجه شدید:

چند کار می‌توانید انجام دهید:
  1. کاهش نسخهٔ کتابخانهٔ websocket-client به 0.47.0
  2. یا دانلود گواهی (wget https://www.tbs-certificats.com/issuerdata/DigiCertGlobalRootCA.crt) و سپس تنظیم متغیر محیطی export WEBSOCKET_CLIENT_CA_BUNDLE=DigiCertGlobalRootCA.crt

جمع‌بندی

خوب، حالا یک Starter Bot ساده دارید که جاهای زیادی در کد دارد که می‌توانید هر ویژگی که می‌خواهید بسازید را به آن اضافه کنید.

کارهای بسیار بیشتری می‌توان با RTM API اسلک و پایتون انجام داد. این نوشته‌ها را ببینید تا یاد بگیرید چه کارهایی می‌توانید انجام دهید:

  • پیوستن یک پایگاه‌دادهٔ رابط‌ای (relational database) یا پشتیبان NoSQL مانند PostgreSQL، MySQL یا SQLite برای ذخیره و بازیابی داده‌های کاربران
  • افزودن کانال دیگری برای تعامل با ربات از طریق پیامک (SMS) یا تماس تلفنی
  • یکپارچه‌سازی سایر Web APIها مانند GitHub یا Twilio
  • بررسی سایر Slack Platform APIs و دلایل استفاده از یکی به‌جای دیگری
  • ساخت یک ربات خوشامدگویی (onboarding bot) با استفاده از Slack Events API
