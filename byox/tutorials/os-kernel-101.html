Kernel 101 — نوشتن اولین هسته‌ی خود (ارجون سری‌داران)

۱. ایدهٔ اصلی

این آموزش دو هستهٔ اولیه را می‌سازد: یکی به زبان اسمبلی و دیگری به زبان C — هر دو با ابزار GRUB بوت می‌شوند تا مجبور نباشیم خودمان بوت‌لودر بنویسیم. هدف، نشان دادن «ساده‌ترین چیزی که هسته‌ی قابل بوت نامیده می‌شود» است: یک فایل ELF که روی صفحه «Hello World» چاپ می‌کند.

۲. کرنل اسمبلی: ورود GRUB و چند وقفه

وقتی GRUB بوت می‌شود، بر اساس استاندارد Multiboot هسته را بارگذاری می‌کند و کنترل را می‌سپارد. یک نکتهٔ ظریف: در این مرحله ESP تعریف‌نشده است (GRUB مقدار قابل اعتمادی برای پشته نمی‌گذارد)، پس اولین کار هسته، ساخت یک پشته برای خودش است:

nasm; kernel.asm — هسته‌ی اسمبلی: تعریف پشته و چاپ پیام
bits 32
section .text

global start
start:
    mov esp, stack_top  ; ساخت پشته (الزامی! ESP تعریف‌نشده است)
    call kmain          ; پرش به کد اصلی
    hlt                 ; توقف پردازنده

section .bss
resb 8192               ; ۸ کیلوبایت فضای پشته
stack_top:

۳. کرنل C: چاپ مستقیم روی حافظهٔ VGA

نسخهٔ C، نکته‌ای زیبا دارد: به‌جای هیچ سیستمی، کافی است در حافظهٔ ویدیویی 0xB8000 (حالت متن VGA) بنویسد. هر کاراکتر = ۲ بایت (کد کاراکتر + ویژگی رنگ). تابع kmain برای هر حرف، ویژگی سبز روی مشکی را می‌نویسد:

c// kmain.c — هسته‌ی C: چاپ در حافظه‌ی ویدیویی VGA
#define VGA_ADDRESS 0xB8000
#define WHITE_ON_BLACK 0x0f00
#define GREEN_ON_BLACK 0x2a00

void kmain(void) {
    const char *str = "my first kernel";
    unsigned short *vga = (unsigned short *) VGA_ADDRESS;

    for (int i = 0; str[i] != '\0'; ++i) {
        vga[i] = GREEN_ON_BLACK | str[i];
    }

    for (;;) {        // حلقه‌ی بی‌پایان: هسته «تمام شد»
        __asm__("hlt");
    }
}

۴. کامپایل و اجرا

کرنل C به یک فایل ELF 32 بیتی لینک می‌شود (آدرس 1MB به بالا) و سپس فایل‌های kernel و grub با ابزار grub-mkrescue در یک ISO بوت‌شونده قرار می‌گیرند:

bash# کامپایل و لینک کرنل
gcc -m32 -c kernel.c -o kernel.o
ld -m elf_i386 -T link.ld kernel.o -o kernel

# ساخت ISO بوت‌شونده با GRUB
grub-mkrescue -o os.iso kernel_dir

# اجرا در QEMU
qemu-system-i386 -cdrom os.iso

بعد از چند ثانیه، عبارت «my first kernel» روی صفحهٔ QEMU دیده می‌شود.

۵. چرا این آموزش مهم است؟

  • کوتاه‌ترین مسیر ممکن به یک «کرنل واقعی» — بدون دردسر نوشتن بوت‌لودر.
  • مفهوم Multiboot را شفاف و با مثال یاد می‌دهد.
  • لینک‌دادن و ELF برای bare-metal با فایل لینکر توضیح داده شده.
  • پل خوبی به Kernel 201 (همین نویسنده) است که ورودی صفحه‌کلید و صفحه‌نمایش را اضافه می‌کند.
