ugit — درون‌های گیت را با ساختن خود گیت یاد بگیر

⚙ زبان: Python ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمه فارسی «Git Internals - Learn by Building Your Own Git» از نیکیتا لشنکو (Nikita Leshenko) است — آموزش تعاملی مرحله‌ای (با commitهای قابل پیمایش، diff و قابلیت Clone روی گیت‌هاب و کامنت) که درون‌های گیت را با ساختن ugit از صفر می‌آموزد. باید با گیت آشنا باشید و راحتی کار با commit، branch، merge و push را تجربه کرده باشید؛ این آموزش دربارهٔ «استفاده» از گیت نیست، بلکه برای کسانی است که می‌خواهند «چگونگی» کار درون آن را درک کنند. آموزش ساختار جذابی دارد: هر گام یک تغییر کد مشخص (diff) است با توضیح کامل در کنار آن؛ در همان صفحه می‌توانید هر گام را Checkout کنید، diff آن را ببینید، برای آن کامنت بگذارید (ورود با گیت‌هاب) و کل محتوای آموزش را Clone کنید (لینک Download در صفحه).
↗ مشاهده منبع اصلی

آموزش چیست؟

گیت سیستم بزرگی است و می‌تواند ترسناک به نظر برسد، اما درون‌های آن در واقع بسیار ساده‌اند. بهترین راه برای درک آن، ساختن یک نسخه از روی گیت از صفر است: این همان چیزی است که در این آموزش انجام می‌دهیم.

ugit ("یوگیت") پیاده‌سازی آموزشی گیت در پایتون است. در طول دوره با ساختن گام‌به‌گام آن، این مفاهیم را یاد می‌گیرید: ساختار objectهای گیت (blob، tree، commit و tag)، هش‌ها و فایل‌سیستم content-addressed، فایل index و ناحیه stage، refها و شاخه‌ها، HEAD، merge، و دستورهای add، commit، log، diff، show، branch، checkout، merge، status و... — همه فقط با کتابخانه استاندارد پایتون.

این آموزش ساختار تعاملی دارد: هر گام یک تغییر کد مشخص با توضیح کنار آن است؛ همان‌طور که در جعبهٔ منبع بالا گفته شد، در خود صفحه می‌توانید هر گام را Checkout و diff کنید و کامنت بگذارید.

روش گام‌به‌گام

دوره در بخش‌هایی با نام commitهای مختلفِ مخزن ugit سازمان‌یافته است. سرفصل‌های اصلی:

  1. مقدمه — چرا گیت را بسازیم؛ آناتومی گیت: پایگاه داده اشیاء، فایل index، refها
  2. خواندن و نوشتن اشیاء — قالب ذخیره‌سازی (نوع + جداکننده + محتوا، با sha1 در نام فایل)، hash-object و cat-file
  3. blob، tree و commit — درخت‌های پوشه، عکس فوری‌ها، زنجیره والدها، Merkle tree و خواص content-addressing (همان محتوا = همان هش؛ تغییر کوچک = هش کاملاً متفاوت)
  4. refs و branchها — فایل‌های refs/heads، HEAD و وضعیت detached
  5. index و stage — قالب باینری index، add و وضعیت‌ها (staged, modified, untracked)
  6. merge — پیدا کردن جد مشترک، merge سه‌جانبه (three-way)، fast-forward و تعارض‌ها
ترمینال$ python3 ugit init
$ python3 ugit add README.md
$ python3 ugit commit -m "First commit"
$ python3 ugit log
$ python3 ugit checkout 
$ python3 ugit merge

هر گام با «آزمون رفتاری» همراه است: قبل از کدنویسی مشخص می‌کنید رفتار موردنظر چیست، بعد کد واقعی گام را پیاده می‌کنید. مثلاً خواندن یک شیء یعنی: باز کردن فایل objects/<sha>، جداسازی نوع با partition(b'\x00') و برگرداندن محتوا — همین چند خط، قلب خواندن هر شیء گیتی است.

مثال واقعی کد — خواندن یک شیء

یک تفاوت مهم که در خود آموزش هم تصریح شده: برخلاف گیتِ واقعی، ugit برای سادگی آموزشی اشیاء را فشرده نمی‌کند (بدون zlib)، حالت اجرایی فایل‌ها و زمان ثبت commit را ذخیره نمی‌کند. نام فایل هر شیء هش sha1 آن است و قالب داخلی آن ساده است. توابع اصلی که در گام‌های آغازین نوشته می‌شوند (مطابق کد واقعی آموزش):

pythondef hash_object(data, type_='blob'):
    obj = type_.encode() + b'\x00' + data
    oid = hashlib.sha1(obj).hexdigest()
    with open(f'{GIT_DIR}/objects/{oid}', 'wb') as out:
        out.write(obj)
    return oid

def get_object(oid, expected='blob'):
    with open(f'{GIT_DIR}/objects/{oid}', 'rb') as f:
        obj = f.read()
    type_, _, content = obj.partition(b'\x00')
    type_ = type_.decode()
    assert type_ == expected, f'Expected {expected}, got {type_}'
    return content

چرا این کار ارزشش را دارد؟

  • می‌فهمید دستورهای گیت که هر روز استفاده می‌کنید واقعاً چه کار می‌کنند (add, commit, log, branch, checkout, merge, status, diff...)
  • خواص شگفت‌انگیز مدل داده گیت را می‌بینید: deduplication خودکار (همان محتوا = همان هش)، یکپارچگی داده با هش‌ها، و تاریخچه تغییرناپذیر
  • مهارت‌های سیستم‌سازی و کار با فایل‌سیستم/فشرده‌سازی را تمرین می‌کنید

در پایان دوره، ugit شما (چند صد خط پایتون خالص، بدون هیچ وابستگی خارجی) همه دستورهای اصلی را در یک مخزن محلی پیاده می‌کند: init، hash-object، cat-file، write-tree، read-tree، commit، log، status، diff، show، branch، checkout، merge، rebase و push/pull — و سپس می‌بینید که مدل دادهٔ گیت واقعی تا چه حد به همین سادگی است. برای دیدن نمونهٔ کد کامل، fork های عمومی ugit در گیت‌هاب (مانند VarunBarad/ugit) در دسترس‌اند.
