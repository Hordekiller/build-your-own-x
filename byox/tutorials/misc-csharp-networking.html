چرا شبکه با پروژه؟

بسیاری از آموزش‌های شبکه فقط «API» را معرفی می‌کنند؛ اما این مجموعه هر مفهوم را به‌صورت یک پروژهٔ کامل و اجرایی (چت، بازی، pong) می‌سازد. این رویکرد باعث می‌شود «چرا» و «چطور» هر تصمیم (TCP یا UDP، بافر و encode) را عمیقاً بفهمید.

TCP: سرور چت

اولین پروژه، سرور چت TCP است که چند کلاینت را نگه می‌دارد و پیام‌ها را بین آن‌ها پخش می‌کند. نکتهٔ اصلی، همزمان‌سازی است: هر کلاینت به یک نخ (یا async) اختصاص دارد و پیام باید atomic ارسال شود:

C#// سرور چت ساده با پذیرش client و پخش پیام
using System.Net.Sockets;
using System.Text;

var listener = new TcpListener(System.Net.IPAddress.Any, 8888);
listener.Start();
Console.WriteLine("سرور آماده است...");

while (true) {
    TcpClient client = listener.AcceptTcpClient();
    _ = Task.Run(() => HandleClient(client));
}

void HandleClient(TcpClient client) {
    using var stream = client.GetStream();
    byte[] buffer = new byte[1024];
    while (true) {
        int read = stream.Read(buffer, 0, buffer.Length);
        if (read == 0) break;                    // کلاینت بسته شد
        string msg = Encoding.UTF8.GetString(buffer, 0, read);
        Broadcast($"[{client.Client.RemoteEndPoint}] {msg}");
    }
}

با این ساختار ساده، اولین چت چندکلاینت کار می‌کند. گام بعدی، پروتکل encode (طول پیام + داده) است تا پیام‌های طولانی به‌درستی جدا شوند.

UDP: Pong

بازی‌های سریع مثل Pong با UDP انجام می‌شوند چون تأخیر کم مهم‌تر از تضمین همهٔ پیام‌هاست. در UDP، هر بسته باید خودش حاوی همهٔ اطلاعات (مثلاً وضعیت کامل بازی) باشد:

C#// ارسال وضعیت بازی با UDP (هر فریم)
using System.Net;
using System.Net.Sockets;
using System.Text;

var socket = new Socket(AddressFamily.InterNetwork,
                        SocketType.Dgram, ProtocolType.Udp);
var server = new IPEndPoint(IPAddress.Parse("127.0.0.1"), 9000);

// وضعیت بازی: موقعیت‌ها را به یک رشته تبدیل می‌کنیم
string state = $"{paddle1X};{paddle1Y};{ballX};{ballY}";
byte[] data = Encoding.UTF8.GetBytes(state);
socket.SendTo(data, server);

نکتهٔ حیاتی UDP: اگر یک بسته گم شود، جایگزینش به کمک «بستهٔ بعدی» می‌آید؛ پس هر بسته باید نسخهٔ کامل وضعیت باشد.

بازی TCP چندنفره

در پایان، یک بازی گرافیکی ساده ساخته می‌شود که کلاینت‌ها روی TCP با هم ارتباط دارند و رویدادهای بازی (حرکت، ضربه) به سرور reporting می‌شود و سرور به همه پخش می‌کند.
