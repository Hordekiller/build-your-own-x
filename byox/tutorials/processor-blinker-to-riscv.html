از چراغ چشمک‌زن تا پردازنده RISC-V (From Blinker to RISC-V) — FemtoRV

⚙ زبان: Verilog 📚 برد: IceStick / IceBreaker / ULX3S ✅ ترجمه شده 🔗 منبع اصلی
منبع اصلی: این صفحه ترجمهٔ فارسی و مرور آموزش «From Blinker to RISC-V» از برونو لوی (Bruno Levy) در مخزن FemtoRV است؛ یک سفر تدریجی از یک طراحی سادهٔ «چشمک‌زن» تا یک هستهٔ کامل RISC-V که در پایان فقط حدود ۲۰۰ خط Verilog دارد.
↗ مشاهده منبع اصلی

۱. ایدهٔ کلی: چرا این سفر باورکردنی نیست؟

پردازنده‌ها در ذهن اکثر ما «جعبه‌های سیاه» هستند، اما این آموزش نشان می‌دهد که یک پردازندهٔ کاربردی تا چه اندازه می‌تواند ساده باشد. شما از یک بلینکی (چشمک‌زن LED) شروع می‌کنید و قدم‌به‌قدم، همان مدار را به یک ریزکنترلر RV32I کامل تبدیل می‌کنید که قادر است کد C کامپایل‌شده را اجرا کند. بخش شگفت‌انگیز آموزش این جمله است: «پردازنده‌ای که در قدم ۱۶ می‌سازیم بیشتر از ۲۰۰ خط Verilog نیست — من وقتی فهمیدم ساختن یک پردازنده این‌قدر ساده است، حیرت‌زده شدم.»

آموزش با این بردها کار می‌کند: IceStick (Ice40HX1K) — کوچک‌ترین و ارزان‌ترین — و همچنین IceBreaker، ULX3S، ARTY و Tang Nano 9K. با همین کوچک‌ترین FPGA می‌توانید کل آموزش را جلو ببرید و در پایان یک ریزکنترلر RV32I داشته باشید.

  • هر قدم یک پوشه با فایل stepN.v دارد؛ می‌توانید با شبیه‌سازی (icarus verilog) یا روی برد واقعی پیش بروید.
  • پیش‌نیاز خاصی جز آشنایی مقدماتی با سخت‌افزار و کمی صبر ندارید؛ Verilog را هم در حین کار یاد می‌گیرید.
  • کل آموزش حول یک ماژول SOC می‌چرخد — «نام بزرگی برای یک بلینکی، اما همین است که در نهایت به System-on-Chip تبدیل می‌شود».

۲. قدم ۱ و ۲: اولین بلینکی و بلینکی آهسته

اولین کد، یک ماژول Verilog ساده است که شمرده شمرده LEDهای برد را روشن می‌کند. ورودی/خروجی‌های ثابت کل آموزش همین‌ها هستند: ساعت (CLK)، دکمهٔ ریست (RESET)، ۵ LED (LEDS) و دو سیم RXD/TXD که به چیپ FTDI وصل‌اند — همان چیزی که بعداً تبدیل به خروجی سریال (UART) می‌شود:

verilogmodule SOC (
    input  CLK,
    input  RESET,
    output [4:0] LEDS,
    input  RXD,
    output TXD
);
   reg [4:0] count = 0;
   always @(posedge CLK) begin
      count <= count + 1;
   end
   assign LEDS = count;
   assign TXD  = 1'b0; // فعلاً استفاده نمی‌شود
endmodule

در قدم ۲ یک ماژول Clockworks معرفی می‌شود: یک «گیربکس» که فرکانس ساعت را تقسیم می‌کند (.SLOW(21) یعنی تقسیم بر ۲۲۱) تا تغییر LEDها با چشم قابل‌دیدن شود، و همچنین مدار ریست — چون IC40 در ابتدا مشکل راه‌اندازی دارد و باید مدار ریست آن را دور بزند. نکتهٔ سخت‌افزاری جالبی است که در شبیه‌سازی هرگز آن را نمی‌بینید، اما روی سخت‌افزار واقعی ضروری است.

۳. قدم ۳ و ۴: حافظه، شمارندهٔ برنامه و رمزگشای دستور

قدم ۳ مفهوم کلیدی را معرفی می‌کند: شمارندهٔ برنامه (PC). در این قدم به‌جای شمارندهٔ ساده، الگوهای LED از یک حافظهٔ از‌پیش‌پر (MEM[PC]) خوانده می‌شوند — همان مکانیزم «fetch» که قلب هر پردازنده است:

verilog   reg [4:0] PC  = 0;
   reg [4:0] leds = 0;
   always @(posedge clk) begin
      leds <= MEM[PC];
      PC   <= (!resetn || PC==20) ? 0 : (PC+1);
   end

قدم ۴ اولین نگاه واقعی به دستورهای RISC-V است: حافظه را با کلمه‌های ۳۲-بیتیِ دستور پر می‌کنیم و رمزگشا یاد می‌گیرد هر دستور را از روی instr[6:0] (opcode) بشناسد. جدول رمزگشای کلاسیک RISC-V (همان جدول صفحهٔ ۱۳۰ مرجع رسمی) اینجا معرفی می‌شود:

verilog   wire isALUreg  = (instr[6:0] == 7'b0110011); // rd <- rs1 OP rs2
   wire isALUimm  = (instr[6:0] == 7'b0010011); // rd <- rs1 OP Iimm
   wire isBranch  = (instr[6:0] == 7'b1100011); // if(rs1 OP rs2) PC<-PC+Bimm
   wire isJALR    = (instr[6:0] == 7'b1100111); // rd <- PC+4; PC<-rs1+Iimm
   wire isJAL     = (instr[6:0] == 7'b1101111); // rd <- PC+4; PC<-PC+Jimm
   wire isAUIPC   = (instr[6:0] == 7'b0010111); // rd <- PC + Uimm
   wire isLUI     = (instr[6:0] == 7'b0110111); // rd <- Uimm
   wire isLoad    = (instr[6:0] == 7'b0000011); // rd <- mem[rs1+Iimm]
   wire isStore   = (instr[6:0] == 7'b0100011); // mem[rs1+Simm] <- rs2
   wire isSYSTEM  = (instr[6:0] == 7'b1110011); // ویژه

همچنین ۵ قالب Immediate (U/I/S/B/J) با یک خط Verilog معرفی می‌شوند — با گسترش علامت (sign extension) — و پنج «کاراکتر» این قالب‌ها بعداً کلید محاسبهٔ آدرس‌های پرش می‌شوند.

۴. قدم ۵ تا ۷: بلوک ثبات، ماشین حالت و ALU

قدم ۵ بلوک ثبات — آرایه‌ای از ۳۲ ثبات ۳۲-بیتی (RegisterBank [0:31]) — و ماشین حالت پردازنده را اضافه می‌کند؛ همین ماشین حالتی که در کل مسیر می‌ماند:

verilog   // The state machine — بن‌مایهٔ ماشین حالت همهٔ پردازنده‌ها
   localparam FETCH_INSTR = 0;   // درخواست خواندن دستور
   localparam WAIT_INSTR  = 1;   // منتظر رسیدن دستور از حافظه
   localparam FETCH_REGS  = 2;   // خواندن rs1 و rs2 از بلوک ثبات
   localparam EXECUTE     = 3;   // اجرا/محاسبه
   localparam LOAD        = 4;   // درخواست خواندن داده
   localparam WAIT_DATA   = 5;   // منتظر رسیدن داده
   localparam STORE       = 6;   // نوشتن در حافظه
   reg [2:0] state = FETCH_INSTR;

قدم ۶ واحد محاسبهٔ منطقی (ALU) است: جمع/تفریق، مقایسه‌های LT/LTU، XOR/OR/AND و شیفت (SLL/SRL/SRA) — حتی برای شیفت‌ها یک «بشکه‌شکن» دو-مرحله‌ای برای صرفه‌جویی در سلول‌ها. نکتهٔ ظریف: دستور ADD و SUB هر دو opcode یک‌سانی دارند و تفاوتشان در بیت funct7[5] است؛ آموزش این الگوهای ظریف رمزگشایی را دقیق توضیح می‌دهد.

قدم ۷ یک هدیهٔ سخت‌افزاری است: اسمبلر Verilog (riscv_assembly.v). به‌جای اینکه بردار ۳۲-بیتی دستورها را با دست بنویسید، برنامه‌ها را با اسمبلی استاندارد (مثل LI، SW، ADD…) می‌نویسید و هنگام سنتز/شبیه‌سازی، همین اسمبلر ماکروها را به کد ماشین تبدیل می‌کند:

verilog   // شمارش ۰ تا ۱۵ روی LEDها و فرستادن abcdef...xyz روی UART
   LI(s0,16);          // حد بالای حلقه
   LI(a0,0);
   Label(L1_);
   SW(a0,gp,IO_BIT_TO_OFFSET(IO_LEDS_bit));  // نوشتن روی LEDها
   CALL(LabelRef(wait_));
   ADDI(a0,a0,1);
   BNE(a0,s0,LabelRef(L1_));

۵. قدم ۸ تا ۱۱: پرش‌ها، شاخه‌ها و حافظهٔ مستقل

قدم ۸ پرش‌های بدون قید (JAL/JALR) را اضافه می‌کند — و این‌جا یک تصمیم سخت‌افزاری واقعی گرفته می‌شود: آدرس پرش با یک adder مشترک محاسبه می‌شود تا سلول‌های FPGA هدر نرود (PCplusImm که برای Branch و JAL و AUIPC به‌طور مشترک استفاده می‌شود). قدم ۹ شاخه‌های شرطی است: تابع takeBranch که برای هر funct3 مقایسهٔ درست را انتخاب می‌کند (BEQ/BNE/BLT/BGE/BLTU/BGEU). قدم ۱۰ دو دستور LUI و AUIPC را با تغییر تنها writeBackEn و writeBackData اضافه می‌کند:

verilog   assign writeBackData = (isJAL || isJALR) ? PCplus4 :
                          isLUI  ? Uimm :
                          isAUIPC? PCplusImm :
                          isLoad ? LOAD_data :
                                   aluOut;

   wire [31:0] nextPC = ((isBranch && takeBranch) || isJAL) ? PCplusImm :
                        isJALR ? {aluPlus[31:1],1'b0} :
                                 PCplus4;

قدم ۱۱ پردازنده را تمیز تقسیم می‌کند: حافظه به یک ماژول جدا (Memory) منتقل می‌شود و پردازنده فقط از طریق سیگنال‌های mem_addr/mem_rdata/ mem_rstrb با آن حرف می‌زند — دقیقاً همان شکلی که یک گذرگاه حافظه در SoCهای واقعی طراحی می‌شود.

۶. قدم‌های پایانی: Load/Store، IO نگاشت‌شده و UART

در قدم‌های بعد، دستورهای Store و Load با مدیریت دقیق ترازبندی (byte/halfword/word) پیاده می‌شوند؛ مدار Load باید بسته به funct3 و بیت‌های آدرس، بایت/نیم‌کلمهٔ درست را از دادهٔ ۳۲-بیتی برگزیند و بسته به علامت‌دار بودن، گسترش علامت بدهد. مرحلهٔ پایانی — Memory-mapped IO — قشنگ‌ترین بخش است: پردازنده به‌جای سیم‌های اضافه، LEDها و UART را مثل حافظه می‌بیند؛ کافی است مقدار را در آدرس ثابتی بنویسد (صفحهٔ IO در آدرس 0x400000) و یک دیکودر آدرس، نوشتن را به LED یا فرستندهٔ سریال می‌رساند:

verilog   localparam IO_LEDS_bit    = 0; // W  پنج LED
   localparam IO_UART_DAT_bit= 1; // W  داده برای ارسال (۸ بیت)
   localparam IO_UART_CNTL_bit=2; // R  وضعیت؛ بیتِ ۹: مشغول ارسال

   always @(posedge clk) begin
      if(isIO & mem_wstrb & mem_wordaddr[IO_LEDS_bit]) begin
         LEDS <= mem_wdata;          // نوشتن روی LEDها مثل یک ثبات حافظه
      end
   end

   corescore_emitter_uart #(.clk_freq_hz(`CPU_FREQ*1000000)) UART(
      .i_clk(clk), .i_rst(!resetn),
      .i_data(mem_wdata[7:0]), .i_valid(uart_valid), .o_ready(uart_ready),
      .o_uart_tx(TXD));

و نتیجه؟ یک ریزکنترلر RV32I که کد کمپایل‌شده با ابزار GNU RISC-V را اجرا می‌کند — در C یا اسمبلی. کل SoC (پردازنده + حافظه ۶ کیلوبایتی + UART + LED) روی IceStick با کمتر از ~۱۱۸۰ سلول LUT جا می‌شود و با فرکانس ۸۰ مگاهرتز اجرا می‌شود. نسخهٔ دوم آموزش (PIPELINE.md) همین پردازنده را به یک نسخهٔ Pipeline پنج‌مرحله‌ای تبدیل می‌کند.

۷. چه چیزهایی یاد می‌گیرید

  • آناتومی یک CPU: fetch/decode/execute، بلوک ثبات، ALU، پرش‌ها و شاخه‌ها — بدون هیچ جعبهٔ سیاهی.
  • اصول FPGA: ماژول‌های Verilog، گیربکس ساعت، مدار ریست، شبیه‌سازی با Icarus Verilog.
  • هم‌صحبتی با سخت‌افزار: Memory-mapped IO و طراحی SoC با UART.
  • ابزارهای واقعی: اسمبلر داخل Verilog، کامپایل C با تارگت RV32I، تبدیل ELF به firmware.hex و اجرا از SPI Flash.
نکته: کل آموزش منبع‌باز است و فایل‌های stepN.v هر قدم همراه کد کامل در دسترس‌اند. اگر برد خیلی ارزانی مثل IceStick (حدود ۳۰ دلار) دارید، می‌توانید قدم‌به‌قدم بدون هیچ ابزار مالکیتی (ابزار متن‌باز IceStorm: Yosys + nextpnr + iceprog) جلو بروید — همه‌چیز از جنس «خودت بساز» است.

۸. جمع‌بندی

«از چراغ چشمک‌زن تا RISC-V» ثابت می‌کند فاصلهٔ یک مدار ۵ خطی تا یک پردازندهٔ واقعی، فقط ۱۵ قدمِ کوچک است. در پایان، افسانهٔ CPU برای همیشه برایتان شکسته می‌شود: «من حیرت‌زده شدم که ساختن یک پردازنده این‌قدر ساده است.»

کپیرایت: آموزش «From Blinker to RISC-V» و پروژهٔ FemtoRV اثر برونو لوی (Bruno Levy) است و در مخزن متن‌باز learn-fpga/FemtoRV (لایسنس MIT) منتشر شده. تمام حقوق محتوا، تصاویر و کدها متعلق به نویسندهٔ اصلی است. سایت اصلی
